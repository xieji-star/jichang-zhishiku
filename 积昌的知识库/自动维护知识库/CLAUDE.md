# CLAUDE.md — LLM Wiki 维护指令

> 本文档定义了"自动维护知识库"Wiki 的结构、约定和维护工作流。
> 它是让 Claude 成为一个有纪律的 Wiki 维护者的关键配置文件。

## 架构三层

| 层级 | 位置 | 角色 | 权限 |
|------|------|------|------|
| **原始来源（Raw Sources）** | `../总结好的大纲以及笔记/` | 不可变的源文件（文章、笔记、PDF、图片） | **只读** —— 绝不修改 |
| **Wiki（知识库）** | `自动维护知识库/wiki/` | Claude 生成的结构化 Markdown 文件 | Claude 拥有完全写权限 |
| **Schema（模式）** | `自动维护知识库/CLAUDE.md`（本文件） | 告诉 Claude 如何维护 Wiki | 与用户共同演进 |

## 页面约定

每个 Wiki 页面应包含：

```yaml
---
title: "页面标题"
category: "分类名称"
tags:
  - tag1
  - tag2
source: "[[../总结好的大纲以及笔记/对应源文件路径]]"
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

### 页面内容结构

1. **概述（摘要）**：2-3 句话概括本页核心内容
2. **核心要点**：从原始来源中提取的关键知识
3. **关键概念/术语**：本主题涉及的重要定义
4. **关联页面**：使用 `[[wiki/...]]` 的内部交叉引用
5. **待深入**：标记尚未覆盖的子主题（作为未来摄取或 Lint 的线索）

## 工作流

### 摄取（Ingest）

当用户将新来源添加到 `../总结好的大纲以及笔记/` 并要求处理时：

1. 读取新来源文件
2. 与用户讨论关键要点和强调方向
3. 在 `wiki/` 下创建或更新相关实体/概念页面
4. 更新 `index.md`（添加新页面、更新描述）
5. 在 `log.md` 中追加条目（前缀 `## [YYYY-MM-DD] ingest | 来源标题`）

**粒度指南**：
- 如果来源非常大（>500 行或 >10 个不同主题），可以拆分为多个页面
- 如果来源是已有主题的更新，修改现有页面并注明最新来源
- 每个页面应保持聚焦（一个页面 ≈ 一个实体/概念/方法论）

### 查询（Query）

当用户围绕 Wiki 提问时：

1. 首先读取 `index.md` 以找到相关页面
2. 深入阅读找到的页面
3. 综合给出带引用的答案
4. **如果答案有价值，将其归档回 Wiki 作为新页面**（用户确认后）
   - 对比 → 新页面
   - 分析 → 新页面
   - 发现 → 新页面

### Lint（健康检查）

定期或按用户要求，对 Wiki 进行健康检查：

1. **矛盾检测**：不同页面之间是否有矛盾的断言？
2. **过时声明**：较新的来源是否取代了较旧的说法？
3. **孤立页面**：是否有入站链接为零的页面？
4. **缺失页面**：是否有重要概念被引用但缺少专属页面？
5. **交叉引用缺失**：内容相关但页面之间没有链接吗？
6. **数据缺口**：是否有可以通过网络搜索填补的空白？

## 语言约定

- 所有输出使用**双语**：英文在前，中文（简体中文）在后
- 页面内容以中文为主，必要时附英文术语
- 代码和命令使用原始语言

## 来源引用格式

当引用 `../总结好的大纲以及笔记/` 中的原始来源时，使用 Obsidian 内部链接：

```markdown
来源：[[../总结好的大纲以及笔记/分类/子文件夹/文件名.md]]
```

对于 PDF 来源：
```markdown
来源：[[../总结好的大纲以及笔记/分类/子文件夹/文件名.pdf]]
```

## 关键原则

1. **Wiki 是持久化的复合物**——交叉引用已存在，矛盾已标记，综合已经反映已读的一切
2. **你撰写，用户阅读**——用户负责来源管理和提出正确问题；Claude 完成所有总结、交叉引用和归档
3. **好的答案归档回 Wiki**——用户要求对比、分析或发现的内容具有价值，不应消失在聊天历史中
4. **index.md 是目录**——每次 Lint 通过时都要查它，每次摄取时都要更新它
5. **log.md 是时间线**——所有操作的追加记录，前缀一致，可被简单工具解析
