# 短视频爆款采集系统

## 概述

本项目是一套**本地部署的短视频/推文爆款采集与分析系统**：基于开源 MediaCrawler 框架在本地抓取抖音数据，按统一的 S/A/B/C 评分标准自动识别"爆款"，用于矩阵账号的内容选题与竞品分析。系统以"本地主力 + 云端应急"双架构运行，成本约 **¥0.5/月**，并与付费工具"轻抖"做了差距对比与改进规划。

2026-08 中旬起项目持续迭代，先后落地：**多账号并发池、Edge 登录态克隆、风控/对抗组件、速度专项优化、图文识别、字幕直取评估、前端切换、云端 BUG 修复**（详见「项目演进」章节）。2026-08 下旬（0819-0823）进入 **Codex 多 Agent 接力研发 + 生产门禁（代码总监/物理许可/证据封印）**阶段：**字幕直取找到 APP 端签名直取新路径（douyin-sign 开源签名库）但生产 NO-GO**，新增 **链接采集（Link Collection）**功能（架构获批、实现未投产），并沉淀了 **Codex 交接文档体系**（Codex接力棒 → 0823 交接文档）。

## 核心要点

### 采集架构：MediaCrawler 三模式

| 模式 | 用途 | 说明 |
|------|------|------|
| **detail 模式** | 采集指定作品的详情数据 | 适合对已知爆款做深挖 |
| **creator 模式** | 采集指定创作者的视频列表 | 适合跟踪竞品/对标账号 |
| **search 模式** | 按关键词搜索采集 | 适合选题与热点发现 |

### 双架构：本地主力 + 云端应急

- **本地主力**：日常采集在本地运行，数据不出本机，隐私与稳定性可控
- **云端应急**：本地不可用（如外出/断电）时切到云端节点补采，保证数据不中断

### 出口与触发

- **飞书唯一出口**：采集结果统一汇总到飞书，作为唯一对外出口（与知识库飞书落盘规则一致）
- **开机补采 + 手动触发**：开机自动补采上次未完成的任务，也可手动触发指定采集

### 爆款评分：S/A/B/C 四档

| 档位 | 含义 | 判定 |
|:----:|------|------|
| **S** | 现象级爆款 | 各项数据远超账号基准线 |
| **A** | 优质爆款 | 显著高于基准线 |
| **B** | 中等表现 | 达到基准线 |
| **C** | 普通/不达标 | 低于基准线 |

**评分公式**（加权）：

> **综合分 = 点赞 40% + 评论 30% + 收藏/转发 30%**

不同账号因粉丝量级不同，S/A/B/C 的**基准线各不相同**，需按账号分别校准。

### 成本

本地部署 + 自建采集，全月运行成本约 **¥0.5/月**（主要为云应急节点费用），远低于付费数据工具。

## 与"轻抖"的差距与改进

**轻抖**是市面常见付费工具，其优势在于**字幕直取 + 缓存复用**：

| 维度 | 轻抖 | 本项目（自研） |
|------|------|----------------|
| 字幕获取 | 直接从接口直取 | 下载视频后 CPU 识别（慢） |
| 数据缓存 | 有缓存复用 | 每次重新采集（重复劳动） |
| 处理性能 | 有加速 | CPU 识别慢 |

**五步改进计划进展**（2026-08-17 更新）：

1. **字幕直取** — ✅ 已评估：抖音 **web 端无字幕数据源**（detail 接口无字幕字段、播放器无字幕请求、分享页无 videoInfoRes，多轮实测），结论不可行；替代走 **"下载 + GPU ASR"** 已闭环（149/150 达标）；**APP 端签名直取已找到可行路径**（douyin-sign 开源签名库，见「字幕直取（APP 端签名直取）」），但受生产门禁约束 **NO-GO**
2. **缓存复用** — 部分实现：media_url 落库（转录下载走官方直链）、账号数据落库（douyin_creator）
3. **GPU 加速** — ✅ 转录已接入 GPU ASR（`_asr_8765.py`）
4. **拆开 120s 截止** — 由 **VAD 静音过滤**（长视频转录提速 30-50%）缓解
5. **减少采集层失败** — 已优化：缺 creator_url 账号跳过、云端同步黑名单降噪（消除每轮 150 条无效重试）、采集-转录流水线化

## 项目演进（2026-08 迭代）

### 多账号并发池

- **账号级受控并发**：多账号时每账号独立 CDP 端口 / 登录态目录 / 采集库（防 Cookie 串味）；默认 `MEDIACRAWLER_CONCURRENT_ACCOUNTS=1`（串行，行为零变化）
- **兼容设计**：单账号走老路径（共享登录态），多账号走隔离

### 登录态与 Edge 一次登录

- **Edge 一次登录**：本地增强方案（**不加装 CookieCloud**，登录态不出本机）——克隆原子化（staging→.trash→切换→回滚）+ robocopy 自动刷新 + 三级登录态探测（Cookie 新鲜度→CDP 探测→error_logs 信号），25/25 账号目录克隆成功
- **平台限制**：克隆 Cookie 对**新 Edge 环境不保证免验证**（抖音识别新设备要求扫码）——串行模式（共享登录态）可全自动免扫码
- **Edge 窗口卫生**：任务结束后项目打开的任何窗口一律杀死（账号级/hook级/任务级三层清理）

### 风控与对抗组件

> ⚠️ **2026-08-16 用户决策**：突破原合规红线，①类对抗组件投入使用，接受账号风控/法律风险。

- **保留投产（全部免费且实测可用）**：熔断器、随机错峰、全局限速、指数退避、curl_cffi（Chrome TLS 指纹）、mss 截图、patchright、CloakBrowser、fingerprintjs 自测页
- **删除（付费/无法稳定投产，2026-08-16 用户指令释放硬盘）**：NopeCHA（无 Key）、代理池（缺 HTTPS 源）、nodriver、Botright、haipproxy
- **验证**：十轮测试全部通过、成功率 100%、十轮真实采集**零账号封锁**；新增服务只监听 127.0.0.1 回环，既有链路零破坏

### 速度专项优化（0817）

- 转录工作线 4→6（口播稿并行度 +50%）；错峰收窄 20-60s→15-30s（整轮省 ~2.5 分钟）
- 采集-转录流水线化（单账号 542s→~480s）
- VAD 静音过滤（长视频转录提速 30-50%）；转录异步修复（消除 timed out）
- media_url 落库（转录下载走官方直链）；主页资料并入采集进程（每账号省 ~20s）
- 登录固定等待 env 化；二维码弹图根治（`MEDIACRAWLER_SKIP_QRCODE_DISPLAY`）

### 图文笔记识别

- 图文笔记（aweme_type=163 图文、2 图集）只采数据、**不生成口播稿**——避免把 BGM 歌词当口播稿（历史假成功教训）

### 字幕直取结论

- 抖音 web 端无字幕数据源 → 口播稿走 **"下载 + GPU ASR"**（已闭环 149/150 达标）

### 字幕直取（APP 端签名直取）—— 2026-08 下旬新路径

> ⚠️ **约束性结论：技术方案可行，但生产 NO-GO（保持 OFF）**——信任（字幕域名）/许可/身份/ACL/canary 等外部授权证据缺失，`APP_SUBTITLE_ENABLED` / `SUBTITLE_DIRECT_ENABLED` 保持默认 OFF。

- **"网页端没有字幕"未翻案**；但**抖音 APP 端接口**响应里有字幕字段（`video.cla_info.caption_infos`），此前被 **X-Gorgon / X-Argus / X-Ladon** 设备签名挡住
- **钥匙**：GitHub 开源库 **douyin-sign**（`7452323/douyin-sign`，免费，nightly CI 自动更新签名常量）——签名只是 HTTP 请求头参数，**电脑端模拟 APP 设备头 + 正确签名即可调用 APP 端接口拿到字幕**
- **收益**：单条字幕秒级（~1-2s），比 GPU 转写快 10 倍+、不占 GPU、官方字幕更工整、免费；接入约半天工程
- **架构**：独立本地签名服务（127.0.0.1）与主链路解耦；字幕仍是"第 0 顺位"，不过**三重质量闸门**（≥20字 / 无 BGM 标签 / zh 语言+标题实词交集）自动降级 ASR（安全兜底）
- **风险**：签名算法更新需跟随上游、设备伪装需合理、部分视频无字幕轨道（创作者未开 AI 字幕）→ 正常降级

### 链接采集（Link Collection）—— 2026-08 下旬新功能

> 📌 **产品定位**："不采达人、只采指定视频"——一个任务输入多条不同达人的链接，只采**视频级数据 + 口播稿**；绝不进入达人资料/账号/评论/头像/搜索/热榜/合集/主页路径。

- **GitHub 两轮审批**：全部第三方候选淘汰（yt-dlp/Douyin_TikTok_Download_API 仅作既有参考；TikTokDownloader/f2/MediaCrawler/jiji262 均因越界/凭据暴露/许可证/缺陷被拒）→ 条件获批**洁净本地自研**（0 新增安装、0 新增依赖）
- **实现状态**：R1-R4C/P2 各层源码已实现且**仅代码 GREEN**（精确 SHA-256 冻结，含运行时 close 竞态修复）；**尚未通过第 5 轮门禁、未投产**
- **关键约束**：独立 `LinkCollectionRequest`/runner，不得复用 `selected_video_ids`；严格公开 HTTPS 校验、稳定 ID 去重、解析 ID 精确匹配、串行有界处理、仅哈希日志；缺作者/标题不补采达人资料，直接 ASR 兜底
- **生产门禁**：Round-5 整体 RED；0823 交接时标准采集仅在 `round5_manual_local` 授权下开放（用户手动非商业测试，两次手测均因评论预算 16/15 + risk_paused 失败）；多账号同时采集/商业/SaaS/字幕直取/Agent 自主发起仍阻断
