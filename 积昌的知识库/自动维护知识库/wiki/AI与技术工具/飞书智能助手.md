## 概述

飞书智能助手是一个 Python 编写的本地服务，通过飞书官方 CLI 工具 `lark-cli` 监听飞书即时消息，将用户发送的消息和文件交由 Claude CLI（实际调用 DeepSeek API）处理，最终将处理结果写入 Obsidian Vault 并通过飞书回复用户。其核心优势在于**无需内网穿透**（lark-cli 通过 WebSocket 长连接主动连接飞书服务器），并支持**双模式接管**（自动/人工）和**管理员远程控制**（admin.py）。

## 核心要点

### 系统架构

```
飞书 (Feishu) → lark-cli event consume (WebSocket 长连接) → Python 服务 → Claude CLI → Obsidian Vault
                                                                    ↓
                                                          lark-cli im send (回复用户)
```

### 架构核心特点

| 特点 | 说明 |
|------|------|
| **无内网穿透** | lark-cli 主动连接飞书服务器建立 WebSocket，无需暴露本地端口 |
| **多线程协作** | 6 个线程各司其职，通过 Queue 解耦 |
| **多轮对话** | 会话状态机实现文件→询问→追问→执行的完整流程 |
| **本地快速响应** | 问候/帮助/模式切换等简单请求由 Python 直接回复（<1 秒） |
| **双模式接管** | 自动处理 / 人工接管，可在飞书中随时切换 |
| **管理员远程控制** | admin.py 允许 Claude Code 远程查看和操控飞书助手 |

### 核心技术栈

| 层级 | 技术 | 用途 |
|------|------|------|
| 服务端语言 | **Python 3.13** | 主服务逻辑、事件处理、进程管理 |
| 飞书通信 | **lark-cli** (npm) | 事件监听（WebSocket）、消息发送、文件下载 |
| AI 引擎 | **Claude CLI** | AI 任务执行引擎 |
| AI 模型后端 | **DeepSeek API** (deepseek-v4-flash) | 实际推理后端 |
| PDF 加速 | **PyMuPDF (fitz)** | PDF 文本预提取（可选） |
| 知识库 | **Obsidian** | 笔记存储与知识管理 |

### lark-cli 关键命令

| 命令 | 用途 |
|------|------|
| `lark-cli event consume im.message.receive_v1 --as bot` | 建立 WebSocket 长连接，实时接收消息事件 |
| `lark-cli im +messages-send` | 发送文本消息 |
| `lark-cli im +messages-resources-download` | 下载消息中的文件 |
| `lark-cli auth status` | 验证当前认证状态 |

> **重要**：所有操作必须使用 `--as bot` 参数（应用身份）。必须使用 `.exe` 路径而非 `.cmd` 批处理，否则特殊字符参数会解析错误。

### Claude CLI + DeepSeek API 架构

```
Claude CLI (客户端，作为 AI 代理层)
    │  ANTHROPIC_BASE_URL 重定向
    ▼
DeepSeek API (服务端，Anthropic 兼容接口)
    │
    ▼
deepseek-v4-flash (模型)
```

Claude CLI 本身不运行任何 Claude 模型，而是作为文件系统交互的代理层。

### 双模式接管系统

| 模式 | 说明 |
|------|------|
| **自动模式** | 服务自动处理所有消息，通过会话状态机与用户交互后执行任务 |
| **人工接管** | 消息不触发 Claude CLI，由管理员在本地查看后手动处理 |

通过飞书发送特定指令即可在两种模式间切换，无需任何手动配置。

### 管理员远程控制 (admin.py)

admin.py 是飞书助手独有的远程管理 CLI，允许 Claude Code 在外部（如通过 Claude CLI 所在目录）远程操作：

- 📋 `list` — 查看最近消息列表
- 📖 `read <id>` — 查看消息详情
- 📨 `reply <id> <content>` — 以助手身份回复消息
- ❌ `cancel <id>` — 取消正在处理的任务
- 🔄 `resume` — 覆盖接管模式强制处理下一条消息

### 配置要点

| 配置项 | 说明 |
|--------|------|
| `timeout_seconds: 1800` | 30 分钟超时，满足大 PDF 文件处理 |
| `max_budget_usd: 5.0` | 确保复杂任务不因预算不足中断 |
| `settings.json` 优先级 | Claude CLI 全局 settings.json 的 env 配置优先级高于进程 config.json |

## 关键概念/术语

| 术语 | 定义 |
|------|------|
| **lark-cli** | 飞书官方 CLI 工具，支持事件监听、消息收发、文件下载等功能 |
| **NDJSON** | Newline Delimited JSON，lark-cli 事件流的输出格式，每行一个 JSON 事件 |
| **双模式接管** | 自动处理和人工接管两种运行模式，可在飞书中切换 |
| **管理员远程控制** | 通过 admin.py 工具从外部操控飞书助手的 CLI 能力 |

## 对比要点（企业微信 vs 飞书）

| 对比项 | 企业微信 | 飞书 |
|--------|---------|------|
| 消息获取方式 | HTTP 回调（被动推送） | WebSocket 长连接（主动监听） |
| 内网穿透 | 需要（LocalTunnel/Cloudflare） | **不需要** |
| 服务框架 | FastAPI + uvicorn | 纯 Python 脚本 |
| 快速命令响应 | 全部走 Claude CLI | **本地命令处理器**（<1秒） |
| 接管模式 | 仅自动处理 | **双模式 + 管理员 CLI 远程控制** |
