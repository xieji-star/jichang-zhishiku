# HTTP 错误概述

## 概述

HTTP 状态码是服务器对客户端请求的响应标识。4xx 表示客户端错误，5xx 表示服务器端错误。理解和区分常见 HTTP 错误，是 Web 开发和调试的基本功。本页重点解析 400 和 502 两个高频错误。

## 核心错误解析

### 400 Bad Request

**含义**：服务器无法理解客户端的请求，问题出在客户端。

**通俗理解**：就像你去柜台办事，工作人员说"你递给我的这张表填错了，我看不明白"。

**常见原因**：
1. **语法错误** — URL 包含非法字符（空格、中文未编码）
2. **缺少必要参数** — 服务器需要的信息你没给（如登录只填用户名没填密码）
3. **参数值不符合要求** — 给的类型错误（年龄字段填了"abc"）
4. **请求体太大** — 上传文件超过服务器限制
5. **请求头错误** — Content-Type 声明 JSON 但实际发纯文本

> 参数格式错误和缺少必要参数占 400 错误的 80% 以上。

**调试方法**：
- 打开浏览器开发者工具 → Network 面板查看请求详情
- 检查 URL 是否正确编码（使用 `encodeURIComponent()`）
- 验证请求体格式（JSON 是否合法、字段名是否匹配）
- 检查 `Content-Type` 请求头

### 502 Bad Gateway

**含义**：网关/代理将请求转发给上游服务器，但上游服务器无法正常响应。

**通俗理解**：你点了一份牛排（发起请求），服务员传给后厨（网关转发），但厨师今天罢工了，服务员只好告诉你"后厨出问题了"。

**常见原因**：

| 原因 | 通俗解释 | 常见场景 |
|------|----------|----------|
| 上游服务器挂了 | 厨师没上班 | 后端服务进程崩溃 |
| 上游服务器过载 | 厨师忙不过来 | 高并发响应超时 |
| 网关配置错误 | 服务员记错后厨位置 | Nginx upstream 地址配错 |
| 防火墙拦截 | 后厨门被锁了 | 安全策略阻止连接 |
| PHP-FPM 进程挂掉 | 厨师长倒下了 | PHP 站点常见 |
| 代理超时 | 做菜太久等不及 | `proxy_read_timeout` 太短 |

**调试方法**：
```bash
# 查看网关日志
tail -f /var/log/nginx/error.log

# 检查上游服务是否存活
curl -I http://127.0.0.1:8080/health
systemctl status your-backend-service

# 检查 PHP-FPM
systemctl status php-fpm

# 检查防火墙
iptables -L -n | grep <port>
```

### 502 vs 504 的区别

- **502** = 上游服务器根本不理你（连接拒绝、崩溃、无响应）
- **504** = 上游服务器理你了，但反应太慢，网关等不及了

### 常见 HTTP 状态码速查

| 状态码 | 含义 | 问题在哪 |
|--------|------|----------|
| **400** | Bad Request | 客户端请求有问题 |
| **401** | Unauthorized | 需要登录认证 |
| **403** | Forbidden | 服务器拒绝访问 |
| **404** | Not Found | 资源不存在 |
| **429** | Too Many Requests | 请求频率过高 |
| **500** | Internal Server Error | 后端服务器出错 |
| **502** | Bad Gateway | 网关到后端之间 |
| **503** | Service Unavailable | 服务器过载或维护 |
| **504** | Gateway Timeout | 网关等后端超时 |

## 关键概念

- **4xx 错误**：客户端错误，问题出在请求方（浏览器、App、代码）
- **5xx 错误**：服务器端错误，问题出在服务方
- **网关/反向代理**：中间层服务（如 Nginx），负责转发请求到后端
- **上游服务器**：实际处理业务逻辑的后端服务
