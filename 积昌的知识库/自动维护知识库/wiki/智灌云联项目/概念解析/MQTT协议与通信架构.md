# MQTT 协议与通信架构

## 概述

MQTT 是专为物联网（IoT）设计的轻量级消息传输协议，核心设计理念是**轻量、省电、可靠**，专门解决在网络不稳定、带宽有限、设备资源受限的场景下高效传输数据的问题。在智灌云联项目中，MQTT 是连接田间设备与云端大脑的"神经系统"。

## 核心要点

### 工作原理：发布/订阅模式

MQTT 采用**发布/订阅（Publish/Subscribe）**模式，包含三个关键角色：

| 角色 | 说明 | 在项目中的对应 |
|------|------|----------------|
| **发布者（Publisher）** | 发送消息的设备 | 田间传感器、Jetson Nano |
| **订阅者（Subscriber）** | 接收消息的设备或软件 | 云端服务器、农户手机 APP |
| **代理（Broker）** | 消息中转站，转发消息给订阅者 | 阿里云物联网平台 |

### 核心优势

1. **极致轻量，节省带宽**：消息头最小仅 2 字节，远小于 HTTP 动辄几百字节的头部，按流量计费的 4G 网络能显著节省成本

2. **3 种 QoS 等级**：

| 等级 | 名称 | 适用场景 |
|------|------|----------|
| QoS 0 | 最多一次 | 环境温度等允许偶尔丢失的数据 |
| QoS 1 | 至少一次 | 一般传感器读数 |
| QoS 2 | 恰好一次 | 阀门开关等关键指令 |

3. **适应弱网**：持久连接 + 自动重连机制，遗嘱消息（LWT）在设备异常离线时自动通知服务器，保留消息让新接入设备立即获取最新状态

### 在智灌云联中的应用

- **设备数据上云**：Jetson Nano 将 EC/pH 值、土壤墒情等封装为轻量 JSON 数据包，通过 MQTT 经 4G 模块上传至云端
- **远程指令下发**：农户在 APP 点击"一键灌溉"，APP 作为 MQTT 客户端将指令通过云端 Broker 下发至田间 Jetson Nano
- **跨平台数据共享**：标准 MQTT 协议，数据可对接阿里云、腾讯云等任意支持 MQTT 的第三方平台

### 对比 HTTP 的优势

| 场景 | HTTP | MQTT |
|------|------|------|
| 每次传输头部大小 | 几百字节 | 2 字节起 |
| 连接方式 | 短连接（每次新建） | 长连接（持续保持） |
| 弱网表现 | 连接超时率高 | 自动重连，消息可靠 |
| 功耗 | 高 | 低 |

## 关键概念

- **Broker**：MQTT 消息代理/中转站，所有消息的中心节点
- **QoS（服务质量）**：消息传递的可靠性等级
- **遗嘱消息（LWT）**：设备异常离线时的自动通知机制
- **保留消息**：新接入设备可立即获取的最新状态
