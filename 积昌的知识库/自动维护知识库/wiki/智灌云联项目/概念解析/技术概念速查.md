# 技术概念速查

## 概述

本页整理了智灌云联项目中涉及的核心技术名词，按模块分类，配有通俗解释。适合答辩前快速复习、团队统一技术口径。

---

## 一、硬件层

| 名词 | 通俗解释 | 在项目中的角色 |
|------|----------|----------------|
| **Jetson Nano** | 英伟达出的 AI 微型电脑，内含 GPU 加速核心 | 上位机大脑，跑 LSTM 模型做 AI 推理 |
| **STM32** | 微控制器芯片（MCU），无操作系统，永远不卡顿 | 下位机执行核心，跑模糊 PID 做实时控制 |
| **树莓派** | 通用微型电脑，适合做联网/界面等通用任务 | 对比参照（我们选用算力更强的 Jetson Nano） |
| **MPPT 控制器** | 太阳能充电"最优档位"自动寻找器 | 太阳能方案中提升充电效率 20-30% |
| **PWM（脉宽调制）** | 通过快速开关控制平均功率，像快速眨眼 | 以 1kHz 频率控制注肥泵转速 |
| **UART 串口** | 两块板子之间最简单的通信方式（3 根线） | Jetson Nano 与 STM32 之间的通信桥梁 |
| **RS485** | 工业常用串行通信标准，传输距离远 | 连接智能传感器，支持 Modbus 协议 |
| **4-20mA 接口** | 工业模拟信号标准 | 连接老式模拟传感器 |
| **IP65 防护** | 完全防尘 + 防喷水（非防浸水） | 设备机箱防护等级，安装需抬高 30cm+ |
| **硅氟橡胶密封圈** | 耐 -50℃ 的橡胶材料 | 东北严寒环境保持机箱密封 |
| **热管传导** | 利用液体蒸发吸热+冷凝放热循环散热 | 密封机箱内的高效散热方式，比普通散热片效率高 5-10 倍 |
| **双分区启动（A/B分区）** | 存储分两个区，升级失败可从旧分区启动 | OTA 升级安全保障，防止设备"变砖" |

## 二、算法层

| 名词 | 通俗解释 | 在项目中的角色 |
|------|----------|----------------|
| **LSTM** | 带三道"门"的神经网络，能主动选择记住/忘记历史信息 | 核心 AI 模型，根据 7 天气象数据预测未来 3 天需水需肥量 |
| **RNN** | 带记忆功能的神经网络总称 | LSTM 是 RNN 的升级版 |
| **BP（反向传播）** | 训练神经网络时"对答案、调参数"的数学方法 | 训练 LSTM 模型的核心算法 |
| **GRU** | LSTM 的简化版，少一道"门" | LSTM 在项目中表现优于 GRU（4.8% vs 5.1%） |
| **Transformer** | 目前很火的 AI 架构，需要大量数据 | 在小数据场景下不如 LSTM（误差 5.8%） |
| **Dropout** | 训练时随机关闭部分神经元 | 防止过拟合，项目中设为 0.3 |
| **早停法** | 验证集误差不再下降时提前终止训练 | 防止过拟合的另一种手段 |
| **数据增强** | 人工制造更多训练数据 | 将 2 万条数据扩充至 10 万条（温度±0.5℃，降雨±5%） |
| **留一法交叉验证** | 用 N-1 年数据训练，预测第 N 年，轮换 N 次取平均 | 验证模型精度的方法，项目中 7 年数据轮换 7 次 |
| **消融实验** | 逐个去掉输入特征，观察精度下降程度 | 证明温度/降雨/日照是核心特征，风速/湿度边际贡献仅 0.3-0.5% |
| **迁移学习** | 把已学会的知识迁移到新任务上 | 未来扩展新作物时，用 1-2 个生长季数据微调而非从头训练 |
| **SHAP 值** | 衡量每个输入因素对输出贡献大小的数值 | 解释黑箱模型，生成"温度贡献 60%"等可读结论 |
| **LIME** | 针对单次预测的局部解释方法 | 快速排查异常预测的原因 |
| **RMSE（均方根误差）** | 评估预测精度的标准统计学指标 | 计算预测值与真实值的偏离程度 |

## 三、控制层

| 名词 | 通俗解释 | 在项目中的角色 |
|------|----------|----------------|
| **PID 控制** | 比例-积分-微分：工业最经典的控制算法，让实际值"死咬"目标值 | 控制注肥泵达到目标 EC 值 |
| **模糊 PID** | PID 的升级版，能根据偏差变化趋势提前调节 | 比传统 PID 更平滑、更快，实现 12 秒响应（传统 90 秒） |
| **Kp/Ki/Kd（PID 参数）** | 三个"旋钮"：比例/积分/微分系数 | 不同生育期使用不同参数（苗期小 Kp，抽雄大 Kp） |
| **智能 Agent** | 一套"规则引擎+模糊 PID 控制器" | 不是通用 AI，而是面向玉米水肥决策的专用控制程序 |
| **开环模式** | 系统只下指令，不检查执行结果 | 无传感器模式下，靠气象预测+生育期模型工作 |
| **闭环模式** | 系统下指令后检测执行效果，不达标则修正 | 有传感器模式下，基于反馈持续修正 |
| **EC 值** | 电导率，衡量肥液浓度的指标 | 水肥一体机核心控制目标 |
| **阶跃响应时间** | 从改变设定值到实际值稳定的时间 | 本项目 EC 调节响应 ≤12 秒 |
| **死区效应** | 占空比太低时泵无法启动的现象 | 注肥泵最小有效占空比设为 8% |
| **作物系数（Kc 值）** | 将参考蒸散量换算为作物实际耗水量的调节系数 | 苗期 Kc≈0.3-0.5，抽雄期 Kc≈1.0-1.2 |

## 四、数据与模型层

| 名词 | 通俗解释 | 在项目中的角色 |
|------|----------|----------------|
| **GDD（生长度日）** | 衡量玉米"长到哪个阶段了"的温度累加指标 | 比单纯按天数判断生育期更科学 |
| **水量平衡法** | 计算"水进来多少、出去多少、存下来多少" | 确定玉米实际需水量的方法 |
| **植株全量分析法** | 通过检测植株样品确定实际吸收的养分量 | 确定玉米实际需肥量的方法 |
| **过拟合** | 模型背下训练数据但没学会真正规律 | 用 Dropout+L2 正则化+早停法控制 |
| **边际效益递减** | 额外增加一个因素带来的精度提升越来越小 | 增加风速仅降误差 0.3%，不值得 |
| **数据分布偏移** | 训练数据和应用场景的数据分布不一样 | 试验田→农户大田的迁移问题，用管理水平因子校正 |
| **BOM 成本** | 制造设备的全部零件和材料成本之和 | 6500 元不含研发和营销费用 |
| **投资回收期** | 从购买设备到通过增收覆盖投入的时间 | 本项目 2-3 年（进口 5-8 年） |
| **网络效应** | 使用的人越多产品价值越大 | 用户越多，协议库越丰富，模型精度越高 |

## 五、快速检验表：评委必问 7 题

| 评委问题 | 一句话回答 |
|----------|------------|
| 数据从哪来？ | 黑大试验田 7 个生长季、每天实测、逐日记录 |
| 5% 误差怎么算的？ | 留一法交叉验证：6 年训练→预测第 7 年，轮换 7 次取平均 |
| 跟耐特菲姆比怎么样？ | 精度略低（5% vs 2%），但成本低约 60%（6500 元 vs 3 万+） |
| 没有传感器怎么工作？ | 用气象数据+生育期模型预测，类似看天气预报决定要不要洗衣服 |
| 核心壁垒是什么？ | 7 年数据积累+国产化供应链 |
| 最怕评委问什么？ | "数据就 7 年，够吗？"——坦诚回答不够，正在积累更多数据 |
| 黑箱模型怎么让农户信？ | 用 SHAP 生成"温度贡献 60%、降雨贡献 -20%"等可读解释 |
