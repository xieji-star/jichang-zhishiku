# 智能Agent决策

## 概述

智能Agent 是位于 LSTM 预测模型与硬件执行层之间的**规则引擎**，负责将"未来 3 天需水需肥总量"拆解为"今天浇多少、比例调到多少"，并按玉米生育期自动切换水肥配比。

> Agent 不是 AI 模型，而是一套基于农艺规则的调度系统。

## 核心要点

### Agent 在系统架构中的位置

```
LSTM（预测3天总量）
       ↓
Agent（规则引擎）
  ├── 接收未来3天总量预测
  ├── 判断当前生育期（苗期/拔节/抽雄/灌浆）
  ├── 按内置农艺规则拆总量为每日指令
  └── 下发目标 EC 值
       ↓
STM32（模糊PID执行）
```

### 四大生育期配比切换

| 生育期 | N:P:K 配比特点 | 需水特点 |
|--------|---------------|----------|
| **苗期** | 需肥少，以磷促根 | 需水少 |
| **拔节期** | 氮需求激增 | 需水逐增 |
| **抽雄吐丝期** | 水肥需求最高峰 | 需水最大 |
| **灌浆期** | 钾需求增加 | 需水渐降 |

> Agent 根据固定天数法判断当前生育期。未来计划用有效积温（GDD）法替代。

### 开环模式 vs 闭环模式

| 对比维度 | 开环模式 | 闭环模式 |
|----------|----------|----------|
| 传感器 | 无需 | 需 RS485 土壤传感器 |
| 决策依据 | LSTM 预测 + Agent 规则 | LSTM 预测 + Agent 规则 + 实时传感器反馈修正 |
| 纠错能力 | 无反馈，偏差可能累积 | 有反馈闭环修正 |
| 适用场景 | 普通农户，快速部署 | 高精度需求，极端条件 |

### 开环模式的风险与应对

- **偏差累积**：连续高估需水量 → 多灌 → 浪费
- **暂无自动检测**：开环本质是"只管输出不管反馈"
- **未来方案**：考虑"虚拟传感器"（用水量平衡方程推算土壤含水量作为伪反馈）

### 模糊PID控制

| 参数 | 说明 |
|------|------|
| 位置 | 跑在 **STM32** 上 |
| 频率 | 每秒检测 EC 值**几十次** |
| 功能 | 快速调整注肥泵转速，保证肥液浓度稳定 |
| 响应时间 | EC 阶跃响应 ≤ 12 秒 |
| 特点 | 比普通 PID 更稳、更抗干扰，误差忽大忽小时自动换控制系数 |

### 异常处理策略

| 异常场景 | 处理逻辑 |
|----------|----------|
| 注肥泵卡死 | 检测到 → 停止施肥 + 继续灌溉（仅灌水）或全部停止 |
| EC 传感器漂移 | 系统可能"跟着漂移"，需定期校准提醒 |
| 预报有雨但量不足 | Agent 判断：等雨 vs 先灌 → 依据降雨量和玉米当前需水阈值 |
| Jetson 死机/重启 | STM32 仍按最近一次指令稳定执行 PID，不会烧苗 |
| 无网络 | 本地 SQLite 存最近 30 天数据，恢复后自动同步云端 |

## 关键概念

- **规则引擎 vs AI 模型**：Agent 是规则引擎（查表+逻辑判断），不是机器学习模型
- **固定天数法 vs 有效积温（GDD）法**：当前用前者，未来计划迁移至后者
- **模糊PID**：带模糊逻辑的 PID 控制器，能根据偏差大小自动切换参数组
- **EC 值**：电导率，反映肥料溶液浓度
