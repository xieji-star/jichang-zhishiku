# HTTP 502 Bad Gateway 错误详解

> [!info] 📊 台账速览
> 本文档为 **HTTP 状态码知识科普**，非具体事故记录。台账对应 **F8「HTTP 400 / HTTP 502 错误」累计 1 次**（[[00-报错统计台账]]），供通用报错解读参考。

## 一、502 是什么？

**502 Bad Gateway**（错误网关）是 HTTP 协议中的一个状态码。简单来说就是：

> **你访问网站 A，网站 A 需要去请求网站 B 拿数据，结果网站 B 没响应或者返回了错误信息，网站 A 没办法，只好告诉你："我上游出问题了，我也没办法。"**

## 二、生活中的类比

### 餐厅例子 🍽️

```
你（客户端） → 服务员（网关/代理） → 厨师（上游服务器）
```

- 你点了一份牛排（发起请求）
- 服务员把你的订单传给后厨（网关转发请求）
- 厨师今天罢工了，或者食材没了，做不出来
- 服务员回来告诉你："抱歉，后厨出问题了，做不了" → **这就是 502**

你并没有和服务员吵架（你和服务员的沟通是正常的），问题出在服务员和厨师之间。

## 三、技术上的工作原理

```
客户端 (浏览器)
    │
    ↓ 请求
反向代理 / 网关 / Nginx
    │
    ↓ 转发请求
上游服务器 (后端 / API / PHP-FPM / Tomcat 等)
    │
    ↑ 响应异常或无响应
反向代理 / 网关
    │
    ↑ 返回 502
客户端 (浏览器)
```

**关键点：** 网关本身是正常的（所以它还能给你返回错误页面），但它和上游服务器之间的通信出了问题。

## 四、常见的 502 原因

| 原因 | 通俗解释 | 常见场景 |
|------|---------|---------|
| **上游服务器挂了** | 厨师今天没上班 | 后端服务进程崩溃或被杀死 |
| **上游服务器过载** | 厨师忙不过来，新订单没人处理 | 高并发下服务器响应超时 |
| **网关配置错误** | 服务员记错了后厨位置 | Nginx 配错了 upstream 地址 |
| **防火墙/安全组拦截** | 后厨的门被锁了，服务员进不去 | 安全策略阻止了网关到后端的连接 |
| **PHP-FPM 进程挂掉** | 厨师长倒下了，整个厨房瘫痪 | PHP 站点常见，`php-fpm.sock` 失效 |
| **代理超时** | 厨师做菜太久，服务员等不及了 | 网关设置的 `proxy_read_timeout` 太短 |
| **DNS 解析失败** | 服务员找不到后厨在哪 | 上游域名无法解析 |

## 五、如何排查和解决

### 如果你是普通用户 👤

- **刷新页面** —— 可能是临时问题，刷新就好了
- **等一会儿再试** —— 服务器可能在重启或维护
- **访问其他网站** —— 判断是不是自己网络的问题

### 如果你是开发者/运维 🛠️

```bash
# 1. 查看网关日志
tail -f /var/log/nginx/error.log

# 2. 检查上游服务是否存活
curl -I http://127.0.0.1:8080/health
systemctl status your-backend-service

# 3. 检查 PHP-FPM 状态（如果是 PHP 站点）
systemctl status php-fpm
# 或检查 sock 文件
ls -la /var/run/php-fpm.sock

# 4. 检查防火墙
iptables -L -n | grep <port>

# 5. 检查代理超时配置
grep proxy_read_timeout /etc/nginx/nginx.conf
```

## 六、502 与 其他错误的区别

| 状态码 | 含义 | 问题在哪 |
|--------|------|---------|
| **502** | Bad Gateway | 网关到后端之间 |
| **400** | Bad Request | 客户端请求有问题 |
| **403** | Forbidden | 服务器拒绝访问 |
| **404** | Not Found | 资源不存在 |
| **500** | Internal Server Error | 后端服务器本身出错了 |
| **503** | Service Unavailable | 服务器暂时过载或维护 |
| **504** | Gateway Timeout | 网关等后端等超时了 |

> 小贴士：**502 和 504 是兄弟关系**
> - 502 = 上游服务器根本不理你（连接拒绝、崩溃、无响应）
> - 504 = 上游服务器理你了，但反应太慢，网关等不及了

## 七、一句话总结

> **502 就是"中间人"（网关）把请求转给了"后端"（上游服务器），但后端无法正常响应，中间人只好告诉你——"我尽力了，上游出了点问题。"**
