# 🛫 机场订阅到期导致小火箭节点清空（全站境外无法访问）

> [!summary] 📊 报错统计速览（截至 2026-09-18）
> 🔥 **本文档共记录 <span style="color:#e74c3c">1 次报错/修复事件</span>**（2026-09-18 原始事件 1 次，暂无复发）。主根因为 **「机场订阅到期，机场返回 0 节点空配置」**（台账 N16，累计 1 次）。
>
> | 根因 | 台账累计 | 主要发生地 |
> |------|:---:|------|
> | 🔴 机场订阅到期（`expire=2026-09-17 15:41`）→ 订阅返回 `proxies: 0` | **1** | 22 |
> | 🟠 小火箭把空配置写入 `rocket.yaml`，代理核心无任何节点 | **1** | 22 |
> | 🔵 无节点 → 流量兜底走 DIRECT → 境外站点（GitHub）被墙 | **1** | 22 |
>
> 📊 完整统计口径见 [[00-报错统计台账]]。

> [!info] 📍 适用环境：🏠 本地 Windows 11
> 本文档记录**机场账号层**的问题——**订阅到期**导致节点清单为空。与同属"境外连不上"大类的其余故障（[[05-Codex网络故障-青旅环境]] 代理模式、[[06-国外网站访问慢但Codex正常]] 分流、[[16-小火箭代理节点失效导致境外无法访问（PR_END_OF_FILE_ERROR）]] 节点失效）<span style="color:#1e90ff">根因层次完全不同</span>：那些是**配置/节点质量**问题，本文是**账号有效期**问题。

> [!SUMMARY] 📌 结论摘要
> GitHub 增量备份脚本连报 `Recv failure: Connection was reset`。逐层排查发现：<span style="color:#ff0000">**不是网络、不是代理软件故障、也不是分流规则问题**</span>——而是小火箭（Rocket）的 **机场订阅已于 2026-09-17 15:41 到期**，机场对过期订阅返回了一份**只有规则、没有节点**的空配置（`proxies: 0`）。小火箭把这份空配置写入 `rocket.yaml`（本地 8-31 备份中该文件尚有 **196 个节点**，现在变成 **0 个**），代理核心因无节点可选中，只能把**全部流量兜底走 DIRECT 直连**；而 GitHub 在国内直连被墙 → 备份脚本报「连接被重置」。<span style="color:#1e90ff">决定性证据是订阅响应头里的 `subscription-userinfo: upload=0; download=0; total=0; expire=1789630877`——换算后到期时间恰为 2026-09-17 15:41:17，早于本次排查时间约 21 小时。</span>
>
> ⚠️ **这是账号续费问题，不是技术故障**：需要**在机场后台续费**，然后在**小火箭里点「更新订阅」**，节点即可恢复，GitHub 备份随即可正常执行。

## 🧩 根本原因

| 层级 | 根因 | 证据 | 处置 |
|---|---|---|---|
| 🔴 账号层（主根因） | <span style="color:#ff0000">机场订阅已于 **2026-09-17 15:41:17** 到期；机场对过期订阅返回"有规则、无节点"的空配置（`proxies: 0`）</span> | 订阅响应头 `subscription-userinfo: ...; expire=1789630877`，换算即 2026-09-17 15:41:17；直接抓订阅源（绕开小火箭）同样返回 0 节点 | **需用户到机场后台续费**，再在小火箭内「更新订阅」 |
| 🟠 配置层（传导） | <span style="color:#ff8c00">小火箭把这份空配置原样写入 `rocket.yaml`，「🔰国外流量」代理组变成空壳（0 成员）</span> | `rocket.yaml` 与 8-31 备份对比：`proxies` 由 **196 → 0**，组内成员由 **189 → 0**；规则 674 条未变 | 续费后重新拉取订阅即可自动覆盖修复 |
| 🔵 运行层（后果） | <span style="color:#1e90ff">代理核心无任何节点可选中，分流规则中指向"🔰国外流量"的境外流量无处可去，只能兜底 `DIRECT` 直连；GitHub 在国内直连被墙 → 连接被重置</span> | `/proxies` API 仅返回 `DIRECT / GLOBAL / REJECT` 三项；`GLOBAL.now = DIRECT` | 无需单独处理，节点恢复后自动消失 |

> [!IMPORTANT] ⚠️ 关键澄清：这不是"小火箭坏了"
> 排查确认**代理软件本身工作正常**：进程 `clashr-windows-amd64`（PID 24604）在运行、端口 `4780/4781/4788` 正常监听、控制 API 可访问、`mode=rule` 与规则集（674 条）完好。坏掉的**只有节点清单**——换句话说，<span style="color:#ff0000">软件是好的，是"弹药"（节点账号）过期了</span>。因此**重装/重启小火箭、改分流规则、换端口都无济于事**，唯一解法是续费。

### 1. 网络层（先分清"国内 / 境外"）

| 测试路径 | 命令 | 结果 |
|---|---|---|
| 国内直连 | `curl https://www.baidu.com` | ✅ <span style="color:#1e90ff">200，0.597 s</span> |
| 境外直连 | `curl https://github.com` | ❌ 000，12.0 s（超时） |
| 境外走代理 4780 | `curl -x http://127.0.0.1:4780 https://github.com` | ❌ 000，5.0 s |

> [!NOTE] 💡 判读
> 「国内通、境外不通、**且走代理也不通**」——说明故障<b>不在"浏览器/程序用没用代理"，而在"代理本身出不了境"</b>。若走代理能通、只是某个程序不通，那是应用层问题（参见 [[15-校园网Firefox不走代理导致境外无法访问]]、[[21-关闭代理软件后浏览器打不开国内网站（Firefox手动代理残留）]]）。

### 2. 代理核心层（找到"零节点"）

- 代理进程：`E:\...\Rocket\resources\clash-binaries\clashr-windows-amd64.exe`，PID 24604，配置目录 `C:\Users\asus\AppData\Roaming\Rocket\clash-configs`。
- 监听端口：`0.0.0.0:4780`（HTTP 代理）、`0.0.0.0:4781`（SOCKS5）、`127.0.0.1:4788`（RESTful 控制 API）。
- 控制 API `GET /configs`：`{"port":4780,"socks-port":4781,"mode":"rule","log-level":"silent","ipv6":false,...}` —— <span style="color:#1e90ff">核心配置本身无异常</span>。
- 控制 API `GET /proxies`：<span style="color:#ff0000">代理条目总数 = 3，全部为兜底项</span>：

```text
DIRECT  | Direct
GLOBAL  | Selector | now=DIRECT     ← 唯一的选择器指向直连，说明没有真实节点可选
REJECT  | Reject
```

### 3. 配置文件层（锁定"何时被清空"）

| 文件 | 大小 | proxies 节点数 | 🔰国外流量 组成员数 | rules | 备注 |

| `rocket.yaml`（mtime 2026-09-18 09:07） | 27941 B | **0** | **0** | 674 | 今晨订阅更新后写入，<span style="color:#ff0000">节点被清空</span> |

- 小火箭自身的选路缓存 `.cache` 中仍记着**上次选中的节点** `🔰国外流量 → 香港 01 HKIX`，`configs.json` 中 `currentProxy` 亦为 `香港 01 HKIX` —— <span style="color:#1e90ff">佐证"曾经有节点、是这次更新后才消失"</span>。
- `clashy-configs/subscriptions.json` 内容为 `{"subscriptions": []}`（订阅列表项为空），但 `configs.json` 的 `currentProfile` 仍保留着**有效订阅链接**（形如 `https://212.50.235.33:22696/ssp/huojian/link/<已打码>?clash=9`）。<span style="color:#ff8c00">注意：`subscriptions.json` 为空是**结果不是原因**——先确认续费状态再考虑是否重加订阅。</span>

### 4. 订阅源层（决定性一步：绕开小火箭直连机场）

直接抓取 `currentProfile` 中的订阅链接（不经过小火箭），结果：

- HTTP <span style="color:#1e90ff">200</span>，`Content-Length: 28165`，`Content-Type: application/octet-stream`，`content-disposition: attachment; filename=Clash_1789705484.yaml`。
- 内容解析：**`proxies` 数量 = 0**，「🔰国外流量」组 = **0 个成员**，`proxy-groups` 6 个、`rules` 674 条——**与本地已损坏的 `rocket.yaml` 完全一致**。
- 响应头：<span style="color:#ff0000">`subscription-userinfo: upload=0; download=0; total=0; expire=1789630877`</span>

> [!IMPORTANT] 🎯 根因闭合
> 订阅源**自己**返回 0 节点 ⇒ 排除"小火箭写坏了配置"这一可能。<br>
> `expire=1789630877` 换算 = **2026-09-17 15:41:17**，排查时刻为 **2026-09-18 12:24:50** ⇒ **已过期约 21 小时**。<br>
> <span style="color:#ff0000">根因 = 机场订阅到期，机场停发节点。</span>定位到此闭合。

## 🛠️ 修复过程

1. **确认报错与复现**：重跑 `bash .claude/hooks/kb-github-backup.sh`，第 2 步 `git pull` 稳定复现 `Recv failure: Connection was reset`（3 次重试均失败）——排除偶发抖动。
2. **分层连通性实测**：国内（baidu 200）/ 境外直连（超时）/ 境外走代理（超时）三路对照，把故障范围锁定在"代理出口"。
3. **检查代理核心状态**：确认进程在跑、端口在听、控制 API 可访问、`mode=rule` 与 674 条规则完好——**排除"软件故障/配置丢失"**。
4. **查核心代理清单**：`GET /proxies` 仅 3 项兜底条目，确认核心**零节点**。
5. **对比配置文件**：以 8-31 备份为基线，确认 `rocket.yaml` 的节点数由 196 → 0、组内成员由 189 → 0，且 mtime = 今晨 09:07（订阅更新时间）。
6. **绕开小火箭直连订阅源**：抓取 `currentProfile` 链接，得到一份同样 `proxies: 0` 的配置，并读到 `subscription-userinfo` 响应头——<span style="color:#1e90ff">由此锁定"订阅到期"这一账号级根因</span>。
7. **给出处置**：本次故障**不在"修复"而在"续费"**——技术侧已完成定位与闭环验证，剩下需用户操作：
   - ① 到机场后台（`https://212.50.235.33:22696/...` 所属站点）**续费/续期订阅**；
   - ② 在小火箭中点击「**更新订阅**」（或重新添加订阅链接）；
   - ③ 恢复后重跑 `bash .claude/hooks/kb-github-backup.sh` 验证。

> [!WARNING] 🔐 安全说明
> 本文档中所有订阅链接的 token 段一律以 `<已打码>` 占位，**不回填真实 token**；如需重配订阅，请从小火箭「订阅」页面复制原始链接。

## 🧰 技术栈与术语

| 术语 | 通俗解释 |
|---|---|
| 小火箭 / Rocket | 本机使用的 Windows 代理客户端，内核为 `clashr-windows-amd64`（一个 Clash 分支） |
| `clashr-windows-amd64` | 代理核心进程；把配置文件里的节点按规则转发流量。**它本身不会自己产生节点**，配置里没有节点它就无从代理 |
| `rocket.yaml` | 小火箭生成的**运行配置**：`proxies`（节点清单）+ `proxy-groups`（代理组）+ `rules`（分流规则）。由订阅内容转换而来 |
| `proxies` | 配置文件中的**节点清单**。为 0 即"没有可用的服务器"，代理功能等于失效 |
| 代理组（`proxy-groups`） | 把节点分组供选择/自动测速。示例中「🔰国外流量」是境外流量入口，**成员为 0 时等于入口通向空房间** |
| `DIRECT` / `REJECT` | Clash 的两个内建策略：`DIRECT` = 直连不走代理；`REJECT` = 丢弃连接。它们**不是节点** |
| 分流规则（`rules`） | 决定"哪个域名走哪个代理组"。规则完好但组内无节点时，境外域名会被送去空的境外组，最终兜底直连 |
| 机场 | 提供代理节点订阅的服务商。订阅通常有**流量额度**与**有效期**，到期/超额后停发节点 |
| 订阅（订阅链接 / `currentProfile`） | 一个带 token 的网址，客户端定时 GET 它获取最新节点配置。**token 属敏感信息** |
| `subscription-userinfo` | 订阅服务端返回的**标准响应头**，格式 `upload=; download=; total=; expire=`（字节 / 秒级时间戳），客户端据此显示"已用流量 / 到期时间" |
| `expire=1789630877` | Unix 时间戳（秒），换算 = **2026-09-17 15:41:17**。小于当前时间即已过期 |
| RESTful 控制 API | Clash 内核在本机开的 HTTP 管理接口（此处为 `127.0.0.1:4788`），可用于查询 `/configs`、`/proxies` 等运行态信息 |
| `Recv failure: Connection was reset` | Git/curl 层面的"连接被重置"。在本场景中并非 GitHub 主动拒绝，而是**流量直连出境时被中间网络重置** |

## 🧱 排查中遇到的问题（踩坑）

1. **<span style="color:#ff0000">第一反应容易指向"代理软件出故障"，方向错了半程。</span>** 看到"走代理也超时"，很自然会怀疑小火箭崩了、配置坏了。但实测进程在跑、端口在听、规则完好——**软件是好的，是节点没了**。教训：**"代理不通"要先区分"软件没运行 / 无节点 / 节点失效"三种，别一上来就重启软件。**
2. **<span style="color:#ff8c00">只看本地文件会误判为"小火箭写坏了配置"。</span>** `rocket.yaml` 节点从 196 掉到 0，表面上很像客户端 bug。**关键一步是"绕开客户端、直连订阅源再抓一次"**——结果订阅源自己也是 0 节点，才把责任方从"客户端"纠正到"机场/账号"。
3. **<span style="color:#1e90ff">`subscriptions.json` 为空极具误导性。</span>** 一开始看到订阅列表是空数组，容易得出"订阅被删了"。实际上 `currentProfile` 仍保存着可用链接，订阅源也仍可访问（200）——**空的只是本地列表项，不是账号**。判断订阅状态应看**订阅源的响应头**，而不是本地列表。
4. **<span style="color:#ff8c00">规则完好 ≠ 代理可用。</span>** 674 条分流规则一条不缺，给人"配置很健康"的错觉；但**规则只是"路标"，节点才是"路"**——没有节点，再精细的分流也无处可去。
5. **<span style="color:#1e90ff">"连接被重置"具有欺骗性。</span>** 报错字面像是"GitHub 那边拒绝了我"，实际是**本地流量根本没走代理、直连出境被墙**。判断此类错误，务必先用"国内 / 境外 / 走代理"三路对照，而不是直接去查 GitHub 侧。
6. **`expire` 时间戳需要换算才看得懂。** `subscription-userinfo` 里的 `expire` 是秒级 Unix 时间戳，肉眼看不出是否过期；**必须换算成日期并与当前时间比对**（本次即靠这一步拿到"过期 21 小时"的铁证）。

## 🛡️ 后续建议

1. **立即处置**：到机场后台**续费** → 小火箭内「**更新订阅**」→ 重跑 `bash .claude/hooks/kb-github-backup.sh`。三步走完，GitHub 备份即可恢复正常。
2. **把"到期时间"纳入巡检**：本次故障的隐蔽性在于<b>软件全绿、只差账号余额</b>。<span style="color:#1e90ff">建议每月固定检查一次订阅状态</span>——在小火箭订阅详情页看"到期时间 / 已用流量"，或直接抓订阅链接看 `subscription-userinfo` 响应头。
3. **同款症状的快速判别法（可复用）**：
   - 「国内通、境外不通、**走代理也不通**」→ 优先查**代理节点是否可用 / 订阅是否到期**（本文）；
   - 「国内通、境外不通、**走代理能通**」→ 是**应用/浏览器没走代理**（见 [[15-校园网Firefox不走代理导致境外无法访问]]）；
   - 「**一关代理软件，连国内都打不开**」→ 是**应用被钉死在本地代理端口**（见 [[21-关闭代理软件后浏览器打不开国内网站（Firefox手动代理残留）]]）。
4. **<span style="color:#ff8c00">GitHub 备份脚本可加"前置健康检查"</span>**：在 `kb-github-backup.sh` 的 `git pull` 前，先探测代理出口是否可用（如 `curl -x <代理> -m 5 https://github.com` 判 200/超时），不通则直接给出"代理不可用，疑似节点/订阅问题"的明确提示，而不是让用户看到含糊的 `Recv failure`。<span style="color:#1e90ff">（本次未改动脚本，列入待办）</span>
5. **本类故障的归档价值**：这是台账中**第一个"账号有效期"类**根因（此前均归为配置/节点质量/分流类）。<span style="color:#1e90ff">日后凡"全站境外不通 + 软件正常"的报错，应首先怀疑订阅到期/超额。</span>
