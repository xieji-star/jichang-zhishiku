# 🔴 Obsidian 反复报错 "Request too large (max 32MB)"

> [!summary] 📊 报错统计速览（截至 2026-08-13）
> 🔥 **本文档共记录 <span style="color:#e74c3c">1 次报错事件</span>**（2026-07-28/08-01 首发 1 次，暂无复发记录）。主根因为 **「PDF 渲染体积超限（Request too large）」**，同案涉及次生根因 **「poppler 缺失」**（环境层缺依赖）。
>
> | 根因 | 台账累计 | 主要发生地 |
> |------|:---:|------|
> | 🟠 PDF 渲染体积超限（Request too large） | **1** | 01 |
> | 🟠 poppler 缺失（pdftoppm failed） | **1** | 01 |
>
> 📊 完整统计口径见 [[00-报错统计台账]]。

## 错误信息

```
Error: invalid_requestRequest too large (max 32MB). Try with a smaller file.
```

## 现象

在 Obsidian 中通过 realclaudian 插件与 Claude 交互时，**反复弹出**此错误。即使没有主动操作，错误也会出现。删除 vault 中的大文件**无法解决**此问题。

## 正确原因

**⚠️ 此错误与 vault 中的文件大小无关。** 真正的来源是：

> **Anthropic API（Claude）的 HTTP 请求体上限为 32MB。当 realclaudian 插件发送的请求体超过此限制时，API 网关拒绝请求并返回此错误。**

### 为什么请求体会超过 32MB？

realclaudian 插件每次与 Claude API 通信时，会发送：

| 请求体组成 | 内容 | 说明 |
|-----------|------|------|
| **System Prompt** | 系统指令 + CLAUDE.md × 2 + 所有 Skill 描述 + 所有工具定义 + 系统上下文 | 每次请求都携带，固定较大 |
| **Messages** | 整段对话历史（用户消息 + AI 回复 + 工具调用 + 工具结果） | **随对话轮次增加不断累积** |
| **Tools** | 所有可用工具的完整 JSON Schema 定义 | 每次请求都携带 |

当对话进行多轮后，尤其是涉及大量**文件读取、Agent 搜索、长篇幅回复**时，累积的消息体量会不断增长。最终序列化为 JSON 后突破 32MB 限制。

### 为什么 "一直在报"？

因为每次插件重试或用户继续对话，都会再次发送同样大的请求体 → 再次被拒绝 → 再次报错 → 形成死循环。

### 为什么删除大文件没用？

因为错误**不是**插件在扫描 vault 文件时触发的，而是**API 通信层面**的问题。删除 vault 中的文件不会减少请求体的大小。

## 解决方案

### 方案一：清理旧会话 + 重启 Obsidian（首选）

```bash
# 1. 备份后删除所有旧会话的 meta.json 文件（释放插件缓存）
#    （注意：这会丢失所有历史会话记录）
rm -rf "F:\积昌的知识库 - 副本\.claudian\sessions\"

# 2. 重启 Obsidian（让插件以全新状态初始化）
```

### 方案二：开启新对话

如果不想清除所有历史，也可以：
1. 在 realclaudian 插件中开启一个**全新的对话**
2. 新对话的上下文从零开始，请求体很小，不会触发 32MB 限制

### 方案三：减少单次请求的数据量

- 避免在同一个对话中连续进行大量文件读取
- 避免在同一个对话中多次调用 Agent 进行全库搜索
- 长对话完成后及时开启新对话

## 验证修复

1. 执行清理后重启 Obsidian
2. 如果错误不再弹出 → ✅ **已修复（原因是旧会话积累的数据已清除）**
3. 如果仍报错 → 可能是插件本身存在问题，需检查 realclaudian 插件更新

## 根本原因总结

| 项目 | 结论 |
|------|------|
| ❌ 不是 vault 文件过大 | 删除大文件后错误依旧 |
| ❌ 不是飞书智能助手 | 用户未调用飞书功能 |
| ✅ 是 **API 请求体超限** | realclaudian 插件 → Anthropic API 的请求 JSON 超过 32MB |
| ✅ 根本驱动因素 | **单次对话中累积了大量工具调用结果**（文件读取、Agent 搜索、Grep 结果等） |

## 预防措施

| 措施 | 说明 |
|------|------|
| **定期开新对话** | 长对话（超过 10-15 轮高强度交互）完成后及时开启新会话 |
| **避免过量文件读取** | 需要读取大量文件时，分批进行或使用摘要而非全文 |
| **清理旧会话** | `.claudian/sessions/` 中的旧 .meta.json 文件会积累到 ~17MB，定期清理无用的历史会话 |

## 诊断命令

```bash
# 查看会话文件总大小
du -sh "F:\积昌的知识库 - 副本\.claudian\sessions\"

# 查看最大的历史会话
ls -lhS "F:\积昌的知识库 - 副本\.claudian\sessions\" | head -10

# 删除所有会话（谨慎！会丢失历史记录）
rm -rf "F:\积昌的知识库 - 副本\.claudian\sessions\"
```
