## 一、数据获取与输入层


### Q1：气象数据来源？更新频率？网络中断如何应对？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 数据来源 | 中国气象数据网（免费API，API即应用程序接口，简单说就是两个软件之间互相“喊话”的通道） + 和风天气（备用商业API） |
| ② 更新频率 | 每6小时调用一次，获取未来72小时预报 |
| ③ 断网应对 | 3级保障：本地缓存（设备上暂存最近7天的数据）7天 → 标准曲线（提前设定好的固定灌溉方案）应急模式 → 用户手动输入 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 免费版精度够吗？ | 温度±0.5℃、降雨±0.1mm，满足大田需求；对比付费数据差异＜2% |
| 气象站距农田太远？ | 空间插值修正（根据周围多个气象站的数据估算农田位置的天气数据，像两张照片之间模糊过渡） + 土壤传感器（闭环）校准 + 模型已学习偏差规律 |
| 断网超3天怎么办？ | 转入“应急模式”，用标准曲线决策，精度8-12%，优于人工经验 |


### Q2：播种日期输入误差如何影响？有何校验机制？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 影响程度 | 偏差5天：全生育期误差5-8%；偏差10天：10-15% |

| ③ 修改机制 | APP可随时修改，系统自动重新计算GDD（生长度日，即玉米每天积累的“生长热量”，类似攒积分，攒够一定分值就进入下一个生长阶段）和生育期 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 为何不直接用“出苗日期”？ | 农户记不住出苗日期，但记得播种日期；后台用GDD反推出苗时间 |
| 填错了能否改？ | 可以，历史记录不丢，系统自动重算后续计划 |
| 用户不填怎么办？ | 系统自动填入该地区历史平均播种日期，并提示用户确认 |

### Q6：模型输入为何只用温度、降雨、日照三项？忽略风速、湿度等？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 核心原因 | 三因素决定玉米需水需肥的80-90%，其余因素边际贡献（额外增加一个因素能带来的精度提升）有限 |
| ② 数据可获得性 | 免费API不提供风速湿度（需付费），为保持低成本选择最关键特征 |
| ③ 消融实验（逐个去掉输入因素，看去掉哪个影响最大——类似做菜时逐个去掉调料看哪个最影响味道） | 增加风速仅降低误差0.3%，增加湿度仅0.5%，不值得增加复杂度 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 干旱大风天低估需水量？ | 大风影响部分反映在温度中；极端组合误差升至7-8%，计划2027年增加风速参数 |
| 增加风速湿度需重新训练？ | 需重新训练，但可用迁移学习（把已学会的知识迁移到新任务上，类似学会了开轿车再开SUV只需要适应一下），需先解决数据源问题 |
| 消融实验具体结果？ | 温度（8.2%）→+降雨（6.1%）→+日照（4.8%）→+风速（4.5%）→五项全加（4.4%），边际效益递减（越往后加的提升越小） |


### Q7：RS485通信距离有限，远距离如何解决？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 中继方案 | RS485中继器（信号放大器，把快衰减的信号重新放大再传出去，200-300元），通信距离可延长至2-3km |
| ② 无线方案 | 支持LoRa无线传感器（一种低功耗远距离无线通信技术，类似对讲机，3-5km），用户可自行采购 |
| ③ 软件适配 | 协议库同样支持LoRa传感器 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 最多挂载多少节点？ | 理论256个，设计建议32个，20个节点采集周期约10-15秒 |
| 不同波特率（通信速度，相当于说话的快慢，两边必须速度一致才能听懂）如何适配？ | 自动波特率检测（9600→115200逐步尝试，像自动试对暗号） |
| 电平（电压高低代表数字信号0和1，不同设备可能用不同电压标准）不匹配怎么办？ | 宽电压设计3.3V-5V自适应；特殊传感器可单独供电 |


### Q8：“兼容90%传感器”如何统计？手动配置难度？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① “90%”统计口径 | 以市场销量份额为权重，Modbus-RTU（一种工业通信“普通话”，大多数设备都懂）占60%+，SDI-12（另一种通信“方言”，农业传感器常用）占15-20%，合计覆盖90% |
| ② 实际测试情况 | 已测15款，14款通过；1款需手动配置 |
| ③ 手动配置难度 | “三步走”操作（品牌→寄存器地址即传感器内部数据的“门牌号”→数据类型），3-5分钟完成 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 未兼容的10%是什么？ | 完全封闭的私有协议（厂家自己发明的“暗号”，不公开）或已停产老旧型号 |
| 手动配置农户能独立完成？ | 设计为“三步走”，提供视频教程和客服远程协助 |
| 协议库如何更新？ | OTA在线升级（通过无线网络下载更新，像手机系统升级）；用户可自行添加新协议并生成二维码分享 |


## 二、LSTM预测模型层


### Q9：7年数据是否包含极端年份？数据量是否足够？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 极端年份覆盖 | 2018旱年、2021涝年、2023高温年，覆盖三种极端场景 |
| ② 数据量处理 | 2万条小时级数据（小样本）→ 用L2正则化（给模型加“复杂度罚款”，防止它学得太复杂）、Dropout（训练时随机关闭部分神经元，强制其他神经元独立学习）、早停法（验证集误差不再下降时提前终止训练，防止学过头）防过拟合（模型死记硬背了训练数据但遇到新数据就不会了——像背答案的学生遇到新题就懵了） |
| ③ 数据增强 | 对时间序列进行小幅扰动（温度±0.5℃、降雨量±5%），扩充至约10万条 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 是否存在数据泄露（训练时不小心用了未来数据，相当于考试前看了考题）？ | 严格按时间顺序隔离验证集，杜绝用“未来预测过去” |
| 7年数据对深度学习够吗？ | 偏少，但用正则化+数据增强应对；验证集与训练集误差差＜2%，无严重过拟合 |
| 数据增加后如何更新？ | 每年秋收后进行增量训练（Fine-tuning——在已训练好的模型上用新数据做少量额外训练，像老员工接受新培训），计算成本低 |


### Q10：输入窗口为何选7天？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 选择依据 | 玉米需水响应有3-5天滞后（今天的干旱不会立刻让玉米渴，要几天后才表现出来），7天能捕捉中期趋势，网格搜索（把各种可能的参数组合都试一遍，像试密码）验证7天最优（误差4.8%） |
| ② 逐小时vs日平均 | 逐小时更优（5.3%→4.8%），能捕捉日内温度变化影响 |
| ③ 数据处理 | 数据缺失时用前向填充（用前一个时刻的值补上，像把昨天的值抄到今天）或线性插值（用前后两个点的平均值补上）；连续缺失超3天则标记为低质量样本 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 不同生育期需不同窗口？ | 是，但统一7天保证决策平滑性；未来计划引入Attention机制（让模型自己学会关注哪些时间点更重要，像人类阅读时注意力有重点）实现软动态 |
| 7天预测在实际操作中合理？ | 合理，农户通常每周检查一次农田，与田间管理节奏匹配 |
| 7天中某天数据缺失？ | 前向填充；连续缺失超2天用线性插值；超3天标记低质量样本，训练时降权（减少它对模型的影响） |


### Q11：LSTM为何预测3天？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 预测周期选择 | 3天是精度与实用性的最佳平衡——气象预报72小时准确率85-90%，7天降至60-70% |
| ② 执行方式 | 滚动预测（每天重新算一遍未来3天，但只执行第1天的计划，像每天看最新天气预报决定今天穿什么）：每天预测3天、只执行第1天，次日重新预测 |
| ③ 动态调整 | 次日预报有雨则自动减少灌溉量，无需用户干预 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 第2天下雨能否动态调整？ | 滚动预测机制确保每天重新计算，自动适应天气变化 |
| 用户想要7天农事安排？ | APP提供“长周期预览”（趋势性预测），但每日决策仍以3天滚动为准 |
| 滚动预测计算成本？ | Jetson Nano（英伟达出的边缘计算小电脑，专门跑AI模型）推理0.5秒/次，每天1次，算力完全足够 |


### Q12：N、P、K分别预测的精度和交互效应？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 模型结构 | 多输出LSTM（一个模型、三个输出头，像一棵树上结三种果子），能捕捉N、P、K的协同变化 |
| ② 各自精度 | N：5.2%，P：6.8%，K：7.5%（K偏高因土壤移动性强，容易流失不好测） |
| ③ 低置信度处理 | APP标注置信度等级（对预测结果有多大把握），采用保守策略（预测值与标准值加权平均取折中） |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 为何不三个独立模型？ | 多输出模型共享隐藏层，能学习N、P、K间的协同变化规律 |
| 钾精度低如何改进？ | 低置信度时采用保守策略；计划2027年引入不确定性加权（让模型自己判断哪个任务更重要）多任务学习 |
| 未来改进方向？ | 不确定性加权（Uncertainty Weighting——让模型自动学习各任务的权重，不用人工设定）自动学习各任务权重 |


### Q13：5%误差如何验证？最差情况如何？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 验证方法 | 按时间顺序留一法交叉验证：6年训练→预测第7年，轮换7次 |
| ② 5%含义 | 7次平均误差4.8%，最小3.9%（平年），最大7.2%（极端涝年） |
| ③ 诚信表态 | 主动披露平均值和范围（3.9%-7.2%），而非仅宣传最优值 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 平均误差vs最大误差？ | 5%是平均值，单年最大7.2%（2021极端涝年），PPT同时展示 |
| 第三方验证误差＞5%怎么办？ | 公开结果、分析原因、改进模型——科学的态度是接受独立检验 |
| 误差最大年份原因？ | 2021极端涝年，训练数据中涝年样本仅1年，计划通过数据增强补充极端场景 |


### Q14：超参数如何确定？为何选LSTM？

**回答框架**

| 层次     | 要点                                                                                                                                                               |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 搜索方法 | 网格搜索（把所有参数组合全试一遍）+随机搜索（在参数空间随机采样试）                                                                                                                               |
| ② 最优配置 | 双层LSTM、128单元、学习率0.005（每次学习的步长，步子太大容易跨过头，太小学得太慢）、Dropout=0.3、批大小32（每次喂给模型的数据条数）                                                                                   |
| ③ 框架选择 | LSTM优于GRU（4.8% vs 5.1%，GRU是LSTM的简化版，少一个“门”），优于简单Transformer（5.8%，Transformer是目前很火的AI架构但需要大量数据），门控机制（LSTM特有的“遗忘门”“输入门”“输出门”，像三个筛子控制信息的保留和更新）更适合处理农业时间序列的长期趋势+短期波动 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 128单元如何确定？ | 64精度不足（6.5%），256精度提升有限（4.3%）但计算量翻倍，128是精度与效率最佳平衡 |
| Jetson Nano推理性能？ | 推理0.5秒/次，内存150MB，4GB完全够用 |
| 需要剪枝（去掉模型中不重要的连接，让模型更小更快）或量化（把模型中的小数变整数，牺牲一点精度换取速度和体积）吗？ | 当前0.5秒已够快，暂不需要；未来若需高频预测，INT8量化（把32位小数变成8位整数，速度提升2-3倍）可将速度提升2-3倍 |


### Q15：试验田最优管理数据用于农户是否“理想化”？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 问题承认 | 试验田管理优于普通农户，确实存在“数据分布偏移”（训练数据和应用场景的数据分布不一样——相当于在城里学的开车技术在乡下泥巴路上不一定好使） |
| ② 应对措施 | 管理水平调节因子（粗放×0.8、精细×1.1）+2026年200亩真实农户地块数据采集 |
| ③ 决策原则 | “保守优先”——宁愿少施，不愿过量 |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|

### Q24：每日灌溉量如何执行？多次还是单次？

### Q25：PWM（脉宽调制——通过快速开关控制平均功率，类似快速眨眼，睁眼时间长就亮、闭眼时间长就暗）控制频率？死区如何处理？

**回答框架**

| 层次 | 要点 |
|------|------|
| ① 频率选择 | 1kHz（工业蠕动泵常用频率，驱动力与寿命的最佳平衡） |
| ② 死区（占空比太小，泵无法启动的“盲区”）问题 | 占空比＜5%泵无法启动 → 最小有效占空比设为8% |
| ③ 非线性补偿 | 实测流量-占空比校正曲线，软件线性化补偿（把实际测得的曲线“拉直”，让控制更精准）（R²=0.97，R²越接近1说明线性关系越好） |


**追问框架**

| 追问方向 | 回应要点 |
|----------|----------|
| 流量-占空比线性吗？ | 基本线性R²=0.97，低占空比＜15%和高占空比＞85%存在轻微非线性，已做软件补偿 |
| 温度影响如何补偿？ | 入水口安装温度传感器，低温时自动增加PWM占空比（每降低10℃补偿3-5%） |

### Q26：EC（电导率——代表肥液浓度，水里的肥越多导电性越强）阶跃响应（突然改变设定值后系统跟上的速度）12秒如何测量？
