# ChatGPT → Codex 交接文档提示词

> **用途**：把下面这段提示词**整段复制粘贴到网页版 ChatGPT**，让 ChatGPT **基于它和你这段对话的聊天记录**自行总结出一份《交接文档》，供你随后把它交给 **Codex** 继续之前的任务。
>
> **写文档的是谁**：ChatGPT 网页版（读不到本地文件、不能跑命令）
> **文档是写给谁**：Codex（能读文件、能跑 PowerShell 命令）
> **文档类型**：给 AI 版交接文档（14 节结构；含【〇·六】任务类型判断——无代码/生图任务会自动改用"任务物视角"，去掉代码视角）
> **生成日期**：2026-09-07

--- 以下为可直接复制给 ChatGPT 的提示词（用 ``` 包起来的整段） ---

```markdown
你正在结束一段工作，现在要把当前工作交接给下一个续作智能体 Codex（AI）。
请基于我们这段对话的聊天记录，写一份《<按对话内容确定的项目名> 交接文档（给 Codex 版）》。

Codex 对项目几乎零了解。你的写稿目标：让 Codex 读完这份文档后，不靠问任何人、不查任何额外资料，就能——①看懂这项目在做什么、做到哪了；②知道哪些做完了、哪些没做完、为什么没做完；③能照着文档直接动手干第一步；④每一步做完都能自己判断"做得对不对"。

═══════════════════════════════════════
【零、先明确三件事（动笔前必读）】
═══════════════════════════════════════
1. 你的身份：你现在是"交接文档撰写人"，不是普通聊天助手，也不是项目的新开发员。你的唯一产出就是这份交接文档。
2. 文档读者：下一个续作智能体 Codex（AI）。写的时候始终站在读者角度问自己："这段他能看懂吗？这步他能照做吗？"
3. 你的信息边界：素材 = 这段对话的聊天记录。**你读不到本地文件、不能跑命令。** 聊天记录里没有的，你需要请用户手动粘贴文件内容给你、或代跑命令确认；无法核实的标注"❓待确认"，绝不编造。

═══════════════════════════════════════
【〇·五、动笔前先做「总任务目标 + 当前任务进度」双总结（硬性锚点，写在交接摘要之后）】
═══════════════════════════════════════
动笔写正文前，先输出两块"精确总结"，放在文档开头（交接摘要之后），作为整份文档的锚点；后文所有小节都要能挂回这两块：

**A. 总任务目标总结**（3-5 句话精确概括整个任务的最终目标）：
- 做什么：任务/项目的一句话定义。
- 为谁做：服务对象 / 使用场景。
- 做到什么算成功：验收标准 / 成功定义（可检验，能写数字就写数字）。
- 终极交付物：产出一份什么（交付物清单，含路径）。

**B. 当前任务进度总结**（用"百分比 + 阶段 + 差距"精确给出，对照 A 写）：
- 整体完成度百分比（如"约 70%"），并给出判断依据（哪些证据支撑该百分比）。
- 当前所处阶段 / 里程碑：已走完哪些、正在哪一步、还剩哪些。
- 已完成 / 进行中 / 未开始 三档全量清单。
- 与总目标的差距：还差哪几块才算达到 A 的验收标准。
- 当前阻塞点（如有，逐条列出）。

要求：
- A 对应正文"项目总览与验收"小节，B 对应正文"当前精确进度"小节；0 交接摘要中也各用一两句话点出 A、B 核心。
- "未完成接力棒"每一条都要标注"它服务于总目标的哪一部分 / 补完它之后总进度推进到多少"。
- A 或 B 的任何一项若无法从聊天记录或文件核实，标"❓待确认"，绝不编造。

═══════════════════════════════════════
【〇·六、先判断任务类型（代码 / 无代码 / 混合）——硬性，动笔前必须先判断】
═══════════════════════════════════════
动笔前，先判断这段对话所交接的"任务"属于哪一类，并在标题或交接摘要里明确标注：
- **代码任务**：交付物是代码/程序/脚本/工程（开发 App、写爬虫、搭后端、写自动化脚本）。→ 全用"代码视角"：代码完成度、文件:行号/函数名、命令行验证、代码文件地图。
- **无代码任务**：交付物不是代码（纯生图、文案、海报/PPT、剪视频、整理数据、调研、写文档）。→ **去掉一切"代码视角"字段**，改用"任务物视角"：产出物、素材/输入、参数/设定、使用的工具/模型、验证=看成品效果。**绝不要写"代码完成度""从哪行代码继续""跑什么命令"这类子虚乌有的内容**——本任务根本没有代码，写了就是错。
- **混合任务**：既有代码又有非代码（如"做了一个能生成图片的程序"+"生产了 30 张图"）。→ 代码部分用代码视角、非代码部分用任务物视角，在文档里明确区分。

**【词表替换（无代码/混合的非代码部分适用）】**：
- "代码完成度/完成度" → 任务整体完成度（如"约 60%：文案+20 张图完成，还差 10 张"）
- "从哪行代码/哪个函数继续" → 用哪个工具 / 哪个 prompt / 继续哪个素材 / 哪个步骤
- "跑什么命令/测试验证" → 看成品效果 / 对照需求是否达标
- "文件地图/代码文件" → 任务物清单（已产出、素材/输入、参数/设定、使用的工具/模型、参考资源）
- 无代码任务的"验证/完成"一律以**成品效果、需求达标**为准，而非"测试通过/接口返回什么"。
判不准就默认"混合"，但在文档里区分清楚。

═══════════════════════════════════════
【一、必须回答的四个问题（四要素）——缺一不可，尤其 ③④ 不许一笔带过】
═══════════════════════════════════════
① 当前已经做了什么（每条写满 4 字段：做了什么 / 产出物在哪 / 怎么验证有效 / 关键数据与效果）
② 还有什么没做的（每条写满 7 字段：还差什么 / 为什么没做完 / 前置条件 / 优先级 / 做到什么算完成 / 从哪开始 / 验证信号）
③ 接下来要接着做什么（与②一一对应、编号一致）
④ 接下来该怎么做（把③展开成 1-N 步，每步：做什么 → 打开哪个文件/跑哪条命令/找谁 → 看到什么结果算做对 → 卡住看哪个文档/问谁）
> 判优标准：Codex 能否不问人、不查东西，照着 ③④ 直接动手第一步？不能 → 继续补。
> 🚫 禁止"一笔带过"：❌"还有几件事没做完，下次继续" ❌"详见之前的记录" ❌"等等/后续再说" ❌"这块比较复杂你自己看"。

═══════════════════════════════════════
【二、必须有一张「A→B 接力总览表」】
═══════════════════════════════════════
| # | A 没做完的（接力棒） | 接手方要做什么 | 从哪开始（给 Codex 的是 PowerShell 命令 + 文件:行号/函数名；若你记不清，就贴出关键内容并标 ✅/🔶/❓） | 做到什么算完成（用户帮跑什么命令、看到什么输出） |
|---|--------------------|---------------|---------------------------------------------|-----------------------------------------------|
要求：编号与②③一致；因为读者是 Codex，**"从哪开始"列尽量给出它能直接执行的文件:行号 / 函数名 / PowerShell 命令**；但你自己读不到文件，凡是你没核实过的入口，都要贴出相关内容并标 ❓，请用户核对；"做到什么算完成"列给"用户帮跑什么命令、看到什么输出"；表末给"接力开工第一步"。

═══════════════════════════════════════
【三、文档结构（按交接对象选一套，逐节完整写出，不能跳节/合并/整节删除）】
═══════════════════════════════════════
- **给 AI 版（Codex）→ 14 节**：0 交接摘要 1 项目总览与验收 2 文件地图 3 已完成工作 4 当前精确进度 5 未完成接力棒 6 A→B接力总览 7 命令级行动计划 8 环境与配置 9 数据与状态快照 10 关键决策与踩坑 11 风险与待确认 12 续作启动手册 13 按智能体定制附加节。
- 文档读者是 Codex（L1 自治型，能读文件、能跑 PowerShell），所以"文件地图""命令级行动计划""续作启动手册"都要给**精确路径 + PowerShell 命令 + 函数/行号级定位**，让它拿到就能直接跑；但你自己读不到文件、不能跑命令，所以**所有你无法亲自核实的路径/命令/函数都必须标 ❓ 或贴出内容请用户核对**，绝不凭记忆编一个可能不对的入口。
- 自包含要求贯穿所有节：凡是你记忆里有把握的内容就贴出来，没把握的标 ❓ 并明确"请用户粘贴/代跑"。

═══════════════════════════════════════
【四、信息收集方式与真实纪律】
═══════════════════════════════════════
1. 优先基于聊天记录：先把这段对话里的目标、进度、决策、踩坑、文件路径、数据全部提取出来作为主素材。
2. 信息不足时的补救顺序：**明确列出"需要用户提供哪些文件内容 / 代跑哪些命令"** → 用户提供后再补 → 仍缺的标注"❓待确认"。
3. 真实纪律（硬性）：你读不到文件，所以凡是路径、命令、函数、状态，必须标证据分级：✅确定 / 🔶推断 / ❓待确认；**禁止把推断写成确定**；绝不编造。

═══════════════════════════════════════
【五、写作规范与禁止事项】
═══════════════════════════════════════
1. 宁可多，不可漏；能写数字就写数字（条数/时长/通过率/完成度百分比）。
2. 每条路径给相对路径＋一句话用途；命令给完整可复制版本＋预期输出。
3. 全文用 Markdown；给 Codex 的要零废话、入口精确（PowerShell 命令 + 函数/行号），但你自己没核实过的要标 ❓。
4. 密钥/token 一律脱敏，值写 <已脱敏>。

═══════════════════════════════════════
【六、按你的能力定制的写作方式（务必照做）】
═══════════════════════════════════════
你（ChatGPT 网页版）读不到本地文件、不能跑命令；但这份文档的读者是 Codex（能读文件、能跑 PowerShell）、不是人。请记住这几点：
⓪ **先按上面【〇·六】判断本次任务类型**：若是**无代码任务**（如纯生图），一定要把代码视角字段（代码完成度/从哪行代码继续/跑什么命令验证/代码文件地图）全部换成任务物视角（产出物/素材/参数/所用工具模型/成品效果）；若是**混合任务**，代码部分与非代码部分分开放、都写清。
① **自包含**：关键代码、配置、命令、路径、数据一律直接贴进文档正文，绝不只写"在 xxx 文件里"。
② **先给"上下文包"**：把项目核心背景 + 关键文件内容压缩成一段"给 Codex 读的上下文"，放在文档开头附近。
③ **明确标注"哪些部分需要用户手动粘贴/代跑"**：请用户把聊天记录之外的关键文件内容粘贴给你，并列出"需要用户提供哪些文件内容 / 代跑哪些命令"的清单。
④ **验证靠人代跑**：每个验证步骤写成"请用户代跑 XXX，看到 YYY 输出即成功"。
⑤ **证据分级**：每条信息标注 ✅确定 / 🔶推断 / ❓待确认，绝不装确定。
⑥ 每步只做一件事，每步给一个可观察信号；把歧义全部消掉，不要让你猜。
⑦ **给 Codex 的入口要 Windows/PowerShell 风格**（`.ps1`、`robocopy`、`tasklist`、`Get-NetTCPConnection`、文件:行号 / 函数名），因为 Codex 在 Windows 上能直接跑；你记忆里没把握的入口，标 ❓ 并请用户核对后再交付。

═══════════════════════════════════════
【七、输出要求】
═══════════════════════════════════════
1. 输出一份完整的 Markdown 交接文档，不要只给大纲/要点/节选。
2. 文档开头保留元信息：项目名 / 交接对象（Codex）/ 交接日期。
3. 文档末尾附一栏"遗留不确定项（❓）汇总"，**以及"请用户核对的清单"（含需要用户粘贴/代跑的内容）**。
4. 保存路径：直接在回复中输出完整 Markdown 供复制。
5. 交稿前必须对照【八】的自查清单逐条检查，全部通过才算完成。

═══════════════════════════════════════
【八、交稿前自查清单（逐条打勾，缺一不可）】
═══════════════════════════════════════
- [ ] 四要素齐全（①4字段②7字段③对应④1-N步带验证信号）
- [ ] A→B 接力总览表存在，编号与②③一致，表末有"接力开工第一步"
- [ ] 已按【〇·六】判断任务类型（代码/无代码/混合），并在标题/交接摘要标注；无代码任务已去掉代码视角字段、改用任务物视角（产出物/素材/参数/工具/成品效果）
- [ ] 选定的结构（给 Codex 的 AI 版 14 节）每一节都写到了
- [ ] 全文无"等等/下次继续/详见以前记录/后续再说"等一笔带过
- [ ] 无编造：每条路径/命令/结论要么有出处、要么标 ❓
- [ ] 关键内容已自包含贴进正文；已提供"上下文包"
- [ ] 已列出"需要用户提供哪些文件内容 / 代跑哪些命令"的清单

- [ ] 密钥/token 已脱敏；元信息齐全；末尾附 ❓ 汇总
- [ ] 开头有「总任务目标 + 当前任务进度」双总结（A 目标含验收标准，B 进度含完成度百分比/阶段/差距），且与正文各节逐条对应
- [ ] 判优标准复核：Codex 能否不问人、不查资料，照着③④直接动手第一步？
```
