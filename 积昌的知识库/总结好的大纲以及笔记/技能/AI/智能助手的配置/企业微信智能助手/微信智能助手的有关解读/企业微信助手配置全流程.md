## 一、概述

### 1.1 系统架构

```
微信 (WeChat) → 企业微信 (WeCom) → Cloudflare Tunnel / LocalTunnel → Python FastAPI 服务 → Claude CLI → Obsidian Vault
                                                   ↓
                                         企业微信 API (发送回复给用户)
```

### 1.2 数据流

1. **📱 用户在微信/企业微信** 中发送消息/文件给自建应用
2. **🔄 企业微信** 通过回调 URL（Cloudflare Tunnel / LocalTunnel 内网穿透）推送消息到本地 Python 服务
3. **⚙️ Python 服务** 解析消息类型、下载文件、生成 Prompt
4. **🧠 Claude CLI**（实际调用 DeepSeek API）处理任务
5. **💾 处理结果** 写入 Obsidian Vault + 通过企业微信 API 回复用户

### 1.3 技术栈

| 技术 | 用途 | 版本 |
|------|------|------|
| 🐍 Python | 服务端编程 | 3.13 |
| ⚡ FastAPI | Web 框架（处理回调） | 最新 |
| 🌐 uvicorn | ASGI 服务器 | 最新 |
| 🔐 wechatpy | 企业微信 SDK（加解密、API） | 最新 |
| 📡 httpx | HTTP 客户端（下载文件） | 最新 |
| 🔗 Cloudflare Tunnel | 内网穿透（cloudflared，主力方案） | Cloudflare 官方 |
| 🔗 LocalTunnel | 内网穿透备用方案（localtunnel） | Node.js 工具 |
| 🤖 Claude CLI | AI 任务执行引擎 | Anthropic 官方 |
| 🧠 DeepSeek API | AI 模型后端 | deepseek-v4-flash |
| 🏗️ nssm | Windows 服务管理器 | 最新 |
| 📒 Obsidian | 知识库 | - |

> [!TIP] 💡 关于模型选择
> 实际使用的 AI 模型是 **DeepSeek**（当前使用 **deepseek-v4-flash** 快速模型），而非 Anthropic 官方模型。通过 `ANTHROPIC_BASE_URL` 环境变量指向 DeepSeek 的 Anthropic 兼容 API 端点实现。详见 ↓ [[#3.1 主配置文件 `config.json`]]

## 二、前置准备

### 2.1 企业微信管理后台配置

1. 登录 [企业微信管理后台](https://work.weixin.qq.com/wework_admin/frame)
2. **创建自建应用**
   - 进入「应用管理」→「自建」→「创建应用」
   - 应用名称：如"知识库助手"
   - 📝 记录以下信息：
     - **CorpID**（企业 ID，在「我的企业」中查看）
     - **AgentID**（应用 ID）
     - **Secret**（应用 Secret）

3. **配置消息回调**
   - 进入应用详情 →「接收消息」→「设置 API 接收」
   - 自定义 **Token**（10 位以上英文数字）
   - 生成 **EncodingAESKey**（43 位随机字符）
   - 📌 回调 URL：**先留空**，等 LocalTunnel 启动后再填写

4. **配置应用权限**
   - 进入「应用管理」→ 应用详情 →「权限」
   - 开启**「企业客户」**权限（用于微信互通）
   - 设置可见范围包含用户本人

5. **开启微信互通**
   - 进入「我的企业」→「微信互通」→ 开启
   - 确保应用可见范围包含用户

> [!CAUTION] 🔴 注意
> 如果开启了微信互通，请确保自建应用的可见范围包含所有需要使用本助手的用户，否则收不到回调。

## 四、核心代码解析

### 4.1 服务入口 `server.py`

#### 4.1.1 URL 验证（GET /wecom/callback）

> 企业微信配置回调 URL 时，会发送 GET 请求验证 URL 合法性：

```python
@app.get("/wecom/callback")
async def wecom_verify(msg_signature, timestamp, nonce, echostr):
    decrypted = crypto.check_signature(
        msg_signature, timestamp, nonce, echostr
    )
    return PlainTextResponse(content=decrypted)
```

#### 4.1.2 消息接收（POST /wecom/callback）

> 企业微信推送消息到回调 URL：

```python
@app.post("/wecom/callback")
async def wecom_callback(request, msg_signature, timestamp, nonce):
    raw_body = await request.body()
    decrypted_xml = crypto.decrypt_message(
        xml_str, msg_signature, timestamp, nonce
    )
    msg_data = parse_xml_message(decrypted_xml)
    # 判断消息类型：text / file / event
    # 加入任务队列处理
    return PlainTextResponse(content="success")  # ⚠️ 必须返回 success
```

> [!CAUTION] 🔴 重要
> 回调端点必须返回 `PlainTextResponse(content="success")`，否则企业微信会认为回调失败并反复重试推送。

#### 4.1.3 文件下载

```python
def download_media(media_id: str) -> Optional[bytes]:
    token = get_access_token()
    url = f"https://qyapi.weixin.qq.com/cgi-bin/media/get?access_token={token}&media_id={media_id}"
    response = http_client.get(url)
    # 检查 Content-Type 是否为 application/json（错误响应）
    if "application/json" in response.headers.get("Content-Type", ""):
        error_data = response.json()
        logger.error(f"下载媒体文件失败: {error_data}")
        return None
    return response.content  # 保存到 中间文件/wecom-resources/
```

#### 4.1.4 Claude CLI 调用

```python
def run_claude_task(prompt: str) -> str:
    cmd = [
        "claude", "-p", prompt,
        "--settings", "claude-settings.json",
        "--output-format", "text",
        "--max-budget-usd", "5.0",
        "--no-session-persistence",
    ]
    result = subprocess.run(
        cmd, cwd=vault_root,
        capture_output=True, text=True,
        timeout=600, env=env,  # 传递 DeepSeek API 环境变量（大文件建议 1800）
    )
    return result.stdout.strip()
```

根据消息类型生成不同的 Claude 指令：

| 消息类型 | 命令 | Prompt 行为 |
|---------|------|------------|
| text | `整理笔记 [文件夹] [名称]` | 调用 meeting-summary skill 处理关联文件 |
| text | `/帮助` / `帮助` | 生成本机器人帮助信息 |
| text | `/搜索 [关键词]` | 在 Vault 中搜索内容 |
| text | 自然语言 | 理解意图并执行 |
| file | - | 下载文件并分析内容 |

### 4.3 任务队列与并发控制

```python
task_queue: queue.Queue = queue.Queue()
processing_lock = threading.Lock()  # 🔒 确保 Claude CLI 单实例运行
```

> [!WARNING] ⚠️ 并发限制
> Claude CLI 是重量级进程（加载模型需要大量内存），通过 `processing_lock` 确保同时只有一个任务在运行。其他任务在队列中排队等待。

## 五、内网穿透方案

### 5.1 为什么需要内网穿透？

企业微信回调 URL 必须是公网可访问的地址。本机开发环境在局域网内，需要通过内网穿透工具暴露服务。

### 5.2 方案选择

提供两种内网穿透方案：

| 方案 | 工具 | 适用场景 | 固定子域名 |
|------|------|---------|-----------|
| **方案 A（推荐）** | Cloudflare Tunnel (`cloudflared`) | 默认场景 | ❌ trycloudflare URL 每次重启变化 |
| **方案 B（备选）** | LocalTunnel (`lt`) | 启用 Cloudflare WARP 时 | ✅ 可通过哈希生成固定子域名 |

> Cloudflare WARP 会劫持 cloudflared 的 DNS/流量，导致无法连接。如使用 WARP，请改用 **LocalTunnel**（基于 HTTPS WebSocket，不受影响）。

### 5.3 方案 A：Cloudflare Tunnel

```bash
# 安装 cloudflared
winget install Cloudflare.cloudflared

# 启动隧道
cloudflared tunnel --url http://localhost:8800

# 输出示例：
# https://your-tunnel-name.trycloudflare.com
```

然后将此 URL + `/wecom/callback` 填入企业微信管理后台。

### 5.4 方案 B：LocalTunnel

```bash
# 安装
npm install -g localtunnel

# 启动隧道（带固定子域名）
lt --port 8800 --subdomain jichang-vault-xxxxxx

# 输出示例：
# your url is: https://jichang-vault-xxxxxx.loca.lt
```

固定子域名通过企业 CorpID 的哈希值生成：

```python
corp_id = wecom_config.get("corp_id", "default")
subdomain_hash = hashlib.sha256(corp_id.encode()).hexdigest()[:10]
desired_subdomain = f"jichang-vault-{subdomain_hash}"
```

> [!TIP] 💡 固定子域名优势
> 每次重启 URL 不变，避免频繁手动更新企业微信后台的回调 URL 配置。

### 5.5 启动脚本

`start-with-tunnel.bat` 同时启动 Cloudflare Tunnel 和服务：

```batch
@echo off
start "CloudflareTunnel" cmd /c ""C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://localhost:8800 > logs\tunnel.log 2>&1"
timeout /t 10
python server.py
```

如果需要使用 LocalTunnel，启动服务时添加 `--with-tunnel` 参数：

```bash
python F:\积昌的知识库 - 副本\总结好的大纲以及笔记\技能\AI\智能助手的配置\企业微信智能助手\微信智能助手\server.py --with-tunnel
```

### 5.6 重启脚本（restart-service.bat）的 Tunnel URL 检测

`restart-service.bat` 在重启服务后会自动等待 Tunnel URL 生成（最长 60 秒），并在终端中显示：

```batch
REM 等待 Tunnel URL（每 3 秒检测一次，最多 20 次 = 60 秒）
for /l %%i in (1,1,20) do (
    timeout /t 3 /nobreak >nul
    if exist "%SCRIPT_DIR%\current-tunnel-url.txt" (
        echo 当前 Tunnel URL:
        type "%SCRIPT_DIR%\current-tunnel-url.txt"
        goto :SHOW_INFO
    )
)
```

执行流程：
1. 停止所有 python.exe 和 node.exe 进程（释放子域名）
2. 删除旧 tunnel.log 和 wecom-service.log
3. 启动 `server.py --with-tunnel`（后台运行）
4. 每 3 秒检测 `current-tunnel-url.txt` 是否生成
5. 一旦检测到，显示 URL 并提示用户更新企业微信后台
6. 如果 60 秒后仍未检测到，提示查看日志排查问题

> 如果期望子域名被占用，`current-tunnel-url.txt` 中会显示随机子域名（而不是固定域名），此时需手动更新企业微信后台的回调 URL。

## 八、常见问题

> [!QUESTION] ❓ Q1: 文件消息收不到回调？

检查企业微信管理后台：
1. 应用权限是否开启「企业客户」
2. 回调 URL 是否正确配置
3. 应用可见范围是否包含用户
4. 微信互通是否开启

> [!WARNING] ❓ Q2: Cloudflare Tunnel 无法连接？

Cloudflare WARP 会劫持 DNS/流量。解决方案：
- ✅ 关闭 WARP 后启动 tunnel
- ✅ 或改用 LocalTunnel（不受 WARP 影响）

> [!CAUTION] ❓ Q3: Claude CLI 执行超时？

- 检查 DeepSeek API Key 是否有效
- 增大 `config.json` 中的 `timeout_seconds`（默认 600）
- 文件过大时考虑分解处理

> [!TIP] ❓ Q4: 服务启动失败？

```bash
# 查看日志定位问题
type F:\积昌的知识库 - 副本\总结好的大纲以及笔记\技能\AI\智能助手的配置\企业微信智能助手\微信智能助手\logs\wecom-service.log
type F:\积昌的知识库 - 副本\总结好的大纲以及笔记\技能\AI\智能助手的配置\企业微信智能助手\微信智能助手\logs\service-stderr.log
```

> [!CAUTION] ❓ Q5: 修改 config.json 后模型仍为旧版本（pro）？

> [!CAUTION] 🔴 全局 settings.json 覆盖问题
> Claude CLI 启动时会读取 `C:\Users\asus\.claude\settings.json` 中的 `env` 配置，**该文件中的环境变量优先级高于 `config.json` 中设置的进程环境变量**。如果修改了服务 `config.json` 但未更新全局 settings.json，模型将不会生效。
> - **解决方法**：同步更新 `C:\Users\asus\.claude\settings.json` 中的 `ANTHROPIC_MODEL` 为 `deepseek-v4-flash`
> - **验证方法**：启动服务后查看日志中 `ANTHROPIC_MODEL=` 的输出值
