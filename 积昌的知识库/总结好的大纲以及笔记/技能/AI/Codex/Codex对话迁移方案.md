## 1. 结论：聊天记录在本机，与账号无关

🔥 **<span style="color:#e74c3c">核心结论：Codex 聊天记录全部保存在本机，与登录账号完全无关。</span>**

- 会话记录是**纯本地文件**，账号只在登录时决定"你以谁的身份访问 OpenAI"，**不影响本机已存的历史记录**。
- 因此"把聊天记录转到另一个号"的本质是：**把本机会话文件带到目标账号所在环境**，让目标账号登录后能读取这些本地文件。
- ⚠️ **<span style="color:#e74c3c">迁移时唯一不能带过去的就是 `auth.json`</span>**——那是旧账号的登录令牌，带过去会顶掉新账号登录。

## 2. Codex 数据存储结构

💡 **<span style="color:#2980b9">Codex（Windows 桌面端）把数据存在用户主目录下的 `.codex` 文件夹中。</span>** 经本机实测，关键文件如下：

| 内容 | 位置 | 说明 |
|---|---|---|
| **聊天记录（会话）** | `C:\Users\asus\.codex\sessions\`（共 233MB、24 个文件） | 纯本地 JSONL 明文，按 `年份/月/日/` 分层，文件名为 `rollout-*.jsonl` |
| **历史列表索引** | `C:\Users\asus\.codex\session_index.jsonl` | 左侧历史栏显示会话标题/时间靠它，每行一个会话的 id、thread_name、updated_at |
| **登录令牌（账号）** | `C:\Users\asus\.codex\auth.json` | ⚠️ 唯一和账号绑定、且**不该迁移**的文件 |
| 模型/供应商配置 | `C:\Users\asus\.codex\config.toml` | 如配置过第三方模型（deepseek 等），迁移时建议一并带走 |

📊 **<span style="color:#e67e22">实测数据量：会话目录 233MB（7 月 75MB + 8 月 158MB），共 24 个 `rollout-*.jsonl` 文件，`session_index.jsonl` 记录 10 条索引。</span>**

专业名词：
- **JSONL**（JSON Lines）：一种纯文本格式，**每一行是一个独立的 JSON 对象**，Codex 用它对会话逐事件追加记录。
- **rollout-*.jsonl**：一次对话运行（rollout）的完整事件流文件，是聊天记录的**最小实体**。
- **session_meta**：会话文件头部的一条元信息记录，包含 session_id、parent_thread_id、cwd、originator、cli_version、model_provider、base_instructions（完整系统提示词）等。
- **base_instructions**：Codex 每个会话加载的完整系统提示词，属于高价值内容，备份时必须原文保留。
- **cwd**（Current Working Directory）：会话运行时的项目工作目录。

> 提示：Codex 桌面端连接 ChatGPT 依赖代理与分流规则，相关环境排查见 [[05-Codex网络故障-青旅环境]] 和 [[06-国外网站访问慢但Codex正常]]。

## 3. 迁移方案：同机换号与换机换号

### 3.1 情况一：同一台电脑，只是换另一个号登录

✅ **<span style="color:#1eaf75">什么都不用转移。</span>** 会话文件是本地共享的，切换账号不影响历史记录。

1. 关闭 Codex（退出前等它保存完）。
2. 打开 Codex → 点头像/设置 → 退出登录。
3. 用新账号登录。
4. 左侧历史栏里原来的会话**依然在**，点开即可继续。

> 安全起见，动手前先做一次备份（见 3.2 的命令）。

### 3.2 情况二：换一台电脑 / 全新安装，用另一个号登录

**核心口诀：拷会话、不拷 auth。**

**① 在源机器（这台）打包会话数据**

```bash
rem 备份会话文件 + 索引
robocopy "%USERPROFILE%\.codex\sessions"          "D:\codex-transfer\sessions"  /E
copy   "%USERPROFILE%\.codex\session_index.jsonl" "D:\codex-transfer\"
rem 可选：模型/供应商配置也带上（如果你配过 deepseek 等第三方模型）
copy   "%USERPROFILE%\.codex\config.toml"         "D:\codex-transfer\"
```

> 233MB 比较大，跨机器传建议压成 zip。

**② 放到目标机器新账号的 `.codex` 目录**

```bash
rem 目标机器上，先把 Codex 完全退出，再执行
robocopy  "D:\codex-transfer\sessions"            "%USERPROFILE%\.codex\sessions"  /E
copy      "D:\codex-transfer\session_index.jsonl" "%USERPROFILE%\.codex\"
copy      "D:\codex-transfer\config.toml"         "%USERPROFILE%\.codex\"  rem 如有
```

**③ 启动 Codex，用新账号登录**

- 登录后历史栏会出现原来的会话 → 点开即可**继续任务**。
- 若历史栏没立即显示，重启一次 Codex 让它重新扫描。

## 4. 完整备份提示词：逐字全量导出

> 用途：把这段提示词发给**保存着历史记录的 Codex**，让它自己读取本机全部会话文件，解析成**尽可能详细**的可读文档并打包保存，作为迁移的底层保险。

```text
# 任务：完整备份 Codex 全部历史对话（尽可能详细）

你是 Codex。请把你本机存储的**全部历史会话记录**，原原本本地解析、整理、打包并保存下来，供迁移到其他账号/机器后继续使用。
⚠️ 最高要求：**保存的内容要尽可能详细——禁止省略、禁止概括、禁止截断、禁止"总结大意"替代原文。**

## 1. 数据源（你的本地会话文件）

- 会话目录：`C:\Users\asus\.codex\sessions\`
- 索引文件：`C:\Users\asus\.codex\session_index.jsonl`（含每个会话的 id / thread_name / updated_at）
- 会话文件：目录下按 `年份/月/日/` 分层的 `rollout-*.jsonl`（共约 24 个，单个最大约 7MB）

执行第一步：用工具确认目录存在，列出全部 `rollout-*.jsonl` 的清单（路径、大小、行数），并存为待处理清单。

## 2. 输出位置（可自行修改）

默认输出到：`C:\Users\asus\Documents\Codex会话导出\`
（若想放进知识库，可改为 `F:\积昌的知识库 - 副本\收件箱\Codex会话导出\`）

最终结构：
- `00_总览.md` —— 全部会话清单 + 末尾「校验报告」
- `会话索引_原始.txt` —— session_index.jsonl 的原文完整内容
- `<日期>_<会话标题前30字>_<session_id前8位>.md` —— 每个会话一个 Markdown
- `原始备份/` —— 原样复制的 `sessions` 整个目录 + `session_index.jsonl`（不动一行）
- 最终打包：`Codex会话导出_YYYYMMDD_HHMM.zip`（放在输出目录的上级）

## 3. 解析要求（尽可能详细）

请**写一个 Python 脚本**（脚本放临时目录，任务结束前不要删除）批量解析所有 `rollout-*.jsonl`。每行是一个 JSON 事件，对每个事件**完整保留原始字段**，转成 Markdown，规则如下：

- `session_meta`：在文件头部生成元信息表 —— session_id、parent_thread_id、cwd、originator、cli_version、model_provider、timestamp；并把 payload 里的 `base_instructions`（完整系统提示词/判定规则）**原文完整抄录**到该会话文件最前头，不得省略。
- 消息类（user / assistant / agent_message / reasoning 等）：保留 role、时间戳、**完整正文**；含代码块、文件路径、报错原文时一律原样保留，不换行截断。
- `tool_use` / 工具调用：完整保留工具名 + **全部参数 JSON**（格式化后逐字段呈现）。
- `tool_result` / 工具结果：**完整保留输出**（命令 stdout/stderr、文件内容、报错堆栈、退出的 exit code）。
- 文件修改类（diffs / edits / apply_patch 等）：完整保留 diff / patch / 修改前后内容。
- `approval` / 权限请求：保留请求内容、用户最终决定（同意/拒绝）。
- `agent` / 子代理事件（如 guardian）：保留子代理的任务描述、上下文与结论。
- `summary` / 里程碑：保留摘要全文。
- `error`：保留完整错误信息与堆栈。
- 其他未知 type：**原样保留整行 JSON**，绝不丢弃。

每个会话 Markdown 内部结构：
1. 标题（日期 + 会话标题 + session_id）
2. 元信息表
3. 完整系统提示词（base_instructions 原文）
4. 正文（按时间顺序展开全部事件）
5. 文末「完整性检查」小节：该 rollout 总行数 == 已解析事件数，逐项核对

## 4. 打包

全部导出后，把整个输出文件夹压缩为 zip（zip 放输出目录的**上级**）。zip 内必须包含：`00_总览.md`、`会话索引_原始.txt`、全部会话 `.md`、`原始备份/` 整目录。

## 5. 校验（必须执行）

- 核对 zip 内 .md 数量 == rollout-*.jsonl 数量（24）。
- 抽查 2 个文件（1 个大 1 个小），确认内容完整、无乱码、无截断。
- 校验每个 .md 的元信息能对应回原 `session_meta`。
- 确认 `原始备份/` 与原 sessions 目录文件大小一致（可对比文件数 + 总字节数）。
- 将全部校验结果写入 `00_总览.md` 末尾的「校验报告」小节。

## 6. 汇报

完成后用 3~5 句话汇报：导出目录路径、zip 路径、会话数量、总大小、校验是否通过；若有解析失败/跳过的文件，逐一列出原因。
```

### 4.1 设计要点

- 逐字全量：对 `session_meta`、消息、工具调用、工具结果、diff、approval、agent、error、未知类型**全保留**，绝不丢弃。
- 双层保险：既出**可读 Markdown**，又保留**原始 JSONL 备份**。
- 强制校验：会话数对得上、抽查大/小文件、原始备份字节一致，校验结果写入总览。

## 5. 项目交接文档提示词：新号续作核心

> 用途：让 Codex **通读目标对话/项目**，按 **13 大项**把**当前状态全量导出**成《当前状态全量交接单》——工作进度、干到哪里了、已完成/未完成、下一步、文件地图、决策踩坑、环境依赖、数据现状、风险、续作手册，逐项详尽、一项不漏，方便新号直接拿着它续作。

```text
# 任务：全面导出 Codex 对话/项目的「当前状态全量交接单」

你是 Codex。请从你的本地会话记录中，把**指定对话/项目的当前状态**全部、逐条、详尽地提炼并导出成一份《当前状态全量交接单》，供换到另一个账号/机器后无缝续作。

⚠️ 范围定义（重要）：
- 这里要导出的"所有内容"＝当前状态的全量信息：**工作进度、干到哪里了、已完成/未完成、下一步、涉及文件、关键决策、环境配置、数据现状、风险、续作步骤**。
- **不要导出**对话原文全文、工具输出大段日志、系统提示词等原始内容——只导出"状态与进度"，但要做到逐条详尽、一项不漏。

## 1. 确定目标对话/项目

- 我指定了会话（标题 / session_id / 日期 / 话题）→ 只处理那一个；若同一项目横跨多个会话，自动归并分析。
- 我没指定 → 自动定位**最近一次仍在进行中的项目会话**（参考 `C:\Users\asus\.codex\session_index.jsonl` 的 thread_name 与 updated_at，以及最新的 rollout-*.jsonl）。

## 2. 数据源

- 会话目录：`C:\Users\asus\.codex\sessions\`
- 索引文件：`C:\Users\asus\.codex\session_index.jsonl`
- 第一步：列出目标会话对应的 rollout-*.jsonl 清单（路径、行数），确认命中范围。

## 3. 全量信息提取（核心：按 13 大项逐项产出，每项给足细节，禁止省略）

对每个目标项目，按下述 13 大项逐项编写，每项都必须写满细节，不得用一句话带过：

**1. 项目总览**
- 项目名称、一句话定位、最终要达成的目标
- 当前整体完成度估算（如"约 70%"），并说明判断依据

**2. 验收标准**
- 当初定义"这件事做完了"的标准是什么
- 当前离验收还差哪几项

**3. 背景与来龙去脉**
- 项目怎么来的、为什么做、要解决什么问题
- 关键前置信息、约束条件、用户偏好

**4. 工作目录与文件地图**
- cwd 工作目录路径
- 涉及的全部关键文件/文件夹清单：路径、作用、当前状态（新建/修改/已完成/未动/临时）
- 入口文件、配置文件、产出物的准确位置

**5. 已完成工作（全量逐条）**
- 每条写明：做了什么、完成时间、产出物路径、如何验证有效
- 按时间或模块分组，**一条不漏**地全量列出

**6. 当前精确进度**
- 最后一次会话停在哪一步（最后一条有效操作是什么）
- 整体处于哪个阶段、做到第几步
- 当前代码/文档/数据处于什么具体状态

**7. 未完成事项（全量逐条）**
- 每条写明：还差什么、为什么没完成（阻塞原因）、前置条件、优先级（紧急/重要/一般）
- 明确"做到什么程度算完成"

**8. 下一步行动计划**
- 按顺序列出接下来 1-N 步具体动作
- 每步可执行、可检验，标注预期产出
- 区分"立即做"与"之后做"

**9. 关键决策与踩坑记录**
- 做过的技术选型、为什么这么选
- 踩过的坑：出错现象、根因、规避/修复方案
- 试错过但放弃的方案及放弃原因

**10. 环境与配置依赖（完整清单）**
- 模型/供应商、代理与网络设置、端口、环境变量
- 依赖的库/软件/服务及版本
- 密钥/token 存放位置（**密钥值脱敏**，用 `<已脱敏>` 占位并注明在哪查）

**11. 数据与状态快照**
- 涉及的数据（数据库表、文件、接口返回）当前状态
- 有无临时数据、测试数据需要清理
- 有无需要保留的中间产物

**12. 风险与待确认项**
- 不确定的地方、需要我人工确认的点，逐条标"❓"
- 可能翻车、有隐患的地方

**13. 续作启动手册**
- 换号后从零恢复的完整步骤：打开哪个文件、跑哪条命令、启动哪个服务
- 如何验证"续上了"（看到什么现象算成功）
- 从哪个会话/文件继续最合适

## 4. 详细度与真实性要求

- **逐项给足细节，禁止省略**：每项有内容就写满，宁可多写不可漏写；同类内容（如已完成、未完成列表）必须全量列出，不得只挑几条。
- 全部信息必须来自会话真实内容，引用真实路径/命令/结论，**禁止编造、禁止脑补**。
- 未完成项、下一步必须具体到可执行的粒度，禁止"继续做""后续完善"这类空话。
- 不确定处标注"❓需人工确认"，不要硬写。

## 5. 保存

- 输出一份 Markdown：`C:\Users\asus\Documents\Codex状态交接_<项目名或日期>.md`（路径可自行修改）。
- 文件开头一行元信息：目标会话标题、session_id、导出时间。
- 文件结构按上述 13 大项组织，每项一个二级标题。
- 不打包、不生成 zip、不备份原始会话。

## 6. 校验（必须执行）

- 对照 13 大项逐项核对，确认都有内容、无缺项；
- 抽查：已完成/未完成列表是否全量（对照会话实际出现过的事项逐一比对）；
- 确认没有把对话原文/大段工具日志拷进文档；
- 确认"下一步行动计划 / 续作启动手册"可以直接照做。

## 7. 汇报

用 2~3 句话汇报：保存路径、导出了哪个项目、当前进度结论（做到哪、还差什么）；有 ❓ 待确认项要逐条列出。
```

## 6. 使用流程

🚀 **<span style="color:#e67e22">完整流程：旧机打包 → 传输 zip → 新号续作。</span>**

1. **在哪个 Codex 上执行**：提示词必须在**保存着历史记录的这台机器**（当前账号的 Codex）里运行——因为会话文件 `C:\Users\asus\.codex\sessions\` 在这台机器上。它会让自己读文件、自己解析、自己打包。
2. **跑完得到什么**：一个 zip，里面既有**逐字逐句的 Markdown 可读版**（含完整系统提示词、每轮对话、工具调用与输出、diff、报错），又有**原封不动的原始 JSONL 备份**，以及最重要的 **`00_交接文档.md`（工作交接单）**。
3. **迁移到另一个号**：
   - 把 zip 传到新账号那台机器 → 解压；
   - 给新号 Codex 看 **`00_交接文档.md`** 即可继续未完成的项目；
   - `原始备份/` 和逐字 Markdown 是底层保险，需要细节时再查。

## 7. 注意事项与关键认知

⚠️ **<span style="color:#e74c3c">① 千万别拷 `auth.json`。</span>** 那是旧账号的登录态（含 token），拷过去会顶掉新账号登录；目标机器要让新账号**自己登录**。

⚠️ **<span style="color:#e74c3c">② 新账号要有同等权限。</span>** 能访问原任务用到的模型。若改过 `config.toml` 接第三方模型（如 deepseek），务必把 `config.toml` 一起带过去，否则可能提示模型不可用。

⚠️ **<span style="color:#e74c3c">③ 云端会话迁移不了。</span>** 如果指的是在 `chatgpt.com/codex` 网页里创建的"云端会话"（服务器同步），它绑死在账号服务器上，本地复制无效，只能原账号继续或手动复制对话内容。**本机这 24 个 `rollout-*.jsonl` 属于本地会话，完全可迁移。**

⚠️ **<span style="color:#e74c3c">④ 别覆盖目标机器已有会话。</span>** 目标 `.codex\sessions` 若已有内容，先备份再拷，防止误覆盖。

💡 **<span style="color:#2980b9">⑤ 交接文档要"实证、可执行"。</span>** 提示词强制要求：引用真实路径/命令、未完成事项落到可执行下一步、不确定标"❓需人工确认"——避免交接单变成空话。

📌 **<span style="color:#e67e22">⑥ 提示词里的路径是当前机器实测值</span>**（`C:\Users\asus\.codex\`）。换账号机器路径相同（都在用户主目录下），但输出目录按需自行修改。
