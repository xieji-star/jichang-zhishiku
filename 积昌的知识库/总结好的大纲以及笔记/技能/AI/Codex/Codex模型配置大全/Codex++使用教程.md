## 1. Codex++ 简介

**Codex++** 是一个面向 OpenAI Codex 桌面端的**外部增强启动器和管理工具**。它是社区开源项目（非官方），不修改 Codex 原始安装文件，而是通过 **Chromium DevTools Protocol (CDP)** 在运行时动态注入增强脚本。

> [!QUOTE] 核心理念
> 把官方没做的"开发者刚需"补齐——插件解锁、会话删除、API 中转、Markdown 导出、用户脚本扩展。

**GitHub 开源地址**：`https://github.com/BigPizzaV3/CodexPlusPlus`

---

## 2. 核心功能

| 功能 | 说明 |
|------|------|
| **插件解锁** | API Key 模式下恢复插件入口，原本在 API Key 模式下被禁用的插件功能可正常使用 |
| **会话删除** | 悬停会话即出现删除按钮，方便管理对话记录 |
| **API 中转注入** | 支持接入 DeepSeek、GLM、Kimi 等第三方大模型 |
| **Markdown 导出** | 将对话记录导出为 Markdown 文件，方便存档和分享（通过管理工具中对应入口操作） |
| **供应商配置** | 灵活切换和管理多个模型供应商（Provider） |
| **用户脚本系统** | 类似 Tampermonkey，支持自定义 UI 和功能 |
| **Provider 同步** | 切换 API 后旧会话不消失，保持会话连续性 |
| **Zed 编辑器集成** | 支持远程 SSH 环境文件编辑 |

### 2.1 插件解锁详解

在 Codex 原版中，如果使用 API Key 模式（非订阅模式），插件功能会被禁用。Codex++ 通过 CDP 注入，在运行时动态解锁插件入口，让 API Key 用户也能正常使用插件功能。

### 2.2 会话管理

Codex 原版不支持删除单个会话，Codex++ 增加了会话悬停删除功能，极大改善了会话管理体验。

## 3. 下载与安装

### 3.1 下载方式

| 平台 | 方式 |
|------|------|
| **GitHub** | `https://github.com/BigPizzaV3/CodexPlusPlus` 的 Releases 页面 |
| **Windows** | 下载 `.exe` 安装包，双击安装 |
| **macOS** | 下载对应版本（Intel 芯片选 x64，Apple Silicon 选 arm64） |

### 3.2 安装后入口

安装完成后，桌面会出现两个入口：

| 入口 | 用途 |
|------|------|
| **Codex++** | 增强版启动器，通过此入口启动才能生效 |
| **Codex++ 管理工具** | 配置面板，管理供应商、脚本等 |

> [!WARNING] 重要提醒
> 安装 Codex 本体后，**请勿直接启动原版 Codex**，必须通过 **Codex++** 入口启动，增强功能才会生效。

### 3.3 启动流程

1. 先安装 Codex 官方桌面端
2. 安装 Codex++ 增强工具
3. 通过桌面的 **Codex++** 图标启动
4. 如需配置供应商，打开 **Codex++ 管理工具**

## 4. 接入第三方模型

以 DeepSeek 为例，核心配置项及步骤在 [[Codex模型配置方法大全]] 中有详细说明，此处仅列出要点：

| 配置项 | 典型值 |
|--------|--------|
| **接入模式** | `纯 API` |
| **Base URL** | `https://api.deepseek.com` |
| **上游协议** | `Chat Completions` |
| **测试模型** | `deepseek-v4-flash` |

配置完成后通过「测试连接」验证（HTTP 200 即成功），保存并启用即可。

除 DeepSeek 外，同样支持 **GLM**、**Kimi**、**通义千问** 及其他 OpenAI 兼容接口的模型。

## 5. 用户脚本系统

### 5.1 概述

Codex++ 内置了类似 **Tampermonkey（油猴）** 的用户脚本系统，允许用户自定义 Codex 桌面端的 UI 和行为。

### 5.2 使用方式

1. 打开 **Codex++ 管理工具**
2. 左侧选择「**用户脚本**」
3. 添加或编写自定义脚本
4. 脚本会在 Codex 启动时自动注入执行

### 5.3 常见脚本用途

- 自定义主题和样式
- 添加快捷键
- 修改界面布局
- 增加额外的功能按钮

## 6. Provider 同步与模型切换

### 6.1 Provider 同步

切换 API 供应商后**旧会话不会消失**，解决了原版中切换 API Key 后历史会话丢失的问题。

### 6.2 模型切换

通过 Codex++ 启动后，在 Codex 界面的模型选择下拉菜单中会出现所有已配置的供应商模型，可随时切换使用。

### 6.3 Zed 编辑器集成

支持与 Zed 编辑器集成，在远程 SSH 环境下可直接通过 Codex 操作 Zed 中的文件，适合远程开发场景。

## 7. 常见问题与解决方案

| 问题 | 原因 | 解决 |
|------|------|------|
| **Codex++ 菜单未出现** | 未通过 Codex++ 入口启动 | 确认是从 Codex++ 图标启动，而非原版 Codex |
| **连接测试失败** | API Key 或 Base URL 配置有误 | 检查 API Key 是否正确、Base URL 是否完整、网络是否正常 |
| **macOS 提示"已损坏"** | macOS 安全策略拦截 | 前往「系统设置 → 隐私与安全 → 仍要打开」 |
| **API Key 模式下插件灰色** | 原版 Codex 限制 | 通过 Codex++ 启动即可解锁 |
| **切换供应商后旧会话丢失** | 未启用 Provider 同步 | 确认 Codex++ 管理工具中相关选项已开启 |
| **配置界面与教程不一致** | 版本差异 | 不同版本界面略有差异，v1.1.7、v1.1.9、v1.2.x 各有不同，但核心逻辑一致 |

### 7.1 版本兼容性

| Codex++ 版本 | 特点 |
|--------------|------|
| **v1.1.7** | 早期版本，配置界面较简洁 |
| **v1.1.9** | 新增部分功能优化 |
| **v1.2.0 / v1.2.3** | 新版 UI，Provider 管理更完善 |

## 8. 技术架构

| 层面 | 技术栈 |
|------|--------|
| **后端** | Rust |
| **管理工具** | Tauri 2.x + React + Vite |
| **注入方式** | Chromium DevTools Protocol (CDP) |
| **打包** | NSIS (Windows) / DMG (macOS) |

Codex 桌面端基于 Electron（Chromium 内核），Codex++ 利用此特性通过 CDP 动态注入，因此无需修改原始文件。

---

## 9. 总结

**Codex++ 是目前 2025-2026 年最热门的 Codex 桌面端增强工具**，核心价值在于：

- 🚀 **接入国内大模型**：DeepSeek、GLM、Kimi 等，降低使用成本
- 🔓 **解锁完整功能**：API Key 模式下也能使用插件
- 🔧 **灵活管理**：多供应商切换、会话管理、Markdown 导出
- 📝 **可扩展性**：用户脚本系统满足个性化需求

> [!SUMMARY] 一句话总结
> 如果你正在使用 Codex 桌面端，Codex++ 是**必装级别**的增强工具，尤其适合希望接入国产大模型、降低使用成本的开发者。
