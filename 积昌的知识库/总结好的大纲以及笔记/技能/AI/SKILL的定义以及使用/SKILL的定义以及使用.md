## 一、开场——什么是 Skill

> 最近 Skill 这个概念非常火，但很多朋友还是困惑：**Skill 到底是什么？它有什么厉害的？**

本节课通过一个**逐步升级的案例**来帮助理解 Skill 的结构和原理，最终学会定制自己的专属 Skill。

**课程目标：**
- ✅ 理解 Skill 的结构和原理
- ✅ 学会定制自己的 Skill
- ✅ 一句话让 AI 生成符合品牌风格的物料图片（海报、优惠券、员工服装等）
- ✅ 了解实用的 Skill 推荐

> [!NOTE]
> 讲师秋之还制作了一个**秋之技能生成器**，只需回答 AI 出的选择题，就能为你量身定制 Skill。所有资料链接和补充资料都已整理成网页。

## 二、Skill 的类比——像厨师的技能一样

**Skill** 翻译过来就是**技能**，它和人类的技能是类似的。

### 厨师的技能类比

| 厨师技能要素 | 对应 AI Skill 要素 |
|-------------|-------------------|
| **流程**（先炒什么、后放什么） | **Instructions**（指令） |
| **配方**（油温多高、盐放多少） | **Rules/参数**（规则/参数） |
| **工具**（煤气灶、锅铲） | **Scripts**（脚本） |
| **材料**（独家食材、一支辣椒） | **References/Assets**（参考资料/资源） |

> **核心观点**：AI 要做菜，也得有流程、配方、工具和材料。在创建 Skill 时，**SKILL.md、references、scripts** 这些东西打包成一个文件夹，这就是一个 Skill。

### 写作 Skill 示例

比如要做一个**写作 Skill**，可以在 SKILL.md 中要求 AI：
1. 先去指定网站搜集信息
2. 按爆款原则写大纲
3. 参考特定语气写稿
4. 按平台要求审稿

> [!QUESTION] 修正存疑
> 原文"6点NBreferencestrips" 根据上下文推测应为 **SKILL.md、references、scripts**（AI 字幕对英文术语的识别错误）。

### Skill ≠ 只是提示词

有朋友会疑惑："这不就是写提示词吗？"

**本质上确实是**——毕竟大模型的交互离不开提示词。但这并不是 Agent Skill 的全部。它在**工程上有更多优势**，远不止拷贝粘贴提示词那么简单。

## 三、创建第一个 Skill——手动方式

### 3.1 所需工具

- **编辑器**：VS Code（用来查看和编辑文件）
- **Agent 工具**：Claude Code（用来处理任务）

> [!QUESTION] 修正存疑
> 原文说"谷歌反重力来做编辑器"，根据上下文推测可能是 **VS Code** 或类似的代码编辑器。此处存疑，请确认。

### 3.2 第一步：创建文件夹结构

按照 Claude Code 的规定，创建 Skill 必须在 `.claude/skills/` 文件夹内进行：

```bash
# 在 .claude/skills/ 下创建 skill 文件夹
mkdir -p .claude/skills/秋之创意
```

### 3.3 第二步：创建 SKILL.md

每个 Skill 文件夹里**必须有一个 `SKILL.md`**（大写 S）文件。

**SKILL.md 的结构：**

```markdown
---
name: 秋之创意
description: 做创意物料用的，当用户说要做个海报什么的物料，它就自己触发
---

# 秋之创意 Skill

我们的餐厅叫做**秋之餐厅**。
品牌风格有这些要求：...
输出格式：...
```

#### 文件结构拆解

| 部分 | 名称 | 作用 |
|------|------|------|
| `---` 之间的内容 | **Metadata（元信息）** | 告诉系统这个 Skill 叫什么名字、是干嘛的、什么时候可以用 |
| `---` 下面的内容 | **Instructions（指令）** | 具体告诉 AI 怎么做（提示词） |

> **示例**：上面这个 Skill 的作用是"做创意物料"，当用户说"做个海报"时，它就会被触发。

### 3.4 测试 Skill

保存好 SKILL.md 后，启动 Claude Code 询问"你有哪些 Skill？"，它就会识别到刚创建的"秋之创意 Skill"。

然后直接说："我要做一个秋之餐厅的春节促销海报，给个创意"。

- Claude Code 提示"正在加载这个 Skill"
- 同意后，它会按照 SKILL.md 中的要求和格式输出创意

## 四、按需加载第 1 层——Metadata 元信息

### 为什么需要按需加载？

当正常和 Claude Code 聊天时，大模型**只会看到**每个 Skill 里的**两行短元信息**（name + description）。

只有当你说到要做一个秋之物料时，它才意识到"该看具体的指令了"，才会去加载**完整的 SKILL.md 指令**。

### 好处

| 优势 | 说明 |
|------|------|
| **同时拥有多个 Skill** | 每次 AI 都会看一遍所有 Skill 的简短元信息（就像一个目录） |
| **回答更精准** | 只有需要时才加载完整指令，没有了其他 Skill 的干扰 |
| **节省 Token** | AI 加载的内容少了，Token 消耗自然就省了 |

> **这就是按需加载的第 1 层。**

## 五、按需加载第 2 层——References 参考资料

### 问题场景

当需求变得复杂时，比如秋之餐厅的物料分很多种：

| 物料类型 | 示例 |
|---------|------|
| **常规物料** | 海报、菜单 |
| **实体物料** | 餐盒、杯子、员工服装 |
| **社交媒体物料** | 公众号封面、微博配图 |

它们的**尺寸不同、配色要求不同、平台规范也不同**。

> [!QUESTION] 修正存疑
> 原文"求职餐厅"根据上下文推测应为 **秋之餐厅**（讲师的品牌名），已统一修正。

如果**把所有物料的要求都写进 SKILL.md**，文件会变得巨长。当只需要做实体餐盒设计时，AI 却要读完整篇包括公众号规格的内容——造成浪费和信息干扰。

### 解决方案：References 文件夹

官方规定了 `references/` 文件夹。可以把不同物料规格**单独拆出来**：

```
秋之创意/
├── SKILL.md                    ← 只留通用要求和指引
└── references/
    ├── 实体物料规格.md          ← 工服、餐盒等线下物料要求
    └── 社交媒体物料规则.md       ← 公众号封面、微博配图尺寸要求
```

在 `SKILL.md` 中写指引：

```markdown
- 如果用户要做**线下实体物料** → 去读 `references/实体物料规格.md`
- 如果用户要做**社交媒体类** → 去读 `references/社交媒体物料规则.md`
```

### 效果

- 做常规物料时：**两个 reference 文件大模型都不会看**
- 做实体餐盒时：AI 会通过 SKILL.md 的指引，**只看** `references/实体物料规格.md`
- 做社交媒体时：同理会**只看** `references/社交媒体物料规则.md`

> **这就是按需加载的第 2 层——进一步精准加载。**

## 六、按需加载第 3 层——Scripts 脚本与 Assets 资源

### 6.1 Scripts 脚本

前面的 Skill 只能**输出创意**，还需要自己去做图。现在想让 AI **直接生成图片**。

这就要用到 `scripts/` 文件夹——里面放的是**可执行的脚本**。

```python
# scripts/generate_image.py
# 调用 AI 绘图 API 的生图脚本
```

**使用方式：**
1. 在 `SKILL.md` 中写指引："如果用户要求直接生成图片，把创意转化成生图提示词，然后按这个命令调用脚本"
2. AI 会运行脚本，不需要读取脚本里面的代码

> **关键**：脚本里的代码 AI 不需要看，只管运行——**一点 Token 都不占**。

但如果 SKILL.md 里的指引写的不够清楚，AI 可能不得不自己去读脚本。

### 6.2 Assets 资源

如果希望生成的物料图片**保持秋之餐厅的 Logo 不变**，还需要提供参考图。

建一个 `assets/` 文件夹，把 Logo 图片放进去：

```
秋之创意/
├── SKILL.md
├── references/
├── scripts/
└── assets/
    ├── logo-white.png
    └── logo-color.png
```

在 SKILL.md 中说明：参考图在 `assets/` 文件夹，生图时要把 Logo 图片当参数传给脚本。

### 完整调用流程

```
用户说"帮我做一张周六饮料免费的实体海报"
    ↓
① 加载 Skill（metadata 层）
    ↓
② 发现是实体物料 → 去读 references/实体物料规格.md
    ↓
③ 需要直接生成图片 → 生成提示词 + 带上 Logo 参考
    ↓
④ 运行 scripts/generate_image.py
    ↓
⑤ 输出符合品牌规范的海报图片 ✓
```

> [!NOTE]
> 实测效果：多次测试生成的图片在**尺寸、配色、Logo**上都完全符合品牌规范。而且如果只要求创意不要图片，脚本也不会被执行。

## 七、Skill 完整形态回顾

### 最简单的 Skill

```
my-skill/
├── SKILL.md    ← 元信息 + 指令（必需）
```

### 完整形态的 Skill

```
my-skill/
├── SKILL.md       ← 必需：元信息 + 指令
├── references/    ← 可选：按需加载的参考资料
├── scripts/       ← 可选：可执行脚本（AI 只执行不读取）
└── assets/        ← 可选：资源文件（图片等）
```

### 按需加载的三层结构（渐进式披露机制）

| 层级 | 名称 | 加载时机 |
|------|------|---------|
| **第 1 层** | **Metadata（元信息）** | **始终加载**——每次对话 AI 都会看到所有 Skill 的 name + description |
| **第 2 层** | **Instructions（指令）** | **触发时加载**——当 AI 判断需要用到该 Skill 时，加载完整 SKILL.md |
| **第 3 层** | **Resources（资源）** | **按需加载**——references 在需要查阅时加载，scripts 只执行不读取 |

## 九、总结与资源

### 核心要点

1. **Skill = 文件夹 + 文件**，在 `.claude/skills/` 下创建
2. **最简单的 Skill** 只需要一个 `SKILL.md`
3. **完整形态的 Skill** = `SKILL.md` + `references/` + `scripts/` + `assets/`
4. **按需加载（渐进式披露）** 是 Skill 最重要的设计——三层结构让 AI 只在需要时加载相应内容
5. **脚本只执行不读取**，不占 Token
6. 创建 Skill 的本质是**用自然语言写程序**
7. 对普通人来说，用 **Skill Creator 工具** 是最便捷的方式

### 推荐实践

> "一个游戏英雄只需要 4 个技能 QWER 就能杀穿全场。所以最有效的还是把你最高频做的事，打磨成你独有的、稳定产出的专属 Skill。"

- **打工人** → 做周报 Skill，让 AI 主动采访你然后出周报
- **老师** → 做备课 Skill，给出课题就生成课件、习题和 PPT
- **内容创作者** → 做配图 Skill，给文章就能按风格配图
- **法务/商务** → 做合同审查 Skill，按你的规矩自动批阅合同
