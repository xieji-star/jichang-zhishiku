## 一、什么是 Skill？

**Skill** 翻译过来就是"技能"，它是 Claude Code 的一个扩展机制。你可以把 Skill 想象成 AI 的"插件"——每个 Skill 都教 AI 学会一项特定的本领。

### Skill 的文件夹结构

```
my-skill/
├── SKILL.md       ← 必需：技能的定义和指令（告诉 AI 怎么做）
├── references/    ← 可选：按需加载的参考资料
├── scripts/       ← 可选：可执行的脚本（AI 只运行不读取代码）
└── assets/        ← 可选：资源文件（图片等）
```

### 怎么用 Skill？

有两种方式：
- **自动触发**：你说的话触发了某个 Skill 的描述（description），AI 自动加载并使用它
- **斜杠命令**：在对话框中输入 `/skill名称` 直接调用

## 二、基础工具类 Skill

这类 Skill 提供了通用的基础能力，不依赖飞书等特定平台。

---

### 1. `/技能创建工具` — 创建和编辑 Skill

**作用：** 这是"制造技能的技能"。当你需要创建一个新的 Skill、修改现有 Skill、或者测试 Skill 的效果时使用。

**什么时候用：**
- "我要创建一个新的 Skill"
- "帮我修改一下某个 Skill"
- "帮我测试一下这个 Skill 好不好用"

**它能做什么：**
- 通过问答形式帮你从头创建 Skill
- 自动生成测试用例来检验 Skill 是否正常工作
- 优化 Skill 的描述文本，让它更容易被正确触发
- 评估和迭代改进已有的 Skill

**不负责：** 如果你只是想了解 Skill 是什么，不需要用它。

---

### 2. `/Markdown排版工具` — Markdown 排版与格式转换

**作用：** 一个专业的 Markdown 排版工具，主要用来做文章排版，支持一键转成微信公众号格式。

**什么时候用：**
- "帮我把这篇 Markdown 排版成好看的文章"
- "我要发到公众号上，帮我转成微信格式"
- "把这个网页内容转成 Markdown"

**它能做什么：**
- 把 Markdown 渲染成带样式的 HTML（支持 14 种排版风格）
- 把 HTML 反过来转成 Markdown
- 从 Markdown 中提取纯文本
- 自动检查和修复 Markdown 格式问题（比如标题后没空格、列表格式不对等）

**常用排版风格：** Ayu Light（默认）、Professional（商务）、Terminal（终端风格）、Newsprint（报纸风格）、Retro（复古风格）等 14 种。

---

### 3. `/提示词优化` — 提示词优化工具

**作用：** 帮你打磨和优化你的提示词（Prompt），让你写的指令更加清晰有效。

**什么时候用：**
- "帮我优化一下这个提示词"
- "我写的 Prompt 不够好，帮我改进一下"
- "想让 AI 更好理解我的需求"

**它能做什么：**
- 和你就任务目标进行深入对话
- 帮你明确交付物和成功标准
- 把模糊的需求整理成清晰的步骤
- 最终生成一份结构清晰的 Markdown 版提示词

**注意：** 这个 Skill 只负责写提示词，**不写任何代码**。

---

### 4. `/Excalidraw图表` — 创建可视化图表

**作用：** 用 Excalidraw 工具创建漂亮的图表，用来展示工作流程、系统架构和概念图。

**什么时候用：**
- "帮我画一个流程图"
- "可视化一下这个系统架构"
- "画个图来解释这个概念"

**它能做什么：**
- 生成 `.excalidraw` 格式的图表文件（可以在 Obsidian 中用 Excalidraw 插件打开）
- 图表不仅是展示信息，更是"用视觉表达观点"
- 支持流程图、架构图、概念图等各种类型
- 自动从参考资料中读取配色方案并应用

---

### 5. `/技能搜索` — 搜索和安装新技能

**作用：** 帮你去 Skill 商店（skills.sh）搜索和安装社区中别人创建好的 Skill。

**什么时候用：**
- "有没有一个能做 X 的 Skill？"
- "帮我找找有没有 PPT 相关的 Skill"
- "我想扩展一下 AI 的能力"

**它能做什么：**
- 搜索 skill 社区（skills.sh）上的公开 Skill
- 查看最流行的 Skill 排行榜
- 一键安装别人做好的 Skill
- 检查 Skill 更新

## 三、飞书办公套件 Skill

以下 Skill 都是围绕**飞书（Lark/Feishu）**的各种功能，需要用到 `lark-cli` 工具来操作。**共 27 个 `lark-*` Skill**，均位于知识库 `.claude/skills/飞书智能助手/` 聚合目录下（连同第 33 号 `feishu-manual-takeover` 共 28 个飞书技能），覆盖了飞书几乎所有功能模块。

### 🔐 基础与共享

#### 6. `/lark-shared` — 飞书认证与权限管理

**作用：** 所有飞书操作的基础。处理登录、身份切换（bot 身份 vs 用户身份）、权限授权等底层事务。

**什么时候用：** 通常不需要直接调用，其他飞书 Skill 会自动使用它。但如果你遇到"权限不足"、"需要登录"等提示，就是这个 Skill 在处理。

**核心概念：**
- **bot 身份**：以应用的身份操作（适合自动化场景）
- **user 身份**：以你的个人身份操作（适合需要你个人数据时）

### 36. `/LLM知识库` — LLM Wiki 知识库维护

**作用：** 管理你的 Obsidian 知识库 Wiki——把新资料"吃进去"并整合到现有知识体系中，回答基于 Wiki 的查询，定期做健康检查。

**什么时候用：**
- "帮我把这篇文章整合到知识库里"
- "更新一下某个 Wiki 页面"
- "根据我的知识库回答这个问题"
- "检查一下知识库的健康状况"

**它能做什么：**

#### ① 摄取（Ingest）—— 整合新资料
当你有一篇新的文章、笔记或 PDF 想加入知识库时：
1. 分析新资料的内容和主题
2. 确定它属于哪个分类
3. 创建新的 Wiki 页面或更新现有页面
4. 建立交叉引用链接
5. 更新目录（index.md）
6. 记录操作日志

#### ② 查询（Query）—— 回答基于知识库的问题
当你问一个需要综合多个 Wiki 页面才能回答的问题时：
1. 找到相关的所有页面
2. 综合信息给出结构化的回答
3. 标注信息来源

#### ③ 健康检查（Lint）—— 维护知识库质量
定期检查知识库是否存在问题：
- **矛盾检测**：不同的页面是否有相互矛盾的说法
- **过时检查**：是否有信息已经过时
- **孤立页面**：是否有页面没有被任何其他页面引用
- **缺失页面**：是否有重要概念被提到但缺少专门的页面
- **交叉引用修复**：相关的页面之间是否建立了链接

**核心原则：**
- 原始来源文件**只读不修改**
- 所有提取和重组都在 Wiki 层完成
- 你负责"探索知识"，AI 负责"整理归档"
