> **交接日期**：2026-08-18

## 复制以下完整内容，粘贴给 DeepSeek Harness

```markdown
你正在结束一段工作，现在要把当前工作交接给下一个续作智能体 Codex。
请基于我们这段对话的聊天记录，写一份《知识库自动化整理项目 交接文档（给 Codex 版）》。

接手方 Codex 对项目几乎零了解。你的写稿目标：让 Codex 读完这份文档后，不靠问任何人、不查任何额外资料，就能——①看懂这项目在做什么、做到哪了；②知道哪些做完了、哪些没做完、为什么没做完；③能照着文档直接动手干第一步；④每一步做完都能自己判断"做得对不对"。

> 项目背景（供你定位）：这是「知识库自动化整理」项目，前一段由 Claude Code 完成了大约一半；现在要由你（DeepSeek Harness）基于这段对话的聊天记录，把交接文档写出来交给 Codex 续作。聊天记录里出现过的所有目标、进度、决策、踩坑、文件路径、数据，都是你的素材。

═══════════════════════════════════════
【零、先明确三件事（动笔前必读）】
═══════════════════════════════════════
1. 你的身份：你现在是"交接文档撰写人"，不是普通聊天助手，也不是项目的新开发员。你的唯一产出就是这份交接文档。
2. 文档读者：下一个续作智能体 Codex（AI）。它是 L1 自治型智能体——能读本地文件、能跑 PowerShell 命令、能自主多步推理。但你（DeepSeek Harness）读不到它所在环境的文件、不能跑命令，所以你要把关键内容"喂到它嘴边"。写的时候始终站在 Codex 的角度问自己："这段它能直接执行吗？这个路径它能直接打开吗？"
3. 你的信息边界：素材 = 这段对话的聊天记录。你主要靠对话记忆，可能读不到本地文件、不能跑命令、上下文有限、容易记岔。所以：聊天记录里没有或记不清的，绝不脑补——要么追问用户，要么标注"❓待确认"写进核对清单，绝不确定地写一个你可能记错的路径/命令/数字。

═══════════════════════════════════════
【一、必须回答的四个问题（四要素）——缺一不可，尤其 ③④ 不许一笔带过】
═══════════════════════════════════════
一份合格的交接文档，必须把下面四个问题全部回答清楚。①② 讲"过去"，③④ 讲"未来"——只有 ③④ 写透，Codex 才能不靠问人直接开工。

① 当前已经做了什么（= 已完成工作全量清单）
- 把已完成的工作全量、逐条列出（按模块或时间分组），不要只挑重要的写。
- 每条写满 4 个字段：
  - 做了什么：一句话说清成果。
  - 产出物在哪：真实相对路径 ＋ 一句话用途。
  - 怎么验证有效：可复现的验证方法（跑哪条命令看到什么输出 / 打开哪个文件看到什么内容）。
  - 关键数据/效果：能写数字就写数字（条数、时长、通过率、性能指标等）。

② 还有什么没做的（= 未完成工作全量清单，是留给 Codex 的"接力棒"）
- 把没做完的事全量、逐条列出，不要因为"不想暴露没做完"而漏掉。
- 每条写满 7 个字段：
  - 还差什么：具体到差哪一块、缺哪个功能/数据/步骤。
  - 为什么没做完：阻塞原因（时间不够 / 技术难题 / 等依赖 / 等决策 / 等授权）。
  - 前置条件：做这件事之前必须满足什么。
  - 优先级：紧急 / 重要 / 一般。
  - 做到什么算完成：可验收的定义（可检验，不说"做完"这种空话）。
  - 从哪开始：入口（文件:行号 / 函数名 / 命令 / 找谁）。
  - 验证信号：看到什么现象算真正完成/接上了。

③ 接下来要接着做什么（= 接力任务，与②一一对应）
- 每个接力任务与②里的某一条一一对应、编号一致。
- 每条写清：接哪个遗留项 / 从哪开始 / 做到什么算完成。

④ 接下来该怎么做（= 具体步骤，把③展开成 1-N 步）
- 把每个接力任务展开成 Codex 能照做的 1-N 步。
- 每步写清：做什么 → 打开哪个文件/跑哪条命令/找谁 → 看到什么结果算做对了 → 卡住了看哪个文档/问谁。
- 区分"立即做"与"之后做"。

> ⚠️ 判优标准：Codex 能不能不问任何人、不查任何东西，就照着 ③④ 动手干第一步？能 → 合格；不能 → ③④ 没写透，继续补。
> 🚫 禁止出现这些"一笔带过"：❌"还有几件事没做完，下次继续" ❌"你接手后把剩下的做一下" ❌"详见之前的记录" ❌"等等/后续再说" ❌"这块比较复杂你自己看" ❌"剩下你应该都会"。出现任何一句，都必须展开成上面带字段的条目。

═══════════════════════════════════════
【二、必须有一张「A→B 接力总览表」】
═══════════════════════════════════════
把②（A 没做完的接力棒）和③④（Codex 接下来要做的）用一张表钉在一起、一一对应，让 Codex 读到就能照着 #1 开工：

| # | A 没做完的（接力棒） | Codex 要做什么 | 从哪开始（贴出关键内容/代码片段，不只写路径） | 做到什么算完成（用户帮跑什么命令、看到什么输出） |
|---|--------------------|---------------|---------------------------------------------|-----------------------------------------------|
| 1 | <遗留事项1> | <要做的事1> | <入口 + 贴出关键代码/配置片段> | <用户帮跑什么命令、看到什么输出> |
| 2 | ... | ... | ... | ... |

要求：
- 每个遗留事项占一行，编号与②③一致。
- "从哪开始"列不能只写路径——把你记得的关键文件内容/代码片段直接贴进这一列，并标证据分级。
- "做到什么算完成"列给"用户帮跑什么命令、看到什么输出"。
- 表末给一句"接力开工第一步"：具体动作 → 出现什么现象算正式接上了。

═══════════════════════════════════════
【三、文档结构（给 AI 版，逐节完整写出）】
═══════════════════════════════════════
采用"给 AI（Codex）版"14 节结构，每一节都要写，不能跳节、不能合并、不能整节删除——没内容也要写"暂无，因为……"：

0. 交接摘要（启动包）：项目做什么、当前做到哪一步；最关键三件事（已完成什么 / A 没做完的接力棒 / Codex 下一步第一件事）；一句话提示从哪继续最省力。
1. 项目总览与验收标准：一句话定位、最终目标、做到什么程度算完成（可检验）。
2. 文件地图（精确路径）：逐个列出文件/文件夹：真实路径、作用、当前状态（新建/修改/已完成/未动/临时）；你读不到文件，就把关键文件内容/要点直接贴出来。
3. 已完成工作：全量逐条，每条写满 4 字段；含关键代码位置/函数名（便于接着改）。
4. 当前精确进度：最后一步有效操作是什么（在哪行代码/哪个文件）；当前代码/文档/数据处于什么具体状态。
5. A 没做完的事（接力棒）：全量逐条，每条写满 7 字段；点明"每个未完成项就是 Codex 要接的活"。
6. A→B 接力总览：见【二】。
7. 下一步行动计划（命令级）：把"Codex 要做什么"展开成 1-N 步；命令给完整可复制版本，写明预期输出；区分"立即做/之后做"。
8. 环境与配置依赖：模型/工具/软件及版本、端口、环境变量、依赖库；关键配置项直接贴出值（脱敏）；密钥/token 只写存放位置，值写 <已脱敏>。
9. 数据与状态快照：涉及的数据/文件/接口当前状态；临时数据/测试数据是否需要清理；需保留的中间产物。
10. 关键决策与踩坑记录：技术选型及原因、踩坑根因与规避方案、放弃的方案及原因。
11. 风险与待确认项：逐条标"❓"。
12. 续作启动手册：从零恢复完整步骤；如何验证"续上了"（写成"请用户代跑 XXX，看到 YYY 输出"）。
13. 按 Codex 定制的附加内容：涉及第三方模型/供应商配置时提示检查 config.toml；涉及外网访问提示代理/分流要求；涉及跨机迁移说明会话文件位置（拷 sessions 不拷 auth.json）。

自包含要求贯穿所有节：凡是涉及路径、代码、配置、命令的地方，都要把内容本身贴出来，绝不只写"在 xxx 文件里"。

═══════════════════════════════════════
【四、信息收集方式与真实纪律】
═══════════════════════════════════════
1. 优先基于聊天记录：先把这段对话里的目标、进度、决策、踩坑、文件路径、数据全部提取出来作为主素材。
2. 信息不足时的补救顺序：先追问用户（你读不到文件）→ 仍然缺的，标注"❓待确认"，写进文档并在末尾的核对清单里请用户补。
3. 真实纪律（硬性）：你读不到文件、不能跑命令，所以凡是路径、命令、函数、状态，必须标证据分级：✅确定（聊天里明确出现）/ 🔶推断（你推理补的）/ ❓待确认（记不清/没明说）。禁止把推断写成确定；绝不编造。

═══════════════════════════════════════
【五、写作规范与禁止事项】
═══════════════════════════════════════
1. 宁可多，不可漏：拿不准要不要写，就写；同类列表全量列出，不挑三拣四。
2. 能写数字就写数字：条数、时长、通过率、性能、完成度百分比（如"约 70%"，并给判断依据）。
3. 每条路径给相对路径＋一句话用途；命令给完整可复制、可执行的版本，并写明预期输出。
4. 全文用 Markdown 排版：标题层级清晰、要点用列表、关键信息加粗或引用块、成对内容用表格。
5. 给"AI"看的版：零废话、入口精确（文件:行号 / 函数名 / 命令）、关键内容自包含、验证信号明确、附"如何验证续上了"。
6. 密钥/token 一律脱敏：只写存放位置，值写 <已脱敏>。

═══════════════════════════════════════
【六、按你的能力定制的写作方式（务必照做）】
═══════════════════════════════════════
你（DeepSeek Harness）主要靠这段对话的聊天记录，可能读不到本地文件、不能跑命令。所以：
① 自包含：关键代码、配置、命令、路径、数据一律直接贴进文档正文，绝不只写"在 xxx 文件里"——你连自己写的路径都可能记错，要给就给全。

④ 每步只做一件事，每步给一个可观察信号；把歧义全部消掉，不要让你猜（不写"等""后续再说"）。
⑤ 文档末尾必附"请用户核对的清单"：把你提到的所有路径/文件状态/命令逐条列出，请用户核对是否属实并代跑确认，修正后再交付 Codex。
```
