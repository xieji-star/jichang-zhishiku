## 1. 开场：百万 Token 能做多少事、要花多少钱

### 1.1 百万 Token 是什么概念

💡 **<span style="color:#2980b9">Token（词元）：大模型处理文本的基本计量单位，粗略理解 1 Token ≈ 1 个汉字。</span>** 以国产大模型 DeepSeek（深度求索公司开发的 AI 模型）为例：

- 📊 **<span style="color:#e67e22">100 万 Token ≈ 100 万汉字的内容</span>**
- 用量感知（不同使用方式，100 万 Token 的消耗速度差别巨大）：
  - 辅助写稿子、偶尔开发小工具：**差不多 1 小时的量**
  - 只是聊天、查资料：**能用个三四天**
  - 重度使用：**10 分钟左右用完都不足为奇**

### 1.2 价格对比：差距为何这么大

光知道用量没用，**真正决定我们用不用它的，说到底还是价格**：

| 模型 | 每百万 Token 输出价格 | 换算人民币 |
|------|----------------------|-----------|
| DeepSeek V4 Pro | 约 0.87 美元 | ≈ 6 元 |
| Claude 最新模型 | 直奔 50 | — |

（各模型定价差异的详细对比见 [[Codex的5.6三大旗舰模型差异]]）

- 如果一天用三四个小时，一个月差不多 600 来块——不算便宜
- 🔥 **<span style="color:#e74c3c">同样的输出量，Claude 最新模型价格直奔 50，与 DeepSeek 差距巨大</span>**

由此引出三个问题：**为什么差距这么大？模型消耗到底是怎么计费的？Token 又该怎么消耗才最值？**

## 2. 计费三大块：输入、输出、命中缓存

其实咱们每一轮花的钱，说到底就花在**三处**：

1. **输入**
2. **输出**
3. **命中缓存**（Prompt Caching，厂商把重复内容的计算结果存下来直接复用）

下面一块一块掰开讲。

## 3. 输入：对话越长越烧钱，规则文件要精简

### 3.1 什么是输入

我们发给大模型的所有内容——**不管是打的字、发的图，还是塞进去的文件，通通都算输入，都要按量计费**。

### 3.2 输入真正烧钱的根因：模型没记忆

- 模型本身是**没有记忆**的，根本记不住每轮对话聊过什么
- 程序只能用笨办法：**每次你发新消息，都得把之前聊过的全部内容重新打包递给他一遍**
- 这就意味着：**对话越长，他每轮要重读的东西就越多，你在输入这块花的钱也就越多**

💡 **<span style="color:#2980b9">输入烧钱的关键不是"你这一句话"，而是"他没记性"导致的重复重读。</span>**

### 3.3 省钱技巧：把规则文件写精简

最实在的一招：**把那些每次都会被自动带上的规则文件写精简**。

- 用 Claude Code（入门与配置见 [[Claude Code 从 0 到 1 完全使用教程（Obsidian版）]]）的话，你的 `CLAUDE.md` 文件（Claude Code 的项目指令文件，每轮对话自动加载）；用 Codex、OpenCode 的话，就是 `AGENTS.md` 文件（Codex / OpenCode 的项目指令文件）
- 这些文件**每一轮对话都会被自动顶到最前面**（相关概念见 [[Claude Code 与 Codex 对比]]）
- 里头的废话和重复**该砍就砍**，别让他悄悄吃掉你的 Token

📌 **<span style="color:#e67e22">规则文件精简 = 每轮自动生效的输入成本削减，性价比最高的省钱方式。</span>**

## 4. 输出：思考也要算钱，管住字数与思考档

### 4.1 输出由两样东西组成

输出就是模型回给你的所有内容，但很多人没注意到，它其实由**两样东西**组成：

1. **回复内容**：你能直接看到的那段回复
2. **思考过程**：他在正式回复你之前，先自己在后台推导一番的过程——现在不少模型都有**思考模式**，给你答复之前会先想一段，这段思考也是他一个字一个字生成出来的

### 4.2 为什么输出往往是账单最贵的一块

- 思考内容**同样算输出、同样按量计费** → 思考档开得越高，花费涨得越凶
- 输出的单价本来就比输入高
- 🔥 **<span style="color:#e74c3c">对大多数人来说，输出往往是整张账单里最贵的一块儿。</span>**

### 4.3 省钱技巧：就两招

1. **让他少说两句**：凡是几句话就能交代清楚的问题，没必要让他长篇大论发挥——他生成的字数越少，你掏的钱越少
2. **别动不动就把思考开到最高**：简单的问题，思考档往下调一调完全够用——他推理的时间越短，花费自然越省

⚠️ **<span style="color:#e74c3c">字数砍太狠、思考压太低，回答质量也会跟着掉——这个度得自己把握，省钱归省钱，别把正经活儿给耽误了。</span>**

## 5. 命中缓存：复用省钱的机制与代价

### 5.1 原理：把重复计算的结果存下来

- 还记得前面说的吗？模型**每轮都要把你的历史对话重新读一遍、重新算一遍**——这个过程最吃力，算力也最贵
- 但厂商发现：**第一轮往后的每轮对话，开头的历史部分基本上是一模一样的**，于是做了个优化：
  1. **头一次**把这些重复内容的计算结果先存下来
  2. 等你下一轮再发消息，只要前面的内容和之前对得上，他就**直接拿来用，跳过最耗时的重新计算那一步**
- 这部分钱就这么省下来了——这就是**命中缓存**

💡 **<span style="color:#2980b9">命中缓存 = 把"重复计算"变成"直接取用"，前提是历史部分内容完全对得上。</span>**

### 5.2 既然是复用，为什么还要收钱

因为每次他都得**把存好的结果重新调出来，加载到这一轮来处理**——这个调取的过程本身也要耗点算力，所以也得适当收点。

### 5.3 省缓存的难点与对策

针对命中缓存怎么省，倒没什么好办法，因为它**最依赖的就是你的上下文窗口**（模型单次能处理的最大内容量）：

- 你如果**清空**了上下文 → 命中缓存就没了
- 不**清空** → 上下文窗口占用超过 50%，模型的输出质量就会下降
- ⚠️ **<span style="color:#e74c3c">清也不是、不清也不是：清空丢缓存，占用超 50% 丢质量。</span>**

📌 **<span style="color:#2980b9">对策：把长任务拆成独立的小任务，在保持上下文占用不高的情况下，通过不断新开对话来规避这个问题。</span>**

## 6. 每轮花费怎么算：三块加总

了解了这三个部分，百万 Token 消耗的价格算下来就是：

1. **新增的输入**（包含没有命中的历史）：按输入价算
2. **输出**：按输出的价格算
3. **缓存命中的部分**：按缓存价算

🧮 **<span style="color:#e67e22">三个部分加一块儿 = 你这轮的总花费</span>**

## 7. 两点特别提醒

### 7.1 分级使用：零碎活用免费模型

- **不费脑子的零碎活**——像整理资料、改格式这种，**丢给免费的模型就够了**
- 等真的碰到**硬茬**，再把主力请出来
- 关于免费模型怎么找：上期视频讲过，没看过的小伙伴可以去翻一翻

### 7.2 别太迷信压缩插件

- 市面上那些号称能帮你省大钱的工具，像 **Roo Code、Roo Cline**（VS Code 里的 AI 编程插件，主打上下文压缩）这类插件，宣传起来动不动号称能省六七成，夸张点的能吹到九成
- 但他们的原理大同小异：AI 在写代码时本身就会产生大量的**中间记录**，这些工具负责**把它们压缩成摘要，再往模型里送**
- 问题有两个：
  1. 他们能压缩的主要是**冗长的过程记录**——这部分在输入里**占比本来就不大**
  2. **压缩这件事儿注定要丢失信息**，很可能会导致莫名其妙的 bug，能改到你怀疑人生

⚠️ **<span style="color:#e74c3c">压缩省下的钱有限，丢信息引发的 bug 却可能更费钱——别迷信省大钱的神器。</span>**
