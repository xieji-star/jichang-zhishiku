# json含义详解

> [!summary] 概要
> JSON（JavaScript Object Notation，JavaScript 对象表示法）是一种**轻量级、与语言无关的文本数据交换格式**——它用一套极简的语法规则，把"数据"组织成人类能读、机器能解析的文本，让不同编程语言、不同系统之间可以互相传数据。JSON 目前是互联网上使用最广泛的数据格式：Web API 的前后端通信、软件的配置文件（如 `settings.json`、`package.json`）、数据库存储、日志输出、AI 接口的请求与响应体，几乎处处都有它的身影。本文从定义、历史、语法、数据类型、典型应用、优缺点到工具，完整拆解 JSON。

## 1. JSON 到底是什么——一句话加一个比喻

🔥 **<span style="color:#e74c3c">一句话定义：JSON 是一种轻量级、与编程语言无关的文本数据交换格式——用一套统一规则把"数据"写成纯文本，让任何程序都能读得懂、传得动。</span>**

打个比方：

> 想象你要寄一批包裹给一个外国朋友。你不能直接把东西丢进邮局，得先按**国际统一的打包规范**装好：纸箱多大、标签怎么贴、里面怎么填防震材料。只要打包规格统一，无论包裹从哪个国家发出，任何一家快递公司都能拆开、核对、送达。
>
> JSON 就是"数据的标准化打包盒"。程序 A 把数据按 JSON 规则"打包"成一段文本，通过网络或文件传给程序 B，程序 B 用现成的解析工具"拆包"，就能还原出原样的数据——**A 用什么语言写的、B 用什么语言写的，都不重要。**

- 💡 **<span style="color:#2980b9">JSON 是"数据格式"，不是"编程语言"</span>**——它不写逻辑、不写循环、不算加法，只负责"存数据"和"传数据"
- 📌 **<span style="color:#e67e22">"文本"是关键词</span>**——JSON 就是一串字符（string），正因为是普通文本，才能在网络上传、在文件里存、被任意语言解析
- ⚠️ **<span style="color:#e74c3c">不要用 `eval()` 解析 JSON</span>**——早期 JS 习惯用 `eval` 把 JSON 当代码执行，极其危险（会执行任意代码），现在一律用 `JSON.parse()`

## 2. JSON 的由来——出身与血统

- 🧑‍💻 **<span style="color:#2980b9">发明人：道格拉斯·克罗克福特（Douglas Crockford）</span>**——2001 年他从 JavaScript 的"对象字面量"语法中提炼出一套独立的数据格式，取名 JSON（JavaScript Object Notation）
- 📅 **标准化的三个里程碑**：
  - 2006 年 → 成为 **RFC 4627** 标准
  - 2013 年 → 更新为 **RFC 7159**
  - 2017 年 → 发布国际标准 **ECMA-404**（与 RFC 8259 内容同步）
- 🧬 **名字带 JS，但和 JavaScript 没有绑定关系**——JSON 是"语言无关"（language-independent）的，Python、Java、Go、C++、PHP 等几乎所有语言都有官方的 JSON 解析与生成库
- 📈 **为什么能火**：2000 年代初，网页前后端通信主要靠 XML，XML 标签冗长、解析笨重。JSON 更短、更直观、解析更快，随着 Ajax 时代的到来迅速取代 XML 成为 Web 数据交换的事实标准

>highlight 【一句话理解】JSON 是"从 JavaScript 里长出来的通用数据格式"——出身于 JS，但早已不属于 JS，属于全世界。

## 3. JSON 的两种核心结构

JSON 的所有数据，都建立在**两种结构**之上，且二者可以无限互相嵌套：

- 📦 **对象（Object）**——用花括号 `{}` 包裹，是"键值对"（key-value pair）的集合
  - 例：`{ "name": "张三", "age": 25 }`
  - 相当于"一张填好的表单"：每个格子（键）对应一个内容（值）
- 📋 **数组（Array）**——用方括号 `[]` 包裹，是"值"的有序列表
  - 例：`["苹果", "香蕉", "橙子"]`
  - 相当于"一张有序的清单"：按顺序排着一串数据

- 💡 **<span style="color:#2980b9">两者可嵌套成任意复杂的结构</span>**：数组里可以放对象，对象的值也可以是数组，再套对象、再套数组……无论多复杂的数据（一篇文章、一个订单、一张全校学生表），都能用这两种结构拼出来
- 🔑 **对象里的"键"必须是字符串（双引号包裹）**，值是任意类型；数组里的每个元素可以是任意类型

## 4. JSON 的六种数据类型

JSON 总共只有 **6 种数据类型**，学会它们就学会了 JSON 的全部"词汇表"：

| 类型 | 写法 | 说明 | 示例 |
|------|------|------|------|
| **字符串** string | `"..."` | 必须用**双引号**包裹（单引号不行） | `"hello"`、`"世界"` |
| **数字** number | 直接写 | 整数、小数、负数、科学计数法 | `42`、`3.14`、`-7`、`1.0e10` |
| **布尔** boolean | `true` / `false` | 只有这两个值（小写） | `true`、`false` |
| **空值** null | `null` | 表示"没有值"，区别于 `0` 和 `""` | `null` |
| **对象** object | `{...}` | 键值对的集合（见上一节） | `{ "a": 1 }` |
| **数组** array | `[...]` | 有序的值列表 | `[1, 2, 3]` |

- 📊 **<span style="color:#e67e22">数字没有"整数/浮点"之分</span>**——JSON 里所有数字统一按双精度浮点数处理，`1` 和 `1.0` 是同一个数
- ⚠️ **<span style="color:#e74c3c">没有的类型要格外注意</span>**——JSON **没有**日期类型（Date）、**没有** undefined、**没有**函数、**没有**注释、**没有**二进制。遇到"时间"只能写成字符串（如 `"2026-08-20T00:24:00Z"` 这种 ISO 8601 格式）
- 💡 **<span style="color:#2980b9">学会判空的三兄弟</span>**：`null`（没有值）、`0`（数字零）、`""`（空字符串）三者含义完全不同，处理数据时别混淆

## 5. JSON 的语法规则——严格是它的命根子

JSON 之所以能"任何语言都通用"，靠的就是**极度的严格**。规则越死板，解析越不会有歧义。以下是必须遵守的硬规则：

- 🔒 **键必须用双引号**：`{ "name": "张三" }` ✅；`{ name: "张三" }` ❌（JS 里能省略引号，JSON 不行）
- 🔒 **字符串必须用双引号**：`"hello"` ✅；`'hello'` ❌（单引号在 JSON 中非法）
- 🔒 **禁止尾逗号**：`{"a": 1, "b": 2}` ✅；`{"a": 1, "b": 2,}` ❌（最后一个元素后不能有逗号）
- 🔒 **禁止注释**：JSON 文件里写不了 `//` 或 `/* */` 注释（很多配置文件因此改用支持注释的 YAML/JSONC）
- 🔒 **布尔值必须小写**：`true` / `false` ✅；`True` / `TRUE` ❌
- 🔒 **空值只能是 `null`**（小写）
- 🔒 **数字不能是 `Infinity`、`NaN`**，也不能带前导零（`01` ❌）
- 🔒 **不允许出现 `undefined`、函数、正则等 JS 特有值**
- 🔒 **编码推荐 UTF-8**，文本内特殊字符需转义（如 `"` 写成 `\"`，换行写成 `\n`）

- ⚠️ **<span style="color:#e74c3c">"严格"是优点也是坑</span>**：多一个尾逗号、少一个引号，整个 JSON 就解析失败。所以写配置文件、传接口数据时，格式错误是最常见的低级错误
- 💡 **<span style="color:#2980b9">转义字符要记</span>**：字符串里的双引号、反斜杠、换行、制表符分别写作 `\"`、`\\`、`\n`、`\t`

## 6. 一个完整的 JSON 示例

先看一个最简单的：

```json
{ "name": "张三", "age": 25, "city": "广州" }
```

再看一个**包含全部 6 种类型、且多层嵌套**的真实感例子（一份"外卖订单"）：

```json
{
  "orderId": "D20260820001",
  "customer": {
    "name": "张三",
    "phone": "13800138000",
    "isMember": true,
    "level": null
  },
  "items": [
    { "name": "牛肉面", "price": 22.5, "count": 2 },
    { "name": "冰可乐", "price": 5.0, "count": 1 }
  ],
  "totalAmount": 50.0,
  "delivery": { "address": "广州市天河区", "status": "配送中" },
  "note": "不要香菜"
}
```

逐层拆解一下这个例子：

- `orderId` 是**字符串**；`customer` 是**对象**，里面又套了字符串、数字、**布尔**（`isMember`）和 **`null`**（`level`）
- `items` 是**数组**，数组里每个元素又是一个**对象**（每道菜的信息）
- `totalAmount` 是**数字**（带小数）
- 整体看：**对象套对象、对象套数组、数组套对象**——这正是第 3 节说的"两种结构无限嵌套"

>highlight 【看懂 JSON 的方法】拿到一段 JSON，先找最外层是 `{}`（对象）还是 `[]`（数组），再一层层往里"剥"。剥到某一层，值是键值对就是对象、是一串值就是数组，遇到 `"..."` 是字符串、裸数字是数字——剥完就全懂了。

## 7. 前端后端怎么用 JSON——JSON.stringify 与 JSON.parse

JSON 在 JavaScript 里用得最顺手，靠的是两个**成对**的方法：

- 🎁 **`JSON.stringify(obj)`——"打包"**：把 JS 对象/数组转成 JSON 字符串（用于发给后端、存进 localStorage、写文件）
- 📦 **`JSON.parse(str)`——"拆包"**：把 JSON 字符串解析回 JS 对象/数组（用于接收后端返回、读取文件后还原）

```javascript
// 打包：对象 → JSON 字符串
const user = { name: "张三", age: 25 };
const jsonStr = JSON.stringify(user);
// 结果: '{"name":"张三","age":25}'

// 拆包：JSON 字符串 → 对象
const back = JSON.parse(jsonStr);
console.log(back.name); // 输出: 张三
```

- 🌐 **<span style="color:#2980b9">前后端交互的标准姿势</span>**：前端 `fetch('/api/user')` 请求后端，后端返回 JSON 字符串，前端 `res.json()` 直接解析成对象——整个过程就是"打包 → 传输 → 拆包"
- 🔁 **<span style="color:#e67e22">其他语言同理</span>**：Python 用 `json.loads()` / `json.dumps()`，Java 用 Jackson/Gson 库，Go 用 `encoding/json`——概念完全一样，只是函数名不同

## 8. JSON 与其他数据格式的对比

| 格式 | 全称 | 特点 | 适合场景 | 短板 |
|------|------|------|---------|------|
| **JSON** | JavaScript Object Notation | 轻量、严格、语言无关、生态最大 | Web API、配置文件、数据存储 | 无注释、无日期类型 |
| **XML** | eXtensible Markup Language | 标签化、可自定义、有属性与命名空间 | 老系统、SOAP 协议、文档标记 | 冗长、解析慢、写起来累 |
| **YAML** | YAML Ain't Markup Language | 缩进式、支持注释、人类最友好 | 配置文件（Docker、K8s、CI/CD） | 缩进敏感易错、格式较松 |
| **TOML** | Tom's Obvious Minimal Language | 简洁、显式、支持注释、类型清晰 | 配置文件（`pyproject.toml`、`Cargo.toml`） | 生态相对小 |
| **CSV** | Comma-Separated Values | 纯表格、极简、Excel 友好 | 表格数据、大数据导入导出 | 不支持嵌套结构 |

- 🔥 **<span style="color:#e74c3c">一句话选型</span>**：**传数据用 JSON**（Web 接口、API、数据交换），**写配置优先 YAML/TOML**（人类要长期维护、需要注释），**表格数据用 CSV**，**兼容老系统才用 XML**
- 💡 **<span style="color:#2980b9">注意到一个有趣现象</span>**：Claude Code 用 `settings.json`（JSON 格式），而 Codex 用 `config.toml`（TOML 格式）——同样是 AI 工具的配置，厂商也会按需求选不同格式（详见 [[Claude Code 与 Codex 对比]] 的"配置文件对比"章节）
- 📌 **<span style="color:#e67e22">YAML 是 JSON 的超集</span>**：任何合法的 JSON 都是合法的 YAML，所以很多工具干脆直接用 JSON 写配置，兼容性最好

## 9. JSON 在计算机领域的典型应用

JSON 几乎无处不在，以下是它最常见的六大战场：

### 9.1 Web API 前后端通信（最大主战场）

前后端通过 HTTP 接口传数据，请求体和响应体几乎清一色是 JSON。你打开任意一个 App、网页，背后都是 JSON 在飞。

- 🔗 相关：请求体的 Content-Type 要声明为 `application/json`，一旦声明与实际格式不符就会报错（详见 [[HTTP 400 错误详解]]）

### 9.2 软件配置文件

- 📄 `package.json`（Node.js 项目配置）、`settings.json`（VS Code / Claude Code 配置）、`tsconfig.json`（TypeScript 配置）等
- 🔗 相关：Claude Code 的 Hook 就配置在 `settings.json` 的 `hooks` 字段里（详见 [[Claude Code中Hook的概念]]），其 Hook 脚本还要返回一段 JSON 来告诉 Claude 做什么

### 9.3 系统间通信与进程间通信（IPC）

- 不同程序、不同服务之间传数据，经常用 JSON 或 NDJSON（每行一个 JSON 的流式格式）
- 🔗 相关：本知识库的飞书智能助手，就用 `lark-cli event consume` 输出的 **NDJSON 事件流**接收消息，用 `admin.py` 读写 **JSON 文件**做远程控制指令（详见 [[飞书智能助手技术栈以及功能介绍]]）

### 9.4 数据存储

- 文档型数据库（如 MongoDB）直接存 JSON 文档
- 轻量应用用 `.json` 文件当数据库（如 electron 应用、爬虫的本地缓存）

### 9.5 结构化日志

- 现代服务端日志常用 JSON 格式（每行一个 JSON），方便用 `jq` 等工具做日志查询、统计、告警

### 9.6 AI / LLM 接口的请求与响应

- 所有主流 AI 接口（Claude API、OpenAI、通义、文心等）的请求体与响应体都是 JSON 格式——你给模型发的消息、模型返回的回答，底层都是一段 JSON
- 模型返回的"函数调用""结构化输出"，本质就是"让模型按 JSON 格式组织回答"

## 10. JSON 的优点

- 🪶 **轻量**：没有多余标签，同样的数据比 XML 短得多，网络传输量小
- 👁️ **人类可读**：纯文本、结构清晰，开发时肉眼就能看懂、能调试
- 🌍 **语言无关**：几乎所有语言都有官方库支持，跨语言、跨平台零障碍
- ⚡ **解析快**：语法简单，解析器实现高效，比 XML 快一个数量级
- 🧠 **与 JS 天然亲和**：浏览器原生支持，前端拿到即可用
- 🧰 **生态成熟**：校验、格式化、查询、Schema 定义等工具链极其丰富
- 📦 **标准统一**：有 RFC / ECMA 国际标准，不同语言实现行为一致，没有"方言"分歧

## 11. JSON 的局限与注意事项

- 📅 **<span style="color:#e67e22">没有日期类型</span>**：时间只能存成字符串（约定好格式，如 ISO 8601），两端需自行解析转换
- 💬 **没有注释**：配置文件里写不了说明文字，是"自解释性"最差的地方（需要注释时可用 JSONC 或改 YAML）
- 🔢 **大数精度陷阱**：数字按双精度浮点存储，超过 `2^53 - 1`（约 900 万亿）的整数会精度丢失——身份证号、订单号等长数字要存成**字符串**
- 🧵 **不支持二进制**：图片、文件等二进制数据必须转 base64 字符串，体积会膨胀约 33%
- 🎲 **对象键值无序**：JSON 对象的键顺序规范上不保证，依赖顺序的场合要小心
- 🧮 **嵌套深度与大小**：超深嵌套、超大 JSON 解析时会吃内存、拖慢速度（如 Read 大 PDF 转文本报 Request too large 就与"传的数据太大"同源）
- 🛡️ **安全性**：永远不要用 `eval()` / `new Function()` 解析 JSON（会执行注入代码），只用标准解析器；接收外部 JSON 前先做合法性校验
- ⚙️ **无内建 Schema**：JSON 本身不约束"必须有哪些字段"，需要时靠 **JSON Schema** 额外定义校验规则

>highlight 【最容易踩的三个坑】① 尾逗号/单引号导致解析失败；② 长整数（身份证号、金额）被精度截断；③ 用 eval 解析外部 JSON 造成安全漏洞。记住这三条，能避开 80% 的 JSON 事故。

## 12. JSON 的常用工具

- 🖥️ **JavaScript（浏览器/Node.js）**：`JSON.stringify()` / `JSON.parse()`——最基础的一对
- 🐍 **Python**：`json` 模块——`json.dumps()`（打包）/ `json.loads()`（拆包）
- ☕ **Java**：Jackson、Gson 库；**Go**：`encoding/json` 标准库
- 🔍 **命令行瑞士军刀 `jq`**：从 JSON 里提取、过滤、统计字段，一条命令搞定（如 `jq '.items[].price'` 提取所有价格）
- 🌐 **在线工具**：JSON 格式化/校验/压缩（如 json.cn、jsonlint.com）、JSON 转 CSV / XML 互相转换
- 📝 **编辑器**：VS Code 等内置 JSON 语法高亮、格式化、错误提示；`.jsonc` 文件支持带注释的 JSON
- 🧾 **JSON Schema**：定义"数据结构长什么样"，用于数据校验与接口文档生成
- 📋 **其他常见格式**：NDJSON（Newline Delimited JSON，每行一个 JSON，适合日志流与事件流，见 [[飞书智能助手技术栈以及功能介绍]]）

## 13. 一分钟速记

- 🔥 **<span style="color:#e74c3c">JSON = 轻量、语言无关的文本数据交换格式，是互联网数据传输的事实标准</span>**
- 🧱 **<span style="color:#e74c3c">只有两种结构（对象 `{}` + 数组 `[]`）和六种类型（字符串、数字、布尔、null、对象、数组），两者无限嵌套</span>**
- 📏 **<span style="color:#e74c3c">语法严格：键和字符串必须双引号、禁尾逗号、禁注释、布尔小写——错一个字符就整体解析失败</span>**
- 🔁 **<span style="color:#2980b9">前后端用法：`JSON.stringify()` 打包对象成字符串，`JSON.parse()` 把字符串拆回对象</span>**
- 🌐 **<span style="color:#2980b9">应用场景：Web API 通信、配置文件（settings.json / package.json）、数据存储、结构化日志、AI 接口请求响应、进程间通信</span>**
- ⚠️ **<span style="color:#e74c3c">三大坑：无日期类型、长整数精度丢失（存字符串）、别用 eval 解析（有安全风险）</span>**

>highlight 【一句话带走】JSON 是程序之间"传数据的普通话"——任何语言写的程序，把数据包成 JSON，对方就能听懂。
