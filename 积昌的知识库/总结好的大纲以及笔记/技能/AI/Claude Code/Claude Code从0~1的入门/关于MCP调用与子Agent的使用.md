## MCP——AI与外部工具的转接头

### MCP 是什么？

**MCP（Model Context Protocol）** 是为了解决 AI 和外部工具、外部服务连接而设计的"转接头"。

> [!TIP] 💡 **MCP 的核心作用**
> 就像给 AI 配了一个转接头，让它能够连接并操作各种各样的外部工具。

### MCP 的应用场景

| 场景 | 说明 |
|------|------|
| 📝 **读取笔记资料** | AI 读取 Notebook 上储存的资料 |
| 🎨 **读取设计稿** | AI 读取 Figma 中的设计稿，按照设计稿直接生成代码 |
| 🔗 **连接外部服务** | 让 AI 调用各种外部 API 和服务 |

### MCP 的现状

> [!WARNING] ⚠️ **MCP 的局限性**
> 目前 MCP 占用的托管数量还是比较大的，比较难大规模使用。因此：
> - **轻量级**的外部工具 → 转向做成 CLI（命令行工具）
> - **重量级**的外部工具 → 转向近几个月非常火的另一种方案（CLI）
> - 我个人现在也只保留了少量的几个 MCP

## CLI——命令行工具与Agent

### CLI 是什么？

**CLI（Command Line Interface）** 是命令行工具，很早就有，原来是方便程序员和程序做一些操作的。

### CLI vs 普通用户操作

| 操作 | 普通用户 | 程序员（CLI） |
|:----:|---------|--------------|
| 📥 **下载文件** | 到网站翻页、点击下载 | 一行命令下载好 |
| 🎬 **压缩视频** | 找专门的压缩应用 | 一行命令搞定 |
| 🤖 **AI 调用** | 让 AI 模拟人类操作（截图、点击、翻页） | AI 直接输出 CLI 命令——**又精准又高效** |

### CLI 对 AI 的意义

> [!TIP] 💡 **为什么 CLI 对 AI 很重要**
> 比起让 AI 去模拟人类操作浏览器（截图、点击、翻页），**AI 输出 CLI 命令又精准又高效**。

很多厂商把他们提供给人类通过点击来操作的接口，也做成了 **CLI 工具**，目的就是让 Agent 能够更方便地调用。

### 📖 案例：飞书的 CLI 工具

飞书把在飞书上能操作的操作都变成了 CLI 命令：
- 创建文档
- 写文档
- 写电子表格
- 发邮件
- 建日历

> 你可以直接让 Claude Code 帮你去偷偷背书了——比如帮你创建一个文档，然后把文档链接发邮件给某某。

### 🔧 常用 CLI 工具：OpenSpread

**OpenSpread** 是一个很流行的工具，把常用的很多网页、很多社交媒体的结构都做成了 CLI。

> [!TIP] 💡 **安装方式**
> 把这个地址给 AI，让它帮你装好就行了。

**使用示例：** 让 Agent 用 OpenSpread 查一查深圳必吃的餐厅——查出来的真的是社交媒体上的真实内容，图片也可以下载下来。这在没有给 Agent 配好这个工具之前，是肯定做不到的。

## 子Agent Sub-agent：分身与下属

### 子Agent 的概念

Claude Code 拥有了**分身和下属（子Agent）** 的功能。

### 自动派生 vs 手动创建

#### 🤖 自动派生

当你给 Claude Code 一个任务时，它自己意识到了之后，自动派生出了子Agent：

> [!TIP] 💡 **案例：调研番茄钟**
> 需求：让 Claude Code 调研一下其他的番茄钟都是怎么做的、数据怎么样、有什么优缺点，然后反馈给开发一点建议。
>
> **传统做法**：让写代码的 AI 停止写代码，去调研项目。
>
> **子Agent 做法**：Claude Code 自动帮你派生出几个子Agent去做调研，这中间不需要你做任何操作。

#### ✋ 手动创建

也可以手动创建子Agent，在之前"Claude Code 作为生活助理"的视频里有详细演示。

## Cook Book——自动触发器

### Cook Book 是什么？

**Cook Book（食谱）** 就是一个**自动触发器**——设定好了一个"当 Claude Code 怎么样的时候，就自动执行什么场景"的规则。

> [!NOTE] 📌 **本质就是条件反射**
> Cook Book 其实就是我们给 Claude Code 设定的一些条件反射。

### 📖 Cook Book 示例

| 示例 | 触发条件 | 自动动作 |
|:----:|---------|---------|
| 🎵 **完成提示音** | 每次完成任务之后 | 发出一个提示音"叮"来提醒 |
| ✅ **代码格式检查** | 每次提交代码之前 | 自动触发代码格式的检查 |

### 配置方式

可以直接跟 Claude Code 说，不需要复杂的配置：

> "我想让 Claude Code 每次完成任务之后都自动发出一个提示音，最好还发一条推送消息。"

Claude Code 就会给你一些方案，你跟它讨论、跟它一起配合去完成就行了。

> [!TIP] 💡 **配置示例**
> ```
> 用户 → "每次完成任务后发出提示音，推送消息"
> CC → 给出配置方案
> 用户 → 讨论调整
> CC → 配合完成配置
> ```

## 插件 Plugin——打包所有扩展

### 插件是什么？

**插件**就是把前面说的这些 **Skills、CLI、MCP** 都给打包在一起。

> [!NOTE] 📌 插件可能只包含一个 Skill，或者只包含一个 MCP，不一定都打包。

### 如何管理插件

在 Claude Code 里输入 `/plugin`（斜杠插件），就能进入插件管理页面：

| 功能 | 说明 |
|:----:|------|
| 🔍 **发现新插件** | 浏览可用的插件 |
| 📋 **管理已安装的插件** | 查看和卸载已安装的插件 |
| ⚙️ **安装插件** | 选一下安装范围，确认即可安装 |

## 📌 总结

1. **MCP**：AI 与外部工具的"转接头"，但目前托管数量较大，使用受限
2. **CLI**：命令行工具让 AI 操作更精准高效，取代了模拟人类点击的方式
3. **子Agent**：Claude Code 可以自动派生或手动创建子Agent，并行处理任务
4. **Cook Book**：条件反射式的自动触发器，无需复杂配置
5. **插件**：将 Skills、CLI、MCP 打包在一起，通过 `/plugin` 管理
