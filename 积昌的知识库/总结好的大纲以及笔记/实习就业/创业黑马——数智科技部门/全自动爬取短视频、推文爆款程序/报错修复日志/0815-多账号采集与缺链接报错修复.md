# 0815 多账号采集与缺链接报错修复日志

> [!summary] 概要
> 用户测试发现：多账号并行采集时**视频全部采集失败**；达人主页数据能采集；未填"达人抖音主页链接"（creator_url）的账号无法采集。排查锁定**两个根因**：① MediaCrawler fork 中 8 处 `USER_DATA_DIR % PLATFORM` 模板格式化在环境变量注入绝对路径时必崩（`TypeError: not all arguments converted`），导致**所有**账号"退出码 1"；② creator 模式必需 `creator_url`（抖音号≠sec_uid），缺链接账号原本会导致整个任务失败。修复后 5 轮实测：**成功率 100%（5/5 轮 completed、40 条视频）、平均耗时 1.9 分钟/轮**、接口稳定（health/active 全程 200）。全程调用 3 个 Agent 协作 + 代码总监审校通过。

## 1. 报错现象与根因定位

### 1.1 现象（用户测试）

| 现象 | 实际结果 |
|------|---------|
| 达人主页数据 | ✅ 能采集 |
| 视频数据 | ❌ **全部失败**（14 账号任务"全部账号均未完成"） |
| 未填主页链接的账号 | ❌ "缺少 creator_url/sec_user_id，抖音号不能直接用于 creator 模式" |

### 1.2 根因①（致命，影响所有账号）：fork 百分比格式化崩溃

**日志铁证**（子进程 traceback）：
```
File "MediaCrawler\tools\cdp_browser.py", line 267, in _launch_browser
  raw_user_data_dir = config.USER_DATA_DIR % config.PLATFORM
TypeError: not all arguments converted during string formatting
```

**根因链**：多账号并发池通过环境变量 `MEDIACRAWLER_USER_DATA_DIR` 注入**绝对路径**（如 `C:\...\browser_data\cdp_生信果果_user_data_dir`）→ fork 内 `USER_DATA_DIR % config.PLATFORM` 把绝对路径当**格式化模板**执行（模板中无 `%s` 占位符）→ 必然 TypeError → 子进程崩溃 → "退出码 1"。

> 🔴 **<span style="color:#e74c3c">Agent 排查纠正了初判：</span>** 崩溃与"中文编码产生 %"无关——**纯 ASCII 绝对路径同样崩溃**。本质是"格式串缺 %s 占位符"。且排查发现**残留 8 处**（douyin 自己的 core.py 也在列，CDP 失败回退路径会再次触发）。

| 文件 | 位置 | 风险 |
|------|:--:|------|
| tools/cdp_browser.py | 主路径 | 已修 ✅ |
| media_platform/douyin/core.py | CDP 失败回退 | 🔴 必崩（多账号下触发） |
| xhs / zhihu / weibo / tieba / kuaishou / bilibili 的 core.py | 各平台 CDP 回退 | 🟠 同类风险 |

### 1.3 根因②：creator 模式必需 creator_url

- MediaCrawler creator 模式需要 **sec_uid**（从分享链接/主页链接解析），**抖音号（douyin_id）≠ sec_uid**，接口无法直接用抖音号定位达人。
- 未填 creator_url 的账号 → backend 校验直接抛错 → 该账号失败；用户测试的 14 账号中多数未填 → **整个任务"全部账号失败"**。

## 2. 修复内容（多 Agent 协作）

### 2.1 修复①：8 处 % 格式化（统一 isabs 守卫）

```python
# 修复前（必崩）
user_data_dir = os.path.join(os.getcwd(), "browser_data", config.USER_DATA_DIR % config.PLATFORM)

# 修复后（绝对路径跳过格式化；相对模板才格式化）
user_data_dir = os.path.join(os.getcwd(), "browser_data",
    (config.USER_DATA_DIR if os.path.isabs(config.USER_DATA_DIR)
     else config.USER_DATA_DIR % config.PLATFORM))
```
- 涉及 8 文件：cdp_browser.py + 7 个平台的 core.py；全部 py_compile 通过。

### 2.2 修复②：缺 creator_url 账号优雅跳过

- `collection.py` `_run` 任务启动前过滤：无 `creator_url` 的账号加入**跳过清单**（日志汇总提示"请在账号管理填写达人主页链接"），不进入采集；有链接的账号正常并发采集；全部无链接 → 明确报错。
- **豁免路径**（代码总监纠正）：`content_mode=="transcript" and selected_video_ids`（纯转录所选视频，不启动采集器，无需链接）。

### 2.3 Agent 协作过程

| Agent | 职责 | 关键产出 |
|-------|------|---------|
| 调试 Agent | 排查 % 格式化残留 | 8 处调用点清单 + 根因纠正（无占位符格式化，非编码问题） |
| 架构 Agent | 设计抖音号直采方案 | search hook 方案设计（见 [[#5. 遗留项与后续计划]]） |
| 代码总监 | 两处修复审校 | 通过 + 2 条纠正指令（死代码 sec_user_id 子句、纯转录豁免） |

## 5. 遗留项与后续计划

**抖音号→sec_uid 自动解析**（架构 Agent 已设计、待实施）：
- 方案：fork 侧新增 search hook（参考 `mediacrawler_profile_hook.py` 的 runpy+monkeypatch 模式），调用 `client.search_info_by_keyword`（USER 频道 `aweme_user_web`，`field.py:28` 已定义）解析抖音号→sec_uid（响应 `data[].user_list[].user_info` 含 sec_uid/short_id/unique_id），校验 short_id/unique_id 匹配后输出 JSON
- 后端：`call_with_policy` 限速 + 三层缓存（内存 TTL → creator_profile_snapshots.source_identity → 回填 accounts.json creator_url）→ 走原 creator 链路零改动
- 风控：每账号仅 1 次请求、sec_uid 永久缓存；验证码沿用人工处理链路
- 实施后：过滤条件恢复放行 `sec_user_id`
