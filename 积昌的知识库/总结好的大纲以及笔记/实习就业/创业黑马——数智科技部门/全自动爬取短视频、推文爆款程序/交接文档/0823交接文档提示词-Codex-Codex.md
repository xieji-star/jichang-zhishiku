# 0823 交接文档提示词 — Codex → Codex

> [!note] 文档元信息
> - **项目名**：全自动爬取短视频、推文爆款程序
> - **用途**：一份**可直接复制粘贴给当前 Codex 会话的提示词**，让 Codex 基于它与用户的聊天记录（+ 它能访问的本地文件/运行环境）**自己总结出一份交接文档**，交给一个**全新的 Codex 对话框**续作使用
> - **目标智能体（写文档的）**：Codex（L1 自治型，能读文件、能跑 PowerShell）
> - **交接对象（读文档的）**：下一个全新的 Codex 对话框（对项目零了解）
> - **交接日期**：2026-08-23
> - **产出物建议命名**：`0823交接文档-Codex-Codex.md`（与本文件同目录）
> - **核心增强**：提示词强制 Codex 在动笔前先做「**总任务目标 + 当前任务进度**」双总结（A 目标块 + B 进度块），作为整份文档的锚点，确保生成的交接文档能**精确反映"总目标是什么、当前进度到哪、还差多少、下一步从哪接"**，便于全新的 Codex 无缝续作。

## 使用说明

1. 打开**当前正在做这个项目的 Codex 会话**（即让它写交接文档的那个对话）。
2. 把下方代码块内的**全部内容**复制，粘贴到该 Codex 会话里，作为一条消息发送。
3. Codex 会基于这段对话的聊天记录，并自行打开本地文件 / 跑 PowerShell 命令核实路径与命令后，**先总结「总任务目标 + 当前任务进度」双锚点，再写出**一份**《全自动爬取短视频、推文爆款程序 交接文档（给 Codex 版）》**（给 AI 版 14 节结构）。
4. 按提示词要求，它应把交接文档保存为 `F:\积昌的知识库 - 副本\总结好的大纲以及笔记\实习就业\全自动爬取短视频、推文爆款程序\交接文档\0823交接文档-Codex-Codex.md`；若无法写入，则会直接在回复中输出完整 Markdown 供你复制保存。
5. 把生成好的交接文档交给**全新的 Codex 对话框**，即可无缝续作。

> ⚠️ 提示词已按 Codex（L1）专属范本整体定制：强调 Windows/PowerShell 环境、函数/行号级接续定位、config.toml 检查、会话可迁移（拷 sessions 不拷 auth.json）、代理/分流注意，并因读者是"全新对话框"而强制文档**自包含**。

## 提示词正文（复制下方代码块内全部内容）

```markdown
你正在结束一段工作，现在要把当前工作交接给**下一个全新的 Codex 对话框**（继续本项目的续作智能体，对项目几乎零了解）。
请基于我们这段对话的聊天记录，以及你实际能访问的本地文件与运行环境（Windows / PowerShell），写一份《**全自动爬取短视频、推文爆款程序 交接文档（给 Codex 版）**》。

接手方**对项目几乎零了解**。你的写稿目标：让接手方读完这份文档后，**不靠问任何人、不查任何额外资料**，就能——①看懂这项目在做什么、做到哪了；②知道哪些做完了、哪些没做完、为什么没做完；③能照着文档直接动手干第一步；④每一步做完都能自己判断"做得对不对"。

═══════════════════════════════════════
【零、先明确三件事（动笔前必读）】
═══════════════════════════════════════
1. **你的身份**：你现在是"交接文档撰写人"，不是普通聊天助手，也不是项目的新开发员。你的唯一产出就是这份交接文档。
2. **文档读者**：下一个全新的 Codex 对话框（L1 自治型续作智能体）。写的时候始终站在读者角度问自己："这段它能看懂吗？这步它能照做吗？"——**不要写"我们之前聊过""正如前面所说"这类依赖当前对话记忆的表述，新对话框没有这段记忆。**
3. **你的信息边界**：素材 = 这段对话的聊天记录 **+ 你能访问的本地文件/运行环境**。你能读文件、能跑 PowerShell 命令——**凡是聊天记录里没有或含糊的路径、命令、函数、文件状态，你必须自己打开文件核实、跑命令验证**，确保每条路径/命令真实可执行。聊天记录与文件里都找不到的，标注"❓待确认"，绝不编造。

═══════════════════════════════════════
【〇·五、动笔前先做「总任务目标 + 当前任务进度」双总结（硬性锚点，写在交接摘要之后）】
═══════════════════════════════════════
动笔写正文前，先输出两块"精确总结"，放在文档开头（交接摘要之后），作为整份文档的锚点；后文所有小节都要能挂回这两块：

**A. 总任务目标总结**（3-5 句话精确概括整个任务的最终目标）：
- 做什么：任务/项目的一句话定义。
- 为谁做：服务对象 / 使用场景。
- 做到什么算成功：验收标准 / 成功定义（可检验，能写数字就写数字）。
- 终极交付物：产出一份什么（交付物清单，含路径）。

**B. 当前任务进度总结**（用"百分比 + 阶段 + 差距"精确给出，对照 A 写）：
- 整体完成度百分比（如"约 70%"），并给出判断依据（哪些证据支撑该百分比）。
- 当前所处阶段 / 里程碑：已走完哪些、正在哪一步、还剩哪些。
- 已完成 / 进行中 / 未开始 三档全量清单。
- 与总目标的差距：还差哪几块才算达到 A 的验收标准。
- 当前阻塞点（如有，逐条列出）。

要求：
- A 对应正文"项目总览与验收"小节，B 对应正文"当前精确进度"小节；0 交接摘要中也各用一两句话点出 A、B 核心。
- "未完成接力棒"每一条都要标注"它服务于总目标的哪一部分 / 补完它之后总进度推进到多少"。
- A 或 B 的任何一项若无法从聊天记录或文件核实，标"❓待确认"，绝不编造。

═══════════════════════════════════════
【一、必须回答的四个问题（四要素）——缺一不可，尤其 ③④ 不许一笔带过】
═══════════════════════════════════════
一份合格的交接文档，必须把下面四个问题全部回答清楚。①② 讲"过去"，③④ 讲"未来"——只有 ③④ 写透，接手方才能不靠问人直接开工。

① **当前已经做了什么**（= 已完成工作全量清单）
- 把已完成的工作**全量、逐条**列出（按模块或时间分组），不要只挑重要的写。
- 每条写满 4 个字段：
  - 做了什么：一句话说清成果。
  - 产出物在哪：真实相对路径 ＋ 一句话用途。
  - 怎么验证有效：可复现的验证方法（跑哪条命令看到什么输出 / 打开哪个文件看到什么内容 / 运行结果如何）。
  - 关键数据/效果：能写数字就写数字（条数、时长、通过率、性能指标等）。

② **还有什么没做的**（= 未完成工作全量清单，是留给接手方的"接力棒"）
- 把没做完的事**全量、逐条**列出，不要因为"不想暴露没做完"而漏掉。
- 每条写满 7 个字段：
  - 还差什么：具体到差哪一块、缺哪个功能/数据/步骤。
  - 为什么没做完：阻塞原因（时间不够 / 技术难题 / 等依赖 / 等决策 / 等授权）。
  - 前置条件：做这件事之前必须满足什么。
  - 优先级：紧急 / 重要 / 一般。
  - 做到什么算完成：可验收的定义（可检验，不说"做完"这种空话）。
  - 从哪开始：入口（文件:行号 / 函数名 / 命令 / 找谁）。
  - 验证信号：看到什么现象算真正完成/接上了。
- **每条接力棒额外标注**：它服务于总目标的哪一部分 / 补完它之后总进度推进到多少（锚定到【〇·五】的 A、B）。

③ **接下来要接着做什么**（= 接力任务，与②一一对应）
- 每个接力任务与②里的某一条**一一对应、编号一致**。
- 每条写清：接哪个遗留项 / 从哪开始 / 做到什么算完成。

④ **接下来该怎么做**（= 具体步骤，把③展开成 1-N 步）
- 把每个接力任务展开成新 Codex 能照做的 1-N 步。
- 每步写清：做什么 → 打开哪个文件/跑哪条命令/找谁 → 看到什么结果算做对了 → 卡住了看哪个文档/问谁。
- 区分"立即做"与"之后做"。

> ⚠️ **判优标准**：接手方（新 Codex）能不能**不问任何人、不查任何东西**，就照着 ③④ 动手干第一步？能 → 合格；不能 → ③④ 没写透，继续补。
> 🚫 **禁止出现这些"一笔带过"**：❌"还有几件事没做完，下次继续" ❌"你接手后把剩下的做一下" ❌"详见之前的记录" ❌"等等/后续再说" ❌"这块比较复杂你自己看" ❌"剩下你应该都会"。出现任何一句，都必须展开成上面带字段的条目。

═══════════════════════════════════════
【二、必须有一张「A→B 接力总览表」】
═══════════════════════════════════════
把②（A 没做完的接力棒）和③④（B 接下来要做的）用一张表**钉在一起**、一一对应，让接手方读到就能照着 #1 开工：

| # | A 没做完的（接力棒） | 接手方要做什么 | 从哪开始（文件:行号/函数名/PowerShell命令/找谁） | 做到什么算完成（怎么验证） |
|---|--------------------|---------------|-----------------------------------------------|---------------------------|
| 1 | <遗留事项1> | <要做的事1> | <入口：文件/函数/行号/命令/联系人> | <可观察的完成信号> |
| 2 | ... | ... | ... | ... |

要求：
- 每个遗留事项占一行，**编号与②③一致**。
- "从哪开始"列用 **PowerShell 命令 + 函数级定位**（如 `.\start.ps1`、`Get-NetTCPConnection`、`函数名`），具体到能直接下手，不能写"看代码"这种空话。
- "做到什么算完成"列必须可观察、可检验（`tasklist` / `curl` / 测试输出等新 Codex 能直接执行的判定信号）。
- 表末给一句"**接力开工第一步**"：具体动作 → 出现什么现象算正式接上了。
- 在接力总览表上方用 1-2 行点出：**这张表里每个任务分别把【〇·五】B 的总进度推进多少**（如"补完 #1 → 总进度 70%→100%"）。

═══════════════════════════════════════
【三、文档结构（按交接对象选一套，逐节完整写出）】
═══════════════════════════════════════
**因为接手方是 Codex（AI），采用「给 AI 版 14 节」结构**，逐节完整写出：

- **0 交接摘要（启动包）**：项目做什么、当前做到哪一步；最关键三件事（已完成什么 / A 没做完的接力棒 / B 下一步第一件事）；一句话提示从哪继续最省力。**并各用一两句话点出【〇·五】A 总目标与 B 当前进度的核心。**
- **1 项目总览与验收标准**：一句话定位、最终目标、验收标准（做到什么程度算完成，可检验）。**= 【〇·五】A 总任务目标的完整展开。**
- **2 文件地图（精确路径）**：逐个列出文件/文件夹：真实路径、作用、当前状态（新建/修改/已完成/未动/临时）；入口文件、配置文件、产出物的准确位置；关键代码片段可直接贴出。
- **3 已完成工作**：全量逐条，每条按四要素①写满 4 字段（做了什么 / 产出物在哪 / 怎么验证有效 / 关键数据与效果）；含关键代码位置/函数名。
- **4 当前精确进度**：最后一步有效操作是什么（在哪行代码/哪个文件）；当前代码/文档/数据处于什么具体状态。**= 【〇·五】B 当前任务进度的完整展开（完成度百分比 + 阶段 + 差距 + 阻塞）。**
- **5 A 没做完的事（接力棒）**：全量逐条，每条按四要素②写满 7 字段；明确"做到什么程度算完成"；点明每个未完成项就是 B 要接的活；**每条锚定它服务的总目标子项。**
- **6 A→B 接力总览**：即【二】的表格，编号与②③一致，表末给"接力开工第一步"。
- **7 下一步行动计划（命令级）**：把每个接力任务展开成 1-N 步，每步给 PowerShell 命令 + 预期输出；区分"立即做/之后做"。
- **8 环境与配置依赖**：模型/工具/软件及版本、端口、环境变量、依赖库、config.toml；密钥/token 只写存放位置，值写 <已脱敏>；涉及外网访问标注代理/分流要求。
- **9 数据与状态快照**：涉及的数据/文件/接口当前状态；临时数据、测试数据是否需要清理；需保留的中间产物。
- **10 关键决策与踩坑记录**：技术选型及原因、踩坑根因与规避方案、放弃的方案及原因。
- **11 风险与待确认项**：逐条标"❓"：不确定处、需人工确认的点。
- **12 续作启动手册（从零恢复）**：清理残留进程 → 启动后端 → 验证续上了 → 继续任务的完整命令序列；"如何验证续上了"给具体信号（日志行/命令输出/接口返回）。
- **13 按 Codex 定制的附加内容**：config.toml 检查、会话可迁移性（拷 sessions 不拷 auth.json）、代理/分流注意、外网访问要求。

> 结构要求：**每一节都要写**，不能跳节、不能合并、不能因为"没内容"就整节删除——没内容也要写"暂无，因为……"。

【四、信息收集方式与真实纪律】
═══════════════════════════════════════
1. **优先基于聊天记录**：先把这段对话里的目标、进度、决策、踩坑、文件路径、数据全部提取出来作为主素材。
2. **信息不足时的补救顺序**：**先自己读本地文件、跑 PowerShell 命令核实**（你能做到）→ 再追问用户 → 仍然缺的，标注"❓待确认"。

【五、写作规范与禁止事项】
═══════════════════════════════════════
1. **宁可多，不可漏**：拿不准要不要写，就写；同类列表全量列出，不挑三拣四。
2. **能写数字就写数字**：条数、时长、通过率、性能、完成度百分比（如"约 70%"，并给判断依据）。
3. **每条路径都给相对路径＋一句话用途**；命令给完整可复制、可执行的版本，并写明预期输出。
4. **全文用 Markdown 排版**：标题层级清晰、要点用列表、关键信息加粗或引用块、成对内容用表格。
5. **给 AI 版要求**：零废话、入口精确（文件:行号 / 函数名 / 命令）、关键内容自包含、验证信号明确、附"如何验证续上了"。
6. **密钥/token 一律脱敏**：只写存放位置，值写 <已脱敏>。

【六、按你的能力定制的写作方式（务必照做）】
═══════════════════════════════════════
你（Codex）能读本地文件、能跑 PowerShell 命令、能自主多步推理。所以：
① 文档里直接给 **Windows/PowerShell 风格命令**（`.ps1`、`robocopy`、`tasklist`、`Get-NetTCPConnection` 等），你自己执行验证，**不必贴大段代码**——给 `文件:行号 / 函数名 / 可执行命令` 即可。
② 交接点定位到**函数/行号**：明确"从哪个函数/哪一行/哪个文件继续"，便于新 Codex 在现有代码上续改。
③ 若项目依赖第三方模型/供应商配置，提醒检查 `config.toml`（如 DeepSeek 接入 OpenAI 的配置）；若涉及外网访问，注意代理/分流要求。
④ 若需跨机迁移，说明会话文件位置与迁移方式（拷 sessions 不拷 auth.json）。
⑤ 接力表"从哪开始"列给 `PowerShell 命令 + 函数级定位`；"做到什么算完成"列给 `tasklist / curl / 测试输出` 等新 Codex 能直接执行的判定信号。
⑥ **因为读者是全新的 Codex 对话框**：文档必须自包含——所有上下文、术语、背景都要在文档里写清楚，不能依赖"当前对话"里才有的隐含信息；开头启动包（0 交接摘要）+【〇·五】双总结块写得足够它快速进入状态。
⑦ **总目标与进度是交接的"主线"**：宁可多花篇幅把 A 总目标、B 进度写精确，也不要只堆砌零散的任务清单——新 Codex 先看懂"目标+进度+差距"，才知道该往哪使劲。

【七、输出要求】
═══════════════════════════════════════
1. 输出一份**完整的 Markdown 交接文档**，不要只给大纲/要点/节选。
2. 文档开头保留元信息：项目名（全自动爬取短视频、推文爆款程序）/ 交接对象（Codex 全新对话框）/ 交接日期（2026-08-23）。
```
