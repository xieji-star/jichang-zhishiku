## 1. 字幕直取 vs 语音识别：两条完全不同的线路

> Codex 反馈"字幕直取没有"，核心原因就是**此前按"语音识别"去采购了插件，而项目真正需要的是"字幕直取"**。两条线路完全不同，绝不能混用。

### 1.1 定义对比

| 维度 | **字幕直取**（Subtitle Direct-Fetch） | **语音识别 / ASR**（Automatic Speech Recognition，自动语音识别） |
|------|------|------|
| 做法 | 直接调平台已生成的字幕接口，把字幕"抄"回来，剥掉时间轴即口播稿 | 下载视频 → 抽取音频 → 喂给识别模型转文字 |
| 算力 | **零下载、零识别、零算力** | 依赖 GPU / CPU，每次推理有耗时 |
| 速度 | **约 3 秒**（对标轻抖） | 秒级 ~ 分钟级（自家实证 30~100s） |
| 准确率 | 字幕即原稿，**与视频字幕一字不差** | 有同音字错误，方言/口音越重越差 |
| 前提 | 视频**有 AI 字幕或创作者字幕** | 任何音频都能识别 |

💡 **<span style="color:#2980b9">一句话区分：字幕直取是"抄作业"，语音识别是"自己做题"。轻抖能十几秒出稿，核心就是它走字幕直取（见 [[轻抖-如何快速实现口播稿件的抓取]] 第⑤步），而不是把视频下载下来慢慢识别。</span>**

### 1.2 为什么这次必须换"字幕直取"

- 🔥 **<span style="color:#e74c3c">此前下载的 FunASR / SenseVoice / faster-whisper 全部属于语音识别（ASR），不符合 Codex 提出的"字幕直取（非语音识别）"要求</span>**；
- 📌 **<span style="color:#e67e22">字幕直取是 [[3条线路设计]] 的线路1（最快最优），也是文章 7.1"第一优先：字幕直取"的改造目标，性价比最高的一条</span>**；
- ✅ 因此本次从 GitHub 高星项目中筛选出**字幕直取三件套**，覆盖抖音 / 快手 / B 站 / YouTube 四大平台。

## 5. 免费 vs 付费：到底要不要花钱

> **结论先行：三件套软件本身全部免费开源，零软件成本。真正可能花钱的是"外围的稳定运行条件"。**

### 5.1 免费的部分（软件本身）

| 组件 | 协议 | 收费？ |
|------|:--:|:--:|
| DouK-Downloader | GPL-3.0 | ❌ 免费开源 |
| BBDown | MIT | ❌ 免费开源 |
| youtube-transcript-api | MIT | ❌ 免费开源 |
| douyin-mcp-server / yt-dlp / f2 / MediaCrawler 等既有组件 | 各有开源协议 | ❌ 免费开源 |

### 5.2 可能需要花钱的部分（隐性成本）

- 💰 **<span style="color:#e74c3c">抖音加密参数服务：DouK-Downloader 的加密签名算法已过期，若要稳定调用抖音接口，要么自己逆向维护（技术成本），要么接第三方加密/打码 API（按量付费）</span>**；
- 💰 **<span style="color:#e67e22">代理 IP 资源：proxy_pool 等代理池软件免费，但高质量代理 IP 本身需要采购（尤其 YouTube 高频抓取）</span>**；
- 💰 验证码打码：nopecha 等打码服务需 API Key，按次计费（风控兜底时才用）；
- 💰 算力：GPU 常驻 ASR 依赖显存，但自有 RTX 5060 已够用，**不属于新增成本**。

> ⚠️ **<span style="color:#e74c3c">免费 ≠ 零成本：软件免费，但"让软件在抖音风控下稳定跑起来"需要加密参数、代理 IP、频控策略，这三样才是真实开销。预算建议优先投"加密参数服务 + 代理 IP"。</span>**

## 7. 常见问题：繁体 / 简体 / 同音字的成因

> 一句话总括：**字幕长什么样，取决于字幕是"谁生成"的、平台默认用"什么语言"、以及"识别模型"准不准**。

### 7.1 字幕的三个来源（决定"为什么有的和视频一模一样"）

| 来源 | 生成者 | 特征 |
|------|-------|------|
| ① **创作者手工字幕** | 视频作者本人上传原稿 | **与视频字幕一字不差**，简体/繁体取决于作者写作习惯 |
| ② **平台 AI 字幕** | 平台用语音识别自动生成 | **同音字错误多**（在/再、的/地/得、它/他），简体/繁体取决于平台默认 |
| ③ **本地 ASR 兜底** | 自家 faster-whisper small | 同音字错误更多（small 模型精度有限），语言默认英文转中文时易繁简混杂 |

💡 **<span style="color:#2980b9">为什么"有时一模一样"？——因为那条视频是创作者手工上传的字幕，字幕即原稿，自然一个标点都不差。这类视频走 [[3条线路设计]] 线路1 字幕直取，命中即秒回。</span>**

### 7.2 为什么有时繁体、有时简体

- 📌 **<span style="color:#e67e22">创作者地区/语言设置：港澳台、海外华人创作者习惯用繁体，其手工字幕即为繁体</span>**；
- 📌 **<span style="color:#e67e22">平台 AI 字幕的默认语言：抖音/B 站对繁体区内容可能默认 zh-Hant（繁体中文），对大陆内容默认 zh-Hans（简体中文）</span>**；
- 📌 **<span style="color:#e67e22">工具语言参数：部分下载器/字幕工具可在参数里指定 `zh-Hans` / `zh-Hant`，不指定时跟随平台默认</span>**。

### 7.3 为什么简体时同音字时多时少

- 🔥 **<span style="color:#e74c3c">同音字错误的根源：平台 AI 字幕本质是"语音识别"，识别模型按概率出字，遇到同音字（在/再、像/向、的/地/得）无法靠音频区分，只能猜，于是出现同音错字</span>**；
- 📊 影响错误率的变量：**口音/方言**（普通话越标准越准）、**语速**（越快越容易错）、**专业词**（人名/术语无先验知识容易错）、**模型精度**（大模型 > small，FunASR 中文 > 通用 Whisper）；
- ✅ **<span style="color:#2980b9">如果发现某条字幕与视频一字不差，基本可判定是"创作者手工字幕"；如果同音字频繁，基本是"平台 AI 识别"或"本地 ASR 兜底"。</span>** 想提高质量，优先走字幕直取（抄原稿），ASR 只做兜底。

## 8. 与三线路 / 响应速度引擎的衔接

> 字幕直取不是孤岛，而是 [[3条线路设计]] 的线路1 + [[辅助组件]] "响应速度引擎"的入口。

```
  分享链接 ──► [线路调度器] 先查缓存(辅助组件·组件1 Redis/SQLite)
      │                        │
      │      命中(<1s) ◄───────┘
      ▼
  [字幕直取三件套·线路1] 有字幕 ──► 剥时间轴 ──► 写缓存 ──► API 返回(辅助组件·组件4)
      │
      ▼ 无字幕 / 被风控
  [接口级下载·线路2] Douyin_API / TikTokDownloader / f2
      │
      ▼ ①②都不可用
  [浏览器采集·线路3] MediaCrawler（含指纹伪装/代理池/验证码）
```

- **剥时间轴**：拿到 `[{start, text}]` 后剥掉 `start`，拼接 `text` 即口播稿（对标轻抖做法，见 [[轻抖-如何快速实现口播稿件的抓取]]）；
- **缓存复用**：以 `video_id` 为唯一键落库（Redis/SQLite），命中缓存直接返回、**零网络请求**——这是"热门秒回"的隐形主力（见 [[辅助组件]] 组件1 与 [[3条线路设计]] 5.5）；
- **降级链**：线路1 → 线路2 → 线路3，由调度器统一健康检测 / 熔断 / 冷却 / 切换（见 [[3条线路设计]] 5.3）。
