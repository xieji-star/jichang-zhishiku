## 2. 最终结论：不加装外部项目

**决策**：使用当前项目已有的 `clone-browser-profiles.ps1` 做**本地增强**，不引入 CookieCloud / sync-your-cookie / OpenBrowser 等任何外部项目。

**理由**（五轮评估收敛）：

| 维度 | 本地增强（B++++） | 外部项目（A/CookieCloud） |
|------|:--:|:--:|
| 登录态不出本机 | ✅ 全程本地文件复制 | ⚠️ 经本机 HTTP 流转（即使加密） |
| 依赖 | ✅ 零新增（robocopy 系统自带） | ❌ Node 服务 + 扩展侧载（Edge 收紧风险） |
| 攻击面 | ✅ 最小 | ⚠️ 新增常驻服务与密钥 |
| 自动化 | ✅ 启动时自动刷新（mtime 触发） | 高，但单点故障全量失效 |
| 评分 | **62/70** | 37~45/70 |

> 📌 **<span style="color:#e67e22">升级路径保留：</span>** 当"多机部署"或"账号数 >10 且周均重登 ≥3 次"时，CookieCloud 插件化方案（C++）作为可选第二阶段，接口已设计为兼容（见 [[#5. 外部项目处置说明]]）。

## 3. 完整实施说明（怎么做）

### 3.1 组件一：克隆原子化（scripts/clone-browser-profiles.ps1 增强）

```
对每个账号：
  1. robocopy 共享目录 → <目标>.staging /E /R:2 /W:2
  2. 成功 → 旧目标改名 <目标>.trash → staging 改名正式目录 → 删除 .trash
  3. 失败 → 删除 staging、保留旧目录、报错退出（单账号独立事务，互不影响）
```

- 目的：克隆中断不污染任何账号的现有登录态（**核心资产**）
- robocopy `/R:2 /W:2`：残留进程锁文件时最多重试 2 次，防默认百万次重试挂死

### 3.2 组件二：自动刷新触发（start.ps1 集成）

```
start.ps1 启动时：
  读 runtime_settings.last_clone 时间戳
  比对共享 profile 的 Cookies 文件 mtime
  共享更新过 → 自动执行克隆（覆盖各账号）→ 回写 last_clone
```

- 效果：**你只要在共享 Edge 登录过一次，之后登录态更新会自动同步到全部账号**，零人工
- 新账号加入 → 启动时自动为其克隆

### 3.3 组件三：登录态三级探测（弱 → 强）

| 级别 | 探测方式 | 作用 |
|:--:|---------|------|
| ① | 共享 profile 的 Cookies mtime（<30 天） | 粗筛 |
| ② | CDP 探测 `http://127.0.0.1:9222/json`：存在 douyin.com 页面且**无 verifycenter iframe** | 会话有效性（复用 backend `browser_stage` 检测逻辑） |
| ③ | `-CheckLogs` 模式：**只读**查询 `data/radar.sqlite3` 的 error_logs 最近 24h，含 "401"/"验证"/"verification_required" 的记录数 ≥2 | 采集实际反馈（不删任何登录态，仅提示） |

### 3.4 组件四：失效自愈闭环

```
探测失效（任一级别命中）
  → start.ps1 提示"请在共享 Edge 重新登录抖音"
  → 用户登录一次（共享 profile）
  → 下次启动自动克隆刷新全部账号
  → 恢复免重登状态
```

> 🔴 **<span style="color:#e74c3c">红线：</span>** 三级探测只"提示"，绝不自动删除任何登录态目录；禁止直接登录各账号目录（防登录态漂移），登录只发生在共享 profile。

## 4. 日常使用 SOP

### 4.1 正常使用（登录态有效期内）

```
.\start.ps1 → 自动克隆（如需）→ 多账号采集 → 各 Edge 免登录
```

### 4.2 登录态过期（采集报 401/验证码时）

```
1. 关闭所有 Edge 窗口
2. 跑单账号采集（或 start.ps1 启动的共享 Edge）登录抖音一次
3. 关闭 Edge → 跑 .\scripts\clone-browser-profiles.ps1 -Force
4. 重新 start.ps1 → 全部账号恢复免登录
```

### 4.3 新账号加入

```
账号管理页添加账号（填 creator_url）→ 重启 start.ps1 → 自动克隆登录态
```

## 7. 落地实测修正（2026-08-16，第 2 轮 10 对标账号实测）

> [!warning] 本章是 B++++ 投产后的真实采集验证与两处落地修正，优先级高于前文设计描述。

### 7.1 实测结论：克隆登录态生效，10 账号 150/150 免扫码

第 2 轮 10 个对标账号（创业黑马/差评君/来自2077年的浩源/展展爱上花衬衫/星球研究所/小弈小弈/马小天（医学版）/小明老师/小羊讲算法/博士大师兄木水），全部 15 条/账号、总计 **150/150 条入库，账号级成功率 100%，全程无扫码**。克隆机制本身有效——**登录一次即可**的说法成立。

### 7.2 落地修正 1：emoji 账号名导致 profile 目录命名错位（小明老师根因）

- **症状**：唯一失败的账号名含 emoji（👨‍🏫），打开抖音后无登录态、走扫码闸门失败；同批克隆的其他账号全部免扫码直采。
- **根因**：克隆脚本（PowerShell）的 `-replace '[^\w\u4e00-\u9fff]','_'` 把 emoji 按 **UTF-16 代理对**替换（👨‍🏫 → 5 个下划线 `小明老师_____`）；而 backend `browser_profiles.py` 的 `re.sub(r'[^\w一-鿿]','_')` 按 **Unicode code point** 替换（→ 3 个下划线 `小明老师___`）。两边目录名不一致 → backend 找不到克隆好的 profile → 用空目录启动 Edge → 无登录态 → 扫码失败。
- **修复（三层保险）**：① 账号名去掉 emoji（`小明老师👨‍🏫` → `小明老师`，与用户对标账号名单一致）；② `clone-browser-profiles.ps1` 的 `Get-AccountKey` 改为**调用与 backend 完全相同的 Python 正则**计算 key（永远一致）；③ 删除错位 profile 后重克隆。
- **验证**：重测 小明老师 15/15 免扫码直采成功。

### 7.3 落地修正 2：老 profile 登录态过期——克隆脚本 skip exists 不刷新

- **症状**：08-06 创建的老 profile（马小天/小明老师/小羊讲算法/博士大师兄木水）在第 2 轮登录失败，日志 `login failed`（探针 25s fail-fast 生效，34s 失败而非 600s）。
- **根因**：老 profile 的 Cookie 是 10 天前的登录态（抖音会话已失效），而克隆脚本默认 `skip (exists)` 不会刷新它们。
- **修复**：删除过期 profile 后重新克隆（新克隆的 Cookie 与源 profile 逐字节一致）。
- **SOP 更新**：**每轮批量采集前**，对「非本轮新克隆的 profile」一律删除后重克隆（或跑 `clone-browser-profiles.ps1 -Force` 全量刷新）；登录态过期时账号会在 25s 内 fail-fast（探针化），不拖慢整轮。

### 7.4 配套修复（同轮投产）

- 登录闸门探针化：`MEDIACRAWLER_LOGIN_CHECK_ATTEMPTS` env 可配（默认 600 保留手动扫码；自动化注入 25，约 25s fail-fast）。
- 单账号任务（1 个账号）走共享 profile 路径、依赖 9222 已登录 Edge；**批量测试必须 ≥2 账号**才会走独立克隆 profile。
