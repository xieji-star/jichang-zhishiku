# 🖥️ 多账号功能下多开 Edge 浏览器的问题详解

> [!summary] 概要
> 用户观察到：多账号采集会同时弹出**多个 Edge 浏览器窗口**，且每个新窗口都要求**重新登录抖音**（明明之前登录过并保存了登录态）；而单账号采集只开一个 Edge 不用重登。本文从项目真实代码出发解释这三个现象，并附"采集是否必须填达人主页链接"的完整说明。

## 1. 为什么多账号采集会同时开多个 Edge？

**根因：多账号并发池的"登录态隔离"设计**（[[多账号的并发池设计（Codex交付版本）]]）。

| 设计项 | 多账号时每个账号获得 |
|--------|---------------------|
| 独立登录态目录 | `%LOCALAPPDATA%\MediaCrawler\browser_data\cdp_<账号名>_user_data_dir` |
| 独立 CDP 端口 | 9222 / 9223 / 9224 …（`browser_profiles.py` 端口自增分配） |
| 独立浏览器实例 | 后端注入 `MEDIACRAWLER_CDP_CONNECT_EXISTING=false` → MediaCrawler fork **自启动一个全新 Edge**（用各自目录+端口，`cdp_browser.py`） |

> 🔴 **<span style="color:#e74c3c">本质原因：</span>** 如果两个账号共用一个 Edge / 一份 Cookie，账号 A 的请求会带账号 B 的 Cookie——**登录态串味 → 风控一锅端**。所以"每账号一个独立 Edge"是并发池的**红线设计**，不是 BUG。

**一句话**：多开 Edge = 每个账号一个"独立的抖音身份容器"，防止 Cookie 互相污染。

## 2. 为什么单账号采集只开一个 Edge？

并发池代码里有**明确的单账号特例**（`backend/app/services/multi_account/runner.py`）：

```python
profile = allocate_profile(name) if len(accounts) > 1 else None
```

- **单账号任务 → profile=None** → 不注入独立环境变量 → fork 走默认模式（`CDP_CONNECT_EXISTING=true`）→ **连接 start.ps1 已启动的那一个 Edge**（共享登录态目录 `cdp_dy_user_data_dir`）→ 只用一个窗口 ✅
- **多账号任务 → 每个账号独立 profile** → 各开各的 Edge

> 📌 这是 2026-08-15 并发池终审时特意加上的兼容设计：**单账号=老路径（共享登录态，不重新扫码），多账号=隔离路径**。

## 3. 为什么每次新 Edge 都要重新登录抖音？

三层原因叠加：

| # | 原因 | 说明 |
|:-:|------|------|
| ① | **新 Edge 用的是全新空 profile 目录** | 你已保存的登录态在**共享目录** `cdp_dy_user_data_dir` 里；多账号的每个 Edge 用**各自全新的目录**（`cdp_<账号名>_user_data_dir`），里面**没有登录态** → 首次必须重新登录 |
| ② | **抖音把"新 profile"识别为新设备** | 每个新 user-data-dir = 全新的浏览器指纹环境，抖音安全策略会要求重新登录/验证（平台账号保护机制，不是项目 BUG） |
| ③ | **你日常登录的 Edge 与采集 Edge 不是同一个** | 手动登录的是日常使用的 Edge；采集用的是项目**自启动的独立 Edge 实例**（两者 profile 完全独立） |

## 4. 正确的使用预期

| 场景 | 预期行为 |
|------|---------|
| 单账号采集 | 复用共享登录态 Edge，**不重登**（除非登录态过期） |
| 多账号采集·每个账号首次 | 每个账号自己的 Edge **首次需扫码登录一次** |
| 多账号采集·之后 | 登录态持久保存在各自 profile 目录，**通常不重登**；若抖音因环境指纹变化偶发要求重登，属平台策略 |
| 人机验证弹出 | 手动完成验证（合规红线：不自动破解） |

> 💡 **<span style="color:#2980b9">实用建议：</span>** 用多账号功能前，先把所有账号**逐个登录一遍**（首次登录后各自 profile 目录保存登录态）；之后日常采集基本不再要求登录。

## 5. 附：采集是否必须填达人主页链接？

### 5.1 直接答案：**当前必须填**——填"达人主页链接"，不是抖音号

### 5.2 为什么（技术本质：抖音号 ≠ sec_uid）

| 概念 | 是什么 | 举例 | 能否用于采集 |
|------|--------|------|:--:|
| **抖音号**（douyin_id） | 用户可随时改名的昵称式 ID | `29609088853`、`kobenba10` | ❌ 接口不认 |
| **sec_uid** | 抖音内部不可变的用户身份 ID | `MS4wLjABAAAAjSp5Y_91...` | ✅ 接口必需 |
| **creator_url**（达人主页链接） | 含 sec_uid 的网页地址 | `https://www.douyin.com/user/MS4wLjAB...` | ✅ 后端解析出 sec_uid |

MediaCrawler 的 creator 采集模式走抖音接口 `aweme/v1/web/aweme/post/`，参数必须是 **sec_uid**；抖音不接受用"抖音号"直接查达人作品。后端校验报错原文：`缺少 creator_url/sec_user_id，抖音号不能直接用于 creator 模式`。

### 5.3 creator_url 支持哪些格式

| 格式 | 示例 | 说明 |
|------|------|------|
| **达人主页链接**（推荐） | `https://www.douyin.com/user/MS4wLjAB...` | 地址栏直接复制，最稳 |
| **视频分享链接** | `https://www.douyin.com/video/7673795098...` | 自动解析作者 sec_uid |
| **短链** | `https://v.douyin.com/xxxx/` | fork 重定向解析 |

### 5.4 怎么获取并填写

1. 浏览器打开达人**抖音主页**（搜索抖音号 → 进主页）
2. 复制**地址栏 URL**（`https://www.douyin.com/user/MS4wLjAB...`）
3. 在项目**账号管理页**（`#/accounts`）该账号的"达人主页链接"字段粘贴保存

### 5.5 当前行为与例外（2026-08-15 修复后）

- ✅ 填了链接的账号：正常采集（5 轮实测 100%）
- ⏭️ 没填链接的账号：采集时**自动跳过**并汇总提示（不再拖垮整个任务）
- 📌 例外：纯"转录已入库视频"模式（勾选已有视频）不需要链接（不启动采集器）
- 📊 现状：25 个账号中 4 个未填

### 5.6 未来计划

"只填抖音号也能自动采集"已设计待实施：fork 侧搜索 hook 把抖音号→sec_uid 自动解析，后端三层缓存永久保存，解析一次终身可用（详见 [[0815-多账号采集与缺链接报错修复]] 第 5 节）。
