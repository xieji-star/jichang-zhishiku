### 5.3 Round-5 race and repair / 第5轮竞态与修复

- **Observed defect / 已观察缺陷**
  - **EN:** Same-runtime worker polling and `close()` pause control both used fail-fast `_link_connect(timeout=0)` plus `BEGIN IMMEDIATE`; their collision could surface `store_ambiguous` during owned executor close.
  - **中文：** 同一 runtime 内的 worker 轮询与 `close()` 暂停控制都使用失败即返的 `_link_connect(timeout=0)` 加 `BEGIN IMMEDIATE`；两者碰撞时，归属 executor 的 close 会暴露 `store_ambiguous`。
- **Repair / 修复**
  - **EN:** One local lock serializes worker Store calls and the close pause CAS inside the same runtime. No retry was added; external database contention still fails fast; injected executor semantics remain unchanged.
  - **中文：** 用一个本地锁串行化同一 runtime 内的 worker Store 调用与 close 暂停 CAS。未增加重试；外部数据库竞争仍失败即返；注入 executor 语义不变。
- **Scope / 范围**
  - **EN:** Exactly two files changed and are frozen: runtime source and its focused test.
  - **中文：** 精确只修改并冻结两个文件：runtime 源码及其专项测试。

## 16. Glossary / 名词解释

| Term / 术语 | Plain-language explanation / 白话解释 |

| Code-only GREEN / 仅代码GREEN | Named source and focused offline tests passed; it does not prove live production. / 指定源码与专项离线测试通过，不证明真实生产。 |
| Frozen identity / 冻结身份 | Exact file bytes represented by a full SHA-256 plus named test evidence. / 用完整 SHA-256 与指定测试证据表示的精确文件字节。 |

| CAS | Compare-and-swap: change state only if the stored prior state exactly matches expectation. / 比较并交换：只有已存状态与预期完全一致时才修改。 |

| Harness / 测试工具 | The temporary runner, paths, fixtures, and network guards surrounding the actual tests. / 包围真实测试的临时 runner、路径、fixture 与网络守卫。 |
| Sentinel / 哨兵 | A watched production file or state whose change would prove isolation failure. / 被监视的生产文件或状态；其变化意味着隔离失败。 |
| Detached mirror / 独立镜像 | A temporary source copy whose project root, data, logs, and test artifacts are separate from production. / 项目根、数据、日志与测试工件均和生产分离的临时源码副本。 |
