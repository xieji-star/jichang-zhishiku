## 1. 多账号并发池落地

### 做什么
按蓝图 [[多账号的并发池设计（Codex交付版本）]] 把"账号严格串行"升级为"账号级受控并发池"。

### 怎么做
| 步骤 | 内容 |
|------|------|
| fork 多实例支持 | MediaCrawler fork 4 处环境变量注入：`MEDIACRAWLER_CDP_PORT` / `MEDIACRAWLER_USER_DATA_DIR` / `MEDIACRAWLER_CDP_CONNECT_EXISTING` / `MEDIACRAWLER_ACCOUNT_DB`（每账号独立端口/登录态目录/采集库） |
| multi_account 包 | 6 模块零依赖：browser_profiles（端口自增分配+回收）/ global_limiter（同步漏桶）/ retry（指数退避）/ account_pool（ThreadPoolExecutor）/ wal_queue（串行写队列）/ runner（调度器） |
| 接线 | db.py 加 account_tasks 表+3 函数；collection.py 账号循环→run_accounts；mediacrawler.py collect_account 支持 profile |
| 兼容设计 | **单账号特例**：`profile = allocate_profile(name) if len(accounts) > 1 else None`——单账号走老路径（共享登录态），多账号走隔离 |

### 为什么这样做
- 每账号独立登录态 = 防 Cookie 串味（多账号并发的红线）
- 默认 `MEDIACRAWLER_CONCURRENT_ACCOUNTS=1` = 默认行为零变化（兼容性硬要求）

### 代码总监评审
两轮审校：第一轮 P1-P8（含 2 致命：采集库隔离未闭环、fork 不消费 ACCOUNT_DB env；2 个新 BUG：profile 变量遮蔽、递归丢 profile）→ 修复后第二轮通过 + AT-RISK 修复（单账号特例）。

### 测试
5 次测试全过（接口健康/环境注入/单账号采集/2 账号真并发三重隔离/account_tasks 闭环），全量回归 264 passed。

## 2. 图文笔记识别与转录策略

- **做什么**：图文笔记（抖音 aweme_type=163 图文、2 图集）只采数据、不生成口播稿。
- **怎么做**：`_read_changed` 读取 aweme_type → `media_kind` 标记 → 业务库 videos 表加列持久化 → 转录组装两处跳过（采集路径+仅转录路径）→ 正确率按"可转录视频数"统计。
- **为什么**：图文无音频，硬转录会把 BGM 歌词当口播稿（第 5 轮测试发现的历史假成功教训）——宁可真跳过，不要假成功。

## 3. 字幕直取插件

- **做什么**：把抖音 detail 接口的 `video.subtitles`（平台 AI 字幕）直取为口播稿，ASR 永远兜底。
- **方案讨论**：3 设计 Agent（A fork 内扩展 / B 独立模块 / C 渐进混合）+ 代码总监两轮审校 → **A+C 整合版**（fork 寄生解析零新增请求面 + Phase 0 止损 + 三重质量闸门 + 灰度），终审 **56/70 通过**。方案文档：[[字幕直取功能插件的开发]]。
- **实施**：fork 4 文件（models 加列 / db 迁移 / subtitles.py vtt 下载清洗 / store 接线）+ backend 5 处（开关 / videos 列 / 导入 / DouyinSubtitleProvider 三重闸门 / 管线第 0 顺位）。
- **状态**：`SUBTITLE_DIRECT_ENABLED` **默认关闭**（未灰度）；5 次测试全过；**Phase 0 实测（覆盖率验证）未做**。

## 5. 多账号报错修复

- **根因 1（致命）**：fork 8 处 `USER_DATA_DIR % config.PLATFORM` 在注入绝对路径时必崩（`TypeError: not all arguments converted`）→ 全部账号"退出码 1"。修复：8 处统一 isabs 守卫（绝对路径跳过格式化）。
- **根因 2**：creator 模式必需 creator_url（抖音号≠sec_uid），缺链接账号拖垮整个任务。修复：任务启动前过滤跳过+汇总提示（纯转录路径豁免）。
- **结果**：5 轮测试 100%（5/5 完成、40 条视频、平均 1.9 分钟/轮）。修复日志：[[0815-多账号采集与缺链接报错修复]]。

## 6. Edge 一次登录方案

- **需求**：多账号每个独立 Edge 都要重新登录，太麻烦。
- **调研**：GitHub 同类项目（CookieCloud 等）清单见 [[Edge一次登录]]。
- **方案讨论**：3 设计 Agent（A 加装 CookieCloud / B 纯本地 / C 混合）+ 代码总监 **5 轮评估打分**：B 58 → B+ 58 → B++ 57 → B+++ 58 → **B++++ 62/70 终审批准**。定稿文档：[[Edge浏览器一次性登录解决]]。
- **结论**：**不加装外部项目**，本地增强（零依赖、登录态不出本机）。
- **实施**：克隆原子化（staging→.trash→切换→回滚）/ robocopy /R:2 /W:2 / start.ps1 mtime 自动刷新 / 三级登录态探测（Cookie 新鲜度→CDP 探测→error_logs 信号计数，只提示不删态）/ 时区统一 UTC / 路径对齐 LOCALAPPDATA。
- **代码总监验收**：第一轮不通过（2 致命：CheckLogs 时间窗口 bug、自动刷新死代码 Default 路径）+ 2 严重（时区、路径分裂）→ 修复后复验**通过**。
- **克隆执行**：25/25 账号目录克隆成功（含 Cookies）。

## 7. 10 轮验收测试（未完成）

用户要求：每轮随机 10 账号 × 20 视频全采集，统计成功率与平均耗时，逐轮复盘迭代、抹数据再下一轮。

| 阶段 | 过程 | 结果 |
|------|------|------|
| 第 1 轮（并发 2） | 随机 10 账号，30 分钟超时 | ❌ 4 账号"未导入作品"，子进程日志 `login_by_qrcode → login failed` |
| 根因分析 | 多开 Edge（新 profile）即使克隆了 Cookie，抖音仍**识别为新设备要求扫码验证** | 平台策略，无法本地绕过 |
| 迭代 | 回退串行模式（并发=1，单账号特例共享登录态免扫码）+ 90 分钟/轮上限 + 轮间冷却 30s | 重跑 |
| 终止 | 用户中途要求停止测试 | ✅ 已清理（任务置 cancelled、杀子进程、删临时脚本） |

**结论**：多账号并发的"免登录"在抖音平台受限于"每账号新环境首次验证"；串行模式（共享登录态）可全自动免扫码。

## 9. 已知风险与注意事项

- ⚠️ **抖音环境指纹验证**：新 profile 的 Edge 被抖音识别为新设备，克隆 Cookie 不保证免验证——这是平台策略，非项目 BUG。
- ⚠️ **合规红线（不变）**：不自动破解验证码（NopeCHA 保持隔离、security/verify.ps1 守护断言不可改）；代理/隐身规避组合不激活。合规开关（熔断/curl_cffi 指纹/随机错峰/代理预检/证据截图）已全部接入，`.env.local` 可开。
- ⚠️ **start.ps1 编码**：PowerShell 5.1 按 GBK 解析无 BOM UTF-8——脚本内中文注释有乱码风险，新加逻辑建议纯 ASCII。
- ⚠️ **backend 实例**：8000 端口偶现 Anaconda python 实例（有守护进程在跑）——功能一致（磁盘最新代码），但排查时注意解释器来源。
- ⚠️ 当前 `.env.local`：`MEDIACRAWLER_CONCURRENT_ACCOUNTS=1`（串行）；`EVIL0CTAL_API_BASE_URL` 已配。
