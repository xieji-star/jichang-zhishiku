## 2. Completed code-only work / 已完成的仅代码工作

### 2.1 Subtitle transport and parser safety / 字幕传输与解析安全

**EN:** The current subtitle path fails closed before network construction when APP transport is disabled or trust is unverified. URL, redirect, final-host, HTTP status, length, UTF-8, JSON shape, duplicate-key, candidate count, unique-attempt count, and format bounds are enforced. Telemetry uses hashed account/video references and excludes raw subtitle bodies and Cookie values.

**中文：** 当前字幕路径在 APP 传输关闭或信任未验证时，会在网络对象构造前失败关闭。URL、重定向、最终主机、HTTP 状态、长度、UTF-8、JSON 结构、重复键、候选数量、唯一尝试数量和格式边界均已强制执行。遥测使用账号/视频哈希引用，不记录原始字幕正文或 Cookie 值。

### 2.2 Subtitle quality gate / 字幕质量闸门

**EN:** Subtitle metadata must be an object with a valid, explicitly supported Chinese language tag. Missing, blank, malformed, unsupported, or non-Chinese language fails neutrally to ASR. Title verification requires defensible CJK n-grams or whole-boundary ASCII tokens and real overlap; an unverifiable title cannot bypass the quality gate.

**中文：** 字幕元数据必须是对象，并带有明确支持的中文语言标签。缺失、空白、畸形、不支持或非中文语言会中性回退 ASR。标题核验要求可辩护的中文 n-gram 或完整边界英文词，并且必须真实重合；无法验证的标题不得绕过质量闸门。

💡 **<span style="color:#2980b9">All new quality-rejection codes now fall through to ASR without poisoning the provider circuit.</span>**

💡 **<span style="color:#2980b9">所有新质量拒绝码现都会回退 ASR，不会污染 Provider 熔断器。</span>**

### 2.3 Live master switch and health truthfulness / 实时总开关与健康真实性

**EN:** `APP_SUBTITLE_ENABLED` is the live, default-OFF master switch used by MediaCrawler child launch and both backend direct providers. `SUBTITLE_DIRECT_ENABLED` remains default-OFF boot admission. Runtime OFF skips both direct providers before circuit acquisition. Health now reports actual wiring, host trust, signer state, account allowlist, platform runtime, Cookie/CDP readiness, evidence process proof, and verified samples instead of treating a merely closed circuit as ready.

**中文：** `APP_SUBTITLE_ENABLED` 是实时且默认关闭的总开关，MediaCrawler 子进程与两条后端直取 Provider 共用该门禁。`SUBTITLE_DIRECT_ENABLED` 继续作为默认关闭的启动期准入。运行时 OFF 会在获取熔断槽之前跳过两条直取线路。健康状态现会报告真实接线、域名信任、签名状态、账号白名单、平台运行时、Cookie/CDP 就绪、证据进程证明及已验证样本，不再把“熔断器只是 closed”误判为可用。

### 2.4 Shared process and diagnostic lifecycle / 共享进程与诊断生命周期

**EN:** Reachable ASR/ffmpeg, SocialKit, risk-control, runtime storage, yt-dlp, Evil and other reviewed subprocess paths use sealed Windows Job/POSIX group boundaries, immutable redacted dual streams, bounded in-memory parsing, validation before `completed`, verified whole-tree teardown, and primary-error preservation with independent terminal evidence.

## 5. Link Collection approved architecture / 链接采集获批架构

### 5.1 Product boundary / 产品边界

**EN:** Link Collection is for cases where the operator wants selected videos from different creators without collecting those creators. It accepts multiple links in one task and collects only video-scoped data and, when requested, the transcript. It must never enter creator-profile, account crawl, comment, avatar, browser manifest, search, hot-list, collection, or homepage paths.

**中文：** 链接采集用于“不采达人，但需要采集不同达人若干指定视频”的场景。一个任务支持输入多条链接，只采视频级数据，并在需要时处理口播稿。它绝不能进入达人资料、账号爬取、评论、头像、浏览器 manifest、搜索、热榜、合集或主页路径。

### 5.2 Dedicated request and runner / 独立请求与runner

- **EN:** Add a dedicated `LinkCollectionRequest` and video-only runner; never reuse `CollectionRequest.selected_video_ids`.
  **中文：** 新增独立 `LinkCollectionRequest` 与仅视频 runner；不得复用 `CollectionRequest.selected_video_ids`。
- **EN:** Add navigation route `/links` with label “链接采集”; use a bounded multi-line input and per-item status.
  **中文：** 新增 `/links` 导航，名称为“链接采集”；使用有界多行输入与逐项状态。
- **EN:** Define fixed `MAX_LINK_ITEMS` and cover 0, 1, max and max+1 cases.
  **中文：** 定义固定 `MAX_LINK_ITEMS`，覆盖0、1、最大值及最大值+1。
- **EN:** Preserve first-input order while deduplicating by `douyin:video:<id>`.
  **中文：** 按 `douyin:video:<id>` 去重，同时保留首次输入顺序。

### 5.3 URL and identity boundary / URL与身份边界

- Strict public Douyin HTTPS authority validation occurs before stable-ID normalization.
- Reject userinfo, passwords, non-default ports, fragments, foreign hosts, missing IDs and conflicting path/query IDs.
- Raw numeric IDs are accepted only when the video is already persisted; uncached raw IDs fail closed.
- Canonical links must contain exactly one stable video ID.
- Resolver output ID must exactly match the expected normalized ID before persistence or transcription.
- Short links fail closed until their bounded resolver path is separately admitted.

- 严格公开抖音 HTTPS authority 校验必须先于稳定 ID 归一化。
- 拒绝 userinfo、密码、非默认端口、fragment、外站域名、缺失 ID 及路径/查询冲突 ID。
- 纯数字 ID 只允许命中已入库视频；未入库裸 ID 失败关闭。
- 规范链接必须且只能包含一个稳定视频 ID。
- 解析器输出 ID 必须与预期归一化 ID 精确一致，之后才能持久化或转录。
- 短链接在其有界解析路径另行准入前失败关闭。

### 5.4 Transcript and subtitle integration / 口播稿与字幕接入

**EN:** Factor reusable domain logic from the existing single-link flow; do not call an HTTP handler as an internal shim. Every eligible item calls the existing singleton `service.transcription.process` exactly once. The runner must not call APP/provider helpers directly and must not accept force-host, force-APP or provenance overrides. APP OFF/untrusted/unproven remains zero APP construction while ASR fallback continues.

**中文：** 应从现有单链接流程抽取可复用领域逻辑，禁止把 HTTP handler 当内部 shim 调用。每个合格项目必须且只能调用现有单例 `service.transcription.process` 一次。runner 不得直接调用 APP/Provider helper，也不得接受强制域名、强制 APP 或来源覆盖。APP 关闭、域名不可信或来源未证明时必须保持 APP 零构造，同时允许 ASR 回退。

💡 **<span style="color:#2980b9">Missing author/title/language must not trigger creator enrichment or be fabricated; direct subtitles fail closed and ASR handles the item.</span>**

💡 **<span style="color:#2980b9">缺少作者、标题或语言时，不得补采达人资料或伪造字段；直取失败关闭，由 ASR 处理该项。</span>**

### 5.5 Execution and logging / 执行与日志

- Serial, bounded processing; no new concurrency increase.
- One outer deadline plus per-item error isolation.
- Preserve cancel and pause semantics; uncertain lifecycle fails closed.
- Skip image-text items through existing classification.
- Logs contain only input/video hashes, item index and stable error codes—never raw URL/query/account/title/body/subtitle/Cookie.

- 严格串行、有界处理，不增加并发。
- 一个总截止时间，同时逐项隔离错误。
- 保留取消和暂停语义；生命周期不确定时失败关闭。
- 通过现有分类逻辑跳过图文项目。
- 日志只记录输入/视频哈希、项目序号和稳定错误码，绝不记录原始 URL/query/账号/标题/正文/字幕/Cookie。
