## 1. 项目总览

### 项目名称与定位

- 项目名称：全自动爬取短视频、推文爆款程序；现有产品名/界面名包括“矩阵内容雷达”。
- 一句话定位：面向华哥组、七哥组、鱼哥组及临时对标达人，按需采集抖音作品与互动快照，支持查询、导出、口播转录和后续爆款分析的内部工作台。
- 使用范围：用户本人和小组内部使用，不对外商业化；用户已明确当前仅用于自己的工作和小组工作。

### 最终目标

1. 从账号主页自动发现作品，不依赖成员手工填视频链接。
2. 管理固定矩阵账号，也能动态添加其他达人/博主。
3. 按视频发布时间查询指定日期/范围，或查看全部视频；采集时间作为高级筛选。
4. 采集视频链接、标题、标签、发布时间和可获得的互动指标，保留历史快照。
5. 从媒体下载地址生成口播稿与 SRT；文本持久化成功后自动删除视频、WAV、SRT 副本和任务日志等中间文件，模型长期保留。
6. 支持 Excel、飞书云文档、飞书多维表格导出。
7. 通过妙搭网站供电脑和手机访问；本地采集按用户指定时间运行，不要求电脑长期在线。
8. 保持数据源、下载器、ASR 和云端展示可替换，方便以后扩展 OCR、爆款评分、聚类和更多平台。

### 项目起因

- 最初考虑 ApiZero、SpiderHubs 等第三方抖音 API，但用户认为套餐昂贵、外币充值不划算且单次调用延迟过高。

- 用户后来加入 pyvideotrans，希望用 MediaCrawler 的媒体链接自动生成口播稿。
- 用户明确要求处理完成后删除视频和中间文件，避免本地/云端磁盘持续增长。

### 用户偏好和约束

- 一次约处理 20 条视频，每月大约运行 5 次。

## 9. 关键决策与踩坑记录

### 已采用的关键决策

- **D 盘唯一源。** F 盘写入慢，只保留知识库；代码和运行数据以 D 为准。
- **妙搭作为托管 UI。** 解决无域名、任意设备访问和团队查看问题；采集器仍按需本地运行。
- **MediaCrawler 替代高价 API。** 降低调用成本，但接受登录/风控和非商业许可边界。
- **稳定 UUID。** 避免账号改名/同名导致视频错配。
- **服务端分页。** 避免“全部视频”把所有数据拉到浏览器。
- **Expand/Backfill/Compatible/Contract。** 防止先上 NOT NULL 导致旧写入接口中断。
- **采集与转录分阶段。** 元数据先成功；转录失败不回滚采集。
- **数据库成功后再删媒体。** 防止清理提前导致唯一口播产物丢失。

### 踩坑、根因和修复

- Cloudflare 把 chatgpt.site 公开隧道拦截；改用妙搭托管地址。
- CSV 中文乱码；改为规范 UTF-8/Excel 导出策略。
- 旧 UI 看不到变化；根因是组件未接页面入口且分支未合并发布，后续完成接线、推送和发布。
- 名称作为账号键不稳定；改为 UUID，导入标识按 accountId → douyinId → 唯一名称优先。
- 客户端全量加载再 slice 不是真分页；改服务端 count/page/pageSize 和 latest snapshot SQL。
- NULL 指标被 `?? 0` 误导；改 none/partial/complete 三态。
- UI 错误态曾遮蔽可用旧数据；拆账号/health warning 与 video blocking error。
- 移动控件视觉 44px 但真实点击区不足；改 Checkbox root、图标、日历和抽屉盒模型。
- `video_download_url` 会跳转到 `douyinvod.com`；白名单最初缺失，实测后补入并继续逐跳 IP 校验。
- pyvideotrans 临时 WAV/日志默认写 vendor 根；增加受控环境目录设计。但当前轻量脚本不走 vendor 链，相关补丁需随最终方案决定去留。
- SRT 解析曾删除纯数字口播和重复句；改为按 SRT block 仅跳序号/时间轴。
- 定时 janitor 曾可能把正在转录的 running 标中断；启动恢复与定时对账职责已拆分。
- 数据库 complete UPDATE 曾不检查 rowcount；已加门禁，0 行时不删任务目录。
- 完整 pyvideotrans `uv sync` 拉取约 426 包、CUDA/PySide 等重依赖；当前 venv 约 7.98 GB，偏离低磁盘目标。轻量方案虽省运行依赖，但未经用户确认且语义改成 faster-whisper。
