## 3. Background and evolution / 背景与来龙去脉

### 3.1 Why the project started / 项目起因

- **English:** The business operates a research-paper-content matrix and needs to identify viral formats without manually tracking every post. The original reference documents defined viral metrics, local analysis, and third-party API options; the first project root was on F drive.
- **中文：** 业务运营科研论文内容矩阵，需要在不人工逐条登记作品的情况下识别爆款形式。最初参考文档定义了爆款指标、本地分析和第三方 API 路线，项目最早位于 F 盘。
- **English:** ApiZero/other paid providers were investigated, but recurring package costs, USD charging, latency, and uncertainty over “works by creator page” made them unsuitable for a low-frequency internal tool.
- **中文：** 项目曾评估 ApiZero 等付费服务，但套餐成本、美元充值、延迟以及“能否按主页获取作品”的不确定性，不适合低频内部工具。
- **English:** The data source was switched to the local open-source MediaCrawler repository to reduce API cost. The user explicitly limited usage to personal and small-group, non-commercial work.
- **中文：** 为降低 API 成本，数据源切换为本地开源 MediaCrawler。用户明确说明仅用于本人和小组内部的非商业工作。

### 3.2 Storage and deployment changes / 存储与部署变化

- **English:** The project moved from `F:\全自动爬取短视频、推文爆款程序` to `D:\全自动爬取短视频、推文爆款程序` because F-drive writes were slow. All code changes must remain on D; F is now documentation/reference storage only.
- **中文：** 因 F 盘写入慢，项目从 `F:\全自动爬取短视频、推文爆款程序` 迁移到 `D:\全自动爬取短视频、推文爆款程序`。此后所有代码修改必须在 D 盘；F 盘只作为知识库和参考资料目录。
- **English:** A temporary Cloudflare tunnel on a borrowed `chatgpt.site` domain was blocked and abandoned. Miaoda was retained for hosted UI, managed data, authentication, and eventual team access; local collection stayed separate.

## 9. Decisions and lessons learned / 关键决策与踩坑记录

### 9.1 Adopted decisions / 已采用决策

- **Provider abstraction over paid lock-in:** MediaCrawler is current, but interfaces remain replaceable. / **数据源适配边界优先：** 当前使用 MediaCrawler，但保持可替换接口。
- **Local-first after cloud cost review:** current operation is local, hosted Miaoda remains an optional UI/data layer. / **云成本评估后本地优先：** 当前本地运行，妙搭保留为可选托管层。
- **Stable UUID identity:** display names are not keys. / **稳定 UUID 身份：** 昵称不再作为主键。
- **Server pagination:** “all videos” is paginated server-side, not client-side full-load and slice. / **服务端分页：** “全部视频”不再客户端全量加载后截断。
- **Published date by default; capture date advanced:** matches the user’s query intent. / **默认发布时间、高级采集时间：** 符合用户查询习惯。
- **Basic data commits independently from transcription:** ASR failure does not roll back collected metadata. / **基础数据与转录解耦：** ASR 失败不回滚作品数据。
- **Official pyvideotrans CLI in isolated Python 3.10:** avoids dependency collision and semantic drift. / **官方 pyvideotrans CLI + 独立 Python 3.10：** 避免依赖冲突和语义跑偏。
- **Successful persistence before cleanup:** protects transcripts from deletion races. / **先写库再清理：** 避免清理竞态导致口播丢失。
- **Default two transcriptions:** fastest practical non-single-item setting for current machine, with explicit high-risk options. / **默认两条口播：** 当前电脑除单条外更稳妥的快速设置，其他数量明确风险。

### 9.2 Major pitfalls, root causes, and fixes / 主要踩坑、根因与修复

1. **All metrics appeared as zero.** Root cause: demo/placeholder normalization and unavailable source fields. Fix: real MediaCrawler import and strict null-not-zero semantics.
   **数据全是 0。** 根因是演示/占位归一化和数据源缺字段；修复为真实 MediaCrawler 导入并坚持空值不等于 0。
2. **Only one account collected.** Root cause: missing/incorrect creator mappings and unstable identity. Fix: 12 stable page identifiers and per-account execution.
   **只有一个账号能采集。** 根因是主页映射缺失/错误和身份不稳定；修复为 12 个稳定主页标识与逐账号执行。
3. **Temporary public URL was blocked.** Root cause: borrowed domain/Cloudflare security. Fix: abandon tunnel, use local or Miaoda hosting.
   **临时公开链接被拦截。** 根因是借用域名和 Cloudflare 安全策略；修复为放弃隧道，改用本地或妙搭。
4. **F-drive slowness.** Fix: move active work to D and reserve F for docs.
   **F 盘缓慢。** 修复为活动项目迁到 D，F 只存文档。
5. **Name used as primary selection key.** Root cause: names can duplicate/change. Fix: stable UUID and identity priority.
   **昵称被当成主选择键。** 根因是昵称可能重复/变化；修复为稳定 UUID 和身份优先级。
6. **Unsafe database migration order.** Root cause: dev schema diff does not carry online DML, and NOT NULL could break old writers. Fix: Expand/backfill/compatible writer/probe/Contract sequence with backups and gates.
   **数据库迁移顺序不安全。** 根因是 dev 结构 diff 不携带 online DML，提前 NOT NULL 会打断旧 writer；修复为 Expand/回填/兼容写入/探针/Contract 门禁链。
7. **Jest silently missed client tests.** Root cause: `testMatch` only covered server paths. Fix: include client specs and validate RED exits non-zero.
   **Jest 静默漏跑前端测试。** 根因是 `testMatch` 只覆盖服务端；修复为纳入前端 spec，并确认 RED 必须非 0。
8. **Nest decorator compile errors.** Root cause: Jest used the frontend tsconfig. Fix: dedicated Jest TypeScript config with decorators enabled.
   **Nest 装饰器测试编译失败。** 根因是 Jest 使用前端 tsconfig；修复为带装饰器配置的专用 Jest TS 配置。
9. **Real DB integration hung.** Root cause: loading the entire AppModule/platform initialization. Fix: narrow DataPaas test module and explicit environment-gated command.
   **真实数据库测试挂起。** 根因是加载完整 AppModule/平台初始化；修复为窄 DataPaas 测试模块和显式门禁命令。
10. **PostgreSQL UUID array cast failed.** Root cause: interpolated array expanded as a record. Fix: parameterized `ARRAY[$1::uuid,...]`.
    **PostgreSQL UUID 数组转换失败。** 根因是插值数组被展开为 record；修复为参数化 `ARRAY[$1::uuid,...]`。
11. **OpenAPI rejected multiple valid identity fields.** Root cause: `oneOf`. Fix: `anyOf` plus schema tests.
    **OpenAPI 拒绝同时提供多个合法身份字段。** 根因是 `oneOf`；修复为 `anyOf` 和结构测试。
12. **`latestCapturedAt` was wrong.** Root cause: reused publish-sorted first row. Fix: independent maximum over capture timestamps.
    **`latestCapturedAt` 错误。** 根因是误用按发布时间排序首行；修复为独立取最大采集时间。
13. **pyvideotrans cannot consume a URL.** Root cause: CLI checks `Path.exists()`. Fix: controlled download to local job file before CLI.
    **pyvideotrans 不能直接读取 URL。** 根因是 CLI 强制检查本地路径；修复为受控下载到任务目录后再调用。
14. **Python dependency conflict.** Root cause: pyvideotrans requires 3.10 while backend/MediaCrawler use 3.12. Fix: isolated `.venv-stt`.
    **Python 依赖冲突。** 根因是 pyvideotrans 要求 3.10，而后端/MediaCrawler 为 3.12；修复为独立 `.venv-stt`。
15. **Vendor temp/log leakage.** Root cause: `--output-dir` did not control pyvideotrans WAV/cache/log directories. Fix: environment-overridable temp/log roots inside each job.
    **vendor 临时文件/日志泄漏。** 根因是 `--output-dir` 不控制 WAV/缓存/日志；修复为环境变量把它们限制到单任务目录。
16. **Unsafe temp cleanup root.** Root cause: early cleanup could traverse arbitrary old directories if misconfigured. Fix: require a dedicated DATA_DIR child, marker ownership, strict `job-` name, and no symlink escape.
    **临时清理根目录存在误删风险。** 根因是早期误配置时可能遍历任意旧目录；修复为强制 DATA_DIR 专用子目录、所有权标记、严格 `job-` 名称和拒绝符号链接逃逸。
17. **Running transcription could be marked interrupted by hourly janitor.** Fix: startup-only interruption recovery and heartbeat-aware periodic reconciliation.
    **运行中的转录可能被定时清理误判中断。** 修复为仅启动时处理中断，并让定时对账识别心跳。
18. **A temporary faster-whisper-only worker drifted from the promised pyvideotrans path.** Fix: return to official CLI and remove the semantic mismatch.
    **临时 faster-whisper-only worker 偏离承诺的 pyvideotrans 路径。** 修复为恢复官方 CLI，消除语义错标。
19. **New UI looked old.** Root causes: opening the old frontend/hosted release, wrong local base path, and unpushed commits. Fix: new Vite URL, HashRouter/static fixes; remaining step is hosted release.
    **新版 UI 看起来仍是旧版。** 根因是打开旧前端/旧线上发布、本地基础路径错误以及提交未推送；已修新 Vite 地址、HashRouter 和静态资源，剩余线上发布。

### 9.3 Abandoned or postponed approaches / 放弃或暂缓方案

- Paid API as primary source — too costly/slow for expected five uses per month. / 付费 API 主路线——对每月约 5 次使用不划算。
- Cloudflare temporary tunnel — blocked and not a stable ownership model. / Cloudflare 临时隧道——被拦截且域名不稳定。
- Always-on GPU server — idle cost too high. / 常驻 GPU 服务器——空闲成本过高。
- Full pyvideotrans dependency stack with CUDA/GUI — multi-GB dependencies contradicted low-disk goals; a lightweight official-CLI STT environment was built instead. / 完整 CUDA/GUI 依赖——体积过大，与低磁盘目标冲突，改为轻量官方 CLI STT 环境。
- Cloud migration for current phase — user explicitly chose local deployment for now. / 当前阶段云端迁移——用户明确选择先本地部署。
