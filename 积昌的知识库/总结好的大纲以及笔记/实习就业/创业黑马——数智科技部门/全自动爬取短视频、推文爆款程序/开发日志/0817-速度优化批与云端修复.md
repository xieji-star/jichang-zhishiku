# 0817 速度优化批与云端修复

## 一、速度专项优化（测试暂停期纯迭代，用户指令）

| 优化项 | 效果 | 落点 |
|---|---|---|
| 转录工作线 4→6 | 口播稿并行度 +50% | config.py `COLLECTION_TRANSCRIPT_WORKERS`（env 可配） |
| 错峰收窄 20-60s→15-30s | 整轮省 ~2.5 分钟 | .env.local `RISK_STAGGER_MIN/MAX_SECONDS` |
| 采集-转录流水线化 | 单账号 542s→~480s（采集与转录重叠） | collection.py 批线程（batch=工作线数，批线程不写 task 级 stage） |
| 转录工作线异步修复 | 消除 timed out（8765 事件循环阻塞根因） | _asr_8765.py 同步 endpoint + 超时 240s |
| VAD 静音过滤 | 长视频转录提速 30-50% | _asr_8765.py vad_filter |
| media_url 落库 | 转录下载走官方直链，绕开失效解析器 | db.py videos 表加列 + 迁移 |
| 主页资料并入采集进程 | 每账号省 ~20s（免独立 hook 子进程） | MC save_creator 落库 douyin_creator + backend prefer_mc_db 读库 |
| 登录固定等待 env 化 | 每账号省 ~7s | MC login.py `MEDIACRAWLER_LOGIN_SETTLE/REDIRECT_SECONDS` |
| 云端同步黑名单降噪 | 消除每轮 150 条无效重试 | sync.py runtime_settings 持久化 |
| 二维码弹图根治 | 自动化采集不再弹图片窗口 | MC crawler_util.py `MEDIACRAWLER_SKIP_QRCODE_DISPLAY` |

## 二、Edge 窗口卫生（用户定版：任务结束后项目打开的任何窗口一律杀死）

- 新增 `backend/app/services/multi_account/edge_cleanup.py`：三层清理（账号级/hook级/任务级终态）；
- 不按进程名过滤（msedge/chrome 通吃）；cmdline 引号剥离+路径归一化+前缀精确到 browser_data\；
- robocopy 克隆进行中跳过（防竞态）；进程树终止（含子进程）；
- 定版：含共享源/9222 手动实例全杀；唯一保留边界=cmdline 无项目目录（用户日常 Edge）；
- config.py `MEDIACRAWLER_BROWSER_DATA_DIR` 默认值改为项目内 D 盘路径（原 C 盘旧路径已删）。

## 三、云端 BUG 修复（用户反馈：账号页查看视频固定指向同一达人）

- 根因：账号页→视频页是独立 Route element，组件完全重挂载；旧初始化逻辑"无条件全选"覆盖用户点击的达人 → 列表固定显示排在首位的达人数据；
- 修复：① radar-selection.ts 初始化优先级 URL指定>当前选择>全选兜底；② 达人 ID 匹配大小写不敏感（URL 同步 effect + normalize 双处）；
- 已构建并部署妙搭（release finished，commit b0aff55）；前端测试 12 通过、tsc 零错误；
- 云端账号映射补建：+db-execute 批量 INSERT 28 个对标账号（internal 12 + benchmark 28）——下轮采集同步不再被"未知抖音号"拒绝。

## 四、字幕直取结论与替代方案评估

- 结论：抖音 web 端无字幕数据源（detail 接口无 cla_info/subtitles 字段、播放器无字幕请求、分享页无 videoInfoRes，多轮实测）；
- 替代：口播稿走下载+GPU ASR（已闭环，149/150 达标）；
- 待评估：APP 签名（X-Gorgon）直取——开源项目 douyin-sign（nightly CI 自动提取常量）/TikTok-Encryption 可支撑，接入为中等工程，待用户拍板。
