### 7.3 开放问题 + 目标扩展决策记录
1. 探针总耗时未设硬预算（最坏 cffi 3×8s + urlopen 2×8s ≈ 40s+）：建议后续加总 deadline。
2. REQUEST_BUDGET fork 侧消费未强制（已知限制，维持现状）。
3. 代理池保持禁用。
4. **2026-08-16 用户定版（目标 B→B''，红线清理完成）**：
   - 决策链条：① 用户决策"突破原合规红线，①类对抗组件全部投入使用（NopeCHA 自动验证码求解、patchright 无检测浏览器、代理轮换等），风险自担"；② 用户定版"**个人使用，没有红线可言**"——原《反不正当竞争法》第 12 条等法律面风险提示在"个人使用"定版下不构成我方劝阻依据，全部红线表述已清理为 enabled_personal_use_2026-08-16 口径。
   - **代码总监保留的技术风险提示（不因"无红线"而消失，供 F1/F2/F3 施工参考）**：
   - **验证码自动求解（F1/NopeCHA）**：① 反噬风险——自动化高频过验证码本身就是强机器行为特征，可能**加速**账号风控升级（从验证码到设备指纹/行为序列封禁）而非规避，实测成功率未知；② 技术依赖——NopeCHA 为第三方 API（延迟/费用/可用性/余额依赖），**必须保留开关降级**：key 空或 API 不可用时回退"人工处理验证码"既有链路，不得硬依赖；③ 口径冲突——原"失败样本只计风控信号"原则被打破，需重新定义成功/失败与熔断输入口径（当前熔断器仅统计 is_risk_signal 命中项，NopeCHA 求解失败不应直接计入熔断，需 F1 明确归类）。
   - **无检测浏览器（F2/patchright）**：① 检测对抗是动态博弈，patchright 签名一旦被识破，账号封禁风险高于普通浏览器；② 兼容性——第 2 轮尝试 1 已实证 patchright Page.evaluate TargetClosedError（fork 连上既有 Edge 后页面被关闭）+ F2 遗留浏览器目录名不匹配（chrome-win64 vs chrome-win）与缺 node driver（已修复：junction 对齐 + patchright install driver，无头冒烟 SMOKE OK: 149.0.7827.55）；③ 保持 RISK_BROWSER_ROUTE 默认空 = 现有 Edge CDP 回退路径，shim 未就绪时不得带半成品跑真实采集。
   - **代理轮换（F3）**：① IP 脏池风险——脏 IP 触发 403/429，须经 proxy_preflight 干净度预检（已有，risk_control.py:193）；② 当前 RISK_PROXY_ENABLED=true 但无 RISK_PROXY_POOL_URL，代理实际不启用（预检 disabled 回退直连）——安全但空转，须 F3 配 URL 才真正生效；③ 稳定性/延迟影响采集速度。
   - **统一要求**：所有对抗开关默认关闭（.env.example=false）、.env.local 显式开启；默认关闭行为与改造前一致（281 测试不回归）；B 阶段已闭环组件语义不得静默改动；F1/F2/F3 完成后向代码总监汇报复审。
