description: 基于用户的工作内容，以选择题提问方式收集数据，生成结构化、专业化的工作日报。适用于矩阵账号运营岗位的日报撰写。必须使用选择题形式向用户提问，禁止编造任何数据。

触发场景（只要满足任意一条就应触发）：
- 用户说"写日报"、"日报"、"工作日报"、"帮我写日报"、"整理日报"、"帮我整理今天的工作"、"记录今天的工作"、"今天干了什么"
- 用户说"工作记录"、"日报模板"、"日报格式"、"复盘今天"、"今日复盘"
- 用户发来今天的工作内容要点并暗示写成日报
- 用户说出具体工作项（如"写了脚本"、"做了视频"、"回复了评论"）且数量≥3项
- **注意：当用户提到具体工作内容并涉及以下关键词时，自动考虑是否需触发：数字人、脚本、评论、线索、灯塔、钩子、矩阵号、抖音、剪映、MiniMax、Heygen**

无需触发的场景：
- 用户只是询问日报怎么写/格式是什么，没有要求生成日报内容
- 用户只是在闲聊今天的工作，没有要求整理成日报
- 用户明确说"不用写日报"或类似否定表达

## 核心原则

1. **STAR-L 法则，极度精简** — 每条工作项按 STAR-L 结构组织，但只保留重点：S/T 一句话带过，A+R 为核心（做了什么+量化结果），L 放在复盘板块。不得展开叙述。
2. **数据量化是铁律** — 每条工作项必须有具体数字（几条、多少次、多少流量、多少转化），不能只有文字描述没有数据。"做了脚本"❌ → "完成4条脚本"✅
3. **短而实，拒绝冗长** — 日报要短，每条工作项一行话说完即可。宁可一句实在话，不要三段空话。
4. **专业表达 + 通俗总结** — 正文保持专业、结构化的表达，末尾附带"通俗版"总结，用大白话概括今天干了什么。
5. **让mentor一眼看懂** — 日报的受众是mentor韩玲，她关心的是：今天产出了什么、数据如何、遇到什么问题需要她协助。
6. **不要过度美化** — 宁可朴实有干货，不要漂亮但空洞。
7. **禁止编造数据** — 所有量化数据必须通过提问从用户处获得。这是最高优先级规则，违反此规则将导致日报内容虚假。

```markdown

```

### 头部信息

```markdown

```

> **运营账号必须写具体** — 不是写"矩阵号"，而是写清楚今天运营了哪几个号，如「科研华哥」「不水论文的华哥」

### 正文结构

#### 一、今日工作

使用编号列表（① ② ③...），按 **STAR-L 精简版** 结构撰写：

| 要素 | 在日报中的体现 | 要求 |
|:----|:-------------|:----|
| **S/T**（情境/任务） | 一句话交代背景 | 控制在 5 字以内，如"脚本""数字人视频""线索" |
| **A+R**（行动+结果） | **核心内容：做了什么 + 量化数据** | 数据必须写具体数字，如"4条""50次""1万+" |
| **L**（学习） | 放在「今日复盘」板块 | 不在工作项中重复 |

**格式**：`序号 **工作项名称（加粗）**：量化行动（可选标注突破）`

**强制规则**：
- **每条必须有数字** — 没有量化数据的工作项不允许出现。如无法量化，先追问用户获取数据。
- **一句话说完，不超一行** — 不要两行。
- **工具/软件自然带出** — MiniMax、Heygen、剪映、灯塔等在生产内容时提及。
- **突破性进展用括号标注** — 如（首次独立产出）、（较昨日+50%）

**示例写法**（STAR-L 精简版，每项一行）：
```
① **脚本创作**：独立完成4条脚本选题与撰写（首次从0到1自主产出）
② **数字人视频**：MiniMax语音+Heygen制作4条数字人视频
③ **线索录入**：灯塔系统录入线索4条
④ **评论区运营**：「科研华哥」「不水论文的华哥」累计回复约50次
⑤ **钩子文档**：完成4个视频钩子制作与排版
⑥ **视频粗剪**：完成1条数字人视频粗剪
```

#### 二、账号数据

**本版块为日报核心，必须包含以下核心数据**（通过选择题提问获得）：

| 板块 | 必须包含的数据项 | 说明 |
|:----:|----------------|------|
| ✅ **回复量** | 今天回复了多少人/多少次 | 必须具体数字，如"50次"而非"较多" |
| ✅ **账号今日曝光量** | 今天账号的总曝光/流量 | 必须具体数字，如"1万+"、"5000" |
| ✅ **线索数** | 今天有多少人给了微信 | 必须具体数字，如"4条" |
| ✅ **互动数据** | 评论数/点赞数/分享数 | 必须具体数字或明确等级 |
| ✅ **生产与发布** | 数字人视频/长推文/科研脚本/剪辑/发布数量 | 制作数≠发布数，两者都要问 |
| ✅ **参考爆款脚本更新** | 今天更新了几个参考爆款脚本 | 必须具体数字，如"2个" |

**表格格式**（数据简明，不拖泥带水）：
```markdown
| 维度 | 数据 |
|------|:---:|
| 今日曝光量 | **X 万** |
| 回复量 | **X 次** |
| 线索获取 | **X 条** |
| 互动数据 | **评论XX / 点赞XX / 分享XX** |
| 数字人视频 | **X 条** |
| 长推文产出 | **X 条** |
| 科研脚本数量 | **X 个** |
| 剪辑数量 | **X 条** |
| 发布抖音视频 | **X 条** |
| 发布抖音长文 | **X 条** |
| 参考爆款脚本更新 | **X 个** |
```

> 📌 **「每天更新」表栏目同步** — 上述栏目与飞书「华哥线索统计」多维表格的「每天更新」表字段一一对应（时间/剪辑数量/发布抖音视频/发布抖音长文/线索数量/科研脚本数量/运营/参考爆款脚本更新）。日报生成后，数据可直接录入该表（`+record-batch-create`，select 选项不足时先 `+field-update` 添加选项；发布数量为 0 时留空不填）。

> 📌 **「账号数据」表逐条同步** — 每条发布内容（视频/长文）还需单独录入「账号数据」表：链接/账号/内容形式/播放量/点赞/评论量/涨粉/视频发布日期/运营，**每条内容=一条记录**。数据来源为题7E，勿编造。

#### 三、所需帮助

> ⚠️ **核心要求：建议必须可落地、有具体执行方案**。不要说空泛的大方向，要说具体怎么做。

**正确示例**：
```
① 建议在数字人视频中插入横屏素材做画中画，测试画面丰富度能否提升爆款率
② 建议数字人形象调整为学长风格，背景用教室/宿舍/自习室，增强代入感
```

**错误示例**（太宏大、不落地）：
```
❌ 建议优化内容策略，提升整体转化率
❌ 建议加强品牌建设，打造IP影响力
```

**如果没有需要帮助的事项，此部分直接省略。**

#### 四、今日复盘（STAR-L 的 L 板块）

这是 STAR-L 中的 **L（Learning）**板块，用于总结今天的收获、发现和反思。语气自然，不要刻意拔高。

**写法要点**：
- 基于数据做复盘，而不是笼统说"今天表现不错"
- 总结今天有什么**进步或突破**（如首次独立完成某事）
- 记录今天发现的**运营观察或问题**（结合数据）
- 提出下一步想**尝试的方向**

**示例**（基于数据复盘）：
```
- **脚本进阶**：首次独立完成4条脚本，从执行优化到自主产出
- **横屏对比测试**：流量1万+但互动一般，想试试竖屏+横屏混搭看对完播率影响
- **线索转化**：曝光8000仅转化1条线索，需优化钩子引导话术
```

#### 五、已掌握技能（可选）

如果今天的工作体现了某些技能，以列表形式呈现。**不需要每天写，只有当有新的技能突破或需要展示技能积累时添加。**

**格式**：
```markdown
## 五、已掌握技能

| 技能模块 | 具体能力 |
|---------|---------|
| **AI数字人生产** | MiniMax语音生成+Heygen数字人视频制作全流程 |
| **视频封面制作** | 剪映封面模板化批量制作，视觉规范统一 |
| **···** | ··· |
```

#### 精华速览

**这是一个独立板块，用于呈现今日工作的最精简版本，方便用户直接复制粘贴到微信群/其他平台。**

**核心要求**：
- 使用 `- ` 无序列表，每条分点明确
- **每条之间不能有空行**（方便整块选中复制）
- 每条一句话，极度精简，只保留关键词+数据；覆盖所有工作类型，每类一行
- 如果有所需帮助或特殊突破，用单独一行写明
- 不加任何修饰词、不写完整句子、不解释背景

**示例写法**：
```markdown
## 精华速览

- 脚本4条 + 数字人视频4条（MiniMax+Heygen全链路）
- 钩子文档4个
- 评论回复约50次
- 灯塔线索录入1条
- 账号总流量1万+
- 视频粗剪1条
- 建议①：视频加横屏素材做画中画
- 建议②：数字人改学长风格+教室背景
```

#### 通俗版

以"通俗版"为小标题，用一段大白话总结今天的工作。控制在一段话内（60-80字），让没时间看完整日报的人也能快速了解。

**写法要点**：
- 用大白话，不要用书面语；一句话概括所有工作，用顿号连接
- 核心数据保留（几条、多少次、多少流量）；所需帮助也用大白话一句话说完
- **越短越好，能60字说完不要写到80字**

**示例**（保持简短）：
```
## 通俗版

写了4条脚本、做了4个钩子文档、回了约50条评论、录了4条线索，流量1万+。建议视频加横屏素材试爆款率，数字人换成学长+教室风格。
```

## 数据收集流程（单选题模式）

> ⚠️ **最高优先级规则：禁止编造任何数据！所有量化数据必须通过提问获得。**
> 
> ⚠️ **提问必须使用选择题形式**，让用户可以直接点选，而不是需要打字输入具体数值。

### 第一步：读取最近日报，了解上下文

先读取最近一份日报（通常是前一天的），了解：
- 最近运营的账号是什么
- 最近的日报格式
- 之前提出的"所需帮助"是否有后续

### 第二步：选择题式数据收集

**核心原则**：同时提出3-4个选择题，而不是一次性把所有问题都抛出来。先问核心的，再根据回答追问细节。

```

A. 数字人视频制作（脚本→MiniMax→Heygen→剪映）
B. 长推文/图文产出
C. 评论/私信运营
D. 钩子文档制作
E. 视频剪辑/粗剪
F. 线索录入（灯塔系统）
G. 其他：_______
```

```
今天账号的总曝光量/流量大概是多少？
A. 5000以下
B. 5000~1万
C. 1万+
D. 5万+
E. 10万+
```

**问题3 — 今日回复量**：
```
今天大约回复了多少次评论/私信互动？
A. 20次以下
B. 20~50次
C. 50~100次
D. 100次以上
E. 没怎么回复
```

**问题4 — 今日线索数**：
```
今天有多少人给了微信（线索）？
A. 0条
B. 1~2条
C. 3~5条
D. 5条以上
```

**问题5 — 今日互动数据**：
```
今天的互动数据大概是什么水平？
A. 一般（评论XX条以内，点赞XX以内）

C. 很好（出了小爆款）
D. 不太清楚/没关注
```
> 如果用户选B或C，追问具体数据。

**问题6 — 所用工具/软件**：
```
今天主要用了哪些工具/软件？（可多选）
A. MiniMax（AI语音生成）
B. Heygen（数字人视频）
C. 剪映（剪辑/封面）
D. 灯塔系统（线索录入）
E. 抖音（发布/运营）
F. 其他：_______
```

**问题7 — 今日运营账号**：
```
今天运营了哪几个账号？（可多选）
A. 科研华哥
B. 不水论文的华哥
C. 搞科研的华哥
D. 华哥聊论文
```

```
今天剪辑了几条视频？发布了几条抖音视频、几条长推文？（制作数≠发布数，需分别确认）
A. 剪辑2条 / 发布视频2条 / 长文0条
B. 剪辑4条 / 发布视频1条 / 长文1条
C. 剪辑6条 / 发布视频2条 / 长文2条
```

```
A. 2个

```
> 选项不足时先 `+field-update` 给 select 字段添加新选项，再写入记录。

**问题7D — 参考爆款脚本更新**（「每天更新」表栏目）：
```
今天更新了几个参考爆款脚本？
A. 2个
B. 4个
C. 6个

```

**问题7E — 发布内容逐条数据**（「账号数据」表栏目，每条发布内容一条）：

```
今天发布的视频/长文，请逐条提供数据（发布几条就提供几条）：
每条包含：账号 | 抖音分享链接 | 内容形式（案例类/选题/长文/真人实拍/咨询结尾）| 播放量 | 点赞 | 评论量 | 涨粉
```

**STAR-L 数据确认** — 收集完所有数据后，快速检查是否每条工作项都有量化数据。如果某项缺少数字，追问："这个做了多少？具体数据是多少？"

**问题8 — 需要什么帮助/建议**：
```
今天有什么需要mentor协助的，或者有什么运营上的想法？
A. 有建议/想法 → [追问具体建议]
B. 没有特别需要帮助的
```
> 如果用户选A，追问具体内容。**必须引导用户说出具体的、可落地的建议**，而不是抽象方向。

**问题9 — 今日复盘/感想**：
```
今天有什么想记录的复盘感想吗？
A. 有收获/突破 → [追问具体内容]
B. 正常工作日，没有特别想记录的
```
> 如果用户选A，追问具体内容。

#### 提问节奏控制

- **第一轮**：先问问题1（工作类型）+ 问题2（曝光量）+ 问题7（运营账号）

## 写作风格指南

### ✅ 正确的写法

| 要点 | 好例子 | 差例子 |
|:----|--------|--------|
| **STAR-L 结构** | "**脚本创作**：独立完成4条脚本（首次自主产出）" | "今天写了脚本，感觉还不错" |
| **数据量化** | "回复评论约50次"、"完成4条脚本"、"曝光1万+" | "大量回复评论"、"流量还行" |
| **具体工具** | "MiniMax语音+Heygen制作数字人视频" | "用AI工具做了视频" |
| **成长记录** | "首次独立完成4条脚本创作，从执行优化到自主产出" | "完成了脚本创作任务" |
| **建议落地** | "建议数字人调整为学长风格，增强代入感" | "建议优化数字人" |
| **结果导向** | "完成4条线索的灯塔系统录入" | "处理了线索" |
| **账号具体** | "运营「科研华哥」「不水论文的华哥」两个账号" | "运营矩阵号" |

### ❌ 要避免的写法

- ❌ **无数据工作项**："写了脚本"❌ → "完成4条脚本"✅
- ❌ **空泛修饰**："精益求精"、"不断优化"、"持续提升"等空洞词汇
- ❌ **过度夸张**："获得巨大成功"、"取得突破性进展"等不实表达
- ❌ **模糊表述**："处理了一些评论"、"做了几个视频"（没有数据）；同一件事不要用不同方式说两遍
- ❌ **宏大建议**："建议优化整体内容策略，提升品牌影响力"（不落地）
- ❌ **堆砌工具名**：不要为了展示工具而写工具，要在具体工作内容中自然带出
- ❌ **编造数据**：这是最严重的错误！

## 注意事项（必读）

1. **STAR-L 精简结构** — 每条工作项 = 工作名 + 量化行动 +（可选突破标注）。不展开叙述。
2. **数据量化是底线** — 每条工作项必须有具体数字。如果用户没有提供，必须追问清楚再写。
3. **先读最近日报** — 每次生成新的日报先读取前一天的日报文件，了解最近的格式和运营账号
4. **选择题提问** — 所有需要收集的数据必须以选择题形式提问，让用户可以直接点选，不要要求用户输入数值
5. **绝对禁止编造数据** — 所有量化数据（曝光量、回复量、线索数、互动数据等）必须通过提问获得
6. **日报要短要实** — 每条工作项一句话说完，不展开、不修饰、不啰嗦
7. **不要一次性全问完** — 分2-3轮提问，每轮3-4个问题，根据回答再追问
8. **运营账号要写具体** — 不是写"矩阵号"，而是写具体账号名
9. **所需帮助必须可落地** — 如果用户提了建议，要引导把建议具体化（怎么做、用什么、预期效果）
10. **保存路径固定** — 日报统一保存到 `总结好的大纲以及笔记/实习就业/工作文件/日报/`
