# 📋 简历素材记录 Skill

将用户的新工作/实习/项目经历，按照「谢积昌简历素材库」的统一格式记录到素材库文档中，**并为每段经历完整标注"可以往哪些岗位方向包装"+ 每个方向的具体理由**——让同一段经历随时能改写成投不同岗位的简历（"一鱼多吃"）。

## 核心工作流

### Step 1：确认工作内容信息

在开始写入之前，必须先理解用户的新经历。用户可能已经提供了完整信息，也可能需要你追问。**需要确认以下字段**：

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 公司/项目名称 | ✅ | 实习的公司名称或项目名称 |
| 所属部门/业务线 | ❌ | 如：数智科技部门·图灵学术 |
| 岗位/角色 | ✅ | 如：矩阵账号运营实习生 |
| 时间 | ✅ | 如：2026.07 — 至今 |
| 工作内容 | ✅ | 具体做了什么，分点描述（越细越好，包装方向的证据全从这里来） |
| 产出/成绩 | ✅ | 量化的结果数据 |
| 创始人/产品形态 | ❌ | 如有，可补充 |

> 💡 **用户可能已提供完整信息**：如果用户一次性说清楚了以上所有信息，则直接进入 Step 2，无需逐一追问。只有当信息明显缺失时才针对性追问。

### Step 2：读取素材库与岗位包装方法论

**① 读取素材库文档**（固定路径）：

```
总结好的大纲以及笔记/实习就业/自己的素材库/简历素材库/谢积昌简历素材库.md
```

> ⚠️ 注意：素材库已迁移至此路径（`实习就业/自己的素材库/简历素材库/`），旧路径（浪尖训练营下）已废弃，禁止使用。

理解：
- **文档结构**：YAML 头部 → 文档索引 → 更新说明 → 一、基本信息 → 二、校内经历 → 三、校外经历 → 四、证书资质 → 五、技能清单 → 六、其他亮点 → 七、经历与岗位匹配速查表 → 八、使用说明 → 附录
- **经历编号规则**：新经历编号 = 当前最大编号 + 1
- **表格格式**：固定使用 `| 项目 | 内容 |` 两列表格
- **包装方向格式**：使用 `> **🎯 可以往哪方面包装：**` 引用块，每个方向三层论证：`- **方向名（推荐度）**` 下挂 **岗位需要 / 经历证据 / 为什么匹配** 三个子项
- **「七、经历与岗位匹配速查表」**：记录现有的岗位方向清单（AI产品实习生 / 新媒体运营 / AI运营实习生 / 产品经理（管培）/ 市场营销 / 设计实习生 / 视频创作 / AI前端开发 / 机器人/硬件产品），新经历的包装方向要能挂靠进速查表

**② 读取岗位包装方法论 wiki**（包装方向的判定依据，两个都必须读）：

```
自动维护知识库/wiki/实习训练营/岗位叫法大全.md
自动维护知识库/wiki/实习求职/简历制作.md
```

- 「岗位叫法大全」提供**六大类岗位关键词库**（内容创作类 / 短视频视频类 / 账号用户私域类 / 综合运营类 / AI方向 / 教培方向）与「一鱼多吃」多方向包装方法论——包装方向的"岗位名"从这里取规范叫法；
- 「简历制作」提供**三要素框架**（流量/产品/交付）与「各岗位核心数据指标」——包装理由的"业务语言"和数据口径从这里取。

### Step 3：判断经历归属类型（校内/校外两大类）

所有经历只分**校内经历**与**校外经历**两大类，再按子类确定插入位置。

**判定口诀**：看经历"发生在哪、为谁创造价值"——服务于校园场景/学生身份的归**校内**；面向真实市场、有真实数据与交付的归**校外**。校外经历宁缺毋滥，校内"过家家"式的课程作业、练习性经历**禁止**放进校外经历。

| 大类 | 子类 | 归类标准 |
|------|------|---------|
| **校内经历** | 1. 校园大使 | 以学生身份为企业做校内推广（如美团/高顿校园大使） |
| | 2. 比赛 | 包含但不限于大创、挑战杯、新生杯等各种比赛——**黑客松除外**（黑客松归校外） |
| | 3. 班干社团 | 学生会、社团、班级等学生组织工作 |
| | 4. 校内项目/课程设计 | 课程设计、调研课题、专利设计等校内项目（"等"类兜底） |
| **校外经历** | 1. 实习经历 | 在公司/组织以正式岗位工作 |
| | 2. 黑客松 | 黑客松类赛事，单独子类（暂无经历也保留该子类） |
| | 3. 项目经历（货真价实） | 真实商业/工程环境下的项目：有真实用户/交付/数据/收入，而非校内"过家家"式练习 |

### Step 4：确定岗位包装方向（核心步骤）

按以下四步把经历拆成"多方向可包装"的素材：

**① 拆解经历**：把经历拆成一个个可分离的工作模块 + 量化成果（如"脚本创作""AI语音生成""评论区运营""线索录入"各算一个模块）。模块拆得越细，能包装的方向越多。

**② 三要素归类**：把每个模块归入 流量（获客/拉新/曝光）/ 产品（内容/方案/功能设计）/ 交付（转化/服务/执行维护），为每个方向准备对应的"行业标准语言"。

**③ 岗位方向映射（宁多勿漏）**：
- 对照「岗位叫法大全」六大类关键词库，找出经历能挂上号的**所有**岗位方向；
- 对照素材库「速查表」已有方向，确保每个方向能挂靠进速查表；
- **AI × 传统双轨检查**：带 AI 元素的经历，除了"AI 岗"方向，必须再检查一遍"传统岗"方向（例：AI新媒体运营 → 同时覆盖"AI新媒体岗"与"传统新媒体岗"，因为脚本/剪辑/发布/互动等环节去掉 AI 也完整成立）；反过来，传统经历也要检查能否挂上 AI 方向；
- 对照素材库「一、基本信息」的意向岗位列表，确保覆盖用户常投的方向。

**④ 逐方向写理由**：每个方向按下方规范，把"岗位需要什么 → 经历里有什么 → 为什么匹配"三层论证写全，让用户看完就能明白**为什么这段经历可以这样包装到该岗位**。

**理由写作规范（硬性要求）**：
- 每个方向展开为**三层论证结构**（不再是单行），格式：

```markdown
> - **{方向名}（{推荐度}）**
>   - **岗位需要**：该岗位的 2-3 条核心职责/能力要求（岗位名从「岗位叫法大全」取规范叫法；岗位考核的数据指标从「简历制作」的「各岗位核心数据指标」表取）
>   - **经历证据**：经历中与之对应的具体工作内容、量化数据、工具技能（必须实指，禁止空话）
>   - **为什么匹配**：逐条讲清"证据→能力→岗位要求"的对应关系——因为做过X所以具备Y，而Y正是该岗位Z职责的要求
```

- 三层的硬性要求：
  - **岗位需要**不能只写泛词（❌"运营能力"），要具体到职责/能力项（✅"多账号矩阵运营、高频内容产出、私域引流与线索转化"）；
  - **经历证据**必须落到**具体内容、量化数据或工具技能**上，与「岗位需要」逐条对应——
    - ❌ "有运营经验，适合运营岗"
    - ✅ 证据"4个抖音矩阵号全流程独立运营"→能力"矩阵账号运营"→岗位要求"负责多账号日常运营"
  - **为什么匹配**是论证核心，禁止只罗列证据不解释——要让用户不用追问"为什么这样可以包装"就能看懂匹配逻辑；
- 推荐度三级：**强烈推荐 / 推荐 / 可选**，依据是该方向与经历核心内容的贴合度；
- 有量化数据的方向优先引用数据（每个岗位关心什么数据，见「简历制作」wiki 的「各岗位核心数据指标」表——写对方真正关心的数据）；
- 经历有突出加分点时加一行 `- **特别亮点**：`（如上市公司背书、平台风控实战经验）；
- 有适合面试直接说的话术时加一行 `- **面试话术**：`。

**包装粒度示例**（以创业黑马——AI新媒体运营岗实习为例，这也是用户验收的基准粒度）：

```markdown
> **🎯 可以往哪方面包装：**
> - **运营方向（强烈推荐）**
>   - **岗位需要**：多账号矩阵运营、高频内容产出、私域引流与线索转化（运营岗三大核心职责）
>   - **经历证据**：4个抖音矩阵号全流程独立运营；单日最高31条脚本+31条推文；评论区引流+灯塔系统线索录入
>   - **为什么匹配**：矩阵号独立运营→直接对应岗位"多账号日常运营"职责；日更31条的产能→证明扛得住运营岗高频内容压力；评论区引流+灯塔线索录入→正是"获客→筛选→转化"完整链路实战，与运营岗的转化考核指标直接对口
> - **AI新媒体方向（强烈推荐）**
>   - **岗位需要**：熟练用AI工具链提效内容生产、有AI内容产品真实落地经验
>   - **经历证据**：MiniMax（AI语音）+Heygen（数字人）+TTS纠错+开拍（AI自动剪辑）全流程实操
>   - **为什么匹配**：覆盖"语音→数字人→剪辑"完整AI内容生产闭环→对应AI新媒体岗"用AI提效生产"的核心要求；且是真实业务场景落地而非尝鲜体验
> - **传统新媒体方向（推荐）**
>   - **岗位需要**：不依赖AI的完整新媒体技能栈（脚本/剪辑/封面/发布/互动/粉丝维护）
>   - **经历证据**：脚本创作、剪映剪辑、封面设计、排期发布、评论区互动、粉丝群维护
>   - **为什么匹配**：以上环节全部独立实操过→去掉AI元素技能栈依然完整成立，传统新媒体岗JD中的常规职责逐条可对上
> - **AI产品经理方向（推荐）**
>   - **岗位需要**：需求定义与产品化思维、理解业务商业闭环
>   - **经历证据**：参与爆款S/A/B/C分级标准定义+内部小工具开发
>   - **为什么匹配**：参与分级标准定义→对应AI产品岗"需求定义与标准制定"职责；理解"内容获客→私域引流→1对1转化→交付"完整商业闭环→产品经理必备的商业思维
> - **特别亮点**：A股上市公司实习背书；从"接收脚本执行"到"全流程独立创作"的能力跃迁；应对平台限流的实战经验
```

### Step 5：写入新经历

按以下模板格式插入新经历：

```markdown
#### 经历{N}：{经历名称} ← 新增

| 项目 | 内容 |
|------|------|
| **公司** | {公司全称} |
| **岗位** | {岗位名称} |
| **时间** | {开始时间} — {结束时间/至今} |
| **工作内容** | {分点描述做了什么} |
| **产出/成绩** | {量化结果数据} |

> **🎯 可以往哪方面包装：**
> - **{方向1}（{推荐度}）**
>   - **岗位需要**：{该岗位核心职责/能力要求}
>   - **经历证据**：{具体工作内容/量化数据/工具技能}
>   - **为什么匹配**：{证据→能力→岗位要求的对应论证}
> - **{方向2}（{推荐度}）**
>   - **岗位需要**：{该岗位核心职责/能力要求}
>   - **经历证据**：{具体工作内容/量化数据/工具技能}
>   - **为什么匹配**：{证据→能力→岗位要求的对应论证}
```

**格式要点：**
- 表格使用 `| **字段名**` 加粗格式
- 时间格式统一为 `YYYY.MM — YYYY.MM` 或 `YYYY.MM — 至今`
- 工作内容中的分点用中文分号 `；` 分隔，**不要使用 Markdown 列表**（保持表格内单行文本）
- 包装方向使用 `> **🎯 可以往哪方面包装：**` 引用块，每个方向用三层论证结构：`- **方向名（推荐度）**` 下挂 `**岗位需要 / 经历证据 / 为什么匹配**` 三个缩进子项
- 方向数量不设上限——只要理由站得住就列出（宁多勿漏），但每个方向的理由必须具体
- 在每个新经历的标题后添加 `← 新增` 标记（仅第一次写入时，后续迭代不再标记）

### Step 6：更新文档头部元数据

更新以下头部字段：

```yaml
最后更新: {当前日期 YYYY-MM-DD}
标签: #简历素材 #求职准备 #经历包装 #新经历相关标签...
```

在「更新说明」中追加记录：
```
{当前日期} 新增经历{编号}：{公司/项目名 — 岗位}，包装方向：{方向1}、{方向2}……
```

### Step 7：更新「经历与岗位匹配速查表」

在 `## 七、经历与岗位匹配速查表` 中，根据 Step 4 判定出的包装方向，逐一挂靠：

| 情况 | 修改方式 |
|------|---------|
| 方向对应速查表**已有行** | 在「最匹配的经历」或「辅助经历」列末尾添加 `**㉒新经历名**`（按贴合度决定放哪列） |
| 方向在速查表中**没有对应行** | 在速查表**新增一行**（方向名沿用包装方向的叫法），并填入新经历 |

同时在表格后追加的 `> 💡 **新增说明**` 中简要说明新增内容与新增方向。

> 包装方向名可以比速查表行名更细（如"AI新媒体方向"挂靠"新媒体运营"行），但必须能说清挂靠关系；速查表确无对应岗位方向时一律新增行，保证速查表始终覆盖所有方向。

### Step 8：更新「其他亮点」中的相关部分

如果新经历有可展示的链接、作品或新增的技能，更新以下部分：
- `### 作品/链接` — 添加作品链接
- `### 个人优势/特点` — 如果衍生出新优势可补充
- `### 技能清单` — 如果涉及新工具/技能可补充

### Step 9：确认结果

写入完成后，向用户简要说明已完成的操作：
- 新增经历编号和名称、插入位置
- **包装方向清单**：逐条列出每个方向 + 「为什么匹配」的核心逻辑一句话（方便用户直接判断往哪个方向投、以及为什么投得成）
- 更新了哪些关联部分（速查表挂靠了哪些行/新增了哪些行）

## 边界情况处理

| 情况 | 处理方式 |
|------|---------|
| 用户信息不完整 | 针对性追问缺失字段，不全部重问 |
| 已有同类经历 | 按编号顺序追加，不覆盖已有内容 |
| 更新已有经历 | 使用「编辑」而非「新建」，并在更新说明中注明；若工作内容有实质变化，同步刷新该经历的包装方向与理由 |
| 用户指定了包装方向 | 以用户指定的方向为准写入，仍按「理由写作规范」写具体理由；可再补充用户没提到但判定成立的方向 |
| 用户未指定包装方向 | 按 Step 4 完整自动判定，所有成立的方向全部列出，不擅自削减 |
| 校内/校外归类存疑 | 按 Step 3"判定口诀"先判断；仍拿不准时先问用户确认，再写入 |
| 判定出的方向速查表没有 | 按 Step 7 规则在速查表新增对应行 |
| 素材库文件不存在 | 报错提示路径错误，不自动创建新文件 |
| 方法论 wiki 缺失 | 若两份包装方法论 wiki 读取失败，报错提示，不凭空编造岗位方向体系 |
