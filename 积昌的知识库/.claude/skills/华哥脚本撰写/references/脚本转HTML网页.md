# 脚本转 HTML 演示网页 / Script-to-HTML Presentation（华哥脚本撰写 · 扩展功能）

> 本文件是「华哥脚本撰写」skill 的**独立功能**：把一条华哥口播脚本转成**可翻页、逐块显现的 16:9 单文件 HTML 演示网页**，供录制视频素材使用。
> SKILL.md 里的正文入口只写触发闸门与概要；**所有执行细节以本文件为准**。

## 〇、触发条件（硬性闸门）

**只有在用户明确要求"生成 HTML 演示网页"时才触发**，例如：

- "把这条脚本做成 HTML 网页"
- "做一版 PPT 式 HTML / 可翻页的网页"
- "生成演示网页 / 出一份网页版演示"
- "把脚本做成画面（网页）方便录制"

其余任何调用本 skill 创作/优化脚本、写推文、判断风格等场景，**一律不触发本功能**，正常走脚本创作流程。`/前端设计` 与 `/提示词优化专家` 等辅助 skill 可在流程中按需调用。

## 一、页数规则（默认 5 页）

除非用户明确指定其它页数，否则**固定 5 页**：

| 页 | 角色 | 内容 | 备注 |
|----|------|------|------|
| 第 1 页 | **封面页** | 脚本主题标题 + 副标题 / 核心问题 | 突出主题即可 |
| 第 2~4 页 | **内容页（共 3 页，一点一页）** | 脚本的核心要点 | 见下方分点判定 |
| 第 5 页 | **结尾回顾页** | 把 3 个分点集中列出，便于回顾 | **每个分点标题严格 ≤ 7 个字** |

### 分点判定（内容页怎么做成 3 点）

- **脚本已明确分点**（"第一点是…/第二点是…/第三点是…"）→ 逐点对应一页，不自行增删。
- **脚本未明确分点** → 由你把脚本内容**梳理成 3 点**（华哥脚本惯例为三点式：通常对应"现象/原因/应对"或"量/门槛/标准"类递进结构）。
- **用户有特殊分点要求**（如"分成 5 点""按 XX 维度分"）→ 按用户要求执行，页数随分点数量变化，**但每一点仍独立一页**，结尾回顾页同步列出全部分点。

## 二、排版要求（质量底线）

1. **每页排版必须不同（给观众新鲜感）**：封面、3 个内容页、结尾回顾页在版式上要**异构**——例如封面居中、内容页用"上标题下数据卡 / 左图右文 / 左文右图"等不同结构、结尾页居中堆叠。禁止 5 页同一种排列。
2. **每页要有层次感（主次分明）**：主标题 / 副标签 / 正文逐级缩放、视觉重心清晰；禁止每页都套同一种"标签＋大标题＋副题＋内容块"的平铺结构。可用横向分层（左文右图）、纵向分层（上大标题下卡片）、编号锚点、对角线倾斜等不同手法制造节奏，让每页读起来有呼吸感。
3. **跨网页也要去同质化（硬性）**：不同网页之间不得"每次都是那几页"。内置 **≥6 套可互换的版式骨架**——S1 封面居中、S2 左文右图、S3 三栏网格、S4 左右对比卡、S5 数字盘点网格、S6 时间线、S7 卡片堆叠、S8 上下分层——制作时：
   - **每份网页按主题从骨架库组合选取**，且**同一份内 5 页版式互不相同**；
   - **相邻两份网页所用主骨架重合度 ≤50%**（上一份用过的，这份尽量换掉）；整体气质、配色、装饰随主题变化，禁止照搬前一份；
   - **结尾回顾页样式也轮换**（居中堆叠 / 编号列表 / 卡片横排），不能每份都一样。
4. **去 AI 味**：语言直接、克制、口语化；**避免**套话、生硬的"首先/其次/最后"、评述性总结、口水话。像真人在讲，不像文案机器。
5. **去廉价塑料感**：配色**低饱和、有层次**；**避免**高饱和渐变、厚阴影、发光、生硬大圆角、廉价 emoji 花哨组合。留白充分，字体层级清晰（中文建议衬线标题 + 无衬线正文）。

## 三、设计辅助

制作时必须**调用 `/前端设计` skill** 辅助完成视觉风格与排版设计。可先定配色与字体，再做每页版式，最后套入内容。

## 三点五、风格自定义设计（视觉风格决策流程 · 硬性）

网页的视觉风格（配色、字体、装饰元素、整体气质）**不得随意选取**，必须按以下优先级顺序确定，让风格"为内容服务"。

### 0. 风格前置询问（硬性闸门）

**每次制作 HTML 之前，必须先问清楚用户要用哪种风格，得到答复后才开始制作**。两种风格：

| 风格 | 定义 | 实现要点 |
|------|------|---------|
| **真实风** | 质感偏向真实 | 到 Pexels **下载与脚本主题相关的图片素材**，转 **base64 内联**（`data:image/jpeg;base64,...`）真正嵌入网页；配色/气质从真实照片提取；整体更真实、有实景质感。**仍保持单文件、无外部依赖**。 |
| **默认** | 目前的抽象/图形风格 | **不插入真实照片**，靠低饱和配色、版式分层、克制装饰（数据卡、三栏、对比卡、网格盘点、线条点缀）表达气质。 |

> 风格选择是"做什么"类问题（本规则允许的提问范围），不是权限请求，直接问即可。

### 1. 用户明确指定了风格参照物时（按参照设计）

典型场景：用户**上传一张图片**，并明确要求"根据这张图片来设计网页"。此时必须逐个提取并落实到网页中：

| 提取项 | 说明 | 落地方式 |
|--------|------|---------|
| **核心元素** | 图片里的构图元素：建筑、图形、纹理、线条、几何、主体物 | 用作版面装饰（背景纹样、分割线、点缀图形、页脚山际线等） |
| **配色方案** | 主色、辅色、背景色、点缀色 | 写入设计令牌 `:root`（CSS 变量）：`--paper/--ink/--accent/--accent-soft/--accent-deep/--line/--bg` 等 |
| **整体气质/风格** | 商务、科技、温暖、冷峻、素雅、复古…… | 决定字体气质（衬线/无衬线）、留白程度、圆角与阴影强度、装饰密度 |

> 目标：让最终网页风格与参照图**高度一致**，而不是"套个通用模板再塞内容"。

### 2. 用户未指定风格参照物时（按脚本主题反推）

此时**不允许**直接套用通用模板，必须**从脚本的主题内容出发反推风格**：

1. **通读脚本，提炼主题关键词**：领域（医学/AI/金融/文学）、行业气质（专业/前沿/人文/严谨）、情绪基调（冷静/鼓励/警示/治愈）；
2. **检索参考图**：**首选 Pexels**（https://www.pexels.com/zh-cn/ ）按主题检索相关图片，借其确立配色与气质（如医学主题 → 蓝白冷调 + 素雅 + 专业；AI 主题 → 深蓝/科技紫 + 网格线条；生活情感主题 → 暖调 + 留白）。**区分两种风格**：若为**默认**——只取色/气质/构图作参照，**不引入图片作素材**（网页仍须单文件、无外部依赖）；若为**真实风**——把这张主题图**下载后转 base64 内联**真正嵌入网页，让实景质感落地。具体采集方法见下方「2.5 Pexels 采集风格素材」；
3. **确立风格三件套**：配色方案（低饱和、克制、有层次）＋ 字体层级（中文建议衬线标题 + 无衬线正文）＋ 克制的主题装饰（1 处点缀即可，不喧宾夺主）。

> **共性底线**：无论走 ①还是②，最终风格都必须符合「二、排版要求」的**去 AI 味、去廉价塑料感**——低饱和、有层次、充分留白，禁止高饱和渐变、厚阴影、发光、生硬大圆角、廉价 emoji 堆砌。

### 2.5 Pexels 采集风格素材（首选来源 + 落地方法）

**用途**：当用户未提供风格参照图、需按脚本主题反推风格时，用 Pexels 收集与主题相关的图片，作为确立网页风格（配色/气质/构图）的素材依据。Pexels 图片均为**免费商用、无需署名**（Pexels License）。

**⚠️ 访问提示（实测）**：Pexels 的**网页搜索页受 Cloudflare 反爬保护**——用 `curl`/`WebFetch` 直接抓 `https://www.pexels.com/zh-cn/search/<关键词>/` 会返回 403（"Just a moment..."）或无法访问；但**图片 CDN `https://images.pexels.com/photos/<id>/pexels-photo-<id>.jpeg` 可直连**（实测 HTTP 200）、**WebSearch 可搜到真实 Pexels 图片页/ID**。因此落地**不走"爬搜索页"，走"搜到 URL → 直接下载图片"**。

**具体流程**：

1. **提炼主题关键词并转英文**：从脚本提炼 2~4 个中文关键词，翻译成英文（Pexels 英文检索效果最佳）：医学→medical / laboratory / microscope；AI→artificial intelligence / data center；教育→education / library 等。
2. **找到相关图片 URL**（二选一）：
   - **WebSearch 检索**：搜索 `pexels <英文关键词> photo`，从结果里拿到 Pexels 图片页（如 `https://www.pexels.com/zh-cn/photo/<id>/`）或直接得到图片 ID；
   - **真人浏览器打开**：`https://www.pexels.com/zh-cn/search/<英文关键词>/` 浏览挑选（需真实浏览器，自动抓取会被 Cloudflare 拦）。
3. **下载图片**：用图片 CDN 直链下载（`curl` 可行）：
   ```bash
   curl -s -o style_ref.jpg "https://images.pexels.com/photos/<id>/pexels-photo-<id>.jpeg?auto=compress&cs=tinysrgb&w=1600"
   ```
   （`<id>` = 图片页里的照片数字 ID，如 `33771472`。）
4. **读图取风格**：用 Read 工具查看下载的图（多模态，可直接读图），提取——
   - **配色**：主色、辅色、背景色、点缀色 → 落到 `:root` 设计令牌（`--paper/--ink/--accent/--accent-soft/--accent-deep/--line/--bg`）；
   - **整体气质**：专业/科技/温暖/素雅/冷峻 → 决定字体与留白；
   - **构图元素**：线条、几何、纹理、主体物 → 作版面装饰参考。
5. **落实到网页并保持单文件**：把取到的配色/气质/元素套到模板。**图片引用方式按风格区分**——
   - **默认**：图片仅作风格参照，**不得**作为外链 `<img src="https://images.pexels.com/...">` 嵌入网页；
   - **真实风**：把下载的图用 `curl` 下载后转 **base64 内联**（`data:image/jpeg;base64,...`）嵌入网页，用作照片、背景或局部插图；保证无外部依赖、发给他人也能正常显示。

**示例**（医学/科研主题）：搜到 Pexels 显微镜照片（ID `33771472`），下载读图后提取——背景浅灰紫（显微镜视场）、点缀深青色/金属青、暗色中性背景 → 落地为"浅灰紫纸面 + 深青强调色 + 深炭灰文字"的科研冷调。

## 三点六、播放过渡动画（沉浸式翻页 · 硬性）

网页在播放/翻页时**必须有过渡动画，禁止生硬地瞬间切换到下一页**。动画需满足：

1. **过渡自然流畅**：页面切换用 CSS `transition`（淡入淡出 + 位移/缩放）或 `animation` 缓动，禁用"啪"一下直接换页；内容显现用逐块淡入（`.anim.on` + `rise` 动画）。
2. **动画与脚本主题相适应**：动画的**节奏、方向、风格**（商务/医疗/科技/情感/治愈）应匹配脚本主题，而非千篇一律的通用动效。例：医疗主题用平稳柔和的缓入缓出；科技主题可用轻微的位移 + 缩放强调"递进"；情感主题用慢速淡入。可通过调整 `transition` 时长与 `cubic-bezier` 缓动曲线、`translateY` 位移方向、`scale` 幅度来体现主题气质。
3. **沉浸感**：过渡动画让观众更快融入视频氛围，避免"下一秒突然变脸"的割裂感——翻页过渡（页间）与页内逐块显现（页内）**协同**发力。
4. **兼顾逐块显现**：除翻页过渡外，**每个文本框/卡片仍要作为独立显现单元**，按"自上而下、自左而右"逐块淡入，不能整页同时出现。

> **实现建议（模板已内置，按主题微调即可）**：`.slide` 过渡 `transition:opacity .7s ease, transform .7s cubic-bezier(...)`；`.anim` 逐块显现 `animation:rise .5s cubic-bezier(...)`；配合 `d1~d7` 延迟类做先后次序。改主题时优先调 `--accent` 与缓动曲线/时长来贴合脚本气质。

## 四、自适应性（硬性要求，防止跨设备出错）

**背景**：本网页常由一个人做好后发给另一个人录制。因此**制作方电脑能正常显示 ≠ 接收方也能**。

1. **制作前先查当前设备分辨率**：先读取当前显示器宽/高（分辨率），据此规划内容密度，避免单页内容超出屏幕。
2. **网页必须随屏幕自适应**：采用**固定设计画布 + 居中等比缩放**（`transform: scale()` 按视口取大边适配，如 `Math.min(innerW/画布W, innerH/画布H)`）。这样同一文件在不同分辨率/窗口下都**整体缩放**，绝不会出现素材或文字溢出/被裁切/横向滚动。
3. **验收标准（硬性）**：
   - 任意一页的任一素材、文字、图表**均不超出画布边界**；
   - 在**不同窗口尺寸**下打开都不裁切、不横向滚动、内容完整显示。

## 五、产出物

一个**完整的单文件 HTML**：

- 内联 CSS + JS，**无任何外部依赖**（不引外链字体、库、图片）。
- **16:9 画布**（建议 `1280×720` 固定设计稿）。
- **可翻页**：键盘（→/←/空格/翻页）、点击左右区域、底部圆点分页、URL 哈希定位。
- **内容逐块显现**：每个文本框/卡片作为一个独立显现单元，按"自上而下、自左而右"逐块淡入（非整页同时出现）。
- 底部可含当前页码/进度条（封面页可隐藏）。

## 六、建议的 HTML 技术结构（可直接用模板）

> 直接用 `assets/脚本转HTML网页模板.html` 作为起点，替换文案并调风格/版式即可。

- **画布与缩放**：
  ```html
  <div id="stage"> <!-- width:1280px;height:720px;transform-origin:center -->
  <script>function fit(){var sc=Math.min(innerWidth/1280, innerHeight/720);stage.style.transform='scale('+sc+')';}
  addEventListener('resize',fit);fit();</script>
  ```
- **幻灯页面**：`.slide{position:absolute;inset:0;padding:...;opacity:0;visibility:hidden;transform:...}`，`.slide.active{opacity:1;visibility:visible;transform:none}`；切换用 `transition`。
- **逐块显现**：`.anim{opacity:0;transform:translateY(16px)}`，`.anim.on{animation:rise .5s ...}`；JS 维护当前页已显现数 `rIdx`，每次 `next` 让下一块 `.on`，全部显现后再 `next` 翻页。
- **控件**：圆点分页、计数器、进度条、左右/点击翻页、键盘事件、哈希定位。
- **设计令牌**：用 `:root` 集中定义配色/字体变量，便于一次换肤。
- **主题装饰**：背景可用低饱和渐变 + 1 处克制点缀（如山际线/建筑线稿/网格纹），不要喧宾夺主。

## 七、交稿前自检清单

- [ ] 一共 **5 页**（或按用户指定页数），页序正确。
- [ ] 第 1 页是封面（主题），第 2~4 页每页一个分点，第 5 页是回顾。
- [ ] 内容页是 **3 点**（或按用户指定分点），一点一页，无遗漏。
- [ ] 结尾回顾页**每个分点标题 ≤ 7 个字**，3 条集中列出。
- [ ] **每页版式不同**（无两页同构），且**每页有层次感**（主/副/正文逐级缩放、主次分明，非同一平铺结构）。
- [ ] **跨网页去同质化**：本份所用版式骨架与上一份**重合度 ≤50%**；本份内 5 页版式互不相同；结尾回顾页样式也轮换、与上一份不同。
- [ ] 语言**无 AI 味**（无套话/评述/口水），配色**无塑料感**（低饱和、克制）。
- [ ] 已调用 `/前端设计` 完成风格与排版。
- [ ] 制作前已**问清风格**（真实风 / 默认），并按所选风格落地：**真实风**已把 Pexels 主题图**转 base64 内联**嵌入网页；**默认**无任何外链图片，只取色/气质/构图。
- [ ] **风格已按决策流程确定**：用户给了参照图 → 已提取其核心元素/配色/气质并落到设计令牌与版面装饰；用户未给参照 → 已按脚本主题反推（**首选 Pexels** 检索参考图确立配色/气质），且始终符合去 AI 味/去塑料感。
