# 交接提示词 · Codex 版

> 使用说明：把下面 ```text 代码块里的全部内容整体复制，粘贴到 Codex 的对话框里，按其中的要求与它对话即可。它产出的《交接文档》是给"人"（同事/领导/未来的自己）看的。

```text
# 你的任务：写一份《交接文档》给"人"看，把我们的知识库自动化整理项目交代清楚

## 一、你的身份与你的优势（先记住这四条）

你正在参与一个「知识库自动化整理项目」（一个 Obsidian 知识库 + 自动化整理脚本的项目，之前由 Claude Code 做了一半，现在你来接手，并把项目状态写清楚交给一个人——可能是同事、领导，或未来的你自己）。

你与普通对话式 AI 最大的不同：**你能读写本地文件系统、能跑 Windows PowerShell 命令、有本地会话记录可查。** 所以你的文档必须**建立在真实核查过的事实上**，而不是靠记忆瞎写。

四条硬约束：
1. **先核查，后动笔**：文档里出现的每一条路径、命令、状态，都必须先到真实环境里核实过再写。核实不了的，标 ❓ 并说明缺什么。
2. **目标读者是人，且可能完全没参与过这个项目、甚至不懂技术**：要比给 AI 看的文档更详细、更啰嗦——解释每个术语、讲来龙去脉、说明为什么这么选、手把手写步骤、标注风险与求助点。
3. **利用你的 L1 能力**：精确到"文件:行号 / 函数名 / PowerShell 命令"，并附上命令的预期输出，让读者能照抄去跑。
4. **全程使用简体中文**；技术标识符（文件名、命令、参数名）保持原名。

## 二、动笔前先做事实核查（这是必做步骤，不是可选项）

用 PowerShell 到真实环境里把项目当前状态查清楚，示例命令（按需选用，不要照搬，也别漏掉关键项）：

- 列目录结构：`Get-ChildItem -Recurse -Name | Select-Object -First 200`
- 读关键文件当前内容：`Get-Content "E:\积昌的知识库 - 副本\<相对路径>\<文件名>"`
- 看版本与未提交改动：`git status`、`git log --oneline -10`
- 验证文件/目录是否存在：`Test-Path "<路径>"`
- 看服务/进程是否在跑：`Get-Process`、`Get-Service | Where-Object {$_.Status -eq 'Running'}`
- 运行测试/启动脚本确认可运行：`python -m pytest -q`、`.\restart.bat` 等
- 检查模型/工具配置：`Get-Content "C:\Users\asus\.codex\config.toml"`、环境变量 `$env:XXX`

把每条结论都写上"**核实方式 + 核实结果**"（例如"核实：`Test-Path '...'` 返回 True，文件存在"），让读者知道这是你查证过的，不是猜的。

## 三、输出的文档必须回答四个问题（四要素，缺一不可）

1. **当前已经做了什么**：已完成工作的全量清单，每一条含 4 个字段——做了什么 / 产出物在哪(真实路径) / 怎么验证有效 / 关键数据（能写数字就写数字）。
2. **还有什么没做**：未完成工作的全量清单（这就是读者要接的"接力棒"），每一条必须写满 **7 个字段**：还差什么 / 为什么没做完(阻塞原因) / 前置条件 / 优先级(紧急/重要/一般) / 做到什么算完成(可验收) / 从哪开始 / 验证信号。
3. **接下来要接着做什么**：读者要接的每件事（接力任务），与第 2 点每一条**一一对应、编号一致**。
4. **接下来该怎么做**：展开成 1-N 步，每步普通人能照做、每步有验证信号、卡住了找谁。

> 最容易翻车的写法（绝对禁止）："还有几件事没做完，下次继续""你接手后把剩下的做一下""详见之前的记录""等等/后续再说"。只要出现这类一笔带过，就是不合格，必须展开成上面带字段的条目。

## 四、文档骨架（照这个写，结构不许乱）

- **0. 一句话定位 + 阅读指引**：用大白话讲这项目是干嘛的；这份文档怎么读、先看哪节、重点看哪节。
- **1. 这份文档是给谁看的**：写这份文档的背景（谁交接给谁、为什么交接）；读者读完应该能达到什么效果。
- **2. 项目总览（大白话）**：这个项目做什么 / 为谁做 / 解决什么问题 / 一句话讲清价值 / 整体完成度估算（如"约 70%"）＋判断依据。
- **3. 背景与来龙去脉**：项目怎么来的、为什么做（业务/组织背景、触发原因）；关键约束、用户偏好；和知识库里其他事情的关系。
- **4. 术语表**：把项目里出现的专业词、缩写、黑话、内部代号逐条解释，格式"术语（英文/缩写）＝ 一句话大白话"。哪怕你觉得很基础也写——读者可能不懂。
- **5. 当前进度（用"人话"讲）**：整体做到哪一步、处于什么阶段；最后一次停在什么位置（以非技术读者能懂的方式描述）。
- **6. 已完成工作（全量逐条）**：按第 3 点四要素第①条写，每条 4 个字段，附产出物真实路径＋一句话用途、关键数据/效果数字。
- **7. A 没做完的事（接力棒，全量逐条）**：按四要素第②条写，每条 7 个字段。开头点明：**这些是前任（A）留下的接力棒，是你的起点，不是你的过错。**
- **8. A→B 接力总览表（核心，把 ⑦ 和 ⑨ 钉在一起）**：

  | # | A 没做完的（接力棒） | 你（读者）接下来要做什么 | 从哪开始（文件/工具/找谁） | 做到什么算完成（怎么验证） |
  |---|----------------------|--------------------------|----------------------------|---------------------------|

  - 全表用大白话；"从哪开始"列写清真实文件路径、或找哪个工具/联系人。
  - 表末给"接力开工第一步"：具体动作（如"打开 `E:\...\xxx.md`，看第 3 节"）→ 出现什么现象算正式接上。
- **9. 下一步怎么做（手把手）**：把第 8 节展开成普通人能照做的 1-N 步——第一步做什么 → 打开哪个文件/找谁/用哪个工具 → 看到什么结果算这一步做对了 → 卡住了看哪个文档/问谁。区分"立即做 / 之后做"。
- **10. 关键决策与踩坑记录**：做过的选型及原因（用大白话讲理由）；踩过的坑（现象+根因+怎么避开，这是最值钱的部分）；试错过但放弃的方案及原因。
- **11. 风险与求助点**：不确定处、需人工确认的点逐条标 ❓；可能翻车/有隐患的地方；**遇到问题找谁**（责任人、关联文档、常用工具位置）。
- **12. 常用资源清单**：关键文件/产出物位置（真实路径＋一句话用途）；账号、密钥、工具的存放位置（密钥值脱敏）；相关文档/链接清单。

## 五、命令与定位要求（充分利用你能读文件、能跑命令的能力）

1. 文档里出现的所有命令统一用 **Windows PowerShell**，写成**读者可以直接复制去跑**的形式，并附**预期输出**（如"看到 `X passed` 即成功""`Get-Service` 显示 `Running` 即成功"）。
2. 需要读者打开文件去改的地方，写到**哪个文件第几行、哪个函数/哪段逻辑**，让人能精准定位，不许只写"在 main.py 里改一下"。
3. 涉及第三方模型/供应商配置时，提醒检查 `C:\Users\asus\.codex\config.toml`，避免模型不可用；涉及外网访问时，标注代理/分流要求。
4. 关键代码位置用 `文件路径:行号` / `函数名` 标注，便于接手者接着改。

## 六、写作风格与硬性要求（违反即重写）

1. **给人版必须比给 AI 版更详细、更啰嗦**：如果这份文档写得比一份"给 AI 的交接文档"还短，说明写漏了，必须补。
2. 每个术语都解释、每步都手把手、每个"为什么"都讲清理由。
3. **禁止编造**路径、命令、状态——全部到环境里核实过再写；核实不了的标 ❓。
4. 禁止"等等/详见以前记录/后续再说"类一笔带过。
5. 写完对照下面的自查清单，全部勾选后才算完成。

## 七、完成自查（交稿前逐条对照）

- [ ] 四要素齐全：①已做了什么 ②还没做什么(每条7字段) ③接下来做什么(与②编号一一对应) ④怎么做(展开成可照做的1-N步)
- [ ] 所有路径/命令/状态都经过实际核查（或在旁边标了 ❓ 并说明缺什么）
- [ ] 有术语表、背景与来去、为什么这么选、风险与求助点
- [ ] 接力总览表存在，且每条"从哪开始"写的是真实文件路径/工具/联系人
- [ ] 命令全是 PowerShell 风格，附预期输出，读者可照抄去跑
- [ ] 步骤普通人都能照做，每步有验证信号
- [ ] 全文没有"等等/详见以前记录/后续再说"这类一笔带过
```
