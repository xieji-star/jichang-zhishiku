# 交接提示词：Codex → 写交接文档给人看

> 目标智能体：**Codex**（L1 自治型——能读本地文件、能跑命令，Windows 环境常用 PowerShell）
> 交接对象：**人**（一位完全没参与过这个项目的同事/接手人）
> 用途：把下面代码块里的内容**整段复制**，粘贴到 Codex 的对话框作为一条提示词发送。它收到后会基于它与你的聊天记录（并利用它读文件、跑命令的能力核实事实），写出一份《知识库自动化整理项目 交接文档（给人版）》。
> 使用方法：复制下方 ```` ``` ```` 之间的全部内容 → 粘贴给 Codex → 它输出交接文档 → 你直接交给接手人阅读。

````markdown
你正在结束一段工作，现在要把当前工作交接给一位【人】——一位完全没参与过这个项目的同事或接手人。请基于我们这段对话的聊天记录，写一份《知识库自动化整理项目 交接文档（给人版）》。

## 〇、先记住你的能力（这决定了你这份文档怎么写，务必利用起来）

- 你能读本地文件、能跑命令（Windows 环境，PowerShell）。文档里可以直接给**精确路径 + PowerShell 命令**，你自己读文件核实、跑命令验证，确保文档里每个路径、每行代码位置、每条命令都**真实可执行**。
- 因为你能读文件，文档里**不必贴大段代码**——给出精确的 `文件路径:行号 / 函数名 / 可执行命令` 让读者知道去哪看即可；你负责先核实它们真实存在。
- **交接点定位到函数/行号**：明确"从哪个函数/哪一行继续"，便于后续在现有代码上续改。
- 若项目依赖第三方模型/供应商配置，检查 `config.toml`；若涉及外网访问，注意代理/分流要求，并在文档中标注。
- 若需要跨机迁移，说明会话文件位置与迁移方式（拷 sessions 不拷 auth.json）。
- 你是作者，但**读者是人**。人不如 AI：每个术语都要解释、每一步都要写到普通人能照做。宁可啰嗦，不可简略。

## 一、必须回答的四个问题（缺一不可，尤其③④不许一笔带过）

① 当前已经做了什么 —— 已完成工作全量清单，每条写清 4 要素：做了什么 / 产出物在哪 / 怎么验证有效 / 关键数据
② 还有什么没做的 —— 未完成工作全量清单（= 留给接手人的接力棒），每条写满 7 要素：还差什么 / 为什么没做完(阻塞原因) / 前置条件 / 优先级 / 做到什么算完成 / 从哪开始 / 验证信号
③ 接下来要接着做什么 —— 与②一一对应（编号一致），每条写清：接哪个遗留项 / 从哪开始 / 做到什么算完成
④ 接下来该怎么做 —— 展开成 1-N 步，每步可照做、有验证信号、卡住了找谁

## 二、必须有一张"A→B 接力总览表"

| # | A 没做完的（接力棒） | 你（接手人）接下来要做什么 | 从哪开始（文件/工具/找谁） | 做到什么算完成（怎么验证） |
|---|--------------------|--------------------------|--------------------------|---------------------------|

把②和③④钉在一起，让接手人读到就能照着 #1 直接开工。这张表是给"人"看的——"从哪开始"用大白话写（打开哪个文件、运行哪个工具、找谁），不要只甩一个命令。

## 三、文档结构（给人版，按下面 12 节写）

1. **这份文档是给谁看的**：写这份文档的背景（谁交接给谁、为什么交接）、读者读完应该能达到什么效果
2. **项目总览（大白话）**：这项目是做什么的、为谁做、解决什么问题、一句话讲清价值、整体完成度估算（如"约 70%"）＋判断依据
3. **背景与来龙去脉**：项目怎么来的、为什么做（业务背景/组织背景/触发原因）、关键约束与前置信息、和公司/团队其他事情的关系
4. **术语表**：把项目里的专业词、缩写、黑话、内部代号逐条解释，格式"术语＝一句话大白话解释"；哪怕你觉得"这很基础"也写——读者可能不懂
5. **当前进度（用"人话"讲）**：整体做到哪一步、处于什么阶段、最后一次停在什么位置
6. **已完成工作（全量逐条，每条按①写满 4 字段）**：按时间/模块分组，做了什么、成果在哪、怎么验证它确实有效、关键数据
7. **A 没做完的事（接力棒，全量逐条，每条按②写满 7 字段）**：开头点明"这些是前任留下的接力棒，是你的起点，不是你的过错"
8. **A→B 接力总览（核心，见上面第二条）**：表末给一句"接力开工第一步"——具体动作 → 出现什么现象算正式接上
9. **下一步怎么做（手把手，按③④写满）**：把接力总览展开成 1-N 步，普通人能照做；区分"立即做/之后做"；每步有验证信号、卡住了看哪个文档/问谁
10. **关键决策与踩坑记录**：选型及理由（用大白话讲）、踩坑现象/根因/怎么避开、试错后放弃的方案及原因
11. **风险与求助点**：不确定处逐条标"❓"、可能翻车有隐患的地方、**遇到问题找谁**（责任人/关联文档/工具位置）
12. **常用资源清单**：关键文件/产出物位置（相对路径＋一句话用途）、账号/密钥/工具的存放位置（密钥脱敏）、相关文档/链接清单

## 四、信息收集方式

- 优先基于聊天记录总结；信息不足可读本地文件核实、跑 PowerShell 命令验证，或问我（用户）追问背景。
- 每条路径、命令、结论必须真实可查；核实不了或不确定的标 ❓，绝不编造。
- 因为你能力强，要求也高：文档里出现的路径/命令请你**亲自核实过再写进去**——给错路径会误导接手人。

## 五、输出

输出为 Markdown 文档。保存到：<此处问用户要保存路径，用户指定后写入该路径>。
````
