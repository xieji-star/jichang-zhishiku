# 交接提示词：DeepSeek Harness → 写交接文档给 Codex 续作

> 目标智能体：**DeepSeek Harness**（L3 对话型——主要靠对话记忆、可能读不到本地文件、不能跑命令）
> 交接对象：**Codex**（L1 自治型——下一个续作的 AI 智能体，能读文件、能跑 PowerShell）
> 用途：把下面代码块里的内容**整段复制**，粘贴到 DeepSeek Harness 的对话框作为一条提示词发送。它收到后会基于它与你的聊天记录，写出一份《知识库自动化整理项目 交接文档（给 Codex 版）》。
> 使用方法：复制下方 ```` ``` ```` 之间的全部内容 → 粘贴给 DeepSeek Harness → 它输出交接文档 → 你按它文档末尾的"请用户核对的清单"逐条核对修正 → 再把交接文档交给 Codex。

````markdown
你正在结束一段工作，现在要把当前工作交接给下一个继续干的 AI 智能体 **Codex**（它接着在你的成果上续作）。请基于我们这段对话的聊天记录，写一份《知识库自动化整理项目 交接文档（给 Codex 版）》。

## 〇、先记住你的能力边界（这决定了你这份文档怎么写，务必照做）

- 你主要靠对话记忆，**可能读不到本地文件**。所以文档里的关键代码、配置、命令必须【直接粘贴进正文】，绝不能只给个路径让接手方自己去找——你作为作者，要给就把内容给全。
- 你自己**不能跑命令**。所以文档里每个"验证"步骤一律写成「请用户代跑 XXX，看到 YYY 输出即成功」的形式。
- 你**可能会记岔**。所以每条信息都要标注证据分级：✅确定 / 🔶推断 / ❓待确认。分级后用户能识别哪些要复核。
- 文档**末尾必须附一栏"请用户核对的清单"**：把你提到的所有路径、文件状态、命令逐条列出，请用户核对是否属实，在把文档交给 Codex 之前修正。
- **每步只做一件事**，每步给一个可观察信号；把歧义全部消掉，不要让人猜。禁止出现"等等""后续再说""详见之前记录"这类一笔带过的话。

## 一、必须回答的四个问题（缺一不可，尤其③④不许一笔带过）

① 当前已经做了什么 —— 已完成工作全量清单，每条写清 4 要素：做了什么 / 产出物在哪 / 怎么验证有效 / 关键数据
② 还有什么没做的 —— 未完成工作全量清单（= 留给 Codex 的接力棒），每条写满 7 要素：还差什么 / 为什么没做完(阻塞原因) / 前置条件 / 优先级 / 做到什么算完成 / 从哪开始 / 验证信号
③ 接下来要接着做什么 —— 与②一一对应（编号一致），每条写清：接哪个遗留项 / 从哪开始 / 做到什么算完成
④ 接下来该怎么做 —— 展开成 1-N 步，每步可照做、有验证信号、卡住了找谁

## 二、必须有一张"A→B 接力总览表"

| # | A 没做完的（接力棒） | Codex 要做什么 | 从哪开始（贴出关键内容/代码/命令，不要只写路径） | 做到什么算完成（怎么验证） |
|---|--------------------|---------------|-----------------------------------------------|---------------------------|

把②和③④钉在一起，让 Codex 读到就能照着 #1 直接开工。**这张表的"从哪开始"列必须自包含**——把关键文件内容、代码片段、配置值直接贴进对应行，而不是只写一个路径。

## 三、文档结构（给 Codex 的 AI 版，按下面 14 节写）

0. **交接摘要（启动包）**：项目做什么、当前做到哪一步、最关键三件事（已完成什么 / 接力棒是什么 / Codex 下一步第一件事）、一句话提示从哪继续最省力
1. **项目总览与验收标准**：一句话定位、最终目标、做到什么程度算完成（可检验）
2. **文件地图（自包含版）**：逐个列出文件/文件夹——真实路径、作用、当前状态（新建/修改/已完成/未动/临时）；**关键文件内容直接贴出或贴出要点，不要只给路径**
3. **已完成工作**：逐条，每条含"产出物在哪 + 如何验证有效"，含关键代码位置/函数名（便于 Codex 接着改）
4. **当前精确进度**：最后一步有效操作是什么（在哪个文件/哪个逻辑块）、当前代码/文档/数据处于什么具体状态
5. **A 没做完的事（接力棒）**：逐条写满 7 要素；开头点明"每个未完成项就是 Codex 要接的活"
6. **A→B 接力总览（核心，见上面第二条）**
7. **下一步行动计划（命令级）**：承接第 6 节，展开成 1-N 步；命令写成 Windows/PowerShell 风格（Codex 的运行环境）；每步只做一件事、每步给"人代跑"的验证信号、证据分级（✅/🔶/❓）；区分"立即做/之后做"
8. **环境与配置依赖**：模型/工具/软件及版本、端口、环境变量、依赖库；**关键配置项直接贴出值（脱敏）**，不要只写"在 .env 里"；密钥只写存放位置，值脱敏为 <已脱敏>
9. **数据与状态快照**：涉及的数据/文件/接口当前状态、临时数据是否需要清理、需保留的中间产物
10. **关键决策与踩坑记录**：技术选型及原因、踩坑根因与规避方案、放弃的方案及原因
11. **风险与待确认项**：逐条标"❓"
12. **续作启动手册**：从零恢复完整步骤；**如何验证"续上了"**——写成"请用户代跑 XXX，看到 YYY 输出"，并附给用户的核对清单
13. **请用户核对的清单（必附）**：把你提到的路径/状态/命令逐条列出，请用户核对是否属实，确认后再交付 Codex
14. **交接元信息**：项目名、交接对象（Codex）、交接日期

## 四、信息收集方式

- 优先基于聊天记录总结。信息不足可问我（用户）追问背景。
- 每条路径、命令、结论必须真实；核实不了或记不准的标 ❓，绝不编造。
- 你读不到文件没关系——把不确定的路径写进第 13 节"请用户核对的清单"，让用户帮你确认。

## 五、输出

输出为 Markdown 文档。保存到：<此处问用户要保存路径，用户指定后写入该路径>。
````
