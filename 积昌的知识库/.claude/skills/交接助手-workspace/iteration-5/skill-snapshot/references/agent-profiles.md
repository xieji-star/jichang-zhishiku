# 智能体习性档案（Agent Profiles）

> 用途：做"给 AI 看的交接文档"（交接助手 skill 模式 B）时，先查本档案，按目标智能体的**习性 + 模型质量**定制文档。**不同 AI 产品能力不同、模型质量不同，用同一份通用模板效果极差**——给强模型的文档可能给弱模型根本接不住。本档案解决"这份文档要写成什么样，那个智能体才接得住"。
>
> 使用步骤：① 确认目标智能体 → ② 判断它的**能力层级（L1/L2/L3）** → ③ 读对应档案 → ④ 按"交接文档定制要点" + "与给其他AI的核心差异"生成 → ⑤ 若目标未收录，按能力层级用「通用」规则。

---

## 0. AI 能力分层总览（先定位，再定制）

> **核心认知：交接文档必须"看菜下饭"。同一个项目，给 Codex（L1）和给 DeepSeek Harness（L3）的文档，从内容密度、自包含程度、指令粒度上都必须不一样。** 判断维度有四条：① 能不能读文件（决定要不要把关键内容贴进正文）；② 能不能跑命令（决定验证方式是自己跑还是让人代跑）；③ 模型强不强 / 上下文大不大（决定指令粒度与结构）；④ 会不会"记岔"（决定要不要证据分级）。

| 层级 | 典型代表 | 能读文件 | 能跑命令 | 模型质量 / 上下文 | 交接文档策略 |
|------|---------|:-------:|:-------:|------------------|-------------|
| **L1 自治型** | Claude Code、Codex、Cursor、Windsurf、Gemini CLI | ✅ | ✅ | 强：理解复杂指令、自主多步推理、上下文大 | 给"精确地图 + 可执行命令 + 精确接续位置"；可紧凑但信息必须完整精确，它自己读文件补细节 |
| **L2 半自治型** | 能读文件但推理/上下文受限的智能体 | ✅ | ⚠️ 部分 | 中：能读文件但长上下文或复杂指令吃力 | 给"地图 + 关键内容摘要"：重要文件内容直接贴出，步骤拆细，每个关键节点给验证信号 |
| **L3 对话型** | DeepSeek Harness、Kimi、豆包、文心一言、通义、ChatGPT 网页版 | ❌/❓ | ❌/❓ | 弱到中：主要靠对话记忆、读不到文件、上下文有限、可能记岔 | 给"自包含教材"：关键代码/配置/命令**全部贴进正文**，步骤最小化、每步带验证信号、证据分级（✅确定/🔶推断/❓待确认） |

> ⚠️ **硬性规则：绝不允许把给 AI-A 的文档改个标题就当给 AI-B 的文档。** 每份给 AI 的文档都必须从零按目标 AI 的能力层级 + 习性档案重新生成。判断自己是否偷懒的标尺：**把这份文档递给目标 AI，它能不能不问人、不查环境就照做第一步？**

## 1. Claude Code（Anthropic 命令行智能体）— L1 自治型

### 能力画像

| 维度 | 说明 |
|------|------|
| 文件系统 | ✅ 可读写本地文件 |
| 命令执行 | ✅ 可执行 bash / PowerShell、git、python 等 |
| 子代理 | ✅ 可启动多个子代理并行处理大任务 |
| 项目规则 | ✅ 自动读取项目根目录 `CLAUDE.md`（全局规则在用户 `~/.claude/CLAUDE.md`） |
| 上下文加载 | ✅ 支持 `<linked_note>` 关联文档、`<editor_selection>` 选中片段 |
| 模型质量 | 强：能理解复杂指令、自主多步推理、上下文窗口大 |
| 擅长 | 代码开发、重构、调试、多文件修改、读整个代码库 |
| 会话迁移 | 会话可被外部工具延续 |

### 交接文档定制要点

1. **给精确路径 + 可执行命令**：Claude Code 能直接跑，文档里每一步都写成可执行指令（`cd`、`python`、`pytest`、`npm` 等），它拿到就能动手。
2. **建议写 CLAUDE.md**：若项目有必须遵守的规则/约束，在文档里建议（或直接帮它）把关键规则写进项目根目录的 `CLAUDE.md`，它会自动加载并遵守。
3. **文件地图按"入口→配置→产出"排列**：标注每个文件可读、作用；它擅长读代码，可给出"关键函数在哪个文件哪一行"。
4. **下一步计划写成任务列表**：它适合逐项执行；给"先做 A、再做 B"的清单，每项可验证。
5. **验证方法必须可跑**：如"跑 `pytest` 通过 281 条""启动服务后看到 XXX 日志行"。
6. **可提示用子代理**：若任务大（如跨多模块重构），提示它可并行派生子代理。
7. **给它留"提问入口"**：交接文档末尾列出❓项，它遇到不确定会主动确认。
8. **接力总览表按"路径+命令+函数"填"从哪开始"列**：入口列直接给 `文件路径:行号`、`函数名`、可执行命令；验证列给"跑什么命令看到什么输出"。
9. **模型强，指令可以"目标+要点"式**：不必把每个文件内容都贴进正文——告诉它看哪个文件、改哪个函数、达到什么效果即可，它能自己读代码补细节。但**结论、路径、命令必须精确**。

### ★ 与给其他 AI 的文档的核心差异

- **vs DeepSeek Harness（L3）**：Claude Code 版**不需要**把关键代码/配置贴进正文（它能自己读文件）；DeepSeek 版**必须**全贴。Claude Code 版指令可以是"目标+要点"式；DeepSeek 版必须"一步步+每个中间信号"。
- **vs Codex（L1）**：Claude Code 版可用跨平台 bash 风格或 PowerShell 均可，且可以建议写 `CLAUDE.md`、可以提示用子代理；Codex 版则偏 PowerShell + 提醒 `config.toml` + 会话文件迁移。

## 2. Codex（OpenAI 智能体）— L1 自治型

### 能力画像

| 维度 | 说明 |
|------|------|
| 文件系统 | ✅ 可读写本地文件 |
| 命令执行 | ✅ 可执行命令（Windows 环境常用 PowerShell；也支持 bash） |
| 会话记录 | ✅ 本地会话文件 `C:\Users\asus\.codex\sessions\*.jsonl`，可跨账号/机器迁移 |
| 模型配置 | `config.toml` 可配第三方模型（如 deepseek） |
| 网络依赖 | 部分环境依赖代理/分流规则（如 OpenAI 专用节点） |
| 模型质量 | 强：能理解复杂指令、自主多步推理、上下文大 |
| 擅长 | 代码、运维、批量处理、长任务 |

### 交接文档定制要点

1. **给 Windows 风格命令**：PowerShell 为主（`.ps1`、`robocopy`、`tasklist` 等），与它的运行环境匹配。
2. **标注"从哪个函数/哪一行继续"**：Codex 要基于现状改代码，文档须明确当前代码状态和接续位置。
3. **提醒 config.toml**：若项目依赖第三方模型/供应商配置，提醒它检查 `config.toml`，避免模型不可用。
4. **说明会话可迁移性**：若需跨机迁移，提示会话文件位置与迁移方式（拷 sessions 不拷 auth.json）。
5. **验证方法**：跑测试/启动服务/检查输出文件；给出明确成功信号。
6. **网络注意事项**：若项目涉及外网访问，在文档标注代理/分流要求（参考知识库 Codex 网络故障档案）。
7. **明确"当前代码状态"**：Codex 强在续改代码，文档要把"现在代码是什么状态、还差什么"写清楚。
8. **接力总览表按"PowerShell 命令+函数级定位"填"从哪开始"列**：入口列给 `文件.ps1`、`Get-NetTCPConnection`、`.\start.ps1`、函数名/行号；验证列给 `tasklist`、`curl`、测试输出等 Codex 能直接执行的判定信号。
9. **模型强，指令可以"目标+要点"式**：与 Claude Code 类似，路径/函数/命令精确即可，不必贴大段代码；它自己读文件补细节。

### ★ 与给其他 AI 的文档的核心差异

- **vs DeepSeek Harness（L3）**：Codex 版给"精确路径 + PowerShell 命令 + 函数级定位"即可，代码不必全贴（它能读文件）；DeepSeek 版**必须自包含**（关键代码/配置全贴进正文），且要附"用户核对清单"防记岔。同一份内容，Codex 版可以更紧凑，DeepSeek 版必须更"保姆级"。
- **vs Claude Code（L1）**：Codex 版统一用 PowerShell 风格命令、提醒 `config.toml`、说明会话文件可迁移；Claude Code 版跨平台命令即可、建议写 `CLAUDE.md`、提示子代理。

## 3. DeepSeek Harness（DeepSeek 智能体）— L3 对话型

### 能力画像

| 维度 | 说明 |
|------|------|
| 文件系统 | ❓ 有限/不确定：主要靠对话上下文，可能无法可靠读取本地文件 |
| 命令执行 | ❓ 不确定：一般不执行本地命令 |
| 会话记录 | ❌ 无本地会话文件可读（不像 Codex 有 sessions） |
| 上下文窗口 | ⚠️ 有限：早期内容可能遗忘 |
| 模型质量 | 中偏弱：复杂指令或超长上下文容易"接不住"或"记岔" |
| 擅长 | 对话式分析、内容生成、基于对话记忆的续作 |

### 交接文档定制要点

1. **自包含（最重要，且宁可多写不可省略）**：关键代码、配置、命令**直接粘贴进文档正文**，不要只给路径——它可能读不到文件。**注意：详细 ≠ 只给结论；每个未完成项都要按七要素写满（还差什么/为什么/前置/优先级/完成定义/从哪开始/验证信号），只是"从哪开始"要贴内容而不是只写路径。**
2. **证据分级**：每条信息标注 ✅确定 / 🔶推断 / ❓待确认——它会"记岔"，分级后用户能识别哪些要复核。
3. **附"给用户的核对清单"**：它看不到文件系统，写的路径可能记错；文档末尾附一栏"请用户核对以下路径/状态是否属实"，由人代跑验证。
4. **结构清晰、关键在前、密度高但不省略**：它上下文有限，把**最关键信息（项目现状 + 接力棒 + 下一步第一步）放最前**；后续细节按需给，但**每条细节本身要写透**，宁可让文档变长，也不准用"等等/后续再议"一笔带过。
5. **给交接摘要放最前**：500 字启动包让它快速进入状态，再按需读全文。
6. **验证方式靠"人代跑"**：它不能自己执行命令，所以每个验证信号要写成"请用户跑 `XXX`，看到 `YYY` 输出即成功"。
7. **步骤最小化**：每步只做一件事，每步结束都问"是否完成"或给一个可观察信号，降低它"一次理解太多"的负担。
8. **接力总览表必须"自包含"**："从哪开始"列不能只写路径——把关键文件内容/代码片段直接贴进对应行；"做到什么算完成"列给"用户帮跑什么命令、看到什么输出"。
9. **不要让它猜**：任何可能产生歧义的地方（路径、函数名、命令、验收口径）都直接写出来，不给它脑补的空间。

### ★ 与给其他 AI 的文档的核心差异

- **vs Codex / Claude Code（L1）**：给 L1 的文档给"精确路径 + 命令"它自己就能读、能跑；给 DeepSeek 的文档**必须把内容本身贴进正文**，验证方式从"你自己跑命令"变成"用户帮你跑命令"。**同一份内容，DeepSeek 版的指令粒度要细得多——几乎每一行都要写到"照着念就能执行"。**
- **模型质量差异**：Codex 能一次吸收"目标+要点"并自行展开；DeepSeek 更容易在长指令或含糊指令上跑偏，所以文档要把歧义消掉、把步骤拆小、把验证信号写死。

## 4. 通用网页版对话 AI（Kimi / 豆包 / 文心一言 / 通义 / ChatGPT 网页版等）— L3 对话型

### 能力画像

| 维度 | 说明 |
|------|------|
| 文件系统 | ❌ 通常读不到本地文件（除非用户手动粘贴文件内容） |
| 命令执行 | ❌ 一般不执行本地命令 |
| 会话记录 | ❌ 无本地会话文件 |
| 上下文窗口 | ⚠️ 因产品而异，普遍有限 |
| 模型质量 | 中偏弱：适合对话式续作，复杂多步任务需更细引导 |
| 擅长 | 内容生成、基于对话记忆的分析与续写 |

### 交接文档定制要点

1. **默认按 L3 对话型处理**：自包含、贴内容、步骤小、验证靠人代跑、证据分级（✅/🔶/❓）。参考 DeepSeek Harness 档案的 9 条，全部适用。
2. **首次交接先给"上下文包"**：因为读不到文件，把项目核心背景 + 关键文件内容压缩成一段"给它读的上下文"，随文档一起给。
3. **让用户参与**：这类 AI 通常需要用户在对话框里贴文档、贴文件内容、代跑命令，所以文档要额外标注"哪些部分需要用户手动粘贴/代跑"。

### ★ 与给其他 AI 的文档的核心差异

- **vs L1（Claude Code/Codex）**：L1 能自己读文件跑命令，文档给"地图+命令"；这类网页 AI 给"地图"也读不到，**必须把地图上的每个关键文件内容直接贴给它**，并明确"请用户代跑以下命令"。

## 5. 通用 AI 智能体（未收录的产品，先按能力层级套用）

### 判定方法

目标产品不在上面清单里时，先回答四个问题判断它属于哪一层：
1. 它能读取本地文件系统吗？→ 能=L1/L2；不能/不确定=L3
2. 它能执行本地命令吗？→ 能=L1；不能/不确定=L3
3. 它的模型强不强、上下文大不大？→ 强=L1 策略可紧凑；弱=L3 策略要保姆级
4. 它会"记岔"吗？→ 会→必须证据分级

### 交接文档定制要点

1. **先定层，再定制**：按判定结果落到 L1 / L2 / L3 的对应策略。
2. **自包含兜底**：拿不准就默认 L3，关键内容直接贴出。
3. **含验证方法**：必须有"如何验证续上了"的信号；不能自跑就让用户代跑。
4. **标注不确定处**：每条 ❓ 让接手方知道哪些需人工确认。
5. **给交接摘要**：开头的启动包适用于所有智能体。
6. **接力总览表自包含**："从哪开始"列贴内容，"做到什么算完成"列给可观察信号。

## 速查对比表

| 智能体 | 层级 | 文件系统 | 跑命令 | 会话可迁移 | 关键定制动作 |
|--------|:----:|:--------:|:------:|:----------:|-------------|
| Claude Code | L1 | ✅ | ✅ | ✅ | 路径+命令、建议写 CLAUDE.md、子代理、可跑验证；**接力表入口=文件:行号/函数/命令**；指令可"目标+要点"式 |
| Codex | L1 | ✅ | ✅ | ✅（sessions） | PowerShell 命令、从哪个函数继续、查 config.toml、代理注意；**接力表入口=PowerShell命令+函数级定位**；指令可"目标+要点"式 |
| DeepSeek Harness | L3 | ❓ | ❓ | ❌ | 自包含**贴内容**、证据分级、附用户核对清单、人代跑验证、步骤最小化；**接力表必须自包含贴内容**；宁可长不可省略 |
| 通用网页 AI | L3 | ❌ | ❌ | ❌ | 按 L3 处理，另加"上下文包"与"哪些部分需用户粘贴/代跑"标注 |
| 通用 AI（未收录） | 先定层 | ❓ | ❓ | ❓ | 按能力层级套用；拿不准默认 L3 自包含 |

## 附：同项目给不同 AI 的文档差异示例（一眼看懂"适配"是什么）

> 以下为同一句交接内容的两种写法，展示 L1 与 L3 的差异：

| 交接点 | 给 Codex（L1）的写法 | 给 DeepSeek Harness（L3）的写法 |
|--------|--------------------|--------------------------------|
| 指出接续位置 | "续写 `backend/app/main.py` 的 `lifespan()`（第 271 行）" | "请打开 `backend/app/main.py` 第 271 行附近，那里有一个 `asyncio.create_task(_run_temp_media_janitor(...))`，你接下来要在它旁边新增一个调度任务。关键代码贴给你：`（贴 271 行前后代码）`" |
| 给出下一步 | "在 `main.py` 新增 `_run_collection_scheduler` 协程并在 `lifespan()` 注册" | "你要做三小步：① 复制下面这段模板代码……② 把里面 `xxx` 改成 `yyy`……③ 在 271 行后面插入 `asyncio.create_task(...)`。做完后请用户运行 `python -c "...检查..."`，看到 `True` 才算完成。" |
| 验证续上 | "跑 `pytest`，全绿即成功" | "请用户在你的机器上运行 `.\\.venv\\Scripts\\python.exe -m pytest -q`，把输出贴给你；看到 `X passed` 就说明环境是好的。" |
