> 本篇面向**同事/人类维护者**，用通俗语言讲清楚"这个项目在做什么、为什么这么做、现在进行到哪、接下来该做什么"。遇到看不懂的术语，翻到第 3 节术语表即可。

## 1. 项目背景

我们手上有一个 Obsidian 笔记库（vault），里面积累了大量的笔记、资料、工作文档。随着笔记越来越多，出现了一个典型问题：**笔记之间是孤岛，找不到、连不起来**。想查一个东西不知道去哪里找，笔记之间的引用关系是断的，新内容不知道往哪里放，放进去之后也没人维护。

为了解决这个问题，我们引入了 **LLM Wiki 方法论**（源自 Karpathy 的《LLM Wiki》思想），把它当成一套"知识库的宪法"来指导整个 vault 的整理。核心理念是：**让 AI 智能体（Claude Code）和人类协作，把笔记库维护成一个可持续生长的 Wiki**——而不是一堆丢在一起的 Markdown 文件。

当前项目已经完成了主体框架的搭建（索引、方法论落地、工作流、双向链接），但还有若干收尾工作没有完成，需要 B（你，以及你手上的 Claude Code）接力。

## 2. 核心方法论：LLM Wiki

LLM Wiki 把知识库划分成三层，各司其职：

| 层级 | 对应目录 | 角色 | 谁在维护 |
|------|---------|------|---------|
| **Wiki 层** | `自动维护知识库/` | 整理后的"正经内容"，像一本维基百科 | Claude（AI 智能体）自动维护 |
| **原始层** | `收件箱/` | 待整理的原生态材料，还没被加工 | 人类随手丢进去 |
| **契约层** | `.claude/` | 规则、配置文件，是知识库的"宪法" | Claude 维护，人类审核 |

三层之间的流动逻辑是：**原始层（收件箱）→ 经过 ingest 加工 → 进入 Wiki 层（自动维护知识库），同时遵守契约层（.claude）的规则。**

这套方法的核心价值：
- **位置明确**：每条内容都有明确的"家"，不会乱放。
- **检索高效**：通过索引（index.md）能快速定位，不用把整个 vault 翻一遍。
- **可自动维护**：Claude Code 按照既定规则例行巡检，人类不用事必躬亲。
- **可追溯**：`log.md` 记录每次维护动作，谁在什么时候做了什么一目了然。

## 3. 术语解释

### 3.1 LLM Wiki
- **全称**：LLM Wiki（Large Language Model Wiki）。
- **是什么**：一种知识库管理方法论，源于 Karpathy《LLM Wiki》一文。核心思想是让 AI（LLM）作为知识库的"园丁"，负责内容的整理、索引、关联和维护，人类负责提供原始素材和把关方向。
- **在本项目里**：体现为三层结构（Wiki 层 / 原始层 / 契约层）+ 三大工作流（ingest / query / lint）+ 索引与日志机制。
- **参考文档**：`自动维护知识库/LLM Wiki.md`，`.claude/LLM-WIKI-SCHEMA.md`。

### 3.2 ingest / query / lint 工作流
这是 LLM Wiki 方法论下的三条例行工作流，分别对应"入库、检索、体检"：

- **ingest（入库/吸收）**：把 `收件箱/` 里的原始材料，加工整理成规范条目，放进 `自动维护知识库/`。好比把散落的原料做成熟菜端上餐桌。
- **query（检索/查询）**：按需从 Wiki 层定位并读取内容。走"索引 → 定位 → 读取"的窄路径，避免把整个库扫一遍浪费资源。好比查图书馆先查目录卡，而不是逐本翻书。
- **lint（体检/检查）**：例行检查知识库的健康状况：链接是否断裂、frontmatter 是否完整、索引是否过期、是否有冗余文件等。好比定期体检，小毛病早发现早处理。

### 3.3 双向链接（Bidirectional Link）
- **是什么**：笔记 A 引用笔记 B 时，系统自动在 B 上也能看到"被 A 引用"的关联。与单向链接不同，双向链接是**可逆**的关联。
- **在本项目里**：Obsidian 原生支持 `[[双链]]` 语法。我们要求整理后的笔记之间用双链互相引用，并配合 `index.md` 索引页，让整个知识库形成一张互联的网，而不是孤立文件。
- **为什么重要**：双链是知识库"活"起来的关键——一条笔记不再是孤岛，顺着链接能漫游到所有相关主题。

### 3.4 frontmatter
- **是什么**：Markdown 文件最顶部的 YAML 元数据块，用 `---` 包裹。存放这篇笔记的"身份证信息"。
- **示例**：
  ```yaml
  ---
  title: 某主题
  tags: [工作, 方法]
  created: 2026-08-17
  updated: 2026-08-17
  status: active
  ---
  ```
- **在本项目里**：每条 Wiki 层笔记都应该有 frontmatter，至少要包含 `title` 和 `tags`，方便检索、分类和 lint 校验。

### 3.5 Wiki 层 / 原始层 / 契约层
- **Wiki 层**（`自动维护知识库/`）：整理完成、可以长期引用的"成品内容"。
- **原始层**（`收件箱/`）：还没加工的原材料，允许乱、允许多。
- **契约层**（`.claude/`）：规则文件（CLAUDE.md、LLM-WIKI-SCHEMA.md 等），约束整个库怎么运行。

6. **frontmatter 纪律**：Wiki 层每个页面顶部必须带 YAML frontmatter（至少含 `title`、`tags`）。
