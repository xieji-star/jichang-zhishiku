## 4. 术语表

- **知识库（Vault）** ＝ 整个 Obsidian 笔记库文件夹，本交接文档的"根目录"。
- **LLM Wiki** ＝ 一种"让 AI 把笔记库当作 wiki 来维护"的方法论（Karpathy 提出）。核心是三层：原始材料 → AI 整理的 wiki → 规则契约。
- **三层架构**：
  - **契约层（Schema）**＝ 规则文件，即 `.claude/` 文件夹里的 `CLAUDE.md` 和 `LLM-WIKI-SCHEMA.md`——告诉 AI"怎么干活"。
  - **Wiki 层**＝ `自动维护知识库/` 文件夹，AI 维护的结构化页面。
  - **原始层（Raw）**＝ 还没整理的原始笔记，规则里指 `收件箱/`。
- **ingest / query / lint** ＝ LLM Wiki 的三种工作流：
  - **ingest（摄入）**＝ 新笔记进来 → AI 读、提炼、写成 wiki 页面；
  - **query（查询）**＝ 用户提问 → AI 先查索引再读页面回答，好答案回存 wiki；
  - **lint（体检）**＝ 定期检查 wiki 是否有矛盾、过时、孤立页面等问题并修复。
- **Hook（钩子）** ＝ Claude Code 的一种自动触发机制：满足条件时自动运行一段脚本。本知识库用 Hook 实现"每天检查是否该整理/备份"。
- **Skill（技能）** ＝ 给 AI 预装的一套"说明书 + 工作流"，放在 `.claude/skills/` 下。AI 遇到对应场景就自动按说明书干活。
- **CLAUDE.md** ＝ Claude Code 的规则文件（AI 启动时自动读取）。Codex 的对应文件叫 `AGENTS.md`。
- **标记文件（marker）** ＝ 根目录下的隐藏小文件（`.last-wiki-maintain`、`.last-github-backup`），记录"上次维护/备份的日期"，Hook 靠它判断是否到期。
- **双向链接（[[...]]）** ＝ Obsidian 的笔记互链语法，`[[页面名]]` 表示指向另一篇笔记。
- **wiki 页面** ＝ `自动维护知识库/wiki/` 下的 `.md` 文件，每个文件讲一个主题。
- **index.md / log.md** ＝ wiki 的"目录"和"时间线日志"：`index.md` 列全部页面，`log.md` 记录每次操作。
- **飞书智能助手 / 企业微信智能助手** ＝ 两个独立的小服务（Python 程序），让用户在飞书/企业微信聊天里给知识库发消息、发文件，由 AI 自动处理。
- **MCP** ＝ 给 AI 接外部工具的一种标准接口（本库配置见 `.claude/mcp.json`）。
- **脱敏（Redact）** ＝ 把密钥、密码等敏感值打码，只保留"放在哪里"，不写明文。

## 9. 关键决策与踩坑记录

### 关键决策

1. **选用 LLM Wiki 方法论**：因为笔记量大且持续增长，需要一个"AI 能自己维护"的结构。替代方案是普通文件夹分类（AI 无法自治）或 RAG 向量库（过度设计），最终选择轻量、纯 Markdown 的 LLM Wiki。
2. **三层架构分离**：原始层（只读）、wiki 层（AI 可写）、契约层（规则）分开，避免 AI 误改原始笔记。
3. **Hook 驱动自动维护**：用 Claude Code 的 UserPromptSubmit Hook 在"每天第一条消息"时检查是否到期，比定时任务（cron）更适合——不需要常驻进程，零成本。
4. **GitHub 存快照而非版本管理**：每次备份新建一个日期文件夹（`积昌的知识库<MMDD>`），保留 10 份，简单直观，对非程序员友好。
5. **双套 skill（`.claude` 中文 + `.agents` 英文）**：同一套技能为 Claude Code（中文名）和 Codex（英文名）各存一份，保证两个智能体都能用。

### 踩过的坑（最值钱的部分）

1. **restart.bat 杀所有 python 进程**：`taskkill /f /im python.exe` 会把整个电脑的 python 全杀掉，包括正在运行的 Claude Code 自己。**教训：手动启动服务用 `python server.py`，不要跑 restart.bat。** 这条已写进规则文件。
2. **Hook 脚本必须幂等、静默**：早期 Hook 可能每天重复提示，导致刷屏。后来加了 `.last-maintenance-prompt` 标记文件，当天提示过就静默退出。
3. **路径硬编码导致失效**：规则和配置里写死盘符，一旦复制到新盘（E: → F:）就全部对不上。**教训：重要路径应相对化，或复制后必须全局搜索盘符并更新。**
4. **wiki 与 index 统计容易脱节**：新增/删除页面后若忘记更新 index.md，统计会错（曾出现"44 页 vs 实际 50 页"）。**教训：每次 ingest/lint 必须同步维护 index.md 和 log.md。**
5. **skill 双副本同步成本**：`.claude/skills` 和 `.agents/skills` 两处内容需保持一致，新增 skill 时常忘了同步另一侧。**教训：更新 skill 后检查 `AGENTS.md` 的映射表。**
6. **空源文件被摄入**：个别原始笔记是空文件，曾被建了无内容的 wiki 页。**教训：ingest 前先确认源文件非空。**

### 试错过但放弃的方案

- **定时任务（cron/scheduler）做自动维护**：需要常驻进程、依赖系统配置，换机器会断，放弃，改用 Hook。
- **向量库 / RAG 做检索**：对几百页的规模过度设计，纯 index.md 目录检索已够快，放弃。
