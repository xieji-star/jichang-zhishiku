# 交接助手（Handover Assistant）

## 这个 skill 解决什么问题

项目做到一半，要换人、换智能体、换设备继续干。最大痛点是：**接手方不了解来龙去脉，光靠口头或零散文件难以快速进入状态**。本 skill 帮你把"项目当前状态"一次性、结构化地交代清楚，让接手方读一份文档就能无缝开工。

### 为什么"给人"和"给 AI"的文档必须分开，且详细度要反过来

- **人**：理解力不如 AI，但能用直觉和上下文。人需要的是**完整背景故事、术语解释、手把手步骤、为什么这么选**——所以给人版必须**比给 AI 版更详细**，要写到"一个没参与过项目的人也能看懂、能照做"的程度。
- **AI 智能体**：理解力强、能跑命令、能读文件，但**每个产品能力不同、模型质量不同**——Claude Code / Codex 能读文件系统+跑命令+自主多步推理；DeepSeek Harness / 通用网页 AI 主要靠对话记忆、读不到文件、上下文有限、容易"记岔"。所以给 AI 版**绝不是通用模板**，必须**按目标智能体的能力层级 + 模型质量量身定制**，它才接得住。

一句话：**给人看"手把手教材"，给 AI 看"专属地图"——而且每个 AI 的地图都不一样。**

### ★ 交接文档必须回答的四个问题（四要素 · 硬性要求）

**一份完整的交接文档，必须把下面四个问题全部回答清楚，缺一不可。** 这是"交接"的定义，不是可选项。

| # | 四要素 | 通俗含义 | 必须写到的详细度 |
|---|--------|---------|-----------------|
| ① | **当前已经做了什么** | A 已完成的工作全量清单 | 每条含：做了什么 / 产出物在哪 / 怎么验证有效 / 关键数据 |
| ② | **还有什么没做的** | A 未完成的工作全量清单（= 接力棒） | 每条含：还差什么 / 为什么没做完(阻塞) / 前置条件 / 优先级 / 做到什么算完成 |
| ③ | **接下来要接着做什么** | B 要接的每件事（= 接力任务，与②一一对应） | 每条含：接哪个遗留项 / 从哪开始 / 做到什么算完成 |
| ④ | **接下来该怎么做** | B 照着做的具体步骤 | 展开成 1-N 步，每步可照做、有验证信号、卡住找谁 |

> ⚠️ **最常见的失败模式就是 ③④ 一笔带过**（如"还有几件事没做完，下次继续""你接手后把剩下的做一下"）。**四要素里 ①② 回答"过去"，③④ 回答"未来"——只有 ③④ 写透，接手方才能不问人直接开工。** 判优标准：**拿到文档的人/智能体，能不能不问任何人、不查任何东西，就照着 ③④ 动手干第一步？** 能 → 合格；不能 → ③④ 没写透，继续补。

### 核心：把"接力棒"交代清楚（A→B 接力）

交接的本质是 **A→B 接力**。A 做到一半停下，把交接文档递给 B，B 要在 A 的工作基础上继续干。所以四要素中 ②③ 必须**成对出现、一一对应**：

1. **A 没做完的（接力棒，= 四要素②）**——A 把项目做到哪一步、哪些事没做完、为什么没做完（阻塞原因）、做到什么程度算完成。这是要交给 B 的"棒"。
2. **B 接下来要做的（接力任务，= 四要素③④）**——B 要在 A 的基础上继续完成什么、从哪开始（哪个文件/哪一行/哪条命令/找谁）、做到什么算完成（怎么验证）、具体怎么做。这是 B 的"开工清单"。

> ❌ **反面例子（最常见的交接文档毛病）**：只列"未完成清单"（A 视角，只管交棒）却不告诉 B 该干什么；或只给"下一步计划"（B 视角）却不说明它接的是 A 的哪件遗留活。这两种都会让接手方"看懂了，但不知道从哪下手"。
> ✅ **正确做法**：用一张 **A→B 接力总览表**把"A 没做完的"和"B 要做的"钉在一起——每个遗留事项对应一个接力任务、一个开工入口、一个完成信号。让 B 读到文档那一刻就能照着 #1 直接开工。

## 第一步：判断交接对象与模式

开工第一件事，判断这次交接文档是给谁看的。拿不准就问用户（"怎么做"问题）：

| 模式 | 适用场景 | 文档特点 |
|------|---------|---------|
| **A 给人看** | 交给同事、领导、未来的自己、实习生、mentor | **最详细**：手把手、讲来龙去脉、解释一切术语 |
| **B 给 AI 看** | 交给下一个 Claude/Codex/DeepSeek 等智能体续作 | **按目标智能体能力层级定制**：精确路径/命令/自包含内容 + 该智能体能接住的格式 |
| **C 两者都要** | 既给人交代，又要让 AI 无缝接手 | 先输出 A（人读总览），再输出 B（AI 专属版）作为附录 |
| **D 生成交接提示词** | **让另一个智能体基于它的聊天记录自己写交接文档**（如"让 Codex 写一份交接给人""给当前智能体一份提示词让它总结"） | 产出**可直接复制粘贴给目标智能体的提示词**（prompt），提示词自包含全部规则，按目标智能体能力层级定制 |
| **E 对话全面总结** | **先把这整轮对话从最初到当前工作结束做全面总结**（想复盘全过程 / 为写交接文档准备素材 / 对话太长怕交接漏细节） | 产出**时间线式结构化对话总结**：对话总览、目标与完成度、分阶段时间线、已完成/未完成全量（4/7字段）、关键决策与踩坑、文件/命令/数据清单、遗留❓、下一步建议；作为交接文档素材底稿 |

- 用户没说给谁 → **默认 C**（先人后 AI）。
- 用户只说"让下一个智能体接上" → 只做 **B**，且要**确认是哪个智能体**。
- 用户只说"给同事/领导交代一下" → 只做 **A**。
- 用户说"给我一份提示词，让 XX（智能体）来写交接文档""让当前智能体基于聊天记录总结交接文档" → 只做 **D**（不是直接写文档，而是给提示词）。

## 第二步：识别目标智能体并判断能力层级（模式 B 专属，关键）

**做给 AI 的交接文档前，必须先确认目标智能体是谁，再判断它属于哪个能力层级，然后读它的习性档案定制文档。** 这决定了文档的格式、详略、内容侧重。

1. 用户指定了智能体（如"转到 Codex""给 Claude Code"）→ 用那个。
2. 用户没说 → 问一句"交接给哪个智能体？"（这是"怎么做"问题）。
3. 确认后，按以下顺序执行：
   - **先定位能力层级**：对照 `references/agent-profiles.md` 的「AI 能力分层总览」——L1 自治型（Claude Code/Codex/Cursor/Windsurf/Gemini CLI）、L2 半自治型、L3 对话型（DeepSeek Harness/Kimi/豆包/文心/通义/ChatGPT 网页版）。
   - **再读对应档案**：按该档案的"交接文档定制要点" + "与给其他 AI 的文档的核心差异"生成。
   - **档案里没收录的智能体**：用「通用 AI 智能体」规则，先按四个问题（能不能读文件/能不能跑命令/模型强不强/会不会记岔）判定层级再定制。

> 💡 为什么必须按层级定制：**给 Codex（L1）的文档给精确路径 + PowerShell 命令 + 函数级定位，它自己会读文件补细节；给 DeepSeek Harness（L3）的文档必须把关键代码/配置/命令直接贴进正文，每步写到"照着念就能做"，验证方式改成"请用户代跑命令"。用错格式，智能体接不住。** 同一份内容，给 L1 可以"目标+要点"式，给 L3 必须"一步步+每个中间信号"。

> ⚠️ **禁止复制粘贴**：绝不允许把给 AI-A 的文档改个标题就当作给 AI-B 的文档。每份给 AI 的文档都必须从零按目标 AI 的能力层级与习性重新生成。

## 第三步：收集信息

根据模式决定收集深度：

1. **当前会话上下文**：本轮对话里的目标、进度、决策、踩坑。
2. **工作目录**：用 Glob/Grep 定位项目相关文件，确认真实路径与状态。
3. **知识库相关笔记**：按"文档查询顺序规则"——先查 `自动维护知识库/index.md` 定位，再深度读对应笔记。
4. **用户补充**：信息不足就问；给人版尤其要多问背景（人需要更多上下文）；做给 AI 版要多问"这个 AI 有什么特殊性/上一步是在哪个环境做的"。

> ⚠️ **实证纪律：每条路径、命令、结论必须真实。** 能核实的一定核实；核实不了标注"❓需人工确认"，绝不编造。

## 第四步：生成文档

按模式套用对应结构。**核心原则：宁可多写，不可遗漏；同类列表全量列出；对象越"弱"文档越保姆级（人 > L3 对话型AI > L1 自治型AI）。** 所有模式都必须贯彻 **四要素完整交接**：①已做了什么、②还没做什么、③接下来做什么、④怎么做——四项全量写透，②③ 落到一张"接力总览表"里成对呈现、一一对应，让接手方读完直接开工。

### ★ 详细度标准（所有模式通用，宁可多写不可少写）

**核心原则：宁可多，不可简略；拿不准要不要写，就写；能写数字就写数字。** 下面给出每个条目的"最低必须写满"的字段，少一个都算不合格，需补写。

**① 已完成项 —— 每条至少写满 4 个字段：**

| 字段 | 要求 |
|------|------|
| 做了什么 | 一句话说清这件事的成果 |
| 产出物在哪 | 真实相对路径 + 一句话用途 |
| 怎么验证有效 | 可观察/可复现的验证方法（命令输出/文件内容/运行结果） |
| 关键数据/效果 | 能写数字就写数字（条数、时长、通过率、性能数据等） |

**② 未完成项 / 接力棒 —— 每条至少写满 7 个字段：**

| 字段 | 要求 |
|------|------|
| 还差什么 | 具体到"差哪一块、缺哪个功能/数据/步骤" |
| 为什么没做完 | 阻塞原因（时间不够/技术难题/等依赖/等决策） |
| 前置条件 | 做这件事之前必须满足什么 |
| 优先级 | 紧急 / 重要 / 一般 |
| 做到什么算完成 | 可验收的定义（可检验，不只说"做完"） |
| 从哪开始 | 入口（文件:行号 / 函数名 / 命令 / 找谁） |
| 验证信号 | 看到什么现象算真正完成/接上 |

**③④ 下一步项 / 接力任务 —— 每条至少写满 5 个字段：**

| 字段 | 要求 |
|------|------|
| 接哪个遗留项 | 对应②的哪条（编号一致，成对出现） |
| 具体步骤 | 展开成 1-N 步，每步可照做（不写"做一下"这种空话） |
| 从哪开始 | 第一个动作（打开哪个文件 / 跑哪条命令 / 找谁） |
| 做到什么算完成 | 可观察的完成信号 |
| 卡住了找谁/看哪 | 求助路径（文档/人/工具） |

> ⚠️ **禁止出现的"一笔带过"话术**：❌"还有几件事没做完，下次继续" ❌"你接手后把剩下的做一下" ❌"详见之前的记录" ❌"等等/后续再说"。→ 全部必须展开成上面的表格，逐条写满。

### 模式 A：给人看的交接文档（手把手详细版）

> 目标读者是"人"：一个没参与过项目的人，读完能**看懂项目、知道做到哪、能照着下一步做**。**这是三种模式里最详细的一种**——人不如 AI，每一个术语、每一步都要解释到位。**篇幅自检：给人版应当比给 AI 版更长、更啰嗦；如果给人版更短，说明写漏了，必须补。**

```markdown
# <项目名> 交接文档（给人版）

> 一句话定位：<用大白话讲这项目是干嘛的>
> 阅读指引：<这份文档怎么读，先看哪节、重点看哪节>

## 1. 这份文档是给谁看的
- 写这份文档的背景（谁交接给谁、为什么交接）
- 读者读完应该能达到什么效果（能独立接手哪些事）

## 2. 项目总览（大白话）
- 这个项目是做什么的、为谁做、解决什么问题
- 一句话讲清项目价值（为什么要做它）
- 整体完成度估算（如"约 70%"）＋判断依据

## 3. 背景与来龙去脉
- 项目怎么来的、为什么做（业务背景、组织背景、触发原因）
- 关键约束、用户偏好、前置信息
- 和公司/团队其他事情的关系

## 4. 术语表
- 把项目里出现的专业词、缩写、黑话、内部代号逐条解释
- 格式：`术语（英文/缩写）＝ 一句话大白话解释`
- 哪怕你觉得"这很基础"，也写——读者可能不懂

## 5. 当前进度（用"人话"讲）
- 整体做到哪一步了、处于什么阶段
- 最后一次停在什么位置（以非技术读者能懂的方式描述）

## 6. 已完成工作（全量逐条，每条按详细度标准①写满 4 字段）
- 按时间/模块分组逐条列出：做了什么、成果在哪、怎么验证它确实有效
- 每条附：产出物位置（用相对路径＋一句话用途）、关键数据/效果数字

## 7. A 没做完的事（需要你接力的，全量逐条，每条按详细度标准②写满 7 字段）
- 逐条：还差什么、为什么没做完（阻塞原因）、前置条件、优先级（紧急/重要/一般）
- 明确"做到什么程度算完成"（可验收的描述）
- 开头点明：**这些是前任（A）留下的"接力棒"，是你的起点，不是你的过错**

## 8. A→B 接力总览（读到就能开工，核心）
- 把第 7 节的"没做完的事"和第 9 节的"你接下来要做的"用一张表**钉在一起**，每条一行：

| # | A 没做完的（接力棒） | 你（B）接下来要做什么 | 从哪开始（文件/工具/找谁） | 做到什么算完成（怎么验证） |
|---|--------------------|----------------------|---------------------------|---------------------------|
| 1 | <遗留事项1> | <你要做的第1件事> | <路径/工具/联系人> | <可观察的完成信号> |
| 2 | ... | ... | ... | ... |

- 表末给一句"**接力开工第一步**"：具体动作 → 出现什么现象算正式接上了
- 这张表就是接手者的"开工地图"：照着 #1 做即可

## 9. 下一步怎么做（手把手，按详细度标准③④）
- 承接第 8 节接力总览，把"你接下来要做的"展开成 1-N 步，每步写成**普通人能照做**的指令：
  - 第一步做什么 → 打开哪个文件/找谁/用哪个工具
  - 看到什么结果算这一步做对了
  - 卡住了该看哪个文档/问谁
- 区分"立即做"与"之后做"

## 10. 关键决策与踩坑记录
- 做过的选型、为什么这么选（用大白话讲理由）
- 踩过的坑：现象、根因、怎么避开（这是给后人最值钱的部分）
- 试错过但放弃的方案及原因

## 11. 风险与求助点
- 不确定处、需要人工确认的点，逐条标"❓"
- 可能翻车、有隐患的地方
- **遇到问题找谁**：责任人、关联文档、常用工具位置

## 12. 常用资源清单
- 关键文件/产出物位置（相对路径＋一句话用途）
- 账号、密钥、工具的存放位置（密钥脱敏）
- 相关文档/链接清单
```

### 模式 B：给 AI 看的交接文档（按目标智能体能力层级定制）

> 目标读者是"AI 智能体"：零废话、可执行、路径命令精确、**按能力层级自包含**。**先生成下面的通用骨架，再按第二步选定的能力层级 + 智能体习性档案（`references/agent-profiles.md`）追加定制要求**——把定制要求穿插进对应小节，或作为末尾"按 <智能体> 定制"附加节。**L1 版可以紧凑但信息完整；L3 版必须自包含贴内容、步骤最小化、验证靠人代跑、证据分级。同一份内容，L3 版必须比 L1 版更"保姆级"。**

```markdown
# <项目名> 交接文档（给 <智能体名> 版）

## 0. 交接摘要（启动包）
- 项目做什么、当前做到哪一步
- 最关键三件事：已完成什么、**A 没做完的（接力棒）**、B 下一步第一件事
- 一句话提示从哪继续最省力

## 1. 项目总览与验收标准
- 一句话定位、最终目标
- 验收标准：做到什么程度算完成（可检验）

## 2. 文件地图（精确路径，按能力层级调整自包含程度）
- 逐个列出文件/文件夹：真实路径、作用、当前状态（新建/修改/已完成/未动/临时）
- 入口文件、配置文件、产出物的准确位置
- **L1 版**：给路径+作用即可（它能自己读）；**L3 版**：把关键文件内容直接贴出或贴出要点

## 3. 已完成工作（全量逐条，每条按详细度标准①写满 4 字段）
- 逐条：做了什么、产出物路径、如何验证有效
- 含关键代码位置/函数名（便于接着改）

## 4. 当前精确进度
- 最后一步有效操作是什么（在哪行代码/哪个文件）
- 当前代码/文档/数据处于什么具体状态

## 5. A 没做完的事（接力棒，全量逐条，每条按详细度标准②写满 7 字段）
- 逐条：还差什么、为什么没做完（阻塞原因）、前置条件、优先级
- 明确"做到什么程度算完成"
- 点明：**每个未完成项就是 B 要接的活**，是 A 留给 B 的接力棒

## 6. A→B 接力总览（读到就能开工，核心）
- 把第 5 节的"接力棒"和第 7 节的"行动计划"用一张表**钉在一起**，每条一行：

| # | A 没做完的（接力棒） | B 要做什么 | 从哪开始（文件/函数/行号/命令/贴内容） | 做到什么算完成（验证信号） |
|---|--------------------|-----------|-------------------------------|---------------------------|
| 1 | <遗留事项1> | <B 要做的第1件事> | <入口文件:行号 / 函数名 / 命令 / 贴出关键内容> | <可观察的信号：日志行/命令输出/接口返回> |
| 2 | ... | ... | ... | ... |

- 表末给"**接力开工第一步**"：跑哪条命令 → 出现什么日志/输出算正式接上
- **这张表就是 AI 的开工清单**：直接按 #1 的"从哪开始"执行，无需再问人
- **L3 版注意**："从哪开始"列不能只写路径——把关键文件内容/代码片段直接贴进对应行

## 7. 下一步行动计划（命令级，按详细度标准③④）
- 承接第 6 节接力总览，把"B 要做什么"展开成 1-N 步：打开哪个文件、跑哪条命令、改哪段逻辑、预期产出
- 命令用目标智能体能执行的风格（Windows 用 PowerShell，参考档案）
- **L1 版**：可"目标+要点"式，给精确入口即可；**L3 版**：每步只做一件事、每步给"人代跑"的验证信号、证据分级（✅确定/🔶推断/❓待确认）
- 区分"立即做/之后做"

## 8. 环境与配置依赖（完整清单）
- 模型/工具/软件及版本、端口、环境变量、依赖库
- 密钥/token：只写存放位置，值脱敏为 <已脱敏>
- **L3 版**：关键配置项直接贴出值（脱敏），不要只写"在 .env 里"

## 9. 数据与状态快照
- 涉及的数据/文件/接口当前状态
- 临时数据、测试数据是否需要清理
- 需保留的中间产物

## 10. 关键决策与踩坑记录
- 技术选型及原因、踩坑根因与规避方案、放弃的方案及原因

## 11. 风险与待确认项
- 逐条标"❓"：不确定处、需人工确认的点

## 12. 续作启动手册
- 从零恢复完整步骤：先读哪个文件、跑哪条命令、启动哪个服务
- **如何验证"续上了"**：看到什么具体现象（日志行/命令输出/接口返回）算成功
- **L3 版**：验证步骤写成"请用户代跑 XXX，看到 YYY 输出"，并附"给用户的核对清单"
- 与第 6 节接力总览的关系：第 6 节是"开工清单"（接 A 的活），本节是"环境还原"（把 A 的环境跑起来）

## 13. 按 <智能体名> 定制的附加内容
- 依第二步的习性档案，追加该智能体特有的要求（见 references/agent-profiles.md）
- 如 Codex 版在接力总览的"从哪开始"列直接用 PowerShell 命令与函数级定位；DeepSeek 版需把关键文件内容直接贴进接力总览，并附"给用户的核对清单"；Claude Code 版给路径+命令让它自己跑，并可建议写 CLAUDE.md
```

### 模式 C：两者都要

- **先输出模式 A（给人版）**，作为整体说明——这是最详细的一份；
- **再输出模式 B（给 AI 版）**，作为附录，并在开头注明目标智能体名；
- 两版之间加一行说明，提醒"给 AI 版可直接复制给 <智能体名>"；
- 两版**都要包含各自的"A→B 接力总览"**（人版用大白话、AI 版用命令级入口），接力内容一致但表述按对象调整；
- **详细度硬性要求**：给人版 ≥ 给 AI 版详细度。人版含术语表、背景、手把手、为什么这么选、求助点；AI 版含精确路径/命令/验证信号。两者四要素都写满，但人版更啰嗦、更通俗。

### 模式 D：生成交接提示词（让另一个智能体基于聊天记录自己写交接文档）

> 目标读者是"用户自己"。用户不是要一份交接文档，而是要**一份提示词（prompt）**，复制粘贴给某个智能体，让那个智能体**基于它与用户的聊天记录**自己总结出交接文档。典型场景："让 Codex 写一份交接给人""让当前智能体基于聊天记录总结交接文档"。
>
> ⚠️ **提示词必须自包含**：目标智能体读不到本 skill、读不到 `agent-profiles.md`——所以四要素、详细度标准、A→B 接力、交接对象结构等**所有规则都必须原样写进提示词文本里**，一个都不能靠"它应该知道"。

**何时用（触发词）**：
- "给我一份提示词，让 Codex 写一份交接给人"
- "让当前智能体基于聊天记录总结交接文档"
- "让 DeepSeek 写交接给 Claude Code"
- "给我一段 prompt，让 XX 自己总结交接"

**开工前确认两件事**（"怎么做"问题，不是权限问题）：
1. **目标智能体是谁**——写文档的那个智能体（用户正在跟谁对话 / 要把提示词发给谁）。用户说"当前智能体"时，问清楚"你当前在跟哪个智能体对话？"（可能是 Codex、Claude Code、DeepSeek、Kimi……）
2. **交接对象是谁**——文档给谁看：人 / 哪个 AI / 两者。

**生成提示词的步骤**：
1. 确认目标智能体**厂家**（Claude Code / Codex / DeepSeek Harness / 通用网页AI / 未收录产品），读 `references/agent-profiles.md` 对应档案。
2. **直接套用该厂家的「★ 完整专属范本」**——每个已收录厂家都有一份整体定制的提示词全文（角色定位、信息收集方式、能力定制、附加提醒都不同）。未收录厂家先定层，再套用对应层级厂家的范本并替换智能体名。**禁止拿下面的通用骨架改个标题就当作给某厂家的提示词。**
3. 产出物 = **一段可直接复制粘贴的提示词文本**，放进 Markdown 代码块（方便一键复制）。

**提示词通用骨架（完整版 · 十小节：零 / 〇·五 / 一 ~ 八）**：⚠️ **本骨架只作"兜底模板 / 结构参考"——已收录厂家（Claude Code / Codex / DeepSeek Harness / 通用网页AI）一律直接套用 `references/agent-profiles.md` 里该厂家的「★ 完整专属范本」，禁止拿本骨架改标题敷衍。** 只有当目标厂家未收录、且你想从零自拟时才用本骨架：把 <占位> 替换掉，并追加下方"按交接对象插入"与"各厂家专属范本速查"两段。**生成时必须保留全部九个小节，只允许替换 <占位> 与插入定制内容，禁止删减任何一节。** 长度自检：完整版骨架全文通常 **150 行以上**；若产出的提示词明显更短，说明漏了小节，必须对照骨架补全——宁可多，不可漏。

```markdown
你正在结束一段工作，现在要把当前工作交接给<交接对象>。
请基于我们这段对话的聊天记录<（以及你实际能访问的本地文件/运行环境）>，写一份《<项目名> 交接文档（<给人版 / 给 <智能体名> 版>）》。

<接手方>对项目几乎零了解。你的写稿目标：让<接手方>读完这份文档后，**不靠问任何人、不查任何额外资料**，就能——①看懂这项目在做什么、做到哪了；②知道哪些做完了、哪些没做完、为什么没做完；③能照着文档直接动手干第一步；④每一步做完都能自己判断"做得对不对"。

═══════════════════════════════════════
【零、先明确三件事（动笔前必读）】
═══════════════════════════════════════
1. **你的身份**：你现在是"交接文档撰写人"，不是普通聊天助手，也不是项目的新开发员。你的唯一产出就是这份交接文档。
2. **文档读者**：<接手方——如：一位完全没参与过项目的实习生（人）/ 下一个续作智能体 Codex（AI）>。写的时候始终站在读者角度问自己："这段他能看懂吗？这步他能照做吗？"
3. **你的信息边界**：你的素材 = 这段对话的聊天记录 <+ 你能访问的文件/环境>。聊天记录里没有的，要么问我（用户）追问，要么读文件核实；都做不到的，标注"❓待确认"，**绝不编造**。

═══════════════════════════════════════
【〇·五、动笔前先做「总任务目标 + 当前任务进度」双总结（硬性锚点，写在交接摘要之后）】
═══════════════════════════════════════
动笔写正文前，先输出两块"精确总结"，放在文档开头（交接摘要之后），作为整份文档的锚点；后文所有小节都要能挂回这两块：

**A. 总任务目标总结**（3-5 句话精确概括整个任务的最终目标）：
- 做什么：任务/项目的一句话定义。
- 为谁做：服务对象 / 使用场景。
- 做到什么算成功：验收标准 / 成功定义（可检验，能写数字就写数字）。
- 终极交付物：产出一份什么（交付物清单，含路径）。

**B. 当前任务进度总结**（用"百分比 + 阶段 + 差距"精确给出，对照 A 写）：
- 整体完成度百分比（如"约 70%"），并给出判断依据（哪些证据支撑该百分比）。
- 当前所处阶段 / 里程碑：已走完哪些、正在哪一步、还剩哪些。
- 已完成 / 进行中 / 未开始 三档全量清单。
- 与总目标的差距：还差哪几块才算达到 A 的验收标准。
- 当前阻塞点（如有，逐条列出）。

要求：
- A 对应正文"项目总览与验收"小节，B 对应正文"当前精确进度"小节；0 交接摘要中也各用一两句话点出 A、B 核心。
- "未完成接力棒"每一条都要标注"它服务于总目标的哪一部分 / 补完它之后总进度推进到多少"。
- A 或 B 的任何一项若无法从聊天记录或文件核实，标"❓待确认"，绝不编造。

═══════════════════════════════════════
【一、必须回答的四个问题（四要素）——缺一不可，尤其 ③④ 不许一笔带过】
═══════════════════════════════════════
一份合格的交接文档，必须把下面四个问题全部回答清楚。①② 讲"过去"，③④ 讲"未来"——只有 ③④ 写透，接手方才能不靠问人直接开工。

① **当前已经做了什么**（= 已完成工作全量清单）
- 把已完成的工作**全量、逐条**列出（按模块或时间分组），不要只挑重要的写。
- 每条写满 4 个字段：
  - 做了什么：一句话说清成果。
  - 产出物在哪：真实相对路径 ＋ 一句话用途。
  - 怎么验证有效：可复现的验证方法（跑哪条命令看到什么输出 / 打开哪个文件看到什么内容 / 运行结果如何）。
  - 关键数据/效果：能写数字就写数字（条数、时长、通过率、性能指标等）。

② **还有什么没做的**（= 未完成工作全量清单，是留给接手方的"接力棒"）
- 把没做完的事**全量、逐条**列出，不要因为"不想暴露没做完"而漏掉。
- 每条写满 7 个字段：
  - 还差什么：具体到差哪一块、缺哪个功能/数据/步骤。
  - 为什么没做完：阻塞原因（时间不够 / 技术难题 / 等依赖 / 等决策 / 等授权）。
  - 前置条件：做这件事之前必须满足什么。
  - 优先级：紧急 / 重要 / 一般。
  - 做到什么算完成：可验收的定义（可检验，不说"做完"这种空话）。
  - 从哪开始：入口（文件:行号 / 函数名 / 命令 / 找谁）。
  - 验证信号：看到什么现象算真正完成/接上了。

③ **接下来要接着做什么**（= 接力任务，与②一一对应）
- 每个接力任务与②里的某一条**一一对应、编号一致**。
- 每条写清：接哪个遗留项 / 从哪开始 / 做到什么算完成。

④ **接下来该怎么做**（= 具体步骤，把③展开成 1-N 步）
- 把每个接力任务展开成普通人/AI 能照做的 1-N 步。
- 每步写清：做什么 → 打开哪个文件/跑哪条命令/找谁 → 看到什么结果算做对了 → 卡住了看哪个文档/问谁。
- 区分"立即做"与"之后做"。

> ⚠️ **判优标准**：接手方能不能**不问任何人、不查任何东西**，就照着 ③④ 动手干第一步？能 → 合格；不能 → ③④ 没写透，继续补。
> 🚫 **禁止出现这些"一笔带过"**：❌"还有几件事没做完，下次继续" ❌"你接手后把剩下的做一下" ❌"详见之前的记录" ❌"等等/后续再说" ❌"这块比较复杂你自己看" ❌"剩下你应该都会"。出现任何一句，都必须展开成上面带字段的条目。

═══════════════════════════════════════
【二、必须有一张「A→B 接力总览表」】
═══════════════════════════════════════
把②（A 没做完的接力棒）和③④（B 接下来要做的）用一张表**钉在一起**、一一对应，让接手方读到就能照着 #1 开工：

| # | A 没做完的（接力棒） | 接手方要做什么 | 从哪开始（文件/工具/找谁） | 做到什么算完成（怎么验证） |
|---|--------------------|---------------|--------------------------|---------------------------|
| 1 | <遗留事项1> | <要做的事1> | <入口：文件/函数/行号/命令/联系人> | <可观察的完成信号> |
| 2 | ... | ... | ... | ... |

要求：
- 每个遗留事项占一行，**编号与②③一致**。
- "从哪开始"列必须具体到能直接下手（文件:行号 / 函数名 / 命令 / 联系人），不能写"看代码"这种空话。
- "做到什么算完成"列必须可观察、可检验（看到什么输出/现象）。
- 表末给一句"**接力开工第一步**"：具体动作 → 出现什么现象算正式接上了。

═══════════════════════════════════════
【三、文档结构（按交接对象选一套，逐节完整写出）】
═══════════════════════════════════════
<在此处插入：给人版 12 节结构 / 给 AI 版 14 节结构，逐节列出每节要写什么，见下方"按交接对象插入">

> 结构要求：选定的一套**每一节都要写**，不能跳节、不能合并、不能因为"没内容"就整节删除——没内容也要写"暂无，因为……"。

═══════════════════════════════════════
【四、信息收集方式与真实纪律】
```

### 模式 E：对话全面总结（把整轮对话从最初到结束做全面总结，作为交接文档素材底稿）

> 目标读者是"用户自己"。用户想把自己和某个 AI（通常就是当前对话）从**第一条消息到现在的工作结束**做一个全面、结构化的总结——既为了复盘，更为了**让接下来的交接文档更详细全面**（对话太长时，接手方或目标智能体不可能逐条读聊天记录，总结把全过程压缩成结构化素材）。
>
> **对话总结 ≠ 交接文档**：对话总结是"按时间线回顾全过程"的素材底稿（覆盖最开始的起源 → 中间每一步 → 当前结束）；交接文档是"面向接手方、按四要素组织"的正式交付物。**模式 E 可单独用，也可作为模式 A/B/C/D 的前置**——先总结对话，再用总结去生成更全面的交接文档。

**何时用（触发词）**：
- "把这整轮对话总结一下"
- "从对话最开始到现在的全面总结"
- "总结我们这轮对话，好写交接文档"
- "先做个对话总结再交接"
- "回顾一下整个过程"
- "对话太长，帮我先总结再交接"

**做什么**：从这一轮对话的第一条消息开始，到最后一条，把整段工作过程做全面总结，输出一份**时间线式结构化对话总结**，覆盖下列 10 个模块（**一个都不能少，宁可多不可漏**）：

| # | 模块 | 必须写到 |
|---|------|---------|
| 1 | **对话总览** | 本轮对话的时间范围 / 涉及的项目 / 一句话目标 / 参与者（谁在跟谁对话） |
| 2 | **目标与完成度** | 最初想做什么 → 当前做到哪；完成度百分比（如"约 70%"）+ 判断依据；最后一次停在什么位置 |
| 3 | **分阶段时间线** | 把整轮对话按工作阶段/重大节点切成若干段，每段写：时间/触发点、做了什么、产出、状态（完成/部分/放弃）——**必须覆盖从最初到当前结束，不遗漏中间阶段** |
| 4 | **已完成工作全量清单** | 每条至少 4 字段：做了什么 / 产出物在哪 / 怎么验证有效 / 关键数据与效果 |
| 5 | **未完成工作全量清单** | 每条至少 7 字段：还差什么 / 为什么没做完 / 前置条件 / 优先级 / 做到什么算完成 / 从哪开始 / 验证信号 |
| 6 | **关键决策与原因** | 做过的选型、为什么这么选（大白话理由）、放弃的方案及原因 |
| 7 | **踩坑与解决** | 现象、根因、怎么规避（这是给后人最值钱的部分） |
| 8 | **涉及的文件/命令/数据清单** | 逐个列出：路径 / 一句话用途 / 当前状态（新建/修改/已完成/未动/临时） |

| 10 | **下一步建议** | 基于现状，接手方/自己接下来该做什么（可预告交接文档的③④） |

1. **忠实于对话内容**：每条信息尽量标注出处（哪一阶段/哪次决策/哪句话），不编造。
