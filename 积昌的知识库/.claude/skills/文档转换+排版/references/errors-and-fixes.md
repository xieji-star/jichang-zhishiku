## 第一类：标题/副标题/作者区错误

### E01 副标题使用了长破折号而非 `--`

**症状：** 副标题被当作普通正文渲染（11pt 黑色左对齐），而非 12pt 黑色加粗居中。

**错误写法：**
```markdown
# 文档标题
— 杜绝数据集陷阱，避开 Direct Reject —    ← 用 — 而不是 --
作者：科研华哥
```

**正确写法：**
```markdown
# 文档标题
-- 杜绝数据集陷阱，避开 Direct Reject
作者：科研华哥
```

**根因：** 解析器使用 `startswith('-- ')` 检测副标题。长破折号 `—`（U+2014）不等于两个连字符 `--`。

**修复方案：** 必须使用 `-- ` 前缀。如果副标题有装饰符号，将 em dash 放在 `-- ` 后面。

---

### E02 标题/副标题/作者之间有空行

**症状：** 副标题或作者渲染为 11pt 普通正文而非指定格式（副标题应为 12pt 黑色加粗居中，作者应为 16pt 灰色居中）。

**错误写法：**
```markdown
# 文档标题

-- 副标题文字 —         ← 空行！解析器跳到下一行找不到副标题

作者：姓名              ← 空行！解析器找不到作者
```

**正确写法：**
```markdown
# 文档标题
-- — 副标题文字 —
作者：姓名
```

**根因：** 解析器只检查 `i+1`（紧挨着的下一行）来寻找副标题和作者。空行导致识别失败。

**验证方法：** 检查 PDF 中副标题是否为 12pt 黑色加粗居中（而非 11pt 黑色左对齐）。

---

### E03 副标题左右不对称

**症状：** 副标题左侧缺少 em dash `—`，右侧有，视觉上不对称。

**错误写法：**
```markdown
# 文档标题
-- 副标题 —    ← 解析后 → "副标题 —"（左侧无装饰）
```

**正确写法：**
```markdown
# 文档标题
-- — 副标题 —  ← 解析后 → "— 副标题 —"（两边对称）
```

**根因：** `-- `（两个连字符+空格）是解析器标记，会被 `[3:]` 完全剥离。装饰符号必须写在 `-- ` 的后面。

---

### E04 作者前缀不兼容

**症状：** `著作人：科研华哥` 被当作普通正文，或只显示"科研华哥"而非"著作人：科研华哥"。

**根因：** 原解析器只检查 `作者：` 前缀。`著作人：` 和 `编著：` 未被识别。

**修复方案：** 增加 `elif` 分支：
- `作者：姓名` → 渲染为"姓名"（灰色 16pt，去前缀）
- `著作人：姓名` → 渲染为"著作人：姓名"（保留前缀）
- `编著：姓名` → 渲染为"编著：姓名"（保留前缀）

## 第二类：正文内容处理错误

### E05 内联 Markdown 符号残留

**症状：** PDF 中出现 `**加粗**`、`` `代码` ``、`*斜体*` 等 Markdown 语法符号，影响美观。

**根因：** 解析器只处理结构（标题/列表/高亮框），不处理内联符号。

**修复方案：** 新增 `clean_inline_markdown()` 函数在渲染前清除：
- `**bold**` → bold
- `` `code` `` → code
- `*italic*` → italic

在 `clean_content()` 中遍历所有文本类型并应用清洗。

---

### E06 标签行 `**` 解析错误

**症状：** `**低阶：** However...` 被处理为 `低阶：** However...`（内层 `**` 残留）。

**错误代码：**
```python
text = line.strip('*').strip()  # 暴力清除头尾星号
```

**修复方案：**
```python
close_pos = line.find('**', 2)  # 精确查找关闭标记位置
if close_pos != -1:
    label_text = line[2:close_pos].strip()
    rest_text = line[close_pos+2:].strip()
```

---

### E07 编号列表被合并为一段

**症状：** 三个编号点连成一段，没有分行。

**错误写法：**
```markdown
1. **尊重的姿态：** 邮件开篇必须给出 Manuscript ID。
2. **给编辑台阶：** 将延迟归因于审稿专家寻找困难。
3. **主动提供帮助：** 表达愿意补充数据的意愿。
```

**原行为：** 三个点被当作普通正文合并为一个段落。

**修复方案：** 解析器增加 `\d+\. ` 正则检测，编号行作为独立 `numbered` 类型处理。

---

### E08 排版时删除原文内容

**症状：** 用户反馈"内容少了"——方括号 `【】` 、复选框 `[ ]` 、括号注、流程图等被删除。

**根因：** AI 在"去 AI 味"的名义下擅自删除了事实性内容和格式标记。

**原则：**
- ❌ 不要删除方括号 `【】`、复选框 `[ ]`、箭头 `►`、括号注等语义格式
- ❌ 不要改写原文结构层级
- ❌ 不要用自己的话重新表述原文
- ✅ 排版美化的目的是让内容更好看，不是让内容变少

## 第三类：特殊元素渲染错误

### E09 高亮框内容为空

**严重等级：** 🔴 严重 Bug — 内容完全丢失

**症状：** 蓝色矩形框正常绘制，但框内没有任何文字。

**错误代码（v1）：**
```python
if line.startswith('>highlight'):
    texts = []          # 初始为空
    i += 1              # ← 跳过 >highlight 同行文本！
    while i < len(lines):
        line = lines[i].strip()
        if not line or line.startswith('#'):
            break
        texts.append(line)
        i += 1
    content.append({'type': 'highlight', 'text': ''.join(texts)})
```

**问题 1：** `i += 1` 跳过了 `>highlight` 同行文本，`texts` 始终为空。
**问题 2：** `''.join(texts)` 将多行无缝拼接，`multi_cell()` 被迫在字符中断行。

**修复后代码（v2）：**
```python
if line.startswith('>highlight'):
    text_after = line[len('>highlight'):].strip()  # 抓取同行文本
    texts = [text_after] if text_after else []
    i += 1
    while i < len(lines):
        ...
    content.append({'type': 'highlight', 'text': '\n'.join(texts)})
    #                                                ^^^^^^^^ 修复 2
```

### E10 写作提醒吞噬后续所有内容

**严重等级：** 🔴 严重 Bug — 章节结构完全丢失

**症状：** `---` 后的所有章节标题和正文全部变成红色正文，章节结构消失，文字断在不合理的位置。

**错误代码：**
```python
while i < len(lines):
    line = lines[i].strip()
    if line:
        body_lines.append(line)
    i += 1
    # ↑ 无终止条件，一路消费到 EOF
```

**修复方案：** 添加边界检测：
```python
while i < len(lines):
    line = lines[i].strip()
    if not line:
        i += 1
        continue
    if line.startswith('#') or line == '---':
        break  # 遇到标题或新分隔符停止
    body_lines.append(line)
    i += 1
```

### E11 写作提醒智能换行

**症状：** 写作提醒正文使用 `multi_cell()` 渲染，即使文字刚好能一行显示也按多行逻辑处理。

**修复方案：** 改为"先测宽、再渲染"：
```python
for line in lines:
    self.set_x(MARGIN_L)
    if self.get_string_width(line) <= CONTENT_W:
        # 单行渲染
        self.cell(CONTENT_W, BODY_LH, line, align='L',
                  new_x="LMARGIN", new_y="NEXT")
    else:
        # 自动换行
        self.multi_cell(CONTENT_W, BODY_LH, line, align='L')
```

### E12 写作提醒禁止手动换行

**症状：** 人为将长句拆分为 ≤45 字符的短行，导致内容未填满就换行，行尾参差不齐。

**错误做法：**
```markdown
---
写作提醒
盲目改投是最大的时间浪费：不处理审稿意见直接投下一个期刊，   ← 约31字，行未满
大概率换一批审稿人，看到同样的问题再拒你一次。               ← 约22字，行未满
```

**正确做法：**
```markdown
---
写作提醒
盲目改投是最大的时间浪费：不处理审稿意见直接投下一个期刊，大概率换一批审稿人，看到同样的问题再拒你一次。
审稿人是你最便宜的顶级顾问：别人花几个小时免费帮你找论文的死穴，把意见用透，这篇论文就成了。
```

**原则：** 保持完整句子为一行，让 `multi_cell()` 自然换行。

---

### E13 ASCII 下划线渲染错位

**症状：** `【__________________】`（ASCII `_`）渲染出现文本框错位、空白、文字偏移。

**根因：** ASCII 下划线 `_`（U+005F）是窄字符，连续下划线形成不可断开的"单词"超过行宽时，`multi_cell()` 无法正确断行。

**修复方案：** 替换为全角下划线 `＿`（U+FF3F），与汉字等宽：

| 写法 | 结果 |
|------|------|
| `【__________________】`（ASCII `_` × 18） | ❌ 渲染错位 |
| `【＿＿＿＿＿＿＿＿＿＿＿＿】`（全角 `＿` × 18） | ✅ 正常显示 |

## 第四类：渲染引擎问题

### E14 fpdf2 cell() 渲染 Bug

**症状：** 副标题（12pt 常规字重）在 `cell()` 中不渲染文字，输出为空。

**根因：** fpdf2 已知 bug：常规字重 + 小字号（12pt）+ 无边框时，`cell()` 可能不渲染。

**修复方案：** 副标题使用 `multi_cell()` 代替 `cell()`。

---

### E15 matplotlib 字体警告

**症状：** 控制台输出 "MERG NOT subset; don't know how to subset; dropped"。

**说明：** matplotlib 的字体子集化警告。**不影响 PDF 输出效果**，可以忽略。
