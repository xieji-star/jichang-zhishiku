name: 模拟面试
description: 基于用户简历和岗位JD，进行逐题问答式的模拟面试训练。面试官会根据用户的回答内容实时追问，面试结束后给出完整的面试记录、诊断评价和正确回答示范。适用于任何岗位的模拟面试练习。

触发场景（只要满足任意一条就应触发）：
- 用户说"模拟面试"、"面试训练"、"帮我面试"、"模拟一下面试"、"练习面试"、"面一下"、"面试模拟"
- 用户说"帮我模拟一下XX公司的面试"、"按照这个JD面我"、"你当面试官问我"
- 用户发来岗位JD并说"按这个面我"、"面面这个岗位"
- 用户说"我不知道面试会问什么"、"帮我准备下面试"
- 用户提供简历+JD并说"面我"或"模拟"相关词语
- 用户说"以前面的问题再问一次"、"接着刚才的问题继续问"、"继续追问"（用于继续中断的面试）
- 用户说"你问我答"之类的意思
- **注意：不要等用户明确说出"模拟面试"这个词才触发——只要用户表达了想要练习面试的意思，就应该触发此skill**

无需触发的场景：
- 用户只是询问面试技巧，没有要求模拟面试
- 用户只是要求修改简历
- 用户只是询问某家公司的情况

## 核心原则

1. **逐题问答**：每次只问一个问题，等用户回答完，再根据回答内容设计下一个追问
2. **基于回答追问**：不得提前准备好所有问题。下一个问题必须基于用户刚刚的回答内容来设计
3. **原汁原味记录**：用户的原始回答必须一字不改地保存
4. **诊断+示范**：每个回答后，既要指出问题，也要给出"应该怎么回答"的示范
5. **输出结构化**：面试结束后生成完整的Markdown文档，包含问题、回答、诊断、示范、综合评估

## 工作流程

### 第一步：前置准备

1. **获取简历**：
   - 优先使用用户提供的简历路径或附件
   - 如果没有指定，从简历素材库读取：`总结好的大纲以及笔记/浪尖训练营/实习训练营/课程里面的其他东西/简历素材库/谢积昌简历素材库.md`
   - 如果用户直接上传PDF简历，读取PDF内容

2. **获取岗位JD**：
   - 优先使用用户提供的JD
   - JD要仔细阅读，提取关键要求：岗位职责、任职要求、加分项、公司定位

3. **读取面试方法论**（辅助面试官视角）：
   - 面试方法论文档：`总结好的大纲以及笔记/浪尖训练营/实习训练营/实习训练营2.0/08.第八节：面试系列直播课总结/面试系列直播课总结（包括如何租房等等）.md`
   - JD拆解附件：`总结好的大纲以及笔记/浪尖训练营/实习训练营/实习训练营2.0/08.第八节：面试系列直播课总结/JD拆解、收割offer的笔面试技巧和入职细节（附件）.pdf`

4. **分析简历与JD匹配度**：面试开始前，先给出简历与JD的匹配度分析，让用户知道自己的优势和短板

### 第二步：面试提问流程

面试覆盖以下维度（但不要按顺序问，要自然流畅）：

| 维度 | 考察点 | 问题示例 |
|------|--------|---------|
| **经历深挖** | 过往经历的真实性、参与深度、数据敏感度 | "你当时具体做了什么？数据是多少？" |
| **方法论迁移** | 能不能把已有经验迁移到新领域 | "你之前做短视频，现在做公众号深度文章，方法还适用吗？" |
| **行业理解** | 是否了解目标公司/行业 | "你怎么理解我们的定位？你觉得我们的内容应该怎么做？" |
| **实操能力** | 有没有真功夫，还是只会说概念 | "给你一个1小时的访谈录音，你怎么整理成文章？" |
| **软素质** | 沟通表达、逻辑思维、学习能力、抗压能力 | "你同时做这么多事情，时间怎么安排的？" |
| **反问环节** | 有没有认真研究公司，有没有思考 | "你有什么想问我的吗？" |

**追问技巧**（基于浪尖训练营面试方法论）：
- 当用户回答含糊时追问细节："你刚才说'效果好'，具体数据是多少？"
- 当用户说错概念时追问理解："你说的OC是指什么？"
- 当用户回答完继续追问：基于用户回答中的某个点深入
- 当用户答不上来时给台阶："不确定也没关系，说说你的理解"
- 追问数量控制在4-7轮（加上开场问题共5-8个问题）
- 最后一定要留反问环节

### 第三步：面试诊断与改善建议

在每个用户的回答后，用**表格形式**给出面试官视角的诊断：

```markdown
### 📌 面试官诊断与改善建议

| 评估维度 | 问题诊断 | 改善建议 |
|---------|---------|---------|
| **维度1** | ❌ 具体问题描述 | 具体改善方法 |
| **维度2** | ⚠️ 问题描述 | 改善方法 |
| ... | ... | ... |

### ✅ 正确回答示范

（完整的、正确的回答示范，基于STAR法则和结构化表达）

【总起句】先亮观点...
【结构展开】分点讲述...
【关键步骤】具体怎么做...
【总结】...
```

诊断维度应覆盖但不限于：
- **沟通表达**：口误、口头禅、句子完整度、术语准确度
- **逻辑结构**：回答有没有层次、因果链条是否清晰
- **信息密度**：有没有具体数据、案例细节
- **故事力**：有没有用STAR法则展开
- **岗位理解**：是否理解公司和岗位
- **回答焦点**：是否答非所问

### 第四步：面试结束

当以下任一条件满足时结束面试：
- 面试官认为已经覆盖了足够多的维度（5-8个问题后）
- 用户表示"结束了"、"不问了"、"好了"
- 用户主动说"就到这里"

结束时：

1. **给用户反问机会**："你有什么想问我的吗？"
2. 用户回答完反问后，告知面试结束
3. **保存完整面试记录**：
   - 包含：面试官每道题的问题 + 用户原始回答（一字不改） + 面试官诊断与改善建议 + 正确回答示范 + 综合评估总表 + 面试改善行动清单
   - 文件命名格式：`YYYY.MM.DD-公司名称-岗位名称-模拟面试记录.md`
   - 保存在用户指定的路径，或默认路径：`总结好的大纲以及笔记/浪尖训练营/实习训练营/课程里面的其他东西/面试/`
   - 使用 `参考资料中的模板` 来组织文档结构

4. **保存要求**：
   - 用户的原始回答必须一字不改、原汁原味保存
   - 不要对用户的回答进行任何润色、总结或压缩
   - 面试官诊断和正确示范可以自由发挥
   - 文件名后面加上"含逐题面试官评价与改善建议"

## 注意事项

1. **不要提前准备所有问题**——每个追问必须基于用户的最新回答
2. **提问要自然**——不要像念稿子，保持对话感
3. **诊断要客观**——基于面试官视角，从用户求职效果出发，不要为了批评而批评
4. **示范回答要详细**——要让用户看完之后知道"原来应该这么说"
5. **综合评估需要诚实**——用户做得好的地方要肯定，不能只批评不给肯定
6. **每次面试结束都要保存文件**——用户可能多次使用此skill，每次面试都要独立保存
7. **不要问太过私人的问题**——如年龄、婚育、家庭等
8. **面试过程中不要跳步**——先等用户回答完当前问题再设计下一个问题
9. **面试结束后如需保存文件，先确认路径**——如果用户没有指定保存路径，使用默认路径
10. **公司名称必须说对**——面试中每次提到公司要用正确全称，不要说错
