## 概述

HTTP 400、403 和 502 错误是 Web 开发中最常见的客户端/服务端错误。本页汇总了三类错误的常见原因、调试方法和修复策略。

## 核心要点

### HTTP 400 Bad Request

- **原因**：请求语法错误、参数格式不正确、请求头过大
- **常见场景**：JSON 格式错误、参数类型不匹配、Cookie 过大
- **调试方法**：检查请求体格式、验证参数类型、查看服务端日志

### HTTP 403 Forbidden

- **原因**：服务器理解请求但拒绝执行。与 401（Unauthorized）不同，403 表示服务器已识别请求方身份但拒绝授予访问权限
- **常见场景**：
  - 文件/目录权限不足（如 Linux 文件权限设置不正确）
  - 访问控制配置（.htaccess、Nginx deny 规则、WAF 拦截）
  - 缺少索引文件（目录无可用的 index.html/index.php）
  - 防盗链设置（Referer 头检查不通过）
- **调试方法**：`tail -f /var/log/nginx/error.log` 检查服务器日志；`ls -la` 检查文件权限；暂时关闭 WAF 排除拦截因素
- **修复方案**：`chmod 755` 修复目录权限；检查 Allow/Deny 规则；WAF 误报时添加白名单；添加索引文件或关闭目录列表

### HTTP 502 Bad Gateway

- **原因**：上游服务不可达、网关超时、代理配置错误
- **常见场景**：后端服务宕机、反向代理配置错误、防火墙拦截
- **调试方法**：检查上游服务健康状态、验证代理配置、查看网关日志
